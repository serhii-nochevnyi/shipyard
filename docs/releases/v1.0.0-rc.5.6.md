# Shipyard 1.0.0-rc.5.6

Patch prerelease based on `v1.0.0-rc.5.5`.

## Fixed

- Push checks use a native Git `pre-push` hook and Git-supplied commit IDs, including non-HEAD and multiple branch updates. The destination branch selects the open PR and its base; repository-qualified graph records and configured integration branches provide explicit fallbacks. Dirty working-tree edits and Bash command spelling no longer decide a push. Refusals report the selected base, its source and file/line findings.
- Native hook installation preserves existing hooks, their arguments and stdin, relative hook paths and linked worktrees. Its immutable payload survives removal of the plugin cache. Managed publication installs the hook before pushing; a conflicting Git override or modified managed hook is refused.
- Executor hosts can finish eligible clean committed work after authenticating the dispatch and approved plan and verifying the exact tree again. A signed attestation retains the original commit. Changed HEAD with a dirty tree, missing work, scope violations and stale verification remain refusals.
- Executor manifests retain authenticated immutable history. Locked preparation permits a fresh attempt without overwriting the old artifact; legacy migration requires the original manifest digest and boundary receipt.
- CI request builders reject external, symlinked, empty or changed evidence before emitting a request. Launch, wait and status expose `boundary_store`; host results also expose `run_id` and `run_store`. Canonical graph and project selectors reach publication gates.
- Comment checks distinguish committed Git blobs from working-tree snapshots, including shortened or absent disk files. Repository-scoped functional annotation and bounded PHPDoc rules preserve configured tags such as `@ai-generated`, `@dataProvider` and `@var`; cleanup preserves accepted documentation and rejects malformed annotations.
- Gate 2 checks exact tracked path spelling in the project or configured target checkout. Reviewed, pinned `case_only_renames` declarations reach executor and repair hosts and the trusted finalizer without relaxing unrelated collision checks.
- Claude installation retains script bundles outside the prunable version cache. Codex generation binds its own bundle root instead of baking in an ambient Claude script path.
- Jira export accepts `--ticket` and includes only its dependency closure and required epics/links. Bounded descriptions reserve acceptance criteria and the source-plan pointer. Empty Jira transition configuration provides a status-name mapping hint while projection stays off until configured.
- A proven own-project repository mapping no longer produces the adoption warning; a foreign mapping still does.
- Front, arm and stop share the authenticated run, ticket and canonical graph, including external graphs. Scoped stop refuses missing owned state, filters journal movement to owned dependencies, preserves another session's ledger and avoids waking the model for unchanged repeated observations.

## Upgrade

Refresh the installed plugin and host components. Managed publication installs the native hook automatically. To cover manual pushes from an existing checkout, run the native hook installer once for that checkout; see README's native push instructions. The legacy Bash tool interceptor no longer infers Git pushes from command text.

Functional comment exceptions are opt-in per repository through `pipeline.comment_docblocks`. Jira projection remains opt-in through `pipeline.jira_transitions`, using status names from the target workflow rather than hard-coded transition IDs.

## Validation

Regression coverage includes real local Git pushes and hook composition, immutable cache pruning, committed snapshots, signed executor recovery on both hosts, historical publication recovery, reviewed case-only renames, evidence containment, graph forwarding and two-session stop isolation. The final independent implementation review is clean.

Release-specific package, unit, smoke and metadata verification is recorded separately. Local fixtures do not substitute for fresh live receipts for both runtimes bound to the final release commit tree; `scripts/release.sh` enforces that requirement before creating a tag. No live GitHub/Jira workflow or publication is claimed by these notes.
