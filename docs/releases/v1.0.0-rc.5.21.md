# Shipyard 1.0.0-rc.5.21

Patch prerelease based on `v1.0.0-rc.5.20`.

## Fixed

- **A Codex review or CI fix is no longer refused after its primary parent was squash-merged.** Before a new repair, the Codex delivery host re-checks the scope of the earlier repair attempts on the same PR. That includes the base they ran against. When the base had moved, the host accepted the move only if the old base was a Git ancestor of the new one.
  - A squash merge writes a new commit on the destination, so the parent PR's head never becomes an ancestor of the new base. A ticket stacked on its parent had its base moved to the epic when the parent was squash-merged. Its next repair was then refused with `confirmed host output lacks authenticated base evolution`, though the move was the normal one.
  - In a native Codex delivery, a criteria fix on #873 was refused after its primary parent #871 was squash-merged.
- **A squash landing of the primary parent is now accepted as proof, checked live.** Git ancestry is still the first proof. When it is missing, the host accepts the move only when all of these hold:
  - the base moved from the ticket's primary parent branch to the destination the board records for that parent, and the board marks the parent `merged`;
  - GitHub reports the parent's PR as `MERGED` from that branch into that destination;
  - the old base is the PR's final head or an ancestor of it, which covers a parent that received more commits after the earlier repair;
  - the PR's squash commit is in the new base and matches the `merge_sha` on the board when one is recorded.
  - Every commit the new base brings in is still signature-checked as before. A base move with ancestry still needs no GitHub call.
  - The recorded proof is checked again whenever the earlier attempt's historical coverage is re-verified. A changed squash commit or parent head is refused.
  - A base move onto a retired epic's integration branch is still refused.
- **Claude delivery is not affected.** Its repair host resolves the base live for every repair and reconciles a moved base by merging it. It does not compare an earlier base with the current one.

## Validation

Codex host cases run against real signed commits. The parent has two commits, and the epic receives their squash and a later commit:
- the squash move is accepted with the parent, PR, head, squash commit and destination recorded, and both imported commits are signed;
- an ancestral move makes no GitHub call;
- refusals cover a PR that is not merged, a different destination, a parent head unrelated to the old base, a new base without the squash commit, a move from another branch, a parent the board does not mark merged, and a board `merge_sha` that differs;
- the recorded proof re-verifies, and a changed squash commit, a changed parent head or a removed proof are refused.

A real GitHub squash commit from a delivery project verifies with `Good signature` from GitHub's web-flow key on the release host.

Release verification results are recorded in the published prerelease.
