# Shipyard 1.0.0-rc.5.23

Patch prerelease based on `v1.0.0-rc.5.22`.

## Fixed

- **Decomposition creates the phase `VALIDATION.md` the GSD checker requires.** In GSD's own `/gsd-plan-phase`, the coordinator writes `NN-VALIDATION.md` from GSD's template at step 5.5. It does so after research and before the planner, when Nyquist validation is on and the research has a `## Validation Architecture` section.
  - Shipyard decomposition skipped that step. The GSD plan checker then blocked with `VALIDATION.md not found`.
  - The planner revision could not repair it, because the planner may write only `CONTEXT.md` and its `PLAN.md` files, and any other phase file is refused as `FOREIGN_EDIT`.
  - This happened in two consecutive phases of a delivery project.
- **The decomposition host now seeds it, on both runtimes.** Before the planner launch, and before the planner's snapshot and containment baseline, the host creates `NN-VALIDATION.md` from the runtime's own GSD template: `~/.claude/gsd-core/templates/VALIDATION.md` or `~/.codex/gsd-core/templates/VALIDATION.md`.
  - It fills only the template's phase, slug and date fields.
  - It runs only when `workflow.nyquist_validation` and `workflow.research` are not turned off and the phase research has a `## Validation Architecture` section.
  - It never overwrites an existing file.
  - A missing template is refused with its path.
  - The seeded file is part of the planner's baseline, not a planner output, so the planner seal, containment and recovery are unchanged.
- **Unresolved research Open Questions now have a revision path.** The GSD checker requires the research's `## Open Questions` to be marked `RESOLVED`. Only the researcher may write `RESEARCH.md`, so the planner-only revision loop could never clear that finding.
  - The decompose command now sends research findings to a researcher revision first, with the checker findings and the current `CONTEXT.md` and plans in its prompt.
  - A question may be marked `RESOLVED` only where `CONTEXT.md` or a plan actually decides it, and the researcher names that decision. A question nothing decides stays open and leads to a block for a person.
  - The context packet is then rebuilt, the planner revised and a fresh checker run. The three dispatches count as one revision cycle.
  - The read-only checker refusal now names both revision paths.

## Validation

- Claude decomposition host cases:
  - the planner launch seeds `38-VALIDATION.md` with the phase number, slug and date;
  - the planner seal still holds only `CONTEXT.md` and the plans;
  - an existing strategy is not overwritten;
  - nothing is seeded with Nyquist off or without a Validation Architecture section;
  - a missing template refuses;
  - a researcher revision after a planner seal marks the Open Questions resolved, and the next planner and checker run on it;
  - a planner that edits `RESEARCH.md` is still refused.
- A Codex decomposition host case runs a native planner through the CLI with a template in `CODEX_HOME`. It shows the seeded file is outside the planner's completed changes.

Release verification results are recorded in the published prerelease.
