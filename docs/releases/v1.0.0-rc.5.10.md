# Shipyard 1.0.0-rc.5.10

Patch prerelease based on `v1.0.0-rc.5.9`.

## Fixed

- **Codex drift-check request.** The request printed by `deliver-dispatch.cjs build drift-check <T> --runtime codex` is now accepted by `codex-delivery-host.cjs --args-file`. Since `v1.0.0-rc.5.5` the builder has written the absolute canonical `graph_dir`, but the host accepted that field only for review and repair roles and refused the drift-check request before launch. The selector is still checked: it must be absolute, it must pass the same canonical-graph check as `--graph-dir` and `SHIPYARD_GRAPH_DIR` (a main checkout, a graph tracked at `HEAD`, or a linked project worktree graph), it must hold the scoped ticket, and it may not conflict with a host graph option. Roles that do not take a graph selector still refuse it.
- **Drift-check ticket binding.** Before launch, the Codex host now checks that the drift-check worktree is on the branch the canonical graph records for the ticket, as the builder and the executor already did. A request naming a graph whose ticket row points at another branch is refused with `SCOPE_MISMATCH`.

## Validation

Unit cases feed the builder's exact Codex drift-check output, including one built from a ticket worktree against a linked project worktree graph, through the host request reader. They also launch drift-check through the host CLI on a main-checkout graph and on a linked project worktree graph. Relative selectors, an untracked graph copy in another repository's worktree, a directory without a graph, a ticket worktree's graph without the ticket, a graph whose ticket branch differs from the worktree and a `graph_dir` on the executor role are refused before launch. Release verification results are recorded in the published prerelease.
