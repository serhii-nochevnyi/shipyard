# Shipyard 1.0.0-rc.5.14

Patch prerelease based on `v1.0.0-rc.5.13`.

## Fixed

- **A review part states every bound the host enforces.** A part of a split integrator or code review was told only that its answer must stay within 32 KiB. The host also refused a part `summary` over 2048 UTF-8 bytes, and `limitations` or `unresolved_sources` entries over 1024 bytes. Two native Codex integrator runs returned part summaries of 7573 and 5947 bytes, and both were refused with `summary must be a non-empty string of at most 2048 bytes`.
  - The part limits are now one shared definition in `code-review-core.cjs`. The part prompt, the part output schema and the host check all read it.
  - Every part prompt now gives each limit: a short summary of at most 2048 UTF-8 bytes, with evidence and detail in findings; at most 128 list entries of at most 1024 bytes each; at most 128 findings.
  - JSON Schema counts characters and the host counts UTF-8 bytes. So the schema allows a quarter as many characters as the byte limit (512 for the summary, 256 for a list entry). An answer that fits the schema therefore passes the host check in any script.
  - A refusal now names the field, its actual size and the limit, for example `part summary is 7573 UTF-8 bytes; the limit is 2048 bytes`. The 32 KiB whole-part refusal and the list-entry refusals report their sizes the same way.
- **A part that breaks only its output format is reviewed again once.** When the host refuses a part answer for its format, it relaunches that part once.
  - The retry is a new launch with its own dispatch and durable receipt. It uses the same authenticated packet, and a host-written line states the refusal.
  - The host never truncates or edits an answer, and does not weaken the check. A part that is still refused after the retry ends the run, and the message says a retry was made.
  - Receipt, identity, custody, transcript and worktree refusals are never retried. Neither is the final reviewer.

## Validation

Core cases cover a part summary that is missing, empty, whitespace-only, valid, exactly at the 2048-byte limit and one byte over, in ASCII, Cyrillic and four-byte emoji. They also check that text at the schema's character limit passes the byte check in each script, cover the list and entry limits with sized refusals, and check the bounds in the prompt. Further cases show that only a part-format refusal is retried, and only once.

Native Codex integrator cases with several parts cover three paths:
- a multibyte summary at the byte limit seals;
- an oversized summary is relaunched once with the refusal, and the final reviewer seals over the retried part;
- a part still oversized after its retry is refused with its size, and no final or evidence follows.

A Claude integrator case covers the relaunch with the refusal and the sealed final.

On the rc.5.13 host the retry case fails with the reported `summary must be a non-empty string of at most 2048 bytes`. A Codex code-review part case checks the bound in the prompt, the sized refusal, and that the retry keeps the authenticated packet. Release verification results are recorded in the published prerelease.
