# Shipyard 1.0.0-rc.5.14

Patch prerelease based on `v1.0.0-rc.5.13`.

## Fixed

- **A review part states every bound the host enforces.** A part of a split integrator or code review was told only that its answer must stay within 32 KiB. The host also refused a part `summary` over 2048 UTF-8 bytes, and `limitations` or `unresolved_sources` entries over 1024 bytes. Two native Codex integrator runs returned part summaries of 7573 and 5947 bytes, and both were refused with `summary must be a non-empty string of at most 2048 bytes`.
  - The part limits are now one shared definition in `code-review-core.cjs`. The part prompt, the part output schema and the host check all read it.
  - Every part prompt now gives each limit: a short summary of at most 2048 UTF-8 bytes, with evidence and detail in findings; at most 128 list entries of at most 1024 bytes each; at most 128 findings.
  - JSON Schema counts characters and the host counts UTF-8 bytes. So the schema allows a quarter as many characters as the byte limit (512 for the summary, 256 for a list entry). An answer that fits the schema therefore passes the host check in any script.
  - A refusal now names the field, its actual size and the limit, for example `part summary is 7573 UTF-8 bytes; the limit is 2048 bytes`. The 32 KiB whole-part refusal and the list-entry refusals report their sizes the same way.
- **A part whose answer breaks a stated bound is reviewed again once.** When the host refuses a parsed part answer because a bound or field is wrong, it relaunches that part once. An answer that is not one JSON object is not retried.
  - The retry is a new launch with its own dispatch and durable receipt. It uses the same authenticated packet, and a host-written line states the refusal.
  - The host never truncates or edits an answer, and does not weaken the check. A part that is still refused after the retry ends the run, and the message says a retry was made.
  - Receipt, identity, custody, transcript and worktree refusals are never retried. Neither is the final reviewer.
- **The final integrator reviewer is told its bounds.** The final reviewer was not told two limits the host enforced.
  - A part-blocker `justification` over 1024 UTF-8 bytes was refused only as `each part BLOCKER needs one justified disposition keyed by its ref`. The final prompt now states the limit, and the refusal names the disposition, its size and the limit.
  - The whole answer, `evidence_markdown` included, must fit 128 KiB. The integrator and code-review final prompts now state this bound. On both runtimes the refusal now reports the actual size and the limit.
  - The integrator reference documents both limits.
- **The arch-review and code-review final reviewers are told their result bounds.** The Codex host refused a review answer over 128 KiB, or an `evidence_markdown` over 96 KiB, but neither prompt stated these limits.
  - The arch-review and code-review final prompts now state both limits on both runtimes. The text comes from the arch-review constants that the host checks.
  - An oversized `evidence_markdown` refusal now reports its size and the limit, for example `evidence_markdown is 98305 UTF-8 bytes; the limit is 98304 bytes`.
  - The arch-review and code-review references document both limits.
- **The Claude GSD planner starts again with GSD 1.21.**
  - The Claude decomposition host builds a GSD role prompt by inlining every `@~/.claude/gsd-core/...` reference recursively. It also inlined references inside fenced code blocks.
  - In GSD 1.21, `gsd-planner` reaches `templates/phase-prompt.md` through `references/planner-guidance.md`. That template quotes the executor's `execute-plan.md`, `summary.md` and `checkpoints.md` inside a markdown fence, as literal lines the planner copies into every PLAN.
  - Inlining them, together with `git-integration.md`, added about 98 KB. The planner prompt grew to about 265 KiB, so every planner launch was refused over the 256 KiB limit, and the planner would have seen the executor's documents in place of the lines it must copy.
  - A reference inside a closed fenced block now stays literal. A fenced block opens on a line that starts with three or more backticks or tildes, indented at most three spaces, and closes on a line of the same character that is at least as long.
  - An inline triple backtick, a closer with a different character and an unclosed fence protect nothing, so the references after them are still inlined and no text is lost.
  - On the installed GSD 1.21.0 the planner prompt is now 194 KiB with 18 references, and the executor documents are no longer inlined. The plan-checker prompt is 88 KiB and the phase-researcher prompt is 61 KiB. The 256 KiB limit is unchanged.

## Validation

Core cases cover a part summary that is missing, empty, whitespace-only, valid, exactly at the 2048-byte limit and one byte over, in ASCII, Cyrillic and four-byte emoji. They also check that text at the schema's character limit passes the byte check in each script, cover the list and entry limits with sized refusals, and check the bounds in the prompt. Further cases show that only a part-format refusal is retried, and only once.

Native Codex integrator cases with several parts cover three paths:
- a multibyte summary at the byte limit seals;
- an oversized summary is relaunched once with the refusal, and the final reviewer seals over the retried part;
- a part still oversized after its retry is refused with its size, and no final or evidence follows.

A Claude integrator case covers the relaunch with the refusal and the sealed final.

Other cases check that the integrator final prompt states the justification and 128 KiB bounds, that the arch-review prompt on both runtimes and the Codex code-review prompt state the 128 KiB and 96 KiB bounds, that an oversized code-review evidence is refused with its size, that an oversized justification is refused with its size, and that the hosts and the shared definition use the same 128 KiB value.

Decomposition host cases cover the fenced-block rules:
- references inside backtick and tilde fences, and inside a longer fence that contains a shorter one, stay literal byte for byte, while the references around them are inlined;
- an inline triple backtick, a mismatched closer and an unclosed fence protect nothing and lose no text;
- a fixture with the sizes of the GSD 1.21 chain from planner guidance to the PLAN template fits 256 KiB and keeps the executor documents out of the prompt.

The fixture overflows the limit when the template has no fences. On rc.5.13 the fixture and the literal-fence case fail.

On the rc.5.13 host the retry case fails with the reported `summary must be a non-empty string of at most 2048 bytes`. A Codex code-review part case checks the bound in the prompt, the sized refusal, and that the retry keeps the authenticated packet. Release verification results are recorded in the published prerelease.
