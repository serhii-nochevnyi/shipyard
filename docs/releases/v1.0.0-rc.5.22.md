# Shipyard 1.0.0-rc.5.22

Patch prerelease based on `v1.0.0-rc.5.21`.

## Fixed

- **A Codex repair after a squash-merged parent now also accepts the child's own merges of that parent.** rc.5.21 accepted the move of the base itself. The host then walks the child branch's history from the earlier attempt's head to the current head. It accepts a commit there only if it is one of these:
  - a host-finalized source commit;
  - a commit the new base brought in;
  - a base merge whose second parent is in the new base.
  - When the child had merged an updated parent head before the parent was squash-merged, the parent's commit and the child's merge of it fit none of these, because the squash keeps no ancestry to them.
  - On #873 the sequence was: parent #871 got a new head `075f81af`, #873 merged it (`1c0e3c73`), #871 was squash-merged (`0ea914b4`), #873 imported the phase branch (`95af7c2e`), and a native CI fix followed (`f2bda159`). The next repair was refused with `confirmed host output lacks an authenticated covered source transition: base import changed its source parent`.
- **The squash proof now covers the parent's own history.**
  - It records the parent commits between the earlier base and the proven parent PR head, and verifies each commit's signature.
  - The walk counts those commits as imports with `semantic_credit: false`.
  - A base merge may now have as its second parent the proven parent head or an ancestor of it, but only when a squash proof exists. Its first parent must still be the previous source commit, its tree must still equal the exact conflict-free `git merge-tree` result, and its signature must still be the expected signer's.
  - Re-verifying historical coverage recomputes the parent commit list and refuses any difference.
  - A merge of a commit outside the new base and the proven parent history is still refused, and so is a merge whose tree differs from the exact merge.

## Validation

A Codex host case builds the #873 graph from real signed commits, in this order: the child merges the updated parent, the parent is squash-merged, the child imports the epic, and a native fix follows.
- Every commit is classified as a parent import, a parent merge, an epic import, an epic merge or the native source commit, and no import or merge earns credit.
- Without the squash proof the same walk refuses with the message #873 hit.
- The recorded walk re-verifies, and a recorded parent commit list that was emptied is refused.
- Refusals cover a merge of a foreign parent, a parent merge whose tree was changed, an unsigned parent merge, and an unsigned parent commit.

Release verification results are recorded in the published prerelease.
