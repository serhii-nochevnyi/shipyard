# Shipyard 1.0.0-rc.5.19

Patch prerelease based on `v1.0.0-rc.5.18`.

## Fixed

- **The Claude decomposition host and the routing policy accept the same `complexity` values.** Before this release, the two used different lists, so a research launch could be refused whatever value the agent picked:
  - the host's request check (`claude-decompose-host.cjs`) accepted `simple`, `moderate`, `complex` and `very-complex`;
  - the routing policy accepted only `normal` and `very-complex`.
  - In a native Claude decomposition, a `gsd-phase-researcher` request with `complexity: complex` passed the host. It was then refused at launch with `signals.complexity "complex" is not normal or very-complex`.
  - Retrying with `normal`, the value the refusal pointed to, would have been refused by the host itself with `invalid complexity signal`. Only `very-complex`, or no signal, passed both.
- **One list.** The policy now exports `COMPLEXITY_SIGNALS` (`normal`, `very-complex`), validates against it, and the decomposition host checks requests against the same list.
  - The host refusal names the value and the allowed values: `invalid complexity signal "complex"; use normal or very-complex, or omit it`.
  - The decompose command states that `complexity` takes only `normal` or `very-complex`, and should be omitted unless the phase is very complex.
  - The policy grid and fingerprint are unchanged. Only `very-complex` escalates research, as before.

## Validation

A decomposition host case runs a set of values through both the host check and the policy: `normal`, `very-complex`, `simple`, `moderate`, `complex`, `Normal` and the empty string. For each, the host accepts the value exactly when the policy resolves it. Each host refusal names the allowed values, and a request without the signal still passes. The `adr-014.v9` fingerprint is unchanged. Release verification results are recorded in the published prerelease.
