# Shipyard 1.0.0-rc.5.9

Patch prerelease based on `v1.0.0-rc.5.8`. It fixes defects reported from a real multi-repository delivery and adds two configuration keys.

## Fixed

- **Pre-push after a base merge.** The comment policy no longer scans comments inherited from the PR base. On a fast-forward push whose PR base is verified, the native pre-push gate scans `merge-base(origin/<base>, head)..head`, which is the PR diff that CI also checks. Comments the ticket adds, including ones added while resolving a merge conflict, are still blocked. The PR base must come from the live PR or the delivery board and must be a real `origin/<base>` sharing history with the head. A force push, an unverified base or a push base with no shared history keeps the old remote-range scan or refuses.
- **Base after the epic lands.** Once the phase epic PR is verified `MERGED` into the integration branch, with a merge commit and no open epic PR, every consumer resolves the integration branch: the delivery board, `ticket-base`, the worktree cut, executor and drift dispatch, the new ticket PR, review context and both delivery hosts. This applies to a ticket whose open PR already targets that branch, and to a pending or branched ticket with no PR yet, including one whose parent was merged into the integration branch after the epic landed. Repeated syncs keep it after a squash merge. The parent's `merged_into` provenance is unchanged. A closed-unmerged epic, an epic merged elsewhere, a missing merge commit, a PR retargeted while the epic is still open, or a parent merged into the integration branch while the epic is unverified keep the epic base and the refusal. Architecture evidence bound to the epic base is not accepted for the new base.
- **Research and context file names.** Phase artifacts are resolved in their unpadded (`1-RESEARCH.md`), zero-padded (`01-RESEARCH.md`, as GSD writes them) and directory-prefixed forms, and duplicates are refused. The Claude researcher seal, the Codex research artifact, decomposition context and delivery context references all use the same resolver. Phases below 10 no longer lose their research in later context.
- **Phase directory lookup.** A missing phase directory now names the searched root, the expected `.planning/phases/01-<slug>/` pattern and the remedy: add the phase to ROADMAP.md and run the decompose GSD chain. A configured GSD `project_code` directory prefix is recognised.
- **Plan checker role.** The checker is read-only, as GSD's own checker is. When it reports `issues_found`, decomposition re-dispatches the planner with the findings and then runs a fresh checker, for up to three revision cycles before blocking for a human. A checker that edits phase files is refused with a message that names this loop.
- **Stale planning writer lease.** A new decomposition run can take over a lease whose holder process has exited, after it confirms that no native child recorded in the holder's launch directory is still running. The epoch is fenced. Leases written without a launch directory keep the time-based expiry.
- **SSH commit signing.** Delivery hosts and the commit finalizer support `gpg.format=ssh`. The signer fingerprint comes from `ssh-keygen` for a public key path, a private key path with a sibling `.pub`, or a `key::` literal. Verification uses a temporary allowed-signers file for that call only and never changes user configuration. OpenPGP is unchanged, and `x509` is refused with a clear message.
- **Jira projection safety.** A primary-label hit whose `Source of truth` names a different plan or repository is refused, never updated. The refusal names both pointers and the remedy. A description without a `Source of truth` line is updated as before, with a warning.
- **Graph in a linked project worktree.** An untracked `.planning/graph` in a linked worktree on a non-delivery branch is resolved and accepted as canonical when its tickets are not a copy of the main checkout's graph. Ticket and epic worktrees with graph copies are still refused. Ticket worktrees of such a graph name it with `--graph-dir` or `SHIPYARD_GRAPH_DIR`. Codex phase code and architecture review accept the same graphs.

## Added

- `delivery_pipeline.epic_jira` maps a phase number or phase directory to the epic's own Jira key. The key names the epic branch when PR hygiene is on and is used for the epic's Jira update. Without it, the epic still takes the first ticket's key.
- `delivery_pipeline.executor_sandbox` lets executors and repairs write to declared toolchain caches (`allow_write`) and, on Claude, reach declared hosts (`allowed_domains`). Paths are resolved before launch, and the home directory, worktree ancestors, the repository and host-owned state are refused. Codex applies only `allow_write` and keeps executor network access off.

## Earlier fixes

The planning host derives its changed paths from its own delta (HS-13, #596), and the sentinel merge gate no longer requires executor coverage evidence (HS-07 #587, HS-08 #589). Both have shipped since `v1.0.0-rc.1`. Users on `v0.74.0` get them by moving to this prerelease line.

## Upgrade

Refresh the plugin and host components on both runtimes. Projects that keep `.planning` in a linked worktree can drop the main-checkout workaround. Operators who patched `pipeline.epic_jira` locally should move it to `delivery_pipeline.epic_jira`.

## Validation

Regression coverage was added for every item above, using real temporary Git repositories for the pre-push, signing, lease and graph cases. Release verification results are recorded in the published prerelease.
