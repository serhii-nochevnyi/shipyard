# Shipyard 1.0.0-rc.5.24

Patch prerelease based on `v1.0.0-rc.5.23`.

## Fixed

- **The typed GSD researcher can run on the decomposition planning subject again.** The run contract accepted the planning subject `phase=N;input=…;repository=…` only for the `decomposition` role, which is used by the planner and the checker. The typed GSD phase researcher runs with the `research` role, so its run was refused before any model launch with `ticket phase=29;input=INV-030-…;repository=… must use the T-... identifier form`.
  - The same check also failed on reading. A Codex decomposition run store that already held an authenticated, completed INV planning-research run became unreadable, which blocked every later run in that namespace.
- **The research role now shares the planning subject, for an INV input only.**
  - Phase and repository are validated exactly as for the planner: the subject phase must equal the run phase, and the subject repository must equal the run's repository identity.
  - An ADR input stays planner-only, so direct-ADR research is still refused.
  - Executor, integrator, drift-check and repair roles are still refused for any planning subject.
  - Existing records are read as they are. No schema changed, and nothing is migrated or rewritten.
  - Claude decomposition is unaffected: its host runs every typed role under the `T-<phase>-DECOMPOSE` ticket.

## Validation

Run-contract cases cover:
- the researcher, planner and checker all accepted on one INV planning subject;
- a wrong phase, a foreign repository and direct-ADR research refused;
- executor, integrator, drift-check, CI-fix and review-fix roles refused.

A run-store case writes a store holding a historical INV planning-research run. It reads unchanged, byte for byte, and then accepts new planner and researcher runs. On the rc.5.23 contract both cases fail with the reported `must use the T-... identifier form`.

The affected delivery project's real Codex decomposition run store was read with the fixed validator, read-only. All of its runs, including the completed historical INV-028 research run, were accepted, and the file's SHA-256 was unchanged before and after.

Native acceptance of the repaired researcher callback still needs a real decomposition run after this release is installed.

Release verification results are recorded in the published prerelease.
