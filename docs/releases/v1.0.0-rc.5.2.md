# Shipyard 1.0.0-rc.5.2

Patch prerelease based on `v1.0.0-rc.5.1`, from the prerelease branch.

## Fixed

- Codex validates the first standalone computed `TASK_SHA256` text item in the first tool call, preserving structured output order. Only the known standalone runtime framing item is ignored. A truncation warning before the digest, a digest embedded in body text, a later marker, or plaintext delivery without first-call proof refuses with `TASK_RELAY_UNVERIFIED`.
- The relay asks for a digest-only first command and bounded subsequent reads, protecting proof from nested and outer output truncation.
- Both Codex and Claude Code checker hosts require an explicit semantic verdict: `pass`, `issues_found`, or `blocked`, with a short explanation and findings. Missing, malformed or contradictory output refuses with `CHECKER_VERDICT_UNVERIFIED`.
- Checker results retain their original conclusion, receipt/transcript references and checked PLAN digests in a bounded archived report. The public Codex planning adapter requires an explicit semantic pass; Claude no longer seals checker completion as a successful planner artifact.

## Receipt and recovery

A verified application receipt proves the role/model/effort and launch evidence. It does not prove a positive checker conclusion. An authenticated checker can return `issues_found` or `blocked`; neither authorizes Gate 2.

After upgrading, retry only the failed checker with a fresh dispatch. Preserve accepted researcher/planner artifacts and original negative evidence. Completed-launch recovery stays bound to the original dispatch and its original conclusion; a later marker or a heading cannot repair a failed original proof. Existing receipts and incident history are not rewritten.

## Validation

Focused relay, semantic verdict, callback, planning adapter and recovery regressions cover both runtimes. Published release notes record the final deterministic and native live results, including their scope limits.
