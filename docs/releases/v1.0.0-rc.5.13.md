# Shipyard 1.0.0-rc.5.13

Patch prerelease based on `v1.0.0-rc.5.12`.

## Fixed

- **A Codex code review returns its launch digest.** The Codex code-review prompt asked the reviewer to repeat a list of host identities, but `launch_digest` was not in that list. It appeared only as a separate line. The reviewer therefore omitted it, and the host refused the review with `ARTIFACT_IDENTITY_MISMATCH: result differs from pinned launch_digest`. The identity list now includes `launch_digest`, and the prompt asks for it to be copied exactly. The host fills in the admitted value only in its own directions before the authenticated packet; packet data is never rewritten. The result is still bound to its launch. An omitted pinned identity is now refused as `ARTIFACT_IDENTITY_MISSING: result omits pinned <field>`, and a different value is still refused as `ARTIFACT_IDENTITY_MISMATCH`.
- **The integrator resolves a phase number against a named graph phase.** The documented in-process Codex integrator launch passes the phase number, for example `12`. When the graph rows carry the full phase name, such as `12-esign-workflow`, the exact lookup refused the launch with `phase 12 is absent from the canonical graph` before the model ran. One shared resolver now accepts a phase number (`12` or `012`) or the exact phase name and returns the canonical phase directory and number. `12` does not match `120-…` or `12.1-…`. When a number matches tickets in more than one plan directory, the resolver refuses and names the directories. The pr-sentinel round lookup had the same number-to-name comparison and now uses the leading phase number. It still requires the canonical plan directory.
- **GSD plans with `<success_criteria>` are accepted.** Plan parsing read acceptance criteria only from a `## Acceptance criteria` section. A GSD plan that keeps its criteria in a `<success_criteria>` block was refused as having no acceptance criteria. The shared plan parser in `frontmatter.cjs` now reads the list items of both forms. The role host and the Jira projection use it. A plan that has both forms yields each criterion once, and a plan with only a heading parses as before. A block without list items still has no criteria.

## Validation

Code-review unit cases use a reviewer that copies identities only from the admitted prompt text. On the rc.5.12 host this case fails with the reported `result differs from pinned launch_digest`. Further cases cover a correct digest and a missing, null, substituted, unadmitted-placeholder or stale digest, and check that the packet part of the prompt is unchanged.

An integrator case runs the documented in-process Codex launch against a graph whose rows carry the full phase name. It runs once with a numeric and once with a named selector. On rc.5.12 it fails with `phase 38 is absent from the canonical graph`. Another case runs the same launch with a GSD plan whose criteria are only in `<success_criteria>`. Direct cases cover the phase resolver (numeric, zero-padded, named, neighbouring numbers, ambiguous and absent phases), the pr-sentinel round lookup and the plan criteria parser. They also cover the Jira projection of a GSD plan. Release verification results are recorded in the published prerelease.
