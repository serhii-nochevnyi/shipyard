# Shipyard 1.0.0-rc.5.12

Patch prerelease based on `v1.0.0-rc.5.11`.

## Fixed

- **A focused Codex architecture review passes the merge gate.** A Codex focused review selects only the decisions that govern the change. For example, it can select 22 of 24 ADRs. The merge-gate consumer in `role-artifact.cjs` read the complete source authority only from the Claude packet. On Codex that authority is in `host_context.source_authority`, so the consumer fell back to the focused selection and compared it with the complete canonical membership. A review with an unchanged catalogue was refused with `SOURCE_AUTHORITY_INVALID: complete canonical architecture membership changed`, and `gate-trailer.cjs write` refused the merge. The Codex focused path now checks completeness against the full `source_authority`, which `validateHistoricalContext` has already authenticated against the original launch. Every selected architecture source must be a member of that authority with the same bytes and digest. An added, removed or replaced ADR, a changed head or base, and a tampered authority are still refused. The Claude path is unchanged.
- **One unauthenticated archive no longer hides every architecture verdict.** `currentArchitectureVerdict` looks at the role archives of every registered worktree. A single unrecorded file in an unrelated worktree's `.shipyard-role-artifacts` used to abort the lookup for every PR. A worktree whose archive fails authentication is now skipped and reported as a named candidate refusal. An unauthenticated archive still yields no verdict.
- **A review comment its own bot edits stays the same feedback.** CodeRabbit edits its own review comments to add status markers such as "✅ Addressed in commit …" or "✅ Confirmed as addressed by @…". It inserts the marker inside the body, often several times. The Codex review-fix host compared the full body of an answered comment in several places: the companion-review relation, the next round's prior-action coverage and the live-feedback recheck. One such edit was therefore refused as a changed action target before the host reached its changed-feedback handling. The host now separates a comment's identity from its body. The id, author, thread, PR and reply relation stay exact. A body change is accepted only when GitHub's complete edit history shows that every edit was made by the comment's own author, matched by both login and node id. Such an edit of a comment the host has already answered is recorded as `feedback_evolved`: the coverage keeps the reply, and the next round judges the current body. An edit by anyone else is named in the refusal, or it reaches the existing `feedback_changed` reassessment. Markers are never parsed or stripped.
- **Repair refusals name their condition.** A refused live-feedback recheck lists the added, removed and changed items and their fields. A refused comment evolution names the comment and the editor. `REPAIR_PREDECESSOR_INVALID`, `REPAIR_ACTION_PENDING` and `REPAIR_SUBJECT_CHANGED` have their own hints. The host no longer prints its name twice on a refusal line.

## Validation

Unit cases seal a native Codex focused review that omits two committed, unrelated ADRs from its selection. They validate and read the result, then check `currentArchitectureVerdict` and the `verifyArchitectureTarget` decision that `gate-trailer.cjs write` uses. The check also runs with a polluted unrelated worktree listed first. On the rc.5.11 consumer the subset case fails with the reported `SOURCE_AUTHORITY_INVALID` error. Without the new per-worktree handling, the polluted worktree aborts the lookup. The following are refused: an added ADR, a removed or modified unselected ADR, a modified selected ADR, a different head or base, a forged authority in the archive, and a selected decision outside the authority.

Review-fix cases cover a CodeRabbit-style marker inserted before the trailing auto-generated marker. One case has the marker during the first action run, and recovery stays confirmed with no reassessment. Another has repeated author edits before the next round, which proceeds and records `feedback_evolved`. Edits by a maintainer are named and refused before the next round, or they reach `feedback_changed` during recovery. On the rc.5.11 host, the next-round case fails with the reported `confirmed reply original comment context changed`, and the first-run case reassesses. A direct case checks incomplete, oversized, foreign, same-login-other-identity and unavailable edit histories, as well as identity changes. The edit-history query was also run read-only against a real CodeRabbit comment, and it returned four edits by the comment's author. Release verification results are recorded in the published prerelease.
