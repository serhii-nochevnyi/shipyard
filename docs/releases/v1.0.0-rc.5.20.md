# Shipyard 1.0.0-rc.5.20

Patch prerelease based on `v1.0.0-rc.5.19`.

## Added

- **`delivery_pipeline.cross_phase_contention: merge-on-land`.** Before this release, Gate 2 refused a graph when tickets in two phases touched the same path without a dependency between them. The remedy was always to re-slice the path into one phase, because a cross-phase dependency cannot cascade. A project can now choose that the later phase adapts instead.
  - `block` is the default and keeps the current behaviour. Its refusal now also names the new mode.
  - Under `merge-on-land`, such a cross-phase clash is a Gate 2 warning that states the landing order: the lowest phase lands first and each later phase adapts. Phase numbers are compared numerically, so phase 2 lands before phase 10.
  - When the earlier epic lands on the default branch, the later epic adapts through the existing `epic-branch.sh refresh`. That step merges the default branch into the later epic. The later epic's PRs, CI and phase reviews then run against the merged head, and judgments bound to its old head are stale.
  - Shipyard never rebases or force-pushes for this. Every signed commit, artifact and review judgment stays bound to its commit, and the base move is a merge, which the existing custody already authenticates.
  - A conflict in that merge still stops for a person, as every refresh conflict does: the paths are named and the epic is left untouched.
  - An unordered pair of tickets inside one phase stays a Gate 2 error in both modes, even when the path is also touched by another phase.
  - An unknown value falls back to `block` with a warning that lists the values.
- The capability declares the setting. The delivery command, the delivery rules for planners and the pipeline protocol describe it.

## Validation

- Gate 2 smoke cases cover:
  - the `block` refusal and its pointer to the new mode;
  - a `merge-on-land` clash between phases 2 and 10, accepted with a warning that names phase 2 as landing first and says a merge conflict stops for a person;
  - an unordered same-phase pair, still refused under `merge-on-land`;
  - an unknown value, which falls back to `block`.
- Configuration cases cover the default, both values, and the warning for an unknown value.

Release verification results are recorded in the published prerelease.
