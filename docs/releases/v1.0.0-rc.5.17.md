# Shipyard 1.0.0-rc.5.17

Patch prerelease based on `v1.0.0-rc.5.16`.

## Changed

- **Epic-flow PRs carry `pdf-review:skip`.** Every PR that `deliver-dispatch.cjs publish` opens into an `epic/*` branch, or stacks onto a parent's `ticket/*` branch, is created with the `pdf-review:skip` label. This applies on both runtimes, because Claude and Codex delivery publish through the same step.
  - In repositories that use the pdf-review merge gate, the label turns the `pdf-review` status green without a review, so these PRs no longer wait on a pdf-review run.
  - A PR into the default branch gets no label. This covers a child of a retired epic, which targets the integration branch, and the epic → `main` PR opened by `epic-branch.sh pr`.
  - Before the push, `publish` lists the repository's labels and compares names exactly. If `pdf-review:skip` is missing, it creates it, without overwriting an existing label. Then `gh pr create --draft` adds the label.
  - If the label cannot be listed or created, `publish` refuses with `PUBLISH_REFUSED` before anything is pushed. No PR is opened and no ledger entry is written. Shipyard never opens an epic-flow PR without the label.
  - Open PRs from earlier releases are not relabeled.
- **pdf-review runs only with the user's permission.** The auto-route text, which both runtimes see on each prompt (the Claude hook and the Codex `AGENTS.md` block), now says:
  - never run pdf-review without the user's explicit permission;
  - review with Shipyard's own review roles and the runtime's own review tools, plus GitHub's reviewers (CodeRabbit, Copilot).
  - The delivery command, the delivery rules for GSD planners and executors, and the pipeline protocol say the same.
  - Dispatched Claude role sessions already run with a fixed tool list (`Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`) and no settings sources, so they cannot load the pdf-review skill. The Codex runtime has no pdf-review plugin.

## Upgrade note

The rule reaches a Codex home through the managed `AGENTS.md` block, which is rewritten when this release is installed there. A Claude Code session picks up the new hook text after a restart.

## Validation

Publish cases cover:
- an `epic/*` base and a `ticket/*` base: the label is listed and created before the push, and `gh pr create` carries `--label pdf-review:skip`;
- an existing label, which is reused by exact name, while a near match such as `pdf-review:skip-old` still leads to creation;
- a default-branch base: no label calls and no `--label`;
- a list refusal, unparseable list output and a create refusal: each refuses before the push, with no PR and no ledger entry.

Auto-route cases check the rule in the Claude text and in the Codex block for both install phases and the marketplace spelling. Release verification results are recorded in the published prerelease.
