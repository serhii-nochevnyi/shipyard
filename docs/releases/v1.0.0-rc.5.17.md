# Shipyard 1.0.0-rc.5.17

Patch prerelease based on `v1.0.0-rc.5.16`.

## Changed

- **Epic-flow PRs carry `pdf-review:skip`.** Every PR that `deliver-dispatch.cjs publish` opens into the ticket's epic branch is created with the `pdf-review:skip` label. So is a PR stacked onto the branch of a parent ticket in the same epic. The epic branch is `epic/<phase>`, or `feat/<slug>` in a target project with PR hygiene. This applies on both runtimes, because Claude and Codex delivery publish through the same step.
  - In repositories that use the pdf-review merge gate, the label turns the `pdf-review` status green without a review, so these PRs no longer wait on a pdf-review run.
  - A PR into the default branch gets no label. This covers a child of a retired epic, which targets the integration branch, and the epic → `main` PR opened by `epic-branch.sh pr`.
  - The decision comes from the canonical graph, not from branch-name prefixes. The base must be the ticket's `epic`, or the `branch` of a graph ticket with the same `epic`.
  - Before the push, `publish` lists the repository's labels (`gh label list --json name --limit 1000`) and compares names exactly. If `pdf-review:skip` is missing, it creates it, without overwriting an existing label. Then `gh pr create --draft` adds the label.
  - If the label cannot be listed or created, `publish` refuses with `PUBLISH_REFUSED` before anything is pushed. No PR is opened and no ledger entry is written. Shipyard never opens an epic-flow PR without the label.
  - Open PRs from earlier releases are not relabeled.
- **pdf-review runs only with the user's permission.** The auto-route text, which both runtimes see on each prompt (the Claude hook and the Codex `AGENTS.md` block), now says:
  - never run pdf-review without the user's explicit permission;
  - review with Shipyard's own review roles and the runtime's own review tools, plus GitHub's reviewers (CodeRabbit, Copilot).
  - The delivery command, the delivery rules for GSD planners and executors, and the pipeline protocol say the same.
  - Dispatched Claude role sessions already run with a fixed tool list (`Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`) and no settings sources, so they cannot load the pdf-review skill. The Codex runtime has no pdf-review plugin.

## Fixed

- **Codex installs GSD again.** GSD 1.22.0 was released on 2026-11-19. Its rebuilt `plugin` ref now points the `gsd-core` marketplace entry at a GitHub source instead of the local `"./"` it had in 1.21.0. Codex installs only local marketplace entries. So `codex plugin add gsd-core@gsd-core` failed with `plugin gsd-core was not found in marketplace gsd-core`, and every new Codex installation of Shipyard stopped at the GSD dependency again.
  - For Codex, Shipyard now builds the `gsd-core` marketplace itself, in `$CODEX_HOME/shipyard-gsd-marketplace`:
    - it clones GSD's prebuilt `plugin` ref from `open-gsd/gsd-core`, which ships the compiled runtime library;
    - it keeps the upstream entry's name, version and description, with the local source `./gsd-core`;
    - it records the repository, ref, commit and version in `shipyard-source.json`.
  - Codex registers that directory as the marketplace and installs and enables `gsd-core@gsd-core` from it.
  - A Codex home whose `gsd-core` marketplace entry is not local, and that has no GSD installed, is switched to this marketplace.
  - A home where GSD is already installed, or whose marketplace entry is already local, is left unchanged. Claude keeps adding `open-gsd/gsd-core` directly.

## Upgrade note

The rule reaches a Codex home through the managed `AGENTS.md` block, which is rewritten when this release is installed there. A Claude Code session picks up the new hook text after a restart.

## Validation

Publish cases cover:
- an `epic/*` epic base, a target-project `feat/*` epic base and a same-epic parent's branch: the label is listed and created before the push, and `gh pr create` carries `--label pdf-review:skip`;
- an existing label, which is reused by exact name, while a near match such as `pdf-review:skip-old` still leads to creation;
- a default-branch base, a ticket branch of another epic and a `ticket/*` name the graph does not know: no label calls and no `--label`;
- a list refusal, unparseable list output and a create refusal: each refuses before the push, with no PR and no ledger entry.

An installer case builds the Codex marketplace from a git fixture of the `plugin` ref, whose entry is a GitHub source. It checks the local `./gsd-core` entry, the copied plugin tree without `.git`, the recorded commit, and the replacement of a Codex snapshot with a non-local entry. A snapshot with a local entry is kept, and Claude still adds the GSD repository. The real Codex CLI 0.171.0 installed and enabled GSD 1.22.0 from the local marketplace in a fresh home, and a second run changed nothing.

The `gh label list --json name --limit 1000` and `gh label create` calls were checked against GitHub on a test repository. The `--search` form of the list returned no output for a name with a colon, so it is not used.

Auto-route cases check the rule in the Claude text and in the Codex block for both install phases and the marketplace spelling. Release verification results are recorded in the published prerelease.
