# Shipyard 1.0.0-rc.5.1

Patch prerelease from `epic/harness-simplification`, based on `v1.0.0-rc.5`.
The 0.x marketplace default and `main` remain unchanged.

## Fixed

- Confirm remote Codex review-fix replies by their exact ID (when retained), authenticated author, body, PR and thread relation independently of unrelated feedback changes. Pending actions from rc.5 can be recovered without posting a duplicate reply.
- Persist each verified reply before attempting thread resolution. Independently confirm the exact resolved thread, including recovery after a lost response.
- Separate concurrent feedback additions, edits and deletions from action confirmation. The sealed action state and CLI result record `feedback_changes` with added/removed IDs and changed fields. `actions.status: feedback_changed` and `requires_reassessment: true` stop the original action group; changed feedback requires a fresh review-fix assessment. Repeating recovery only verifies the saved actions and does not replay replies or resolutions.
- Keep rejection of ambiguous replies, changed reply bodies/authors/targets, invalid companion reviews, and changed source/PLAN/signing policy.

## Recovery

After updating the Codex bundle, repeat the original action recovery command:

```sh
node <bundle>/scripts/codex-delivery-host.cjs --resume-repair-actions <original-dispatch-id> --scope-file <original-scope.json>
```

If the result reports `feedback_changed`, retain its confirmed actions and start a new review-fix assessment against the current complete feedback. Do not treat that result as approval to resolve new findings or merge the PR.

## Validation

Validation results will be recorded in the published prerelease notes. Deterministic recovery fixtures exercise concurrent feedback changes and refusal of forged replies. Live release rounds cover the existing research/decompose/executor/publish/sentinel path; they do not exercise the review-fix recovery scenario.
