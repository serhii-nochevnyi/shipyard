# Shipyard 1.0.0-rc.5.5

Patch prerelease based on `v1.0.0-rc.5.4`.

## Fixed

- `deliver-dispatch.cjs build review-fix` now returns a request for Claude Code instead of the named host-contract refusal. The Claude delivery host binds the review file the way it binds CI evidence: the request carries `reviewEvidence` (path and SHA-256), `expected_head` and `plan_sha256`. The host authenticates the ticket, the recorded and live OPEN PR, the PLAN and the evidence file before launch, again before the agent starts and before the result is sealed. Model and effort come from the native policy and a different value is refused; a bound review repair runs as a dedicated round. The complete review feedback is still fetched by the host, and the file is handed to the fixer as diagnostic data. Codex already supported this role.
- `deliver-dispatch.cjs build drift-check <T> --runtime claude|codex` builds the drift-gate request from the canonical graph: phase, plan, branch, the ticket's own base (the destination of a merged primary parent, resolved to the live origin ref) and the resolved model and effort. `scope.phase` and the hand-assembled request are no longer needed.
- The summary of a Claude launch is cut on code points, ends with an ellipsis when it is cut, and never exceeds the shared 500-character bound; it could previously split a surrogate pair and cut silently. The full text stays in `output`.
- Gate 2 warns when a plan's `files_modified` touches two tracked directories that differ only in letter case.

## Validation

Unit cases cover the bound review repair (delivered evidence, substituted evidence, PLAN, HEAD, PR and symlink, dedicated round, native model), the drift-check builder for both runtimes and a merged parent base, the code-point-safe summary and the case-twin warning in the graph-validator smoke. The live review repair needs real reviewer threads and was not exercised against GitHub; the unit cases use the host's injected feedback and PR doubles.
