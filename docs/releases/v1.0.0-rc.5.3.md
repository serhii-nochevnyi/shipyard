# Shipyard 1.0.0-rc.5.3

Patch prerelease based on `v1.0.0-rc.5.2`.

## Fixed

- The public `deliver-dispatch.cjs build ci-fix` command now produces supported requests for Codex and Claude Code. Both carry the canonical graph selector, ticket, PR, current HEAD, approved PLAN SHA256, and CI evidence path and SHA256.
- Both hosts authenticate the current ticket/worktree/branch, recorded PR and live open PR. They read bounded evidence through a non-symlink file descriptor and recheck the original inputs immediately before launching and before accepting the repair.
- Codex launches its native static CI fixer with explicit policy-selected model and effort. Completion requires the original authenticated receipt, launch/session, complete CLI result and native transcript containing the canonical host prompt. A repair uses existing PLAN verification and signed candidate finalization, followed by host-owned publication and live remote HEAD confirmation. Pending publication can be recovered with the original candidate without a second agent or a replayed uncertain push. Downstream CI remains pending until GitHub confirms its new checks.
- Claude resolves explicit model and effort through its native policy before running the existing trusted fix workflow. The authenticated log is delivered as diagnostic data; receipt, verification, signing and publication remain host-owned.
- Each builder request has a fresh run identity. Base reconciliation runs separately: capture current CI evidence and rebuild the repair request after a merge.

## Validation

Regression cases cover successful native dispatch, changed evidence, PR, PLAN and HEAD, evidence replacement immediately before launch, and a foreign launch receipt. The live CI repair harness creates an actual failing GitHub check, repairs the scoped source through each native host, verifies the signed commit, and requires the resulting GitHub check to pass.
