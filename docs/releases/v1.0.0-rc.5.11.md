# Shipyard 1.0.0-rc.5.11

Patch prerelease based on `v1.0.0-rc.5.10`.

## Fixed

- **Drift-check result identity.** The judge's output contract in `references/drift-check.md` now names every field the trusted consumer requires. Among them is `id`, the exact ticket the judge was asked about. Previously the Output section listed `verdict`, `evidence`, `moved` and `reuse_candidates` but not `id`. A Codex judge could therefore return a well-formed answer that `role-artifact.cjs seal` refused with `ARTIFACT_IDENTITY_MISMATCH`, and the only way forward was to edit the answer by hand. The section also states that the final message is one JSON object, that `moved` is always present, and that every moved finding carries its own unique `id`.
- **Codex host checks the drift answer before reporting success.** `codex-delivery-host.cjs` appends a result contract for the scoped ticket to the drift-check prompt. After the launch it authenticates the judge's final answer against the receipt and the saved native transcript. It then checks the answer with the same rules `seal` applies: `id` equal to the scoped ticket, a `fresh` or `drifted` verdict, unique moved-finding ids, and `reuse_candidates` and `evidence` arrays. It also requires the producer evidence file to exist. A missing or wrong `id`, a missing array, a non-JSON answer or an empty evidence file fails the dispatch. No artifact is sealed and no drift verdict is recorded. On success the host output carries the original answer, unchanged, as `drift_result`. That object is the `--result-file` input for the documented seal, validate and read steps.

## Validation

Unit cases cover the full path from a `deliver-dispatch.cjs build drift-check --runtime codex` request through the host CLI to the judge's original answer. The test seals that answer with `role-artifact.cjs`, then validates and reads it. The answer keeps fields the consumer does not need, as real judge answers do. Answers that omit `id`, name another ticket, drop `evidence` or `reuse_candidates`, give a drifted finding without an id, are prose instead of JSON, or come with an empty evidence file are refused. In each of these cases nothing is archived and no drift record is written. The transcript authentication was also checked against a recorded native drift-check transcript. The original answer, which lacks `id`, is refused, and the same answer with the scoped `id` passes. Release verification results are recorded in the published prerelease.
