## Goal

`test(name, fn)` reports green for any asynchronous body, whatever it asserts.
After this ticket an async test that throws is a FAILURE, the run exits non-zero
for it, and the harness itself is covered by tests that would have caught this.

## Context (Reads)

- `tests/unit/assert-harness.cjs:17-27` — the whole defect:

      function test(name, fn) {
        try { fn(); passed++; console.log(`  ✓ ${name}`); }
        catch (e) { ... }
      }

  `fn()` on an `async` function returns a Promise and returns it IMMEDIATELY.
  The `try` block therefore always completes, `passed++` runs, a tick is
  printed, and the assertions execute later — after `done()` may already have
  called `process.exit(0)`.
- Proof, run before this plan was written: a scratch suite with three tests, one
  sync and two async, all asserting `1 === 2`. Output was
  `✗ синхронний…` / `✓ async…` / `✓ async із await…` → `2 passed, 1 failed`.
  Two tests asserting a falsehood printed a tick.
- `tests/unit/record-stores.test.cjs:106-116` — the only async test declared
  today (a loop of two cases). **CORRECTED, and this correction is why the
  ticket is stacked on T-22-04.** An earlier draft of this plan claimed both
  cases PASS once actually run, "so this ticket is closing the class, not
  chasing a hidden lock bug". That claim came from ONE run of a patched harness,
  and one green run cannot say anything about a race. Re-run with repetition,
  they are red in 4 of 8 — alternating between the escalation store and the
  drift store — and the records are genuinely lost (`kept: T-01, T-02, T-03,
  T-06, T-04` — five of six). The harness fix does not create that defect, it
  UNCOVERS it: the tests were unexecuted, and the thing they were written to
  guard was in fact broken.
- Measured, both directions, eight runs each: with T-22-04's `lock.cjs` repair
  present, 8/8 green; with the same harness and the lock reverted, 4/8 red. That
  is why this ticket cannot land alone — `make test-fast` would be flakily red
  through a file this plan puts out of scope, and CI now runs it on every PR.
- `tests/unit/*.test.cjs` — 337 tests, 1 async declaration. The blast radius is
  small today and unbounded tomorrow, which is the argument for fixing the
  harness rather than rewriting the two callers to be synchronous.
- Reuse check (§5): there is no test framework here on purpose — the repo ships
  no `node_modules` and the image build must not depend on one. Do NOT introduce
  `node:test`, jest or a dependency; keep the harness dependency-free.

## Scope

- `test()` detects a thenable return and records the outcome from the settled
  promise rather than from the synchronous call, pushing it onto a pending list.
- `done()` awaits everything pending before printing the tally and exiting, so
  the process cannot exit while an assertion is still in flight.
- Ordering: async results necessarily print after the synchronous ones. That is
  acceptable and must be stated in a comment — a reader who sees a tick out of
  source order should not think the suite is shuffling.
- Every existing caller keeps working unchanged: `done()` is called at the end
  of each suite file, and its new async nature must not require callers to await
  it (an unhandled rejection there would trade one silent failure for another).
- `tests/unit/harness.test.cjs` (new) covers the harness with itself: a sync
  failure fails, an async rejection fails, an async pass passes, and the tally
  counts each exactly once.

## Acceptance criteria

- An async test whose body throws is reported `✗` and the process exits 1.
- An async test that resolves is reported `✓` exactly once.
- `make test-fast` passes, and the total assertion count does not DROP (a
  silently-skipped test would look like a pass here).
- `node tests/unit/record-stores.test.cjs` is green in EIGHT consecutive runs,
  not one. A single green run is what produced the false claim this plan had to
  correct; repetition is the acceptance criterion for anything touching a race.
- Deleting the fix makes `harness.test.cjs` fail — verify by reverting the
  harness in a scratch copy, not by assertion alone.
