## Goal

Deliver the accepted ADR-012 task-level model ladder as a measured canary for
Claude and Codex. The same classifier must select a task level on both runtime
surfaces, preserve the existing role floors, and record enough requested,
applied and observed evidence to decide whether a later treatment is safe.

## Context (Reads)

- `ADR-005-the-floor-is-opus-and-fable-is-earned.md` — the existing model-floor
  and earned-ceiling decision; this plan does not lower it.
- `ADR-012-task-level-model-ladder.md` — the accepted classifier, runtime
  palettes, rollback and no-Haiku rule.
- `ADR-011-ROLLOUT.md` — baseline, one-treatment-at-a-time and quality/recovery
  gates.
- `pipeline-config.cjs`, `codex-agent.cjs`, `dispatch-record.cjs` and
  `pipeline-stats.cjs` — the resolver, Codex selector, journal writer and
  reporting seam.
- `gen-codex-shipyard.cjs` and `install-shipyard-codex.sh` — generated and
  installed Codex surfaces.

## Scope

1. Add the task-level classifier and adaptive policy switch while preserving
   the existing role floors and keeping automatic Haiku unreachable.
2. Generate role-specific ordinary, critical and recovery Codex files from the
   project policy, including explicit project-root resolution and a safe
   one-entry palette fallback.
3. Carry resolver route, task level, requested model/effort, runtime/backend
   and optional applied/observed values through Workflow, Agent and Codex
   dispatch records without inferring missing observations.
4. Expose the canary policy and telemetry in the operator documentation and
   smoke/unit suites, including rollback to `model_ladder: conservative`.

## Out of scope

- Subscription quota conversion or savings claims.
- Automatic online policy rewriting from observed usage.
- Lowering the Sonnet/Opus role floors or introducing Haiku.
- The phase-32 attribution coverage and batch lifecycle slices (T-32-03,
  T-32-04 and T-32-05), which consume this telemetry as a separate stack.
- Changes to the GSD synchronization work in phase 35.

## Acceptance criteria

- `model_ladder: adaptive` selects the same task level from the same signals on
  Claude and Codex, while `conservative` restores the previous role-floor
  behavior.
- No automatic path emits `haiku`; explicit manual overrides remain governed
  by ADR-005 and all static Codex roles resolve through generated files.
- Critical/recovery selection is mechanically tied to risk, checkpoint,
  repeated signatures or contested judgement; absent signals never qualify for
  a cheaper rung.
- Dispatch records preserve resolver route and task level independently from
  applied and observed evidence; unsupported/unknown values stay explicit.
- Generation from a foreign caller directory still reads the selected
  project's policy, and the generated bundle matches the canonical files.
- Targeted unit and Codex smoke tests pass, with no quota or savings claim made
  from fixture data alone.

## Test strategy

Run the resolver, selector, dispatch-record, stats, generator and failure
signature unit suites plus the generated Codex smoke. Add negative coverage for
missing signals, stale/invalid policy, forbidden Haiku, foreign caller cwd and
missing observation fields. Retain the full `make test-fast` gate for the
integration check.

## Verification

The ticket is complete only when the canary is reversible, every runtime
surface carries truthful attribution, and the observed baseline remains
explicitly unqualified for savings or quality claims.
