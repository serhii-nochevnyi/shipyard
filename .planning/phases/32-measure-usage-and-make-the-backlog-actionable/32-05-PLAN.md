## Goal

Connect the atomic dispatch recorder to the background guard's fan-out path and
remove the repeated per-ticket cleanup that was still charging that path one
process, lock and front refresh per item. The main delivery command is owned by
the parallel GSD synchronization plan and remains untouched here.

## Context (Reads)

ADR-011 D1, D3, D8 and D11; ADR-011-ROLLOUT OPT-03; the `mark-many` contract
from T-32-04; `commands/deliver.md`; `references/pr-sentinel.md`; and the
2026-09-10 audit showing many short orchestration calls and no historical
dispatch attribution coverage.

## Scope

Add an idempotent `clear-many --stdin` companion to `mark-many`, preserving the
single-ticket commands. Update the sentinel contract so its guard/fixer
fan-outs record one validated JSON batch after a launch and clear one batch
after output/park. Keep each item's resolver route,
task-level, runtime/backend and observed/applied evidence independent. Add
negative tests for malformed and duplicate clear payloads and a documentation
contract that both entry points expose the batch path.

## Out of scope

Model or effort policy changes, automatic runtime observation, subscription
attribution, backlog lifecycle writes, global Claude/Codex settings, launch
ordering, and any claim of quota savings. A batch is a transport optimization;
the resulting attribution is still unknown until the host supplies evidence.

## Acceptance criteria

- `clear-many --stdin` validates the complete payload before mutating, removes
  all present records under one lock and refreshes the front once; missing
  records are safe to replay and an empty list is an explicit no-op.
- Duplicate or malformed clear ids leave the existing store unchanged.
- `mark-many` and the single-ticket paths retain their existing semantics and
  all dispatch fields remain separate in the journal.
- `pr-sentinel.md` instructs batch mark/clear for multi-ticket launches and
  preserves the one-ticket fallback.
- Targeted dispatch-record, judgment-contract and docs smoke checks pass; the
  complete unit/smoke gate remains green.

## Test strategy

Exercise valid and invalid `clear-many` subprocess payloads, replay after an
owner-output expiry, and the documentation wiring. Retain the existing
`mark-many` all-or-none and concurrent-write coverage.
