## Goal

The Step 4.3 approval gate — where a human already reviews the ticket table —
asks which risk classes are pre-authorized, and writes `delivery.preauthorized`
into the plans of the tickets that qualify. The 3am interruption becomes a
design-time answer.

## Context (Reads)

- ADR-001 D6. Note the wording: risk CLASSES are pre-authorized. Ask by class
  ("medium-risk tickets in this phase: pre-authorize?"), but RECORD per ticket in
  its plan file — the plan is the single source of truth and the thing that
  survives the session. A class recorded only in config could not say which
  ticket a human actually looked at.
- `decompose.md` Step 4.3 — the existing approval summary already shows id,
  title, wave, `depends_on`, `pr_base`, risk, and "who is high-risk and will wait
  for a human". That last line is exactly where the question belongs; the table
  is already in front of the reader.
- `T-21-01`'s rule: `preauthorized: true` requires `human_checkpoint: true`, so
  only tickets that would actually stop are eligible. Asking about the others
  would be a question with no consequence.
- **Traceability.** The flag must be written only as the result of this approval
  step. State that in the doc, and state what it means to a later reader: this
  is a record of a person's decision, not a default a planner may set to make its
  own phase run unattended.
- CLAUDE.md, the Codex generator: any new paragraph must name MECHANISMS, never
  contrast runtimes by name.
- Reuse check (§5): the frontmatter template in Step 3 already documents
  `human_checkpoint`; the new field is documented beside it, not in a new section.

## Scope

- Step 3's frontmatter template gains `preauthorized` with a one-line meaning.
- Step 4.3 gains the question and the write-back, plus a re-run of
  `validate-graph.cjs` so `tickets.json` carries the result (the same pattern
  Step 5 already uses after writing `delivery.jira`).
- The summary states plainly what pre-authorizing changes: the guard will merge
  those tickets unattended, and their children will cascade behind them.
- Default is NO pre-authorization. Silence is not consent, and an unanswered
  question must leave the conveyor exactly as it behaves today.

## Out of scope

Every script (T-21-01, T-21-02), and any change to how risk itself is assessed.

## Acceptance criteria
