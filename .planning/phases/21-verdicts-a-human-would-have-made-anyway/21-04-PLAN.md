## Goal

A script in the deterministic layer: diff in, findings out. It names the ways a
drive-to-green run can reach green by weakening the measurement rather than
fixing the code. It decides nothing and blocks nothing — T-21-05 wires it in.

## Context (Reads)

- ADR-001 **D7**: "Drive-to-green optimizes the signal it is measured by. The
  failure modes that pass under bots at night are known and enumerable: weakened
  assertion, skip, rewritten snapshot, raised timeout, `any`/`@ts-ignore`,
  swallowed catch, narrowed matcher. This belongs in the deterministic layer
  beside `validate-graph.cjs`: diff in, verdict out."
- **It ships NON-BLOCKING, and the reason is specific to this repository**: it is
  the only item in the programme that can be WRONG about legitimate work, and
  here a blocking gate with false positives gets switched off. Two were removed
  in this same programme — `workflow.use_worktrees` (warned at a value that was
  GSD's own default, so it fired for most projects and taught the user to ignore
  warnings) and the unguarded-merge warning. This script earns blocking status
  from field data, not from argument.
- `validate-graph.cjs` is the model for the SHAPE: collect every finding before
  exiting, report them grouped so the output can be read, and never half-answer.
- Pattern level, not AST. The conveyor's proving ground is TypeScript and this
  repository is CJS and bash; a parser for one would be blind on the other, and
  the enumerated modes are all visible in the hunk text.
- **This repo's own history is the test corpus.** Real examples to draw fixtures
  from rather than inventing: a test that could not fail (T-22-05's harness), a
  guard that checked argument count instead of content (T-22-02), a comment
  asserting behaviour the code lacked (T-22-01). The point is not to detect those
  specific bugs but to shape the patterns against real diffs.

## Scope

- `degenerate-green.cjs <ticket> --diff <file>|--base <ref> --worktree <path> [--json]`,
  resolving its graph the way `graph-dir.cjs` already does (flag/env → cwd →
  the worktree's own repository), because its documented caller stands in a
  ticket worktree.
- One detector per enumerated mode, each reporting file, line, the matched text,
  and a one-line reason a human can judge in isolation.
- Exit 0 ALWAYS when the run itself succeeded, findings or not. A non-zero exit
  is reserved for "could not run" — the whole point is that findings do not
  block. Say this in the usage text, so the next reader does not add a `--strict`
  because they assumed one was missing.
- `--json` emits a stable shape: `{ticket, findings: [...], counts: {...}}`.

## Out of scope

Any caller (T-21-05), any gate outcome, the trailer, and blocking. Do not add a
`--fail-on` flag "for later": a flag that turns a report into a gate is exactly
the thing the ADR defers until the false-positive rate is known.

## Acceptance criteria

- Every enumerated mode is detected on a realistic hunk.
- **Every mode also has a NEGATIVE control** that must NOT fire: a timeout raised
  in a config file rather than around a failing assertion, a test deleted along
  with the feature it covered, an `any` in a type declaration file, a `catch`
  that logs and rethrows. This repository has proven twice this month that a
  check without a negative control proves nothing.
- Findings on a diff with none → empty array, exit 0.
- A malformed or missing diff → non-zero exit with a message naming the cause.
- `--json` output validates against the documented shape.

## Test strategy

Fixture diffs as strings in the test file, one per mode plus its control. Assert
the finding's FILE and LINE, not just its count — a detector that fires on the
wrong hunk is a false positive wearing the right total.
