## Goal

Make the explicit single-ticket escape hatch auditable without allowing a set
selection to bypass the holding rule.

## Context (Reads)

- `.planning/architecture/ADR-009-not-every-ticket-is-available-work.md` — D6,
  including the distinction between a named ticket and a named set.
- `plugins/delivery-pipeline/scripts/tracker-record.cjs` — the D5 store writer
  and generation binding from T31-04.
- `plugins/delivery-pipeline/scripts/log-event.cjs:142-199` — owned event
  refusal and the reason hand-written journal lines are unsafe.
- `plugins/delivery-pipeline/commands/deliver.md:1159-1177` — scope selection
  semantics and the exact-ticket argument shape.
- `tests/unit/log-event.test.cjs` and
  `tests/unit/judgment-contract.test.cjs` — journal ownership and documentation
  wiring contracts.

## Scope

- Add a tracker-record override operation for the exact ticket named by the
  operator. It may carry an eligible, ineligible, or unknown tracker observation
  but must retain what was observed and why the gate was bypassed.
- Store the current-generation override so the front can authorize that one
  ticket during the current delivery round; do not make a set-wide or permanent
  exemption.
- Append a `tracker_override` journal event atomically with the recorder's
  operation, including ticket, Jira key, observed status/assignee or unknown
  reason, and the explicit override reason.
- Add `tracker_override` to `log-event.cjs`'s script-owned event refusal so a
  caller cannot forge the bypass by writing directly to the journal.
- Update `deliver.md` to call the override only for a single exact ticket id or
  key, while `whole phase`, `all ready`, and `everything reachable` continue to
  apply the eligibility gate to every ticket.
- Test idempotent/atomic record shape, unknown observations, journal ownership,
  and the documentation boundary between one ticket and a set.

## Out of scope

The initial tracker read loop, new status configuration, front classification,
assignment writes, tracker transitions, or any bypass for `branched`/PR work.

## Acceptance criteria

- A named ticket can proceed with a current-generation override and the event
  records the tracker facts available at the time.
- A missing tracker answer is recorded as unknown rather than fabricated into a
  To Do/unassigned pair.
- A hand-written `log-event.cjs tracker_override ...` is refused with the
  recorder command named as the sole writer.
- The delivery docs explicitly distinguish `deliver T-xx-yy` from phase/set
  scopes, and no set scope invokes the override operation.
- The override expires with the generation-bound read cache and leaves no
  permanent eligibility exemption.

## Test strategy

Use temporary project graphs and journal fixtures; assert the event and store
are written under one recorder path. Use source/document contracts for the
single-ticket versus set-scope rule. No tracker or GitHub access is required.

- Source contracts for its sole writer and scope restriction.

## Dependencies and risks

This ticket extends the D5 writer after the front knows how to consume its
verdicts. The journal is an audit trail, not a second source of eligibility; the
tracker store remains the current-round input to the front.
