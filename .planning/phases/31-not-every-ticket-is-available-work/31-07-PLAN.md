## Goal

Wire the real cold-start tracker read and the generation-bound cache through all
front writers, so eligibility is observed once per pending ticket and remains
separate from the outbound Jira projection.

## Context (Reads)

- `.planning/architecture/ADR-009-not-every-ticket-is-available-work.md` — D5
  and D7, including the MCP limitation that scripts cannot perform the read and
  the separate expiry rule for the read cache.
- `plugins/delivery-pipeline/commands/deliver.md` Steps 0–1 and the tracker
  projection section — the cold-start ordering, connected-MCP orchestration, and
  exact scope semantics.
- `plugins/delivery-pipeline/scripts/state-sync.cjs` — the locked delivery-state
  and front writer; it must consume local tracker records without adding tracker
  network calls to the tick rate.
- `plugins/delivery-pipeline/scripts/front.cjs` and
  `plugins/delivery-pipeline/scripts/dispatch-record.cjs` — the other front
  computation/write paths that must pass the same active tracker map.
- `plugins/delivery-pipeline/scripts/tracker-record.cjs` and
  `tracker-eligibility.cjs` — the sole cache/predicate contracts from earlier
  tickets.
- `plugins/delivery-pipeline/scripts/jira-project.cjs` and
  `tests/unit/jira-project.test.cjs` — the outbound `jira-projection.json`
  watermark, which must not be reused for eligibility reads.
- `tests/smoke/sentinel-smoke.sh` — stubbed state-sync integration coverage;
  extend it with eligible, assigned, unknown, generation-expiry, and resumed-PR
  cases.

## Scope

- In `deliver.md` Step 1, when `jira_todo_statuses` is non-empty, make one
  connected-MCP issue read per pending ticket being considered. Use the default
  response fields for status and assignee, adapt to the connected MCP's input
  shape without depending on changelog pagination, and record the result with
  `tracker-record.cjs`.
- Record unreadable/missing tracker answers as `unknown` with the error words;
  never continue on the basis of an absent status. Recompute the front after
  recording so the selected ticket is either eligible, parked, or explicitly
  overridden.
- Pass the active current-generation tracker records into every `computeFront`
  caller: state-sync's locked snapshot, the standalone front CLI, and
  `dispatch-record`'s refresh path. Keep tracker reads outside state-sync and
  outside the GitHub state lock.
- Ensure the gate is evaluated only for pending/ready execution candidates;
  branched, PR-open, and merged work uses existing delivery facts and remains
  resumable.
- Keep `tracker.json` as a read cache with its own lock, generation, and expiry;
  do not add tracker fields to `jira-projection.json`, the outbound watermark,
  or the delivery journal except for the explicit `tracker_override` event from
  T31-06.
- Add wiring contracts for one read per pending ticket, no changelog/worklog
  shortcut, and the active cache being passed to all front writers. Extend the
  smoke fixture with the fail-closed and lift behavior.

## Out of scope

Automatic Jira assignment, tracker transitions, `statusCategory` fallback,
priority/label/sprint reads, tracker support beyond Jira, model routing, and
changes to the outbound Jira projection mechanism.

## Acceptance criteria

- With the policy enabled, each pending candidate is read once at Step 1 and its
  status plus assignee is recorded; tracker failure parks only that ticket and
  the rest of the board remains processable.
- A current-generation To Do/unassigned record reaches `execute`; an assigned,
  wrong-status, missing, or unknown record is blocked with the tracker's own
  words.
- A new eligible re-read lifts the ticket; an old record is ignored after the
  next delivery generation, so a stale cache cannot authorize work.
- `state-sync`, `front.cjs`, and `dispatch-record` agree on the same front when
  they consume the cache, while state-sync performs no tracker MCP call.
- `jira-projection.json` remains untouched by eligibility reads and the smoke
  test proves its watermark and the read cache can change independently.
- Existing resumed branch/PR paths remain actionable or guardable regardless of
  tracker availability.

## Test strategy

Run focused unit tests for the front and source contracts, then the stubbed
sentinel/state-sync smoke. The smoke must exercise MCP-shaped input through the
documented adapter fixture without real credentials or network access.

## Artifacts this phase produces

- Cold-start tracker-read instructions and cache wiring across all front writers.

## Dependencies and risks

This is the high-risk integration boundary: it combines an external read made by
the orchestrating loop with local durable state and three concurrent front
writers. The human checkpoint covers that new authority boundary; the outbound
Jira projection remains separate and non-blocking.
