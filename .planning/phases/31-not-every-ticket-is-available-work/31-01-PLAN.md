## Goal

Make external tracker work enter through the investigation loop instead of being
turned directly into an executable plan by delivery.

## Context (Reads)

- `.planning/architecture/ADR-009-not-every-ticket-is-available-work.md` — D2
  and the explanation of why a tracker description cannot supply a safe
  `depends_on` or `files_modified` contract.
- `plugins/delivery-pipeline/commands/deliver.md:1015-1029` — the current
  unmaterialized-decomposition recovery branch, including the IMPORT shortcut
  that must be removed.
- `plugins/delivery-pipeline/commands/investigate.md` and
  `plugins/delivery-pipeline/commands/decompose.md` — the cold-start route and
  the canonical plan/Gate 2 contract that the replacement must name.
- `tests/unit/delivery-cold-start-contract.test.cjs` — a dedicated bounded
  contract for the delivery cold-start branch; keep it separate from the
  cross-phase source-contract suite owned by Phase 30.

## Scope

- Delete the delivery instruction that reads an external Jira/GitHub ticket,
  derives `depends_on` or `files_modified` from its prose, and writes a PLAN.md
  for immediate execution.
- Keep the diagnostic that reports what was found when PLAN files are absent,
  then route the operator to `/shipyard:investigate` from a cold start and only
  after that to `/shipyard:decompose` and Gate 2.
- State that an external ticket is evidence for intake, not a delivery
  contract, and that the normal GSD/Shipyard stages remain required.
- Pin the replacement and the absence of the derivation language in the
  dedicated cold-start contract, with bounded slices so a comment elsewhere
  cannot satisfy the caller contract.

## Out of scope

Tracker status eligibility, Jira reads, durable tracker state, front selection,
direct overrides, model policy, and changes to the investigation or
decomposition commands themselves.

## Acceptance criteria

- When delivery finds no PLAN files but external tickets exist, its documented
  action is investigation from a cold start followed by decomposition; it does
  not offer import or direct execution.
- The docs no longer instruct an agent to infer `depends_on` or
  `files_modified` from tracker content.
- The source contract fails if the old import path or its derivation shortcut is
  reintroduced, while harmless references in ADRs and plans remain outside its
  sweep.

## Test strategy

Use the dedicated cold-start contract only; no tracker, network, or filesystem
import is needed. The external-ticket branch is prose orchestration, so the
negative pin is the meaningful local proof.

## Verification commands

~~~bash
node --test tests/unit/delivery-cold-start-contract.test.cjs
~~~

## Artifacts this phase produces

- A bounded delivery cold-start rule for externally prepared tickets.
- A cold-start contract pinning the absence of the import shortcut.
