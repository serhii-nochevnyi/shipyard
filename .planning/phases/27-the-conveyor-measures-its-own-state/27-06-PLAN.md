## Goal

A board rendered after the world moved says so on its own face, instead of being
read as fact. And a drift round over a mixed-base cascade judges each ticket
against the base that ticket is actually cut from.

## Context (Reads)

- ADR-006 D6.
- `stop-gate.cjs`'s journal-tail rule, which is the proof this is computable
  inside a 75ms budget: read the TAIL only (64KB), count `merge` and
  `attempt … outcome=pushed`, EXCLUDE `status_change` (state-sync writes it, so it
  is contemporaneous with the front by construction) and `dispatch` (the overlay
  already covers it), and shift the first line ONLY when the read actually
  SEEKED — dropping it unconditionally ate the only event in a short journal.
- `.planning/backlog/log-event-does-not-refresh-the-front-but-dispatch-record-does.md`
  — the habit that produced the defect: reading the front after a `log-event`
  write and concluding "nothing actionable" from a board computed before the push.
- `.planning/backlog/drift-gate-judges-one-base-for-a-whole-cascade.md`, and
  `drift-needed.cjs:257` — it already resolves a per-ticket base
  (`delivery-state[id].base`, else `tickets.pr_base`), so the judge does not need
  a new resolver, only to stop being handed one base for the round.
- `install-shipyard-claude-hook.sh:127` — the hook is installed by COPYING the
  single file `stop-gate.cjs`.

## Scope

- **`front.cjs` prints one behind-line** when the journal's tail holds a `merge` or
  an `attempt … pushed` newer than the state it is about to render: the board is
  behind reality, and the remedy named is `state-sync`. It never repeats the stale
  board's contents as fact in that line, because those contents are what is wrong.
- **The tail reader is DUPLICATED, not shared, and the reason is load-bearing.**
  `stop-gate.cjs` is copied as a single file into `~/.claude/hooks/` by the
  installer; it requires only node builtins today, and a `require` of a sibling
  module would break the installed hook while every in-repo test stayed green.
  So `front.cjs` gets its own copy, and each carries a comment naming the other
  as the twin, with the shared rule stated once in each.
- `deliver.md` states the pairing where the loop meets it: after a write that
  moved the world, resync before reading the front.
- **`drift-gate.mjs` takes `baseRef` PER TICKET**, from `delivery-state[id].base`.
  One base for a mixed-base cascade forced a round into two invocations; the
  workflow's own args must express what `drift-needed.cjs` already resolves.

## Out of scope

Making the front resync itself — it is a pure function of the files it reads, and
a renderer that goes to the network is a different thing. `stop-gate.cjs` (its
copy of the rule is T-27-01's file and already correct). `drift-needed.cjs`,
which needs no change.

## Acceptance criteria

- A journal whose tail holds a `merge` timestamped after `generated_at` → the
  behind-line appears and names `state-sync`. On base nothing is printed, so the
  test fails on current code.
- A tail holding only `status_change` and `dispatch` newer than `generated_at` →
  NO behind-line. This is the false-block that fired five times across phases 20
  and 22, and it is the assertion that matters most here.
- A journal shorter than the read window keeps its first line (the seek rule),
  asserted with a one-event journal.
- `drift-gate.mjs` given a cascade with two distinct bases dispatches each judge
  with its own `baseRef`. On base one value is passed for the round.
- `deliver.md` states the resync pairing in the step that writes.
- **Mutation check.** Add `status_change` to the counted events and
  `front.test.cjs` fails on the second criterion. Drop the seek guard and the
  one-event case fails. Collapse `baseRef` back to one value and
  `workflows-args.test.cjs` fails.

## Test strategy

TDD in `front.test.cjs` over temp journals — the EXCLUSION cases first, because
a behind-line that fires on a contemporaneous `status_change` is worse than none:
it teaches the operator to ignore the line, which is how this repository lost a
gate before. `workflows-args.test.cjs` evaluates the workflow's args the way the
runtime does, per T-24-06's correction.
