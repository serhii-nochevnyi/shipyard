## Goal

The gsd-core pin is asserted by a SWEEP over what is tracked, not by a list of
five homes that has to be edited whenever a sixth appears. And two wiring facts
the board depends on stop being asserted by nothing at all.

## Scope

- **Remove the home.** Both `gsd-core@1.7.0` hints in
  `scripts/install-shipyard-capability.sh` become `latest`, matching its three
  sibling scripts.
- **Then the sweep.** `docs-smoke.sh` extracts the pin from `Dockerfile` and
  asserts that every tracked `gsd-core@<semver>` equals it. Enumerate through
  `git ls-files` — a sweep over the working tree would judge untracked scratch
  files. Exclusions, each with its reason in the code: `.planning/` (planning
  records quote historical values on purpose) and the spec document's historical
  §10.5 heading.
- **Fail on more than one match per file.** No `head -1` anywhere in the
  extraction: a file yielding two values is an error naming both, because the
  effective value is the later one and the guard was reading the earlier.
- **`tests/unit/source-contract.test.cjs`** — a new home for assertions about the
  SHAPE of our own source, holding two to begin with: `state-sync.cjs` passes
  `epics:` into its `computeFront` call, and no script under
  `plugins/delivery-pipeline/scripts/`, `capabilities/delivery-pipeline/checks/`
  or `scripts/` contains byte 0x00.

## Out of scope

`pipeline-config.test.cjs` and the ladder-table blind classes (T-27-08 owns that
file — a contested path is a Gate 2 error, and that ticket is already the phase's
sweep). Editing `README.md` or `docs/gsd_multilevel_delivery_pipeline.md`: both
already agree with the `Dockerfile`, so the sweep should pass over them
untouched, and if it does not, the fix is the exclusion in the guard rather than
an edit here. Changing the pin's VALUE.

## Acceptance criteria

- `install-shipyard-capability.sh` contains no semver-pinned `gsd-core@`.
- The sweep passes on the tree as it stands. Then, with the pin changed in
  `Dockerfile` only, it FAILS and names every disagreeing tracked file — including
  `README.md` and the spec document, which the five-home guard never looked at.
- A duplicate `ARG GSD_CORE_VERSION=` line in `Dockerfile` fails the guard. On
  base it passes, so this is the blind class asserted.
- A `.planning/` file holding an old pin does not fail the sweep.
- Deleting `epics: epicInfo` from `state-sync.cjs` fails
  `source-contract.test.cjs`. On base, four suites stay green — cite the count in
  the PR body.
- A NUL byte written into any swept script fails `source-contract.test.cjs`.
- **Mutation check.** All four of the above are themselves the mutation checks;
  run each mutation, record the failure, and revert. This is the ticket ADR-006's
  "an assertion nobody has seen fail is not a guard" was written about.

## Test strategy

Every criterion here is a mutation of a tracked file, so the test IS the run:
apply the mutation in a throwaway copy of the tree (or `git stash` it), run the
guard, assert the failure names the file. Write the duplicate-line case first —
it is the one the shipped guard reads green.
