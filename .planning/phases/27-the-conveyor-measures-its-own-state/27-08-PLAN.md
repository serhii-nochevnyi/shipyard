## Goal

The three readers ADR-004 D2 did not reach stop taking defaults from a config
that does not parse; the shared numeric rule stops accepting `true` as a cap of
one; and no record in this repository asserts what a later amendment retired.

## Context (Reads)

- ADR-006 D8.
- `.planning/backlog/phase-26-followups.md` §"Three real ADR-004 D2 gaps, found by
  arch-review on PR #60", with the reviewer's demonstration: on a corrupt config
  `front.cjs`'s standalone CLI gives `1 actionable — finalize: T-01-01`, a valid
  `off` gives `0 actionable, fixpoint: YES`, and a valid `epic` is
  BYTE-IDENTICAL to the corrupt answer. So it offers a paid `finalize` dispatch —
  a fixer that pushes — with no warning. `deliver.md:43` advertises that CLI as
  "re-runnable on its own", which is what makes the ungated answer reachable from
  documented usage.
- The same note's items 2 and 3: `gsd-tune --global` misattributes conservative
  values to a file that says nothing (project mode is already immune via its own
  hard fail), and `gen-codex-shipyard.cjs:206` bakes default tiers the same way.
- The same note, §"One shared-rule defect": `Number(true) === 1` is a silent cap
  of ONE agent, and `0.5` reads as "dispatch nothing" while `cap.free !== 0`, so
  the capacity fixpoint branch never fires. Both come from the shared numeric rule
  in `loadConfig`, so `max_attempts` behaves identically.
- `.planning/backlog/the-pin-has-eleven-sites-and-the-guard-knows-five.md`,
  "Four blind classes", items 2-4 — the LADDER table's unguarded halves.
- `phase-26-followups.md` §"Five constraints T-26-12's author needed": item 2
  (an ABSENT file is `valid: true, error: null` — a refusal must not fire there)
  and item 3 (`dutySummary()`'s early return must stay a superset).
- ADR-003's Context, which still says the Agent tool accepts full model ids;
  ADR-005's `Supersedes`, which names D3 alone.

## Scope

- **The three readers refuse rather than default.** `front.cjs`'s standalone CLI,
  `gsd-tune --global` and `gen-codex-shipyard.cjs` follow `ci-wait.cjs`'s template:
  count the fact, withhold the mutation, carry the reason on every result, and
  never present a default as something the file said. An ABSENT config is still
  valid and must not refuse.
- **One `Math.floor` and one type check** in `loadConfig`'s shared numeric rule:
  a boolean is not a number, and a fractional value is floored with a warning.
  Every numeric knob is fixed at once, `max_attempts` included.
- **The ladder table's unguarded halves** (`pipeline-config.test.cjs`, and the
  spec document where the prose lives): an `EXEMPT:` row with an empty reason
  fails; a contradictory duplicate row fails rather than being resolved by first
  match; the escalation prose is compared against the resolver, not only the table
  rows. These live here rather than in T-27-07 because this ticket owns the file.
- **The record bookkeeping.** ADR-003's Context is corrected on the Agent tool's
  input vocabulary; ADR-005's `Supersedes` names every decision the amendments
  actually retired.

## Out of scope

Anything about the ladder's VALUES — this is bookkeeping, not a policy change.
`state-sync.cjs`'s degrade-rather-than-refuse behaviour on an invalid config
(T-26-02 chose it deliberately). New knobs.

## Acceptance criteria

- With a corrupt config: `front.cjs` CLI prints the refusal and offers no
  `finalize`; `gsd-tune --global` reports the refusal instead of attributing
  values to the file, and `--apply` writes nothing; `gen-codex-shipyard.cjs`
  refuses to bake tiers. All three are byte-identical to the valid answer on base,
  so each test fails on current code.
- With NO config file at all: all three behave exactly as today. This is the
  regression the refusal could introduce.
- `max_concurrent_agents: true` warns and falls back to the default rather than
  capping at one. `max_concurrent_agents: 4.5` floors to 4 with a warning;
  `0.5` floors to 0 and the capacity fixpoint branch fires. `max_attempts` is
  asserted for the same two values, because the rule is shared.
- An `EXEMPT:` row with an empty reason fails `pipeline-config.test.cjs`; a
  contradictory duplicate row fails; moving `xhigh` between escalation types
  fails. Each passes on base.
- `grep` finds no claim in ADR-003 that the Agent tool accepts a full model id,
  and ADR-005's `Supersedes` names D1, D2, D3, D4, D6 and its Consequences as
  amended.
- **Mutation check.** For each of the three readers, restore the default-taking
  line and watch its own test fail. Remove the type check and the `true` case
  fails. Record all five runs.

## Test strategy

TDD per reader in its own suite, over a temp cwd holding a deliberately
unparseable `.planning/config.json` — three files, one shared fixture helper. The
numeric rule is asserted in `pipeline-config.test.cjs` at the ENDPOINTS AND THE
MIDDLE: probing only the endpoints is precisely how both values were shipped
accepted. The ADR corrections are `grep` assertions in the PR body rather than
tests: a record is not a mechanism, and asserting prose in a unit test is the
habit ADR-006 was written about.
