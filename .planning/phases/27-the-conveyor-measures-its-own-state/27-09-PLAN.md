## Goal

D2 shipped complete and inert. `gate-trailer.cjs carry` is correct and seven
times mutation-checked, and nothing can ever call it, because no caller records
the proof it needs. Wire the value through, and extend the guard that was built
for exactly this class and stopped one row short.

## Context (Reads)

- `.planning/phases/27-the-conveyor-measures-its-own-state/INTEGRATION.md`, the
  phase's integrator verdict — this ticket is its only fix-ticket.
- The measurement: `deliver.md:1404` and `references/pr-sentinel.md:195` are the
  two documented `gate-trailer.cjs write` invocations, and **neither passes
  `--base-tree`** (verified: 0 occurrences in either file). So every trailer this
  conveyor writes records no base tree, and `carry` refuses every time at its own
  "absent proof is not proof" rule — which is the correct behaviour of a correct
  mechanism nobody supplies.
- `references/arch-review.md:36-50` already tells the judge to compute the
  merge-base tree and reports it as `base_tree`. That end is done. The prose there
  even names the flag (`gate-trailer.cjs write … --base-tree <sha>`) — but inside
  an ellipsis, not in either concrete command line a reader copies.
- `tests/unit/trailer.test.cjs:494` — `const OPTIONAL_FLAGS = ['--repo'];`, and
  the test below it pins both docs against the script's `USAGE`. `--base-tree`
  was added to `USAGE` (`gate-trailer.cjs:78`) without a row here, so the guard
  that exists to catch exactly this omission did not see it.
- ADR-006 D2, and the saving the omission costs: ~150k tokens a round, 42% of a
  ticket's cost.

## Scope

- **Both concrete invocations carry the flag.** `deliver.md:1404` and
  `references/pr-sentinel.md:195` pass
  `--base-tree <the judge's reported base_tree>` on the `write` call, and each
  says WHERE the value comes from — arch-review's `base_tree:` output field — so
  the caller is not left to guess and does not invent one.
- **`--base-tree` joins `OPTIONAL_FLAGS`** in `tests/unit/trailer.test.cjs`, so
  both docs are pinned against `USAGE` the way `--repo` already is.

## Out of scope

`gate-trailer.cjs` and `base-merge.cjs` — the mechanism is already correct and
this ticket changes no code in it. Any tolerance in the two identities. Teaching
`carry` to COMPUTE a base tree the judge did not measure: a `base_tree` nobody
measured is precisely what the writer refuses on purpose, and supplying one here
would turn a proof into an assertion.

## Acceptance criteria

- A `gate-trailer.cjs write` invocation in either doc without `--base-tree` fails
  `trailer.test.cjs`. On base both docs lack it and the suite is GREEN, so this
  test fails before the fix — that green is the whole defect.
- Each invocation names the source of the value, so a reader who follows the doc
  cannot supply a branch name or an abbreviation instead.
- **Mutation check (ADR-006 Consequences).** Remove `--base-tree` from either
  doc, watch the pin fail naming that doc, revert, re-run green. Record both runs
  in the PR body.

## Test strategy

No new test file and no new mechanism: the guard already exists and already
reads both docs, so the change is one entry in its list plus the two doc lines it
then requires. Write the `OPTIONAL_FLAGS` entry FIRST and watch it fail against
the unedited docs — that failure is the evidence this ticket is needed at all.
