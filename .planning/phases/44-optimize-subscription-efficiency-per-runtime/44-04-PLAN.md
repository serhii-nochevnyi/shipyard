## Goal

P44-A, D-A2, D-A3, D-A6 and D-X1 (REQ-177, REQ-178, REQ-181, REQ-184). Worker transcripts miss the interactive Claude parent session, and the audit says that session dominates consumption. Only a statusline command sees the parent's `rate_limits`. This ticket first captures the real statusline input as a scrubbed boundary fixture. It then adds `statusline-collector.cjs wrap`, which works as follows:

- It buffers stdin once and forwards identical bytes to the preexisting renderer.
- It never changes the renderer's stdout, stderr or exit status.
- Only after the renderer returns does it record an envelope through the T-44-03 store. Any collector failure is invisible.

The installer that points `settings.json` at the wrapper is T-44-05.

`human_checkpoint: true` because the ticket starts with an operator capture. The sandboxed executor has no interactive Claude session, and headless `claude --print` renders no statusline.

## Scope

- **Capture (human action, first).** The executor prepares the steps and the operator runs them. Development and tests never edit the user's active `~/.claude/settings.json` or `~/.claude/statusline.sh`.
  1. Write a temp settings file under `$TMPDIR` whose `statusLine.command` copies stdin to `$TMPDIR/statusline-raw.jsonl` (one JSON object per line) and prints a fixed string.
  2. The operator starts one interactive session with `claude --settings <that file>`. If `claude --help` does not list `--settings`, the operator uses an isolated config home instead. The operator sends one prompt so that rate limits appear, then exits.
  3. The executor runs `node scripts/capture-boundary-fixtures.cjs --boundary claude-statusline --dry-run --input $TMPDIR/statusline-raw.jsonl`. It commits only the scrubbed `tests/fixtures/captured/claude-statusline.jsonl`, and checks that no e-mail or user id remains.
  4. The executor records the observed `rate_limits` keys, the `resets_at` unit and whether `cost`/`session_id` fields are present in the SUMMARY.
- `scripts/capture-boundary-fixtures.cjs`:
  - Register the `claude-statusline` boundary in `BOUNDARIES`, with a `run` that refuses and names the manual procedure. There is no automatic live capture, because the statusline needs an interactive session.
  - Keep the dry-run path.
- NEW `tests/fixtures/captured/boundaries/claude-statusline.json`:
  - `fixtures`: the new file.
  - `consumers`: `tests/unit/statusline-collector.test.cjs`.
  - `inline_shapes`: a pattern for `"used_percentage"`.
- NEW `plugins/delivery-pipeline/scripts/statusline-collector.cjs`. It requires only `node:fs`, `node:child_process`, `./subscription-observation.cjs` and `./subscription-store.cjs`, all literal. It is the only new module in this phase allowed to use `child_process`, and only to run the preexisting renderer. Its behaviour:
  - `wrap --home <claude-home> --previous-b64 <base64 of the previous command>`. The previous command travels in the argument, so forwarding never depends on reading a file.
  - Read all of fd 0 into one Buffer.
  - `spawnSync('/bin/sh', ['-c', previous], { input: buffer, stdio: ['pipe', 'inherit', 'inherit'], env: process.env })`, or the shell the capture confirms.
  - Exit with the renderer's status. Re-raise the renderer's signal. Exit 127 when the spawn itself fails.
  - After the renderer returns, run `try { collect(buffer, home) } catch {}` with no output. `collect` works as follows:
    - It skips parsing above 1 MiB.
    - It builds one envelope per `rate_limits.<window>` from `used_percentage` and `resets_at`, with `source: 'claude-statusline'`, `observed_at` from the wrapper clock, `freshness: 'observed'` and `concurrency: 'unknown'`.
    - It takes the label from `readLabel({ runtime: 'claude', home })`, and records `unattributed` when there is none.
    - It appends through the store (dedupe per changed series, percent and reset).
  - Export `parseStatusline(json, context)` and `collect` for tests.
- NEW `tests/unit/statusline-collector.test.cjs` (assert-harness). It uses temp homes and `stateRoot`s only. Renderers are temp shell scripts.
- Comment policy: markers only; the empty `catch {}` carries no comment. Codex packaging: `make package-shipyard-codex` runs on the epic, not in this ticket.

## Acceptance criteria

- `tests/fixtures/captured/claude-statusline.jsonl` exists with a `shipyard_fixture` provenance line for boundary `claude-statusline` with `scrubbed: true`. It contains no e-mail address, and `boundary-fixtures.test.cjs` accepts the new manifest.
- For the captured fixture, `parseStatusline` yields `five_hour` and `seven_day` envelopes whose `used_percent` equals the captured `used_percentage` exactly (percent, not ×100), with `window_minutes` 300 and 10080. There is no field outside the T-44-01 allow-list.
- `wrap` forwards stdin byte-identical to the renderer, for both the UTF-8 fixture and a binary buffer containing `0x00` and invalid UTF-8. The test renderer writes its stdin to a file, and the test compares that file with the input bytes.
- `wrap`'s stdout and stderr equal the renderer's, and its exit status equals the renderer's for 0 and 3. A renderer killed by `SIGTERM` makes `wrap` end by the same signal.
- With an unwritable `stateRoot`, a malformed JSON input or an oversize input, `wrap`'s stdout, stderr and exit status are identical to the renderer run directly, and no store file appears.
- Repeated identical renders store one sample. A missing label records `attribution: 'unattributed'`.
- Envelope `status`/verdict fields follow T-44-01: `verdict` stays `'inconclusive'`.
