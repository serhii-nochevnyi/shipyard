## Goal

P44-G, D-G1 and D-X1 (REQ-183, REQ-184). Effort cannot be a treatment today: `effort` is an orchestration-overhead cohort key, so two arms that differ in effort are never a matched pair. This ticket adds a protocol-only module, `effort-experiment.cjs`, with:

- a versioned experiment definition (`shipyard.effort-experiment.v1`);
- a versioned report (`shipyard.effort-experiment-report.v1`);
- a human decision record (`shipyard.effort-experiment-decision.v1`).

It defines eligibility, and its metrics count failed, repair, escalation and abandoned work. Promotion is only ever a recorded human decision above the 20-completion / 95 % attribution / seven-day floor.

Nothing becomes active. The ticket changes no resolver, policy object, config key or dispatch. `TREATMENT_KEYS` and the overhead report schema are not mutated.

## Scope

- NEW `plugins/delivery-pipeline/scripts/effort-experiment.cjs`. It requires only `node:` built-ins, `./orchestration-overhead.cjs` (read exports) and `./model-policy.cjs` (read `POLICY` only). Its exports are frozen:
  - `EXPERIMENT_SCHEMA`, `REPORT_SCHEMA` and `DECISION_SCHEMA` as above.
  - `FLOOR = { min_completions: 20, attribution: 0.95, window_days: 7 }`. The floor is a minimum, not proof.
  - `normalizeExperiment(value)` accepts `{ schema, experiment_id, runtime, role, model, policy_hash, arms: [{ arm_id, effort, baseline }], eligibility, activation, comparison }`. It refuses (`INVALID_EXPERIMENT`):
    - `activation.active !== false` or `activation.allowed !== false`, where `activation.requires` must read `'ADR-014 amendment or separate ADR'`;
    - arms that differ in anything but `effort`, or fewer than two arms, or not exactly one `baseline: true`;
    - a baseline arm whose model or effort differs from the ADR-014 base rung for (runtime, role) in `POLICY`;
    - an effort outside `EFFORTS` for the runtime;
    - a `policy_hash` that is not the current `POLICY_HASH`, which the report records as `policy_mismatch`;
    - a Codex definition with a candidate arm but no `baseline_report_digest`. Codex candidate arms are defined only after a Luna/max baseline report.
  - `comparison` must equal `{ arm_key: 'effort', cohort_key_excludes: ['effort'], overhead_matched_pair: false, reason: 'effort is an orchestration-overhead cohort key; matchedCohorts never pairs effort arms' }`. This states explicitly that the arms are not an overhead treatment pair.
  - `report(experiment, { rows, outcomes, decision, now })`:
    - `rows` are overhead rows, from `latestRows(readStream(graph))`. `outcomes` is an explicit list `[{ ticket, outcome: 'verified' | 'failed' | 'abandoned', completed_at }]`.
    - Eligibility means a row matches runtime, role, model and `policy_hash`, and its effort is one of the arms. Excluded rows are counted with a reason: `runtime`, `role`, `model`, `policy_mismatch`, `effort_not_in_arms` or `unattributed`.
    - Per-arm metrics per verified completion, where the numerator includes the work below as well as verified work:
      - `verified`, `failed` and `abandoned`;
      - `repair` (`ci-fix`/`review-fix` rows for the same ticket);
      - `escalation` (rows whose rung is not the base rung);
      - the estimated tokens of all of these.
    - `attribution` coverage.
    - `floor_met` per arm and `window_days` observed.
    - `verdict` is one of `inconclusive`, `baseline_pending`, `ready_for_human_decision` or `rollback`. The value `promote` is never computed. `ready_for_human_decision` requires every arm to meet `FLOOR`. `rollback` requires more failed or abandoned work in the candidate arm than in the baseline.
    - `report_digest` over the report without `decision`.
    - `decision` is present only when a supplied `DECISION_SCHEMA` record (`decided_by`, `decided_at`, `decision: 'promote' | 'reject'`, `evidence_digest`) has an `evidence_digest` equal to `report_digest` while the verdict is `ready_for_human_decision`. Otherwise it is ignored, with `decision_ignored_reason`.
    - `activation: { active: false, allowed: false }` always, including after a `promote` decision.
    - `status: { implemented: true, installed: rows.length > 0, behaviorally_verified: false, efficiency_measured: false }`.
- CLI (read-only, JSON to stdout, exit 2 on invalid input):
  - `validate --experiment <file>`
  - `report --experiment <file> --graph <dir> --outcomes <file> [--decision <file>]`
  - The report never writes any file.
- NEW `tests/unit/effort-experiment.test.cjs` (assert-harness). It uses temp graph dirs with rows recorded through `orchestration-overhead.recordBatch` and reads baselines from `model-policy.cjs` `POLICY`.

## Acceptance criteria

- `normalizeExperiment` refuses `activation.active: true`, arms that differ in `model`, a Claude executor baseline other than the `POLICY` base rung (sonnet/max), and a Codex definition with a candidate arm and no `baseline_report_digest`.
- A valid Claude executor definition with a `max` baseline and a `high` candidate is accepted, and its `comparison.overhead_matched_pair === false`.
- The report counts failed, repair, escalation and abandoned work in the per-verified-completion numerator. A fixture with one repair round and one escalation shows both counts and their tokens.
- Below the floor in any arm, or with attribution under 0.95, or with fewer than 7 observed days, the verdict is `inconclusive`. Above the floor it is `ready_for_human_decision`. No input yields a verdict of `promote`.
- A decision record with a stale `evidence_digest` is ignored with a reason. A matching `promote` decision is included, and `activation.allowed` stays `false`.
- `orchestration-overhead.TREATMENT_KEYS` deep-equals `['wait_events', 'bounded_context']`, and `REPORT_SCHEMA` equals `'shipyard.orchestration-overhead-report.v1'` after the module loads.
- The module source contains no `resolveDispatch` call and requires none of `child_process`, `net`, `http`, `https` or `dgram` (static check). The `report` CLI leaves the graph dir byte-unchanged.
- Every report carries separate `installed`, `behaviorally_verified` and `efficiency_measured` booleans.
