## Goal

P44-D, D-D1 and D-X1 (REQ-182, REQ-184). `recommendRotation` compares only role, backend and runtime. It does not persist or deduplicate advice, and it has no lifecycle classes. This ticket keeps the one advisory recommender (ADR-019) and changes it as follows:

- The comparable key gains model, effort, policy hash and instruction digest. A missing or mixed dimension gives `unknown`.
- Resume, history-copying fork, compaction and fresh start become separate classes. Their costs include checkpoint collection, successor startup, successor rereads and cache warmup.
- At most one shadow decision is recorded per (recommendation id, source-state fingerprint), and only on explicit request.
- Quota series from T-44-01 are attached as informational evidence.

`automatic_transfer.allowed: false` and T-41-02's ownership invariants are unchanged. No producer of `instruction_digest` exists yet (P44-C is second pass), so current evidence correctly yields `unknown`. This acceptance states that outcome explicitly.

## Scope

- `orchestration-overhead.cjs`:
  - `normalizeObservation` accepts optional `instruction_digest` (a sha256 hex string) and `lifecycle_class` (`resume`, `fork`, `compaction` or `fresh_start`). It spreads each into `dimensions` only when it is non-null, so every existing row keeps its exact `observation_id`.
  - Add stage `successor_reread` to `STAGES` and to `HANDOFF_COST_STAGES`.
  - Add the exported `handoffCostSummary(rows)`, which returns `shipyard.handoff-cost-summary.v1`: per `lifecycle_class`, per-stage totals over the four handoff stages, `missing_stages`, `status: { implemented, installed, behaviorally_verified, efficiency_measured: false }` and `verdict: 'inconclusive'`.
  - `TREATMENT_KEYS`, `COHORT_KEYS`, `REPORT_SCHEMA` and `report()` are unchanged.
- `session-handoff.cjs`:
  - `COMPARABLE_DIMENSIONS = ['role', 'backend', 'runtime', 'model', 'effort', 'policy_hash', 'instruction_digest']`. `comparableKey` and `hasComparableDimensions` use all seven. The startup filter inherits the key.
  - A missing dimension gives `unknown` with reason `missing comparable dimension <name>`. A mixed dimension gives `unknown` with reason `mixed <name>`, which generalizes the single message at `:170`.
  - Mirror `successor_reread` in the local `HANDOFF_COST_STAGES` (`:258`).
  - `recordLifecycleCost` passes through `model`, `effort`, `instruction_digest` and `lifecycle_class`. The defaults come from `createSessionHandoff` options, like `policy_hash`. A field is omitted when absent.
  - `LIFECYCLE_CLASSES` is a frozen table:
    - `resume`: `history_copying: false`.
    - `fork`: `history_copying: true`, and `supported: false` on `codex` because of `fork_turns: none`.
    - `compaction`.
    - `fresh_start`.
    - Each class lists the four cost stages. The recommendation `evidence.lifecycle` carries per-class cost totals from `handoffCostSummary`, which never change `state` or `automatic_transfer`.
  - Optional `options.quota`: a `shipyard.subscription-usage.v1` summary. Its series are copied into a result field `quota` that sits outside the identity, so neither `recommendation_id` nor the fingerprint changes with quota values. A wrong schema is refused as `INVALID_INPUT`.
  - The result gains `measurement: { installed, behaviorally_verified, efficiency_measured: false, verdict: 'inconclusive' }`, also outside the identity.
  - Shadow decisions (Open Question 4: explicit opt-in only):
    - With `record_shadow: true`, or CLI `status --record-shadow`, compute `source_state_fingerprint` as the digest of the sorted `(observation_id, revision)` pairs of every consumed row, plus the phase boundary id, the blockers and the role/runtime/backend scope.
    - `shadow_decision_id = sha256(recommendation_id + '\0' + fingerprint)`.
    - The decision is appended to `<git-common-dir>/shipyard/rotation/shadow-decisions.jsonl` (schema `shipyard.session-rotation-shadow-decision.v1`, metadata only) under `lock.cjs` `withLock`.
    - An existing id returns `{ recorded: false, duplicate: true }`.
    - `inspect` stays read-only.
    - Nothing launches, and no recorder is called other than this append.

## Acceptance criteria

- With all seven dimensions present and equal, the existing recommend and continue scenarios keep their `state`.
- Removing any one of model, effort, policy_hash or instruction_digest gives `state: 'unknown'` with the dimension-specific reason. Mixing any one gives `unknown` naming that dimension.
- Current evidence without `instruction_digest` gives `unknown`, and this is asserted as the intended outcome.
- An overhead row without `instruction_digest` and `lifecycle_class` keeps its exact pre-change `observation_id` (pinned literal).
- `recordHandoffCost` accepts `successor_reread`. `handoffCostSummary` reports four stages per class, lists missing stages, has `verdict: 'inconclusive'`, and records `installed`, `behaviorally_verified` and `efficiency_measured` separately.
- A Codex `fork` class is `supported: false`, and `fork.history_copying === true`.
- Two `record_shadow` calls on identical inputs append one line, and the second returns `duplicate: true`. A changed row revision appends a new line. Two calls that differ only in `quota` values append one line.
- The ownership store bytes under `<git-common-dir>/shipyard/ownership` are unchanged by all recommendation and shadow calls, and every result has `automatic_transfer.allowed === false`.
- `TREATMENT_KEYS` deep-equals `['wait_events', 'bounded_context']` and `COHORT_KEYS` is unchanged. `tests/unit/gen-codex-shipyard.test.cjs` is untouched.
