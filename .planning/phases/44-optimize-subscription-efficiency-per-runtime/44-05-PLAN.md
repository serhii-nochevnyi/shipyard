## Goal

P44-A, D-A2, D-A5, D-A6 and D-X1 (REQ-177, REQ-180, REQ-181, REQ-184). The statusline collector from T-44-04 needs a supported, reversible way into the operator's Claude config. This ticket adds a separate installer, `scripts/install-shipyard-claude-statusline.sh`, with `make` targets. It does not use `install-shipyard-claude-hook.sh`, which pending T-43-03 edits. The installer:

- rewrites only `settings.statusLine`;
- keeps an ownership record;
- restores only what it owns on uninstall;
- offers a read-only `--check`.

The risk is high because the ticket edits the operator's live Claude configuration. `human_checkpoint: true` records a human review of the installer and its smoke before merge.

## Scope

- NEW `scripts/install-shipyard-claude-statusline.sh`. It is bash-3.2 compatible, uses `set -euo pipefail`, and contains no free comments (comment policy; the shebang is exempt). It uses `CLAUDE_HOME` (default `$HOME/.claude`) and `SETTINGS="$CLAUDE_HOME/settings.json"`, and has these modes:
  - **Install** (default):
    - It refuses unless `statusLine` is an object with `type === 'command'`, a non-empty string `command`, and only the optional keys `padding`. An absent `statusLine` is also refused, because there is no renderer to wrap.
    - If the current `statusLine` deep-equals `owned.json.installed`, it changes nothing (the idempotency guard).
    - Otherwise it copies the collector's literal require closure into `$CLAUDE_HOME/shipyard-statusline.XXXX`, runs `node --check` on each file, smoke-runs `wrap` once against `printf ok`, and `mv`s the copy to `$CLAUDE_HOME/shipyard-statusline/`.
    - It writes `owned.json` (`schema: 'shipyard.claude-statusline-ownership.v1'`, `previous`, `installed`) before settings.
    - It then rewrites only `settings.statusLine` to `{ type: 'command', command: "node '<bundle>/statusline-collector.cjs' wrap --home '<CLAUDE_HOME>' --previous-b64 <b64>", padding: <unchanged when present> }` through a `node - <<'NODE'` heredoc that preserves every other key.
    - With `ACCOUNT_LABEL=<label>`, it runs the bundled `subscription-store.cjs label --runtime claude --home "$CLAUDE_HOME" --set "$ACCOUNT_LABEL"`. An invalid label aborts before settings change.
  - **`--remove`:**
    - If the current `statusLine` deep-equals `owned.installed`, it restores `owned.previous` exactly.
    - Otherwise it leaves `settings.json` byte-unchanged and prints that the user changed it.
    - In both cases it deletes only `$CLAUDE_HOME/shipyard-statusline/`. Private samples under `~/.local/state/shipyard/claude/subscription/` are left in place and named in the output.
  - **`--check`** (read-only): prints `installed`, `foreign` or `absent`, and it never writes.
- NEW `tests/smoke/claude-statusline-smoke.sh`. It sets `HOME` and `CLAUDE_HOME` to fresh `mktemp -d` dirs, so the real home is never touched, and uses a fake renderer script that prints fixed bytes to stdout and stderr and exits 3. It checks:
  1. Install is refused for an absent `statusLine`, a string `statusLine` and an object with an unknown key. `settings.json` bytes are unchanged after each refusal.
  2. Install with a valid prior `statusLine` plus unrelated keys: the unrelated keys and `padding` are preserved, `owned.json` exists, and `--check` prints `installed` and leaves the settings sha256 unchanged.
  3. Running the installed command with `tests/fixtures/captured/claude-statusline.jsonl` (minus its provenance line) as stdin gives the renderer's exact stdout, stderr and exit 3 (compared with `cmp`). A sample file appears under `$HOME/.local/state/shipyard/claude/subscription/` with mode 600 in a 700 directory. No file appears under the repository worktree.
  4. `ACCOUNT_LABEL=claude-max-1` install records the label, and `ACCOUNT_LABEL=me@x` aborts with settings unchanged.
  5. Installing twice leaves `owned.previous` equal to the original value. Then `--remove` leaves `settings.json` `cmp`-equal to the original file and the bundle directory gone.
  6. Reinstall, edit `statusLine` by hand, then `--remove`: the edited value is kept and the bundle directory is gone.
- `Makefile`:
  - `install-shipyard-claude-statusline` runs the installer. `remove-shipyard-claude-statusline` runs it with `--remove`.
  - `test-statusline` runs `./tests/smoke/claude-statusline-smoke.sh` and is added to the `test-fast` list.
  - All three go in `.PHONY`.
