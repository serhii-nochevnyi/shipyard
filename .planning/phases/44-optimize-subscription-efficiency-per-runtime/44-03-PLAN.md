## Goal

P44-A, D-A5, D-A6, D-A4 and D-X1 (REQ-180, REQ-181, REQ-179, REQ-184). Per-account quota samples must live only in private host state, `~/.local/state/shipyard/<runtime>/subscription/`, with 0700 directories, 0600 files and bounded retention. `.planning/` is tracked in this repository, so a sample written there would be pushed. The account is an operator-declared local label per runtime home; a missing label makes an observation `unattributed`. This ticket adds `subscription-store.cjs`, the only writer of that state. The statusline collector (T-44-04) and the installer (T-44-05) use it.

## Scope

- NEW `plugins/delivery-pipeline/scripts/subscription-store.cjs`. It requires only `node:` built-ins, `./lock.cjs` and `./subscription-observation.cjs`, all as literal relative requires so the T-44-05 bundle copy works. Its exports are frozen:
  - `resolveRoot({ runtime, stateRoot })`:
    - The default is `path.join(os.homedir(), '.local', 'state', 'shipyard', runtime, 'subscription')`, with `runtime` restricted to `claude` or `codex`.
    - It first canonicalizes the deepest existing ancestor of the requested root with `fs.realpathSync` and appends the remaining components. This resolves operating-system aliases above the store, such as macOS `/var` → `/private/var` and `/tmp` → `/private/tmp`, so `os.tmpdir()` and `mktemp -d` roots are usable in tests and in the T-44-05 smoke.
    - It refuses (`UNSAFE_STATE_ROOT`) when the canonical path has a `.planning` segment or sits inside a git working tree, or when the requested root itself or any directory at or below it (the directories the store owns, for the default root everything from `…/state/shipyard/<runtime>` down) is a symlink. It checks those owned components with `fs.lstatSync` before canonicalization, so a symlinked `subscription/` directory that points into a repository is refused and never followed.
    - The git working-tree check walks up the canonical path with `fs.lstatSync` looking for a `.git` entry and spawns no process.
    - It creates directories with mode `0o700` and re-applies `chmodSync(0o700)`.
  - `append(envelope, { runtime, stateRoot, now })`:
    - It validates the envelope through `validateEnvelope`, and appends under `withLock` with a short wait (`waitMs` ≤ 300).
    - The target file is `samples-YYYY-MM.jsonl`, written with mode `0o600`.
    - It returns `{ appended: false, duplicate: true }` when the last stored sample of the same series has equal `used_percent` and `resets_at` (Open Question 3: dedupe per changed series, percent and reset; no other throttle).
  - `list({ runtime, stateRoot })` returns the stored envelopes.
  - `prune({ runtime, stateRoot, now, retentionDays = 35, maxFileBytes = 1048576 })`: bounded retention by age and by per-file size. These defaults are the recorded choice for assumption A5.
  - `declareLabel({ runtime, home, label, stateRoot })`, `readLabel({ runtime, home, stateRoot })` and `clearLabel(...)`:
    - The label map `labels.json` (mode 0600) is keyed by sha256 of the runtime home's realpath (assumption A6).
    - Labels pass `normalizeLabel`, so an `@` is refused.
    - `readLabel` returns `null` when no label is declared, and callers then record `unattributed`.
  - Every stored object comes from `validateEnvelope` or the fixed label-map shape. The store accepts no free-form fields, prompts, transcript text or credentials.
  - Each `list` result carries `status: { implemented: true, installed: <root exists>, behaviorally_verified: false, efficiency_measured: false }`.
- CLI (JSON to stdout, exit 2 on invalid input):
  - `label --runtime <r> --home <dir> (--set <label> | --clear | --show)`
  - `list --runtime <r>`
  - `prune --runtime <r>`
  - Every subcommand accepts `--state-root <dir>`, which is for tests.
- NEW `tests/unit/subscription-store.test.cjs` (assert-harness). It uses temp `stateRoot`s only and builds envelopes from the captured fixtures through T-44-01's parser.
- Comment policy: markers only. Codex packaging: `make package-shipyard-codex` runs on the epic, not in this ticket.

## Acceptance criteria

- After `append`, `statSync(dir).mode & 0o777 === 0o700` for the store directory and `0o600` for every sample and label file.
- `resolveRoot` refuses a `stateRoot` under a temp git working tree (a directory containing `.git`), a path with a `.planning` segment, a `stateRoot` that is itself a symlink, and a `stateRoot` whose `subscription/` directory is a symlink into a temp git working tree. No file is created in any refused case.
- A `stateRoot` under `os.tmpdir()` is accepted on macOS, where `/var` is a symlink to `/private/var`; the test runs there and on Linux.
- Appending the same Codex fixture envelope twice stores one line (`duplicate: true`). A changed `used_percent` or a `resets_at` change beyond the tolerance stores a new line.
- `prune` removes samples older than the retention window and caps each file at `maxFileBytes`. Samples inside the window survive.
- A missing label → `readLabel` returns `null`. `declareLabel` with `a@b.c` throws `INVALID_LABEL`. Two different runtime homes keep independent labels.
- Stored bytes after appending envelopes from the Codex parent fixture contain none of `creator_user_id`, `credits`, `plan_type`, `balance` or `@`.
- The module source requires none of `child_process`, `net`, `http`, `https` or `dgram` (static check).
- After the test run, no file under the repository worktree was created by the store; the test checks this with a before/after listing of the test's own temp roots only.
