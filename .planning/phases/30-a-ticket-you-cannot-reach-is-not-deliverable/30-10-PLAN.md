## Goal

Make sentinel stack decisions use the live PR branch identity recorded by
state-sync when it differs from the graph's canonical slug.

## Context (Reads)

- ADR-010 and the Phase 30 UAT/VERIFICATION projections — the phase boundary
  and the evidence required before a ticket can land in its stack.
- `plugins/delivery-pipeline/scripts/sentinel.cjs` — the live stack guard,
  checkpoint-parent refusal, limb detection, and post-merge child cascade.
- `plugins/delivery-pipeline/scripts/state-sync.cjs` and
  `plugins/delivery-pipeline/scripts/ticket-pr-match.cjs` — the existing
  `state[id].pr_branch` observation and title-marker match that preserve the
  actual GitHub branch name.
- `tests/unit/sentinel.test.cjs` — current same-phase boundary, checkpoint,
  limb, and cascade fixtures to extend with observed branch identities.

## Scope

Use the canonical graph branch together with the validated ticket's observed
`pr_branch` anywhere sentinel determines whether a base belongs to the ticket's
same-phase stack or whether a child PR must be found for cascade retargeting.
Keep repository and phase filtering unchanged. When an observed branch points
to an open human-checkpoint ticket, retain the checkpoint refusal; when the
parent has merged, retain limb protection. Query live child PRs using the
observed branch and preserve the existing cached fallback and warning behavior.

## Out of scope

Changing how state-sync discovers or records branch drift; changing canonical
branch generation; relaxing cross-repository or cross-phase stack boundaries;
preauthorizing a human checkpoint; changing merge policy, review policy, or
ticket eligibility; and changing the phase's repository reachability resolver.

## Acceptance criteria

- A ticket PR based on a same-phase parent’s observed `pr_branch` passes the
  stack-boundary check when all other live merge gates pass.
- A child targeting an observed branch of an open human-checkpoint parent is
  refused with the checkpoint reason, rather than being classified as outside
  the stack or merged into the checkpoint diff.
- A child of a merged ticket is still recognized as landing on a limb when its
  base uses the parent’s observed branch.
- After a parent merge, cascade retargeting queries the observed child branch
  and moves the live child PR to the phase epic; cached fallback remains
  explicit when the live query is unreadable.
- A branch from another phase or repository remains outside the stack even if
  it is present as an observed branch in state.

## Test strategy

Extend the focused sentinel fixtures with canonical/observed branch pairs for
the stack guard, checkpoint refusal, merged-limb refusal, live cascade, and
cross-phase boundary. Use the existing GitHub stub and exact blocker/retarget
assertions. Keep tests local and deterministic; no live GitHub, tracker,
credential, or provider quota is needed.

## Verification commands

~~~bash
node --test tests/unit/sentinel.test.cjs

~~~

## Artifacts this phase produces

- A sentinel stack guard that follows the observed PR branch identity without
  widening the phase boundary.
- Regression coverage proving checkpoint, limb, cascade, and boundary behavior
  under branch-name drift.

## Dependencies and risks

This is a medium-risk merge-guard correction. It waits for T-30-03 because the
delivery graph and state-sync path that expose observed branch identities must
be landed before this consumer is exercised. The fix changes only recognition
of an already validated same-phase branch and keeps the human-checkpoint gate
closed.
