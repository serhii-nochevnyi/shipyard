## Goal
Persist resolved checkouts and park unreachable work.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 state-sync.cjs repository status output, pipeline-config.cjs config precedence/write conventions, deliver.md multi-repository cold start, and the durable park stores used by drift-needed.cjs.

## Scope
Write a successful resolved slug/path into .planning/config.json atomically, keep .planning/ in the project repository, and park only the affected tickets on failed resolution while the rest of the board continues. Report 404 as either inaccessible or nonexistent, not as a certainty.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- A successful path is written back once and is used on the next cold start without another question.
- A write failure or unreachable clone leaves the board trackable and records the resolver reason.
- Other repositories and tickets continue through state-sync after one repository parks.
- Config write-back is atomic, preserves foreign config keys, and refuses an unparseable config.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/repo-resolve.test.cjs tests/unit/pipeline-config.test.cjs
~~~

## Dependencies and risks
This closes ADR-010: the resolver becomes a durable source for later delivery and never turns a reachability failure into a global stop.
