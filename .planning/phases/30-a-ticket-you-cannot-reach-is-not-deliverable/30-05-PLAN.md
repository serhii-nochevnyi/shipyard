## Goal
Validate repository destinations with the existing nesting rule.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 pipeline-config.cjs:719-800 already validates absolute pipeline.repos paths and nested sub_repos exceptions. Extend this validator rather than creating a second path policy.

## Scope
Declare and parse pipeline.repos_root with the project-parent default, validate resolved clone destinations against the existing nesting/sub_repos rule, and expose the same validation helper to repo-resolve. Preserve warnings for allowed nested sub-repositories and refusal for unsafe destinations.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- The default repository root is the project parent and is absolute.
- A destination nested in the project is rejected unless the declared top segment is in sub_repos.
- Relative and malformed repos_root values are rejected without mutation.
- Resolver and pipeline-config return the same result for each destination fixture.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/pipeline-config.test.cjs tests/unit/repo-resolve.test.cjs
~~~

## Dependencies and risks
The shared validator is the only path policy; the resolver must not reproduce it with ad hoc string checks.
