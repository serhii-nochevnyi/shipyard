## Goal
Resolve configured repositories before fallback discovery.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 state-sync.cjs:1034-1068, pipeline-config.cjs repository parsing, graph-dir.cjs repository selection, and deliver.md multi-repository preparation. No checkout resolver currently exists; a behavior search covered git clone, pipeline.repos, and the local-checkout warning.

## Scope
Create the resolver contract and the first resolution branch: consume a validated delivery.repo slug, use an existing absolute pipeline.repos entry when it is valid, and return a structured trackable-only result when no checkout is configured. Add the deliver cold-start call site and state-sync diagnostics without changing clone or discovery behavior yet.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- A configured existing checkout resolves deterministically and is returned with its repository root.
- A missing or invalid configured path produces a non-actionable structured result with the ticket and reason.
- Unknown repository slugs and malformed resolver arguments fail closed before filesystem mutation.
- The caller can distinguish tracking from executable checkout resolution.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/repo-resolve.test.cjs
~~~

## Dependencies and risks
Later tickets extend the same resolver in ADR order, so this plan is a root for the reachability chain.
