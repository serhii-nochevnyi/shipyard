## Goal
Use a full clone with all refs required for base resolution.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 repo-resolve.cjs clone command, graph-dir.cjs:104 resolveBaseRef, and ticket-worktree.sh:100-135. Base resolution requires refs/remotes/origin/<base>; no existing clone wrapper is present.

## Scope
Perform a full clone to the validated destination with no depth, single-branch, or filter options. Verify the resulting origin refs needed by the graph before reporting success, and include the tested ref requirement in the smoke fixture.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- The clone command has no shallow, single-branch, or filter option.
- A successful clone reports the destination and confirms the named base can resolve from origin.
- A clone missing the required base ref is reported as unknown/parked rather than silently accepted.
- The smoke test proves the command remains compatible with ticket-worktree base selection.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/repo-resolve.test.cjs && bash tests/smoke/repo-resolve-smoke.sh
~~~

## Dependencies and risks
The full clone is deliberate because the bare-name fallback in graph-dir.cjs is unsafe for a new checkout.
