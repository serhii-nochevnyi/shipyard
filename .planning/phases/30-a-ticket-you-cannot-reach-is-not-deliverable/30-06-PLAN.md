## Goal
Mirror the project origin protocol for repository clones.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 repo-resolve.cjs clone branch, the project git remote origin, and the existing gh invocation conventions in reviewers.cjs and epic-branch.sh. The measured host difference between gh protocol preference and project origin is recorded in ADR-010.

## Scope
Implement clone URL selection from the project origin protocol and gh repo metadata. Support SSH and HTTPS project origins, refuse an unavailable protocol/URL instead of silently switching, and keep the chosen URL in the resolver result for audit output.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- An SSH project origin selects the repository sshUrl and an HTTPS origin selects url.
- The resolver never uses gh global protocol preference as its source of truth.
- Missing or inconsistent clone metadata returns an actionable failure without invoking git clone.
- Tests cover both origin forms and ensure no credentials enter output.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/repo-resolve.test.cjs
~~~

## Dependencies and risks
This ticket prepares the actual clone operation while keeping protocol selection deterministic and testable.
