## Goal
Adopt matching checkouts and refuse to clobber other paths.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 repo-resolve.cjs destination handling, lock.cjs ownership rules, and the existing state-sync repository warning. No current delivery script deletes or overwrites a repository directory.

## Scope
Make resolution idempotent: adopt an existing matching-origin git checkout, refuse a non-git or origin-mismatched destination, and preserve the directory untouched. Record refusal/ambiguity as a parkable result and make concurrent resolution atomic with the existing lock discipline.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- Matching origin is adopted without clone or deletion.
- A non-git path and an origin mismatch are hard refusals naming the exact destination.
- No refusal path removes, renames, or overwrites user data.
- Concurrent or repeated resolution yields one stable result and no duplicate checkout.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.
