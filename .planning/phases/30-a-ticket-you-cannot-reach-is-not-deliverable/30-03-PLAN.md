## Goal
Discover repository checkouts by declared origin.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 repo-resolve.cjs from T-30-02, pipeline-config.cjs:719-800 for declared roots and nesting rules, and ticket-worktree.sh:39-55 for sibling checkout placement. No directory-name discovery is reused.

## Scope
Add origin-based discovery over pipeline.repos_root and the project parent one level deep. Normalize SSH/HTTPS/scp-like GitHub origins to an owner/name identity, ignore non-git directories and unrelated forks, and return ambiguity with all candidates rather than selecting one.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- Discovery matches the configured owner/name against git remote origin, never the basename.
- Only declared roots and the documented one-level sibling boundary are scanned.
- Zero candidates, one candidate, and multiple candidates have distinct machine-readable outcomes.
- A candidate with a non-matching origin is never adopted.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

~~~bash
node --test tests/unit/repo-resolve.test.cjs
~~~

The dependency makes the resolver implementation cumulative and prevents two writers from diverging.
