## Goal
Require an explicit operator choice before cloning.

## Context (Reads)
ADR-010, the phase UAT/VERIFICATION projections, and the current delivery owners named below. Existing behavior is verified in the cited source before implementation; new helpers extend the existing lock/store and config patterns.
 repo-resolve.cjs discovery outcomes, deliver.md cold-start interaction conventions, and the existing park/ask patterns in drift-needed.cjs and front.cjs. No existing delivery path asks for a repository path or clone choice.

## Scope
Expose the three-way choice for an undiscovered repository: clone to the validated destination, supply an existing path, or skip. Make unattended/text-mode execution choose skip and park. Validate a supplied path through the same resolver before adoption; do not perform a clone in this ticket.

## Out of scope
Changing tracker eligibility, model policy, or reviewer behavior; deleting user repositories or worktrees; credential repair; monorepo sub-path semantics; and unrelated historical planning repairs.

## Acceptance criteria
- The prompt names the repository slug and presents clone, existing path, and skip choices.
- An unanswered or unattended choice returns trackable-only with a durable park reason.
- A supplied path is accepted only after origin and nesting validation.
- The smoke test proves that the no-answer path performs no filesystem or network write.

## Test strategy
Use focused unit fixtures and negative cases first. Keep network, credentials, live trackers, and provider quota out of local verification; put proving-ground-only behavior in the integration evidence. Preserve the existing full CI gate for the phase.

## Verification commands
~~~bash
node --test tests/unit/repo-resolve.test.cjs && bash tests/smoke/repo-resolve-smoke.sh
~~~

## Dependencies and risks
The high-risk checkpoint covers the new decision to write outside the project; the clone implementation remains behind the explicit choice.
