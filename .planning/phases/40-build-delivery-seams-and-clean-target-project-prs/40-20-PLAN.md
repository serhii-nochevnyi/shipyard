## Goal

In target projects (D-07, D-18, D-27):

- Ticket branches are `<type>/<slug>` or `<type>/<JIRA-KEY>-<slug>`.
- The phase epic branch is `feat/<slug>` or `feat/<JIRA-KEY>-<slug>`.
- The epic → default-branch PR has a conventional title and a neutral body.
- The graph stores every branch, and the ticket ↔ branch and phase ↔ epic mapping stays in the graph.

In the Shipyard repository the `ticket/<ID>-<slug>` and `epic/<phase-dir>` names stay. Two tickets in one graph can no longer share a branch (Pitfall 8).

## Scope

- `validate-graph.cjs`:
  - Compute `hygiene = applies({root: projectRoot, ref: base})` once per run.
  - When `hygiene` is true, `branchFor` returns `${conventionalType(type)}/${jira ? jira + '-' : ''}${slug}` (slug ≤ 40 chars, as today), and the epic is `feat/${jira ? jira + '-' : ''}${phaseSlug}`, where `phaseSlug` is the phase directory name without its leading number.
  - When `hygiene` is false, keep today's names.
  - An explicit `delivery.branch` is validated against the rule for the project kind.
  - A ticket that already has a delivery-state PR on a `ticket/…` head keeps its recorded branch.
  - Two tickets resolving to one branch is an error `DUPLICATE_BRANCH` naming both ids.
  - Store the epic name in the graph phase record.
- `epic-branch.sh pr`: when the epic branch is not `epic/…`, use the title `feat: <phase title in lowercase>` read from the graph (not the branch). Use a body with a short summary of merged changes built from the ticket titles, with no ids, phase numbers or tool names. Before `gh pr create`, run `node pr-hygiene.cjs check` and refuse on violations. Keep today's text for `epic/…` names. Keep `set -euo pipefail`.
- The two `SKILL.md` files: rule 3 describes both naming schemes and which applies where. Executor rule 3 says target projects use conventional commits without ticket ids, and that the Shipyard repository keeps the `feat(T-…)` prefix. Keep the two files identical where they are today.
- `tests/smoke/graph-validator-smoke.sh`:
  - a target-project fixture (no `shipyard` manifest) yields `feat/<slug>` and `fix/<JIRA>-<slug>` branches and a `feat/<slug>` epic;
  - a Shipyard-manifest fixture yields `ticket/…` and `epic/…`;
  - duplicate slugs fail with `DUPLICATE_BRANCH`;
  - a ticket with a recorded legacy PR keeps its `ticket/` branch.
- `tests/smoke/worktree-smoke.sh`: `epic-branch.sh pr` with a `PATH`-stubbed `gh` that records its arguments shows a neutral title and body for `feat/…` epics, and the unchanged text for `epic/…`.
- Comment policy on added lines.

## Out of scope

## Acceptance criteria

- A target-project graph contains no `ticket/` or `epic/` branch for new tickets and phases.
- `validate-graph` fails on duplicate branches.
- The epic PR for a target project passes `pr-hygiene.cjs check`.
