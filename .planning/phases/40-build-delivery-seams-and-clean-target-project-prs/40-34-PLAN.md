## Goal

ADR-018 decision 4 (D-45, D-47). `ticket-worktree.sh` prepares worktrees by construction:

- It writes `info/exclude` entries for the registry's scratch files.
- It materializes the ticket's plan when `.planning/` is untracked.
- It offers `verify`, backed by `worktree-conditions.cjs`.

The finalizer and base-merge consume the same registry instead of their private scratch rules.

## Scope

1. `ticket-worktree.sh create`: after `worktree add`, placed after T-40-27's epic-merge block, and also on both reuse paths, while holding `acquire_git_lock`:
   - resolve the exclude file with `git -C "$wt_dir" rev-parse --git-path info/exclude`, making a relative result relative to `$wt_dir`;
   - `mkdir -p` and `touch` it;
   - append only the missing lines from `node "$conditions_script" exclude-lines` (`grep -qxF`).
   Then, when `git -C "$wt_dir" ls-files --error-unmatch .planning` fails (untracked `.planning`), run `node "$conditions_script" materialize-plan --worktree "$wt_dir" --ticket "$ticket"`. Both steps print nothing on stdout; stdout stays exactly the worktree path. A failure exits non-zero with the command on stderr.
2. New `verify <ticket-id> [--role <r>] [--json]` case: it resolves `$wt_base/$ticket`, runs `node "$conditions_script" verify --worktree … --role … [--json]`, and passes the exit code through. It also reports missing exclude lines, with the remedy `bash <plugin>/scripts/ticket-worktree.sh create <T> <branch> <base>`. Add `verify` to the `usage` echo text only.
3. `delivery-commit-finalizer.cjs`: replace the two-name `SCRATCH` set with `conditions.scratchPaths()`, including `.shipyard-role-artifacts/` entries and every evidence name.
4. `base-merge.cjs`: the tracked-only dirty check ignores registry host-owned graph paths (`conditions.hostOwnedPaths`), so dirty `dispatches.json` and `delivery-front.json` no longer block a base merge (Pitfall 5). A dirty source file still refuses. The CLI and the carry call are unchanged.
5. NEW `tests/unit/ticket-worktree-conditions.test.cjs`, with a hermetic bare origin plus clone in `os.tmpdir()`. Cases:
   - `create` writes each exclude line once, and a second `create` or reuse adds nothing;
   - stdout is only the path;
   - scratch files are invisible to `git status` afterwards;
   - an untracked-`.planning` fixture gets exactly the ticket's plan file;
   - `verify` passes on a clean worktree and refuses a tracked dirty file with the remedy;
   - the finalizer ignores every registry scratch path;
   - base-merge tolerates dirty host-owned graph files and still refuses a dirty source file.
6. Comment policy on added lines. There are no new comment lines in the shell script.

## Acceptance criteria

- Every worktree created or reused by `ticket-worktree.sh create` has all registry scratch lines in its common `info/exclude`, exactly once.
- `ticket-worktree.sh verify` exits 0 on a prepared clean worktree and non-zero with a copyable remedy otherwise.
- The finalizer and base-merge use the registry, and neither keeps a private scratch list.
- A failed diamond merge (exit 13) writes no exclude lines and no plan copy for the removed worktree.
