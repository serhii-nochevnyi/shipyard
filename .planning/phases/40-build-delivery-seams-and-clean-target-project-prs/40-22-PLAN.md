## Goal

REQ-144, second half (D-09, D-23, D-33):

- Every in-flight dispatch writes a provenance sidecar `<graphDir>/provenance/<dispatch_id>.json` with the host's source sha, dirty flag and install kind. It is a sidecar next to, not inside, the ADR-014 application receipt (receipt shape frozen, Pitfall 10).
- The Claude role host (pr-sentinel, arch-review, integrator) records in-flight dispatches through the same store (REQ-139 coverage for role launches), so its launches are stamped too.
- A sentinel merge running from a dogfood host is refused when the PR's base is the repository's default branch.

## Scope

- `dispatch-record.cjs`: `recordInflight` also writes `<graphDir>/provenance/<dispatch_id>.json` = `host-provenance.current({pluginRoot: <this script's plugin root>})` plus `{dispatch_id, ticket, role, recorded_at}`, using `writeAtomic`. It never overwrites an existing sidecar for the same `dispatch_id`. Export `readProvenance(graphDir, dispatch_id)`.
- `claude-role-host.cjs`: call `recordInflight` at role launch with `pid: process.pid` and a `dispatch_id` from the scope, or a host-generated run id, and `clearInflight` in `finally`.
- `sentinel.cjs` `mergeOne`: before `gh pr merge`, when `isDogfood(current(...))` and the PR base equals `defaultBranchCache(repo)`, refuse `DOGFOOD_DEFAULT_MERGE`, naming the release install command (`make install-shipyard-claude-hook` / `make install-shipyard-codex` from a released version). Merges into epic or parent branches stay allowed.
- Tests:
  - `tests/unit/dispatch-record.test.cjs`: the sidecar is written with the provenance fields and is not overwritten.
  - `tests/unit/claude-role-host.test.cjs`: a role launch records and clears in-flight, and writes a sidecar.
  - `tests/unit/sentinel.test.cjs`: a dogfood provenance plus a default-branch base refuses; a dogfood provenance plus an epic base proceeds; a release provenance plus a default base proceeds. Provenance is injected through the module's test seam or an env override, not by editing an installed cache.
- Comment policy on added lines.

## Acceptance criteria

- Every in-flight dispatch recorded through `dispatch-record.cjs` has a provenance sidecar keyed by its `dispatch_id`.
- A dogfood host cannot merge into the default branch.
- ADR-014 receipts are byte-identical to before (asserted by an existing receipt test staying green).

## Test strategy (TDD: failing test first)

1. RED: add the cases to the three test files. Run them; they fail because no sidecar is written, the role host records nothing, and the merge is not refused.
2. GREEN: implement the sidecar, then role-host recording, then the merge refusal.
3. Re-run the three files, plus `node tests/unit/stop-gate.test.cjs` as a read-only guard for the role-host in-flight rows.
4. **checkpoint:human-verify** (a merge-refusal change, so risk is high): with a dogfood install from T-40-21 on a scratch GitHub repository, the operator asks the sentinel to merge one epic PR into the default branch. They confirm the refusal and that `<graphDir>/provenance/` holds a sidecar for the round. They reply "approved" or describe the failure.
