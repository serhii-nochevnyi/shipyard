## Goal

REQ-148 part C5 (D-13). A Codex parent can no longer relay a shortened or rewritten task to its child without the host noticing:

- The host writes the full task to a host-owned file outside the model-writable tree.
- The parent receives only the path and the sha256.
- After the run, the host verifies from the child's native session evidence that the child received exactly that path and digest, and that the file is unchanged.
- Unverifiable evidence is a refusal (RISKS R12).

The Codex boundary fixtures are re-captured from the real CLI with the new launch shape (D-02), and every Codex consumer test replays them, so the registry's `migrating` list from T-40-07 ends empty (REQ-137).

## Scope

- `codex-runtime-host.cjs`:
  - Before launch, write the full task to `<run store>/tasks/<dispatch or run id>.md` with mode 0600 under the existing host state root (never inside the worktree), and compute sha256 with `node:crypto`. Refuse `INVALID_STATE_DIR` if the path resolves inside the worktree.
  - The parent prompt names only `TASK_FILE=<abs path>` and `TASK_SHA256=<hex>`, plus the existing spawn instructions: the child must read that file and follow it exactly.
