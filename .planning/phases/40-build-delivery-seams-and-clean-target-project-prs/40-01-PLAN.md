## Goal

Unit tests that create git repositories pass on a developer machine that has `commit.gpgsign=true` (or a signing key) in its global git config. No unit test creates its temp directory under a fixed `/tmp` path. This applies both through `tests/unit/run.sh` and when a test file is run directly with `node` (D-15, D-34).

## Context (Reads)

- `tests/unit/run.sh:22-26`: the loop that runs every `*.test.cjs` after the `node --check`/`bash -n` syntax pass. It exports no git environment today.
- `tests/unit/assert-harness.cjs`: the helper that 67 unit files `require`. It is the one module loaded by almost every test, so it is where a direct run can be made hermetic.
- `tests/unit/codex-delivery-host.test.cjs:30`: `fs.mkdtempSync('/tmp/scds-')` (40-RESEARCH anchor A27).
- `tests/unit/claude-delivery-host.test.cjs:464, 518, 864, 918`: `fs.mkdtempSync('/tmp/crh-*-gpg-')` GNUPGHOME directories used by the deliberately signing tests.
- Existing implementation: `tests/smoke/worktree-smoke.sh:21-26` and `tests/smoke/reachability-smoke.sh:9-14` already use the `GIT_CONFIG_GLOBAL` + `GIT_CONFIG_NOSYSTEM` pattern. Extend that pattern; do not invent a second one. I searched `tests/unit` for `GIT_CONFIG_GLOBAL`, `gpgsign` and `mkdtempSync('/tmp`. No shared unit-level hermetic helper exists.
- 40-RESEARCH Pitfall 11: gpg-agent sockets live in `GNUPGHOME`, and `os.tmpdir()` on macOS is a long `/var/folders/…/T/` path.

## Scope

- `tests/unit/run.sh` (per D-34): before the test loop, create a temp directory with `mktemp -d "${TMPDIR:-/tmp}/shipyard-unit.XXXXXX"` and remove it with an `EXIT` trap. Write a git config file there with `user.name`, `user.email`, `commit.gpgsign=false`, `tag.gpgsign=false`, `init.defaultBranch=main`. Export `GIT_CONFIG_GLOBAL` pointing at that file and `GIT_CONFIG_NOSYSTEM=1`. Keep `set -euo pipefail` and bash 3.2 compatibility.
- `tests/unit/assert-harness.cjs` (per D-34): when `process.env.GIT_CONFIG_GLOBAL` is unset at require time, create the same config under `fs.mkdtempSync(path.join(os.tmpdir(), 'shy-git-'))` and set `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM` on `process.env`, so child processes inherit them. When the variable is already set (run.sh), leave it alone. Remove the directory on process exit.
- `tests/unit/codex-delivery-host.test.cjs`: replace `fs.mkdtempSync('/tmp/scds-')` with `fs.mkdtempSync(path.join(os.tmpdir(), 'scds-'))`.
- `tests/unit/claude-delivery-host.test.cjs`: replace the four `/tmp/crh-*-gpg-` directories with `os.tmpdir()`-based ones, using a prefix of at most four characters (for example `g1-`) to keep the gpg-agent socket path short. If gpg-agent still refuses because the socket path is too long on the host, fall back to `fs.realpathSync(os.tmpdir())` and report the measured path length in the evidence. The signing tests keep their own `-c` config and `GNUPGHOME`.
- NEW `tests/unit/test-hermeticity.test.cjs`: a source scan with three rules. (1) No file under `tests/unit/` calls `mkdtempSync` with a literal `/tmp` argument (single or double quotes, or a template literal). (2) `tests/unit/run.sh` exports `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM` before the test loop, and the config it writes sets `commit.gpgsign` to false. (3) `assert-harness.cjs` sets both variables when they are absent. A fourth, behavioural case sets `GIT_CONFIG_GLOBAL` to a temp file containing `commit.gpgsign=true` plus a nonexistent `user.signingkey`, requires a fresh copy of the harness in a child `node` process with `GIT_CONFIG_GLOBAL` unset, and shows that `git commit` in an `os.tmpdir()` repository succeeds.
- Comment policy: new lines carry no explanatory or ticket comments.

- `grep -nE "mkdtempSync\\((['\"\`])/tmp" tests/unit/*.cjs` prints nothing.
- `node tests/unit/test-hermeticity.test.cjs` passes, and it fails when a `mkdtempSync('/tmp/x-')` line is added to any unit file (verified once by hand during RED).
- The signed-commit cases in `claude-delivery-host.test.cjs` still pass.
