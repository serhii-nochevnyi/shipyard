## Goal

Ticket ↔ PR matching no longer needs a ticket id in the PR title or branch (D-08). The first key is the PR number recorded at creation. The second is an exact head-branch match. The title / `ticket/<ID>-` marker fallback is used only for legacy PRs whose head starts with `ticket/`.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/ticket-pr-match.cjs:44-69` (anchor A14): `hasIdMarker` and `matchTicketPr(id, ticket, prs)`, which does an exact head match, then the marker plus title similarity. The existing comments in this file are grandfathered; new lines add none.
- `plugins/delivery-pipeline/scripts/state-sync.cjs:549, 552`: the `matchTicketPr` call sites. `delivery-state.json` is rebuilt from GitHub on every sync, so a number recorded only there would be lost. That is why the ledger is a separate durable input (D-31).
- `plugins/delivery-pipeline/scripts/pipeline-stats.cjs:167`: the second caller.
- `plugins/delivery-pipeline/scripts/lock.cjs` `withLock`, `writeAtomic`: the store primitives (Don't Hand-Roll).
- `plugins/delivery-pipeline/scripts/graph-dir.cjs` `resolveGraphDir`: where the ledger lives.
- Existing implementation: I searched for an existing record of "PR number at creation" (`pr_number`, `created`, `recordPr`, `delivery.pr`) in `dispatch-record.cjs`, `state-sync.cjs` and `gsd-sync.cjs`. `gsd-sync.cjs` only reads `plan.delivery.pr` after matching, and `dispatch-record.cjs` records dispatches, not PRs. Nothing records the number at creation, so this ticket adds `pr-ledger.cjs`.

## Scope

- NEW `plugins/delivery-pipeline/scripts/pr-ledger.cjs` (D-31): the store `<graphDir>/pr-ledger.json` is `{schema: 'shipyard.pr-ledger.v1', entries: {<ticket>: {number, head, repo, created_at}}}`, written under `withLock` + `writeAtomic`. Export `recordPr({graphDir, ticket, number, head, repo})` and `readLedger(graphDir)`. The CLI is `record --ticket <id> --number <n> --head <branch> [--repo owner/name] [--graph-dir <dir>]`. Validate the id with the canonical `T-NN-NN` grammar, require a positive integer number, and validate the branch with the existing safe-branch grammar. Refuse to overwrite an entry with a different number unless `--replace` is given. An unreadable or schema-mismatched ledger is a refusal, not an empty ledger.
- `ticket-pr-match.cjs` `matchTicketPr(id, ticket, prs, recorded)`: (1) when `recorded` is present, the PR with that number, provided its head equals `recorded.head` or `ticket.branch`; (2) otherwise, the PR whose `headRefName === ticket.branch`; (3) the marker fallback only for PRs whose `headRefName` starts with `ticket/`. Return `matched_by` values `recorded`, `head`, `legacy-marker`. A recorded number whose PR has a different head is a mismatch that does not fall through to the marker path.
- `state-sync.cjs`: read the ledger once per run, pass `recorded` to both call sites, and write `recorded_pr` into each ticket's delivery-state entry.
- `pipeline-stats.cjs`: pass the ledger entry to its call.
- NEW `tests/unit/pr-ledger.test.cjs` (`os.tmpdir()` graph directory): record/read round trip; a conflicting overwrite refuses; `--replace` works; a corrupt ledger refuses.
- `tests/unit/ticket-pr-match.test.cjs`: add cases for the recorded number winning over a same-branch PR from another workspace, a re-decompose rename (recorded number with the old head still matches), a neutral `feat/<slug>` PR with no id anywhere matching by head, a legacy `ticket/T-…` PR still matching by marker, and a neutral-branch PR whose title carries the id no longer matching by marker.
