## Goal

ADR-018 decision 2 (D-43, D-51). A conform verdict carries across a sibling merge only when two things hold, both proven on git tree objects:

- the ticket's own change is identical before and after the merge;
- the base move touched no path that the ticket declares or changes.

Otherwise arch-review is re-owed. The carry is built on T-40-19's `merge-gate` commit-status carrier, and the status description must hold a full 40-hex `base_tree` within 140 characters.

## Scope

1. NEW `plugins/delivery-pipeline/scripts/carry-proof.cjs`, exporting `proveCarry({git, from, to, judgedBaseTree, baseRef, declared})` → `{carried, reason, newBaseTree}`. It is pure over the injected git runner and makes no `gh` call. The notation: `F = from^{tree}`, `T = to^{tree}`, `J = judgedBaseTree`, `N = tree(merge-base(baseRef, to))`.
   1. `judgedBaseTree` must match `TREE_SHA`; an abbreviation refuses.
   2. `from` must be an ancestor of `to`.
   3. `ΔJF` and `ΔNT` are `git diff-tree -r --no-renames --raw -z --full-index` entry maps. They must be equal on path set, modes and oids.
   4. `B = paths(git diff-tree -r --no-renames --name-only -z J N)`. No `p ∈ B` may be in `paths(ΔJF)` or be owned by a declared glob (`owns(parse(decl), p)`).
   5. On success, `newBaseTree = N`. Every failure gives `carried: false` with a reason that names the violating paths.
2. `gate-trailer.cjs runCarry`:
   - read the gate on `from` through T-40-19's `readGate`;
   - load the ticket row's declared `files` via `resolveGraphDir` plus `loadTickets` (a missing row refuses);
   - keep the no-content carry first; otherwise call `proveCarry`;
   - on success, post the `merge-gate` status on `to` with `base_tree = N`, `carried_from = <first judged head, abbreviated to 7>`, and no `checks=`; on failure, refuse with "arch-review re-owed: <reason>".
3. Status description (D-51): the `merge-gate` description written by T-40-19's writer carries the full 40-hex `base_tree` in place of the short `tree=`. `head` is implicit, because the status is attached to that sha. `readGate` sets `head` to the full sha it queried, so `gateKind` and `gateConform` keep their exact head comparison, and a status read for another sha is never conform. A description in T-40-19's earlier grammar (short `tree=`, no `base_tree`) still parses as the same verdict for the merge gate, but it never carries (absent proof is not proof). The worst-case description with the longest vocabulary values is at most 140 characters, or the writer refuses. When a full `base_tree` cannot fit, the ticket stops and escalates (Open Question 2) rather than abbreviating.
4. NEW `tests/unit/carry-proof.test.cjs` (hermetic git fixture). Cases:
   - a disjoint sibling merge carries;
   - a sibling touching a ticket-changed path refuses;
   - a sibling touching a declared-only path refuses, including a glob declaration;
   - a conflict resolution on a ticket path refuses;
   - an unrelated rename carries, and a rename onto a ticket path refuses;
   - a no-content merge carries;
   - an abbreviated `judgedBaseTree` refuses.
5. `tests/unit/trailer.test.cjs`, with a stub `gh`:
   - the carried status on `to` records `base_tree = N` and `carried_from`;
   - a chained second carry from that status succeeds;
   - the worst-case description is at most 140 characters and holds a 40-hex `base_tree`;
   - a missing ticket row refuses;
   - a T-40-19-format description still reads conform on its own head and refuses to carry.
6. `tests/unit/files-contract.test.cjs`: switch the carry stub `gh` to the `merge-gate` statuses endpoint. Change "a merge that brought content refuses the carry" into two cases. First, a sibling squash on an undeclared path the ticket does not change now carries. Second, the same squash on a path the ticket declares refuses "arch-review re-owed" and posts no status. Keep "a merge that changed nothing carries" and "no board, no carry". Weaken no other assertion.

## Acceptance criteria

- A verdict carries only when `ΔJF ≡ ΔNT` on tree entries with rename detection off, and the base move is disjoint from changed and declared paths.
- Any doubt refuses, and the refusal names arch-review as re-owed.
- The `merge-gate` description holds a full 40-hex `base_tree` and is at most 140 characters in the worst case.
- A carried status chains: its `base_tree` is the new merge-base tree.
