## Goal

- REQ-139 (D-04, D-29): the launching host process writes an in-flight record `{ticket, role, dispatch_id, pid, host, started_at}` into `dispatch-record.cjs` at launch and clears it on exit. The deliver-armed stop gate does not interrupt while the record is live. A dead pid or an expired TTL makes the record not live (fail closed: the ticket is offered again and the gate enforces). The durable dispatch mark still follows the verified receipt.
- REQ-138 part (D-03): both delivery hosts export a pure request validator, so the entry point (T-40-15) validates each request through the host's own parse path before spawning.

## Scope

- `dispatch-record.cjs`:
  - Add an `inflight` section with `recordInflight({graphDir, ticket, role, dispatch_id, pid, host})` and `clearInflight({graphDir, dispatch_id, pid})` (clearing only its own pid).
  - `activeDispatches` projects an in-flight row while `now - started_at < DISPATCH_TTL_MS` and `process.kill(pid, 0)` succeeds. `EPERM` counts as not live. Invalid rows are dropped.
  - Refresh the front after writes, as `reserveRound` does.
- `claude-delivery-host.cjs`:
  - In `runClaudeDeliveryCli`, record in-flight after `controller.begin(scope)` and before `createClaudeDeliveryHost(...).run(...)`, with `pid: process.pid`, and clear it in `finally`.
  - Export `validateRequest(workflow, request)`, composed of the existing `readRequest` checks and `assertScopedWork`. It is pure: no fs writes, no spawn.
- `codex-delivery-host.cjs`: the same record/clear in `runCli`, and export `validateArgs(args)` built from `requestValue`.
- Tests:
  - `tests/unit/dispatch-record.test.cjs`: a live pid within TTL is active; a dead pid (spawn and reap a child, reuse its pid) is not; an expired `started_at` is not; `clearInflight` with a foreign pid does nothing; the durable `mark` path is unchanged.
  - `tests/unit/stop-gate.test.cjs`: with the gate armed, a live in-flight record gives no block, and a dead-pid or expired record gives a block.
  - `tests/unit/claude-delivery-host.test.cjs` and `tests/unit/codex-delivery-host.test.cjs`: the record exists during a stubbed run and is gone after success and after a thrown failure; `validateRequest` / `validateArgs` accept the canonical request and refuse unknown keys and a `signals.type: 'implementation'` (the boundary's `UNSUPPORTED_SIGNAL` surfaces unchanged).
- Stub the runtime launch at the host layer in both host tests; author no Codex exec-stream record (`codex-delivery-host.test.cjs` is in the boundary registry's `migrating` list until T-40-09).
- Comment policy on added lines.

## Acceptance criteria

- The armed stop gate stays silent for a live in-flight dispatch, and blocks for dead-pid and expired records.
- The host removes its record on every exit path the tests exercise.
- Both validators are exported and pure; the entry point can call them without side effects.
