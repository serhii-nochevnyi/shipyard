## Goal

ADR-018 decisions 3 and 5 on the Claude role host (arch-review, integrator, pr-sentinel) (D-44, D-46):

- Before launch, the host runs the `worktree-conditions.cjs` check for the role's profile, and it refuses with the module's remedy. Registry scratch and host-owned files no longer block a launch, so a second role in the same worktree works.
- After the run, any out-of-scope mutation is restored by the host, reported in `error.details`, and the verdict is discarded. That also holds on the failure path. The next launch always sees a clean tree.

## Scope

1. Launch preconditions: replace `:120-124` with `conditions.check(<role profile>, {worktree, graphDir, base, evidencePath, stateRoot, run})`. Surface the module error unchanged (code, message, remedy, details). Report `movedAside` entries in the host result.
2. Fill `hostOwnedFiles` for all three roles from `conditions.hostOwnedPaths(graphDir, worktree)`, and delete the local `['dispatches.json', 'delivery-front.json']` list.
3. Snapshot after `reserveRound` and after T-40-22's `recordInflight`, and before the agent launch: `snap = conditions.snapshot(...)`.
4. Post-run: replace `assertEvidenceOnlyChanges` with `diffSnapshot(snap, {allowed: [evidencePath]})`. When the diff is non-empty, call `conditions.restore(...)` and reject with `role changed paths outside its evidence file (restored: <paths>)`, code `WORKTREE_MUTATED`, and `error.details = {restored, removed, rewritten}`. The verdict is discarded.
5. Failure path: in the `catch`, when `getLaunchCount() === 1`, run the same diff and restore before rethrowing, and attach `details.restored`. A restore failure is added to the error rather than masking it.
6. `tests/unit/claude-role-host.test.cjs` new cases:
   - two arch-reviews in one worktree both succeed, with T-40-22's real in-flight rows and sidecars;
   - a stale untracked own evidence file is moved aside with its sha256 reported and is never sealed;
   - a fake agent that edits a tracked file, creates an untracked file and rewrites an `info/exclude`-listed scratch file gives `WORKTREE_MUTATED`, and afterwards `git status --porcelain --ignored` shows the pre-launch state, with `details.restored`, `removed` and `rewritten` listing all three;
   - a mutation followed by `badEvidence` or a missing receipt is also restored;
   - a symlink planted by the agent is removed without following it, and its target file outside the worktree is unchanged;
   - an agent that forges a provenance sidecar has it removed;
   - a launch in a worktree with a dirty tracked source file refuses `WORKTREE_DIRTY` before any agent launch, and the refusal text the host prints contains the module's remedy command verbatim, including the absolute worktree path;
   - with `.planning/` untracked at HEAD and a host-side graph, an arch-review launch passes the preconditions.
7. Comment policy on added lines.

## Acceptance criteria

- No role-host launch refuses because of registry scratch or host-owned files.
- After any role run, whether it succeeds or fails, the worktree equals its pre-launch snapshot except the role's own evidence file.
- Every restored, removed or rewritten path is reported in `error.details`.
- Every precondition refusal the operator sees carries the module's copyable remedy unchanged.
- Restore never deletes a path outside the worktree and never follows a symlink.
