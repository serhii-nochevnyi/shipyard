## Scope

1. `claude-delivery-host.cjs`:
   - before launch, `conditions.check('executor' | 'repair', …)`;
   - `planPath` passes through `conditions.resolvePlan` (the in-worktree plan is used, or `PLAN_OUTSIDE_WORKTREE` with the `ticket-worktree.sh create` remedy);
   - `signingFingerprint` delegates to `conditions.signerFingerprint`, and the local copy is deleted;
   - the post-run scratch filter at `:606-611` uses `conditions.scratchPaths()`.
2. `codex-delivery-host.cjs`:
   - the same executor and repair preconditions;
   - `SCRATCH_STATUS` and `signerFingerprint` are deleted in favour of the module;
   - existing codes `WORKTREE_NOT_READY` and `SIGNER_UNAVAILABLE` are kept where they match;
   - for judgment roles, `snapshot` before `launchAgent` and `diffSnapshot`/`restore` after, with `allowed` equal to the role's evidence from `JUDGMENT_EVIDENCE_NAMES` or `DRIFT_EVIDENCE_NAME`, plus host-owned graph files for pr-sentinel (its state-sync duty, Assumption A4). An unexpected change refuses `WORKTREE_MUTATED` with `details`. The same restore runs on the failure path. Executors and repairs keep the finalizer-based scope check.
3. `claude-decompose-host.cjs` and `codex-decompose-host.cjs`: before launch, `conditions.check('decompose', …)`. That covers the canonical toplevel, host state outside the worktree (`STATE_INSIDE_WORKTREE`) and graph and research refs inside the worktree. There is no clean-tree check, because decompose writes PLANs into a live checkout (CLAUDE.md "Preserve unrelated worktree changes").
4. NEW `tests/unit/worktree-conditions-hosts.test.cjs`, hermetic via `assert-harness.cjs`, gpg and agent runtimes injected. Cases:
   - the Claude executor refuses a plan outside the worktree with the remedy, and accepts a sha256-equal materialized copy;
   - the Codex executor tolerates every registry scratch file and refuses an unknown untracked file;
   - a Codex arch-review mutation is restored and reported;
   - a Codex pr-sentinel host-owned graph write is allowed;
   - both delivery hosts resolve the signer through one module function, called once per preflight;
   - both decompose hosts refuse host state inside the worktree via the module;
   - the decompose hosts do not refuse unrelated dirty files.
5. Comment policy on added lines.
