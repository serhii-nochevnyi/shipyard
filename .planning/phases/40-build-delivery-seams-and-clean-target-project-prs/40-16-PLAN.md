## Goal

The sentinel seam (D-01, D-05). Before a PR-sentinel round, the conveyor establishes the preconditions itself:

1. Fetch the base ref. Any fetch failure is a refusal.
2. Fast-forward the local base branch when that is possible.
3. Run state-sync.
4. Commit the synced graph when `.planning/graph` is tracked.

Otherwise it refuses with the exact command to run. `claude-role-host.cjs` no longer swallows a failed fetch.

A phase can span several repositories (D-44). Every base is fetched, fast-forwarded and compared in the checkout of the repository that owns the PR, not in the project worktree.

## Scope

- NEW `plugins/delivery-pipeline/scripts/sentinel-preflight.cjs`, exporting `preflight({worktree, base, graphDir, run})` and a CLI `--worktree <wt> --base <branch> [--json]`. All git calls use `execFileSync` argument arrays.
  1. Run `git -C <wt> fetch --no-tags origin +refs/heads/<base>:refs/remotes/origin/<base>`. On failure, refuse `BASE_FETCH_FAILED`, naming that exact command.
  2. When the local `<base>` exists and is an ancestor of `origin/<base>`, fast-forward it with `git -C <wt> update-ref refs/heads/<base> <oid> <old>` (compare-and-swap). When it has diverged, refuse `BASE_DIVERGED`, naming `git -C <wt> branch -f <base> origin/<base>` and the rebase alternative.
  3. Run `state-sync.cjs` for `graphDir`. On failure, refuse naming the command.
  4. When `.planning/graph/delivery-state.json` is tracked and changed, commit only `.planning/graph/` with a conventional subject `chore: sync delivery state`. When untracked, commit nothing.
  5. Refuse `WORKTREE_DIRTY`, naming `git -C <wt> status`, when tracked files outside `.planning/graph/` are dirty.
  It returns `{base_oid, synced, committed}`.
  6. Multi-repository (D-44): `preflightRound({projectWorktree, graphDir, prs: [{ticket, repo, base}], run})` groups the round's PRs by `repo`. The project repository (no `repo`, or the project's own slug) uses `projectWorktree`; every other repository uses `repo_resolution.repository_root` from `delivery-state.json`, which must be `executable: true` with a non-null `repository_root` (`state-sync.cjs:564` can write `null`). Otherwise it refuses `REPO_UNRESOLVED`, naming the ticket, the repository and the `pipeline.repos` key to set. In the project repository steps 1, 2 and 5 run as above. In a foreign repository's checkout (the operator's own clone) the preflight only fetches (step 1) and measures `refs/remotes/origin/<base>`: it never fast-forwards or moves a local branch there and never runs the dirty-worktree check, so unrelated edits in that clone neither block the round nor get touched. Steps 3 and 4 run once, in the project, after all fetches succeed. It returns `{repos: [{repo, root, base, base_oid}], synced, committed}`. The CLI gains `--round --graph-dir <dir>`.
- `claude-role-host.cjs`: in `branchOid`, any fetch failure rejects `BASE_REVISION_UNAVAILABLE` whether or not `expectedOid` is given. `prepareSentinel` calls `preflightRound(...)` first and surfaces its refusal unchanged. For each PR it passes the owning checkout from the preflight result (not `canonical.worktree`) to `branchOid` and to every git read of that PR's base. The identity and base checks are not relaxed, and a PR whose repository is unresolved is refused, never measured in the project worktree.
