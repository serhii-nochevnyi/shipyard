## Goal

Gate verdicts (arch-review, drift-check, tree binding) no longer live in the PR body as a `gate_status:` trailer. They are recorded as a GitHub commit status with context `merge-gate` on the PR head commit (D-20, D-32), so PR bodies stay free of conveyor text (D-07, Pitfall 9).

- The writer (`gate-trailer.cjs write` / `carry`) sets the status.
- The readers (`state-sync.cjs` and `sentinel.cjs` merge) read it.
- The merge gate stays fail-closed.
- A body trailer is honoured only as a legacy fallback for PRs that have no `merge-gate` status yet.

## Scope

- `gate-trailer.cjs`:
  - The writer posts `gh api repos/{owner}/{repo}/statuses/<head sha> -f state=<success|failure|pending> -f context=merge-gate -f description=<trailer grammar with short shas, ≤140 chars>`. It refuses when the description would exceed 140 characters.
  - The writer stops editing the body. When the body contains an old `gate_status:` line, it removes that line in the same edit (the existing filter), so a legacy PR is cleaned when it is re-verdicted.
  - `carry` posts the status on the new head.
  - Add `readGate({repo, sha, body})`: it reads `gh api repos/{owner}/{repo}/commits/<sha>/statuses` and takes the newest `merge-gate` status. Only when none exists does it fall back to `parseGate(body)`.
  - `parseGate`, `gateKind`, `gateConform` and `gateWhy` keep their semantics.
- `state-sync.cjs`: fill `gate` from `readGate` using the head sha it already fetched, so `s.gate` keeps its shape for `front.cjs`.
- `sentinel.cjs` merge (`:1003`): use `readGate` on `pr.headRefOid`. A status for another sha is not a verdict (fail closed).
- `tests/unit/trailer.test.cjs` (stub `gh` on `PATH` in `os.tmpdir()`, recording calls): the writer posts a status and does not add a body trailer; `carry` posts on the new sha; `readGate` prefers the status over a body trailer, falls back to the trailer only without a status, and a status on a stale sha is not conform.
- `tests/unit/files-contract.test.cjs` (base-merge carry suite only): the stub `gh` answers `gh api …/statuses/<sha>` and records the call. "A merge that changed nothing carries the verdict" asserts a conform `merge-gate` status posted on the new head and no body edit. "A merge that brought content refuses the carry" asserts that no status is posted. Leave the file's other suites unchanged.
- `tests/smoke/sentinel-smoke.sh`: the stub `gh` answers the statuses endpoint. State-sync reports the gate from the status, the guard merges only with a conform status on the head, and a PR with only a body trailer still merges (legacy).
- Comment policy on added lines. Existing comments in `gate-trailer.cjs` that describe the body trailer: replace or delete their text without adding new comment lines.

## Acceptance criteria

- New verdicts never add text to a PR body.
- Merge refuses without a conform `merge-gate` status on the exact head sha, unless the PR has no status and a legacy conform trailer bound to that head.
- The status description round-trips through `parseGate` grammar.
