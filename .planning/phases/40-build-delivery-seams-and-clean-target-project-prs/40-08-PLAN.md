## Goal

The Claude stream-json boundary (`claude --print --output-format stream-json --json-schema …` → `claude-runtime-host.cjs` → `claude-dispatch-adapter.cjs` → workflow) is tested against a stream captured from the real Claude CLI, scrubbed and version-stamped (D-02). The synthetic `tests/fixtures/claude-assistant-session.jsonl` and the inline `spawn:` stubs that fabricate stdout are gone from the registered consumer tests. This is the defect class that let three host ↔ workflow bugs pass `make test-fast` in phase 39.

## Scope

- `scripts/capture-boundary-fixtures.cjs`: pass `variant` into `runClaudeStream` and map it to a launch `schema`.
  - `executor`: an object schema requiring `id`, `status` (enum including `committed`) and `summary`.
  - `research`: an object schema requiring `summary` with `maxLength: 500`.
  - Refuse an unknown or missing Claude variant before launch, naming the two valid values.
  - Keep the Codex path unchanged. Add the variant → schema cases to `tests/unit/boundary-fixtures.test.cjs`'s capture-tool coverage only if that test already loads the tool; otherwise assert through the tool's exported helper without launching a CLI.
- Human-action checkpoint (see Test strategy): capture the `claude-stream` boundary for two variants and commit the scrubbed output. The `executor` variant (schema with `status: committed`) goes to `tests/fixtures/captured/claude-stream-executor.jsonl`. The `research` variant (`summary` bounded at 500 characters) goes to `tests/fixtures/captured/claude-stream-research.jsonl`. The CLI version is recorded in each file's provenance line and in the registry entry, not in the file name.
- NEW `tests/fixtures/captured/boundaries/claude-stream.json`: the boundary entry with the Claude CLI version from the provenance line, both fixture paths, consumers `claude-runtime-host.test.cjs` and `claude-workflow-host.test.cjs`, and `inline_shapes` patterns for the Claude stream-json records in both JSON-string and object-literal form. The patterns must be specific to stream-json stdout (for example a `result` record with `subtype` or `structured_output`, or a `system` record with `subtype: 'init'`), because check (3) scans every unit test and `tests/unit/session-observer.test.cjs` and `tests/unit/usage-attribution.test.cjs` legitimately build Claude session-transcript records (`type: 'assistant'`), a different producer. Show in RED that neither of those files matches.
- `tests/unit/claude-runtime-host.test.cjs`: replace `FIXTURE` and the `stream()` / `childFor()` fabrications with a replay helper that feeds the captured file through a fake child process's stdout, record by record. Tests may still vary process-level behaviour (exit codes, stderr, spawn errors) with stubs, but no test may author a stream record. Keep every existing assertion's intent. Where an assertion depended on a synthetic id, assert the scrub placeholder instead.
- `tests/unit/claude-workflow-host.test.cjs`: derive the host results it feeds the workflow by replaying the captured stream through `claude-runtime-host.cjs`'s result parsing, instead of hand-writing `output`. The structured case uses the executor capture's `structured_output`. The text case uses a replayed stream whose result record has no `structured_output`.
- Delete `tests/fixtures/claude-assistant-session.jsonl` once nothing references it (`grep -rn claude-assistant-session tests plugins scripts` prints nothing).
- Comment policy on added lines.
