## Goal

REQ-144, first half (D-09):

- Unreleased host code from a worktree can be run on purpose, through a separate install root, instead of by overwriting the installed release cache.
- Every install records its provenance: release or dogfood, source sha, dirty flag, version.
- `make doctor` reports an installed Claude plugin cache whose files match no release.

Stamping dispatches and refusing dogfood merges is T-40-22.

## Scope

- NEW `plugins/delivery-pipeline/scripts/host-provenance.cjs`:
  - `current({pluginRoot})` reads `<pluginRoot>/.shipyard-provenance.json` when present, else derives it: when `pluginRoot` is inside a git checkout, `source_sha` is `git rev-parse HEAD`, `dirty` comes from `git status --porcelain`, and `install_kind` is `dogfood`; otherwise it is `release` with the plugin.json version and `source_sha: null`. The result is frozen `{schema: 'shipyard.host-provenance.v1', install_kind, version, source_sha, dirty}`.
  - `writeInstallRecord(dir, record)` writes it with mode 0644.
  - `isDogfood(p)`.
- `install-shipyard-claude-hook.sh`: add `--dogfood-root <dir>` (or `SHIPYARD_DOGFOOD_ROOT`).
  - It copies the worktree's `plugins/delivery-pipeline/` payload into `<dir>` and writes `.shipyard-provenance.json` with `install_kind: dogfood`, source sha and dirty flag.
  - It prints the `claude --plugin-dir <dir>` launch line and wires hooks to that root only when asked.
  - It refuses when `<dir>` resolves inside `$CLAUDE_HOME/plugins/cache/`.
  - It validates the preconditions early and keeps `set -euo pipefail`.
  - A release install writes `install_kind: release`.
- `install-shipyard-codex.sh`: the same `--dogfood-root` / `SHIPYARD_DOGFOOD_ROOT`, generating into a separate `CODEX_HOME`-style root and refusing the default `CODEX_HOME`. It writes the provenance record next to the agents manifest.
- `shipyard-doctor.cjs` (read-only):
  - Report each installed root's provenance.
  - For the Claude cache `$CLAUDE_HOME/plugins/cache/shipyard/shipyard/<version>/`, when run from a checkout, compare file digests with `git show v<version>:plugins/delivery-pipeline/<path>`. Report `fail: cache matches no release (<n> files differ: …)` on mismatch, and `skip` when the tag is absent.
  - Report dogfood roots as `warn` with sha and dirty flag.
- NEW `tests/unit/host-provenance.test.cjs` (hermetic git fixture in `os.tmpdir()`): a clean checkout gives dogfood, sha and `dirty: false`; a modified file gives `dirty: true`; an install record wins over derivation; a non-git root gives release.
- `tests/smoke/claude-hook-smoke.sh`:
  - `--dogfood-root` into a temp dir writes the provenance, never touches the fake `CLAUDE_HOME` cache, and refuses a root inside the cache;
  - the doctor flags a fake cache whose file differs from a `v<version>` tag in a temp git repo, and passes when it matches.
- Comment policy on added lines.

## Acceptance criteria

- Neither installer can write dogfood code into the release cache path.
- Doctor output names every cache file that differs from its release tag, and doctor writes nothing.
- The provenance shape is frozen and identical for both runtimes.
