## Goal

Two REQ-149 point fixes on the push path (D-14):

- a. `delivery-state.yaml` written by `state-sync.cjs` has no comment header and is byte-identical for identical state. Two syncs of the same GitHub state produce the same file, and the comment-policy gate no longer blocks a push from the project.
- b. The Claude pre-push hook gates the repository that git resolves for the push target, not a directory guessed from command text (D-28).

## Scope

- `state-sync.cjs` (a): drop both comment lines from the YAML output. Sort keys deterministically wherever the YAML is built from object iteration, and emit no timestamp, generation or other run-varying value in the YAML body. Keep `delivery-state-meta.json` and the stdout generation line unchanged.
- NEW `tests/unit/state-sync-yaml.test.cjs`: drive the YAML writer through its exported function or the CLI against a fixture graph in `os.tmpdir()` with a stubbed `gh` on `PATH` (the pattern in `tests/smoke/sentinel-smoke.sh`). Assert: no line starts with `#`; two runs over the same stub data give byte-identical YAML; the generation still appears on stdout.
- Backlog entry: mark it resolved in the file's existing status convention, naming this ticket's requirement (REQ-149a).
- `scripts/shipyard-pre-push-gate.sh` (b, D-28): collect candidate directories from `git -C <path>` and `cd <path>` (resolved against `payload.cwd` when relative), then the payload `cwd`. Run `git -C <candidate> rev-parse --show-toplevel` on the first candidate the command names. If the command names a target (a `-C` or `cd` argument) and git cannot resolve it (contains `$`, does not exist, not a worktree), refuse with exit 2 and a message naming `git -C <absolute worktree> push`. Only when the command names no target is `payload.cwd` resolved through git. Invoke `publish-gate.cjs` with the git toplevel.
- NEW `tests/unit/pre-push-gate.test.cjs`: spawn the hook with JSON payloads against two hermetic repositories in `os.tmpdir()` (own `GIT_CONFIG_GLOBAL`, `commit.gpgsign=false`) and a stub `publish-gate.cjs` that records the worktree it was given. Cases: `cd "$W"; git push` with `$W` unexpanded refuses naming the remedy; `git -C <abs repo B> push` from a session in repo A gates repo B; `cd <subdir of B> && git push` gates B's toplevel; a plain `git push` gates the git toplevel of `cwd`; a nonexistent `-C` path refuses.
- Comment policy on added lines.
