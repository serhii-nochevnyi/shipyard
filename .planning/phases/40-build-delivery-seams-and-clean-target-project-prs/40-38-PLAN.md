## Scope

1. NEW `plugins/delivery-pipeline/scripts/seed-delivery-state.cjs`, exporting `seed({graphDir})`:
   - it reads `tickets.json` and `delivery-state.json`; a missing state file is treated as `{}`;
   - for each ticket id absent from the state it adds `{branch: row.branch, pr: null, status: 'pending'}`;
   - it never modifies an existing row;
   - it writes atomically with the state-sync formatting;
   - it returns `{added: [ids]}`;
   - it makes no network calls;
   - a missing or invalid `tickets.json` exits non-zero.
   CLI: `--graph <dir> [--json]`, via `resolveGraphDir`.
2. `gsd-sync.cjs`: append to both observation blockers the remedy `— run node <plugin>/scripts/seed-delivery-state.cjs --graph <graph dir>`. Acceptance stays unchanged: missing observations still block.
3. `decompose.md` Step 4, Gate 2: right after `validate-graph.cjs` exits 0, run the seeder, then the existing `gsd-sync.cjs` projection write, in the same planning commit. Add one sentence that the board reports `RESYNC_REQUIRED` until the next state-sync, which deliver runs first.
4. NEW `tests/unit/seed-delivery-state.test.cjs`, hermetic, with a fixture graph in `os.tmpdir()`. Cases:
   - only absent ids get the pending row;
   - existing rows are byte-preserved;
   - a second run is byte-identical;
   - it runs with `PATH` stripped of `gh`;
   - after seeding, `gsd-sync.cjs --check` on the fixture reports no "has no observation" blocker;
   - `wait-events` on the seeded fixture reports `RESYNC_REQUIRED`;
   - `decompose.md` names the seeder after `validate-graph.cjs`;
   - the gsd-sync blocker text contains the seeder remedy.
5. Comment policy on added lines.
