## Goal

The dispatch seam (D-01, D-03). One deterministic script, `deliver-dispatch.cjs`, serves both Claude and Codex:

- it reads the actionable front;
- it builds each host request from the graph: branch from the graph row, plan path from the ticket worktree's graph directory (D-30), and signals mapped from the row with the ticket `type` never copied;
- it validates the request through the host's exported validator;
- it launches the host detached;
- it offers `status` and `wait` through a new `dispatch` wait kind.

The model no longer assembles requests, launches, or polls in the foreground.

## Scope

- NEW `plugins/delivery-pipeline/scripts/deliver-dispatch.cjs` with three subcommands.
  - `launch --runtime claude|codex --ticket <id> --role <role> [--graph-dir <d>]`:
    - Refuse unless the ticket is actionable in `computeFront` for that role.
    - Resolve `graphDir` from the ticket worktree with `resolveGraphDir`.
    - Take `branch` from the row, never recomputed.
    - Set `planPath = path.resolve(graphDir, '..', '..', row.plan)`.
    - Build `signals` from the allow-list only: `risk`, `checkpoint` when `human_checkpoint === true`, `critical` when the row marks it. The row `type` never enters `signals` (Pitfall 1).
    - For executor requests in a target project (`prHygiene.applies({root: projectRoot, ref: base})` is true, T-40-17), set the existing executor argument `prBodyGuide` to `NEUTRAL_PR_BODY_GUIDE`. In the Shipyard repository, leave it unset so today's guide applies.
    - Claude: write a mode-0600 `{schema, scope, args}` request file outside the worktree and call `validateRequest`. Codex: write the args file and call `validateArgs`.
    - For `role: pr-sentinel`, run `sentinel-preflight.cjs` first and refuse with its message on failure.
    - Spawn `process.execPath` with the host script and file, with `detached: true`, `stdio: ['ignore', out, err]`, `env` including `SHIPYARD_GRAPH_DIR=graphDir`, and `unref()`. No intermediate shell (Pitfall 3).
    - Print one JSON line `{dispatch_id, ticket, role, runtime, log, result}`.
  - `status --dispatch <id>`: reads the in-flight record liveness (`activeDispatches`) and the result file, and prints `running | exited-ok | exited-failed | lost`.
  - `wait --dispatch <id> [--timeout-ms n]`: blocks in Node, checking status on an interval with no shell `sleep`. When the host is no longer live it records a `dispatch` wake event via `recordWakeEvent` and prints the final status. On timeout it prints `running` with exit 3.
- `run-waker.cjs`: add `'dispatch'` to `WAIT_KINDS`.
- NEW `tests/unit/deliver-dispatch.test.cjs`: fixture graph plus worktree in `os.tmpdir()`, with a stub host script path injected through an option, not by editing hosts. Cases:
  - Pitfall 1: a row with `type: implementation` yields a request whose `signals` has no `type`, and which the real `validateRequest` accepts.
  - Pitfall 2: `planPath` satisfies `canonicalPlan` when cwd is elsewhere.
  - Branch equals the row value.
  - A non-actionable ticket refuses.
  - A Codex request passes `validateArgs`.
  - The detached child's pid is the host process (the stub writes `process.pid`), and `status`/`wait` report exit and record a `dispatch` wake.
  - `pr-sentinel` runs the preflight first (stubbed preflight refusal propagates).
  - A target-project fixture gets `prBodyGuide === NEUTRAL_PR_BODY_GUIDE`, a fixture with a committed `shipyard` manifest gets no `prBodyGuide`, and both requests pass `validateRequest`.
- `tests/unit/run-waker.test.cjs`: `dispatch` events are accepted, and unknown kinds are still refused.
- Comment policy on added lines.

## Acceptance criteria

- `wait` never uses a shell `sleep`, and returns within one interval after the host exits.
- Ticket `type` never appears under `signals` in any built request.
