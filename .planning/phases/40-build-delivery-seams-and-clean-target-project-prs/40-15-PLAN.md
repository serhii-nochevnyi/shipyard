## Goal

The dispatch seam (D-01, D-03). One deterministic script, `deliver-dispatch.cjs`, serves both Claude and Codex:

- it reads the actionable front;
- it builds each host request from the graph: branch from the graph row, plan path from the canonical project graph (D-43, which supersedes D-30 for target projects), the plan digest, the executor context packet, and signals mapped from the row with the ticket `type` never copied;
- it validates the request through the host's exported validator;
- it launches the host detached;
- it offers `status` and `wait` through a new `dispatch` wait kind.

The model no longer assembles requests, launches, or polls in the foreground.

## Scope

- NEW `plugins/delivery-pipeline/scripts/deliver-dispatch.cjs` with three subcommands.
  - `launch --runtime claude|codex --ticket <id> --role <role> [--graph-dir <d>]`:
    - Refuse unless the ticket is actionable in `computeFront` for that role.
    - Resolve `graphDir` with one rule (D-43): when the ticket worktree has `.planning/graph/tickets.json` tracked at `HEAD` (the Shipyard repository, D-30 unchanged), use the worktree's graph as today; otherwise use the canonical project graph: `--graph-dir`, else `resolveGraphDir` run from the project checkout (the directory the orchestrator runs in), never an untracked copy inside a worktree. Then `assertCanonicalGraph` (T-40-28) against the ticket worktree. Refuse `GRAPH_UNRESOLVED`, naming `--graph-dir <project>/.planning/graph`, when none is found.
    - Take `branch` from the row, never recomputed.
    - Set `planPath = path.resolve(graphDir, '..', '..', row.plan)` (the canonical plan in the project, D-43) and its sha256 `planSha256`. Claude requests carry `planSha256` on the ticket entry; Codex requests carry `context.plan_sha256`.
    - Executor context packet: build it here with `context-packet.cjs` `buildContextPacket`, `root: worktreePath`. When the plan lies inside the worktree (Shipyard), keep today's `requiredRefs: [planPath, ...contextReads]`. Otherwise leave the plan and every `.planning/` context read out of `requiredRefs` and record `planSha256` in `roleContext`; the host-delivered content (T-40-28) is the single copy the agent sees.
    - Build `signals` from the allow-list only: `risk`, `checkpoint` when `human_checkpoint === true`, `critical` when the row marks it. The row `type` never enters `signals` (Pitfall 1).
    - For executor requests in a target project (`prHygiene.applies({root: projectRoot, ref: base})` is true, T-40-17), set the existing executor arguments `prBodyGuide` to `NEUTRAL_PR_BODY_GUIDE` and `deliveryRulesHint` to `NEUTRAL_DELIVERY_RULES_HINT`. The default hint at `workflows/executors.mjs:188` tells the agent to commit with a `(T-id):` prefix, which leaks the id into commit subjects (D-19) whenever the agent commits. In the Shipyard repository, leave both unset so today's guide and hint apply.
    - Claude: write a mode-0600 `{schema, scope, args}` request file outside the worktree and call `validateRequest`. Codex: write the args file and call `validateArgs`.
    - For `role: pr-sentinel`, run `sentinel-preflight.cjs` `preflightRound` first over every repository of the round's PRs (D-44) and refuse with its message on failure.
    - Spawn `process.execPath` with the host script and file, with `detached: true`, `stdio: ['ignore', out, err]`, `env` including `SHIPYARD_GRAPH_DIR=graphDir`, and `unref()`. No intermediate shell (Pitfall 3).
    - Print one JSON line `{dispatch_id, ticket, role, runtime, log, result}`.
  - `status --dispatch <id>`: reads the in-flight record liveness (`activeDispatches`) and the result file, and prints `running | exited-ok | exited-failed | lost`.
  - `wait --dispatch <id> [--timeout-ms n]`: blocks in Node, checking status on an interval with no shell `sleep`. When the host is no longer live it records a `dispatch` wake event via `recordWakeEvent` and prints the final status. On timeout it prints `running` with exit 3.
- `run-waker.cjs`: add `'dispatch'` to `WAIT_KINDS`.
- NEW `tests/unit/deliver-dispatch.test.cjs`: fixture graph plus worktree in `os.tmpdir()`, with a stub host script path injected through an option, not by editing hosts. Cases:

## Acceptance criteria

- Every request the script builds round-trips through the real host validator in the tests. No test hand-writes a request shape.
- `wait` never uses a shell `sleep`, and returns within one interval after the host exits.
- Ticket `type` never appears under `signals` in any built request.
- In a target project the entry point never resolves a graph from a ticket worktree and never builds a packet that requires a path outside the worktree.
