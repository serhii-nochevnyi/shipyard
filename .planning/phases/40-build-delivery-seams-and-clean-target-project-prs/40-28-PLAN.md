## Goal

D-43. In a target project whose `.planning/` is untracked (D-16), and for every cross-repo ticket, the ticket worktree holds neither the graph nor the plan, and the Claude agent runs `--restricted` with cwd = worktree. After this ticket:

- every agent role that works from the ticket contract (executor, drift-check, ci-fix, review-fix) receives the canonical plan, plus the planning files it names that can be delivered, inside its prompt, with digests, on both runtimes;
- neither delivery host accepts a graph directory that is an untracked copy inside a non-main worktree, whoever built the request;
- the agent's read scope is not widened, nothing is written into the worktree, and the Shipyard repository (plan inside the worktree) is unchanged.

## Scope

- NEW `plugins/delivery-pipeline/scripts/plan-delivery.cjs`:
  - `assertCanonicalGraph({graphDir, worktree})` (`worktree` optional): the graph directory is canonical when it lies in the main worktree of the project repository (the first entry of `git worktree list --porcelain` for the repository that contains the graph), when `tickets.json` is tracked at `HEAD` of the worktree that contains it (the Shipyard case; an index-only entry does not count), or when it lies outside every git worktree (test fixtures and plain directories). An untracked graph inside any other worktree of that repository, including the ticket worktree, refuses `GRAPH_NOT_CANONICAL`, naming the directory and whether it came from the flag, `SHIPYARD_GRAPH_DIR` or the default. Git calls use argument arrays.
  - `deliverPlan({graphDir, row, worktree, expectedSha256})`:
    - When the canonical plan's realpath lies inside `worktree` (Shipyard), return `{mode: 'in-worktree'}` and change nothing.
    - Otherwise read the plan (mandatory: missing, empty, non-UTF-8 or over `MAX_REFERENCE_BYTES` refuses `PLAN_UNDELIVERABLE`; a given `expectedSha256` that differs refuses `PLAN_DIGEST_MISMATCH`).
    - Collect optional planning files from the plan's Context (Reads): paths starting with `.planning/`, plus bare phase-file names (`NN-NAME`, with or without `.md`, and `CONTEXT`/`RESEARCH`) resolved against the plan's own phase directory. Strip any `:line` or `:a-b` suffix from every reference. Skip `.planning/graph/` (machine state), directories, and references containing `<`, `>`, `…` or `*`; each skipped reference goes to `not_delivered` with its reason (`machine-state`, `directory`, `placeholder`). Deliver only existing regular UTF-8 files, each at most `MAX_REFERENCE_BYTES`, at most 256 KiB in total, in order of first mention.
    - Return `{mode: 'delivered', plan: {path, sha256, content}, files: [{path, sha256, content}], not_delivered: [{path, reason}]}`. An optional file that is missing, too large or over the total budget goes to `not_delivered` with its reason; it never refuses the launch.
- `claude-delivery-host.cjs`:
  - `graphDirectory` calls `assertCanonicalGraph` (with the request's worktree where the call site has one; the calls at `:167` and `:344` pass none).
  - For each executor, drift-check and repair entry, after `canonicalPlan` accepts it, call `deliverPlan` with the entry's worktree and attach the result to that entry (`planDelivery`), so a multi-ticket drift call gets one delivery per ticket. Pass it through `prepareArgs`.
  - `prepareArgs` keeps a caller-supplied `deliveryRulesHint` and uses the host's own text only when none is given.
- `codex-delivery-host.cjs`:
  - `graphFile` calls `assertCanonicalGraph`. With no flag and no `SHIPYARD_GRAPH_DIR`, when `.planning/graph/tickets.json` is tracked at `HEAD` of the scope worktree (Shipyard), it resolves the worktree's graph instead of `repoRootOf(worktree)` (`codex-delivery-host.cjs:71-73`, `graph-dir.cjs:33-38`), so every Codex role in the Shipyard repository gets `in-worktree` and an unchanged prompt.
  - The request may carry `context.plan_sha256` (written by `deliver-dispatch`, T-40-15); any other `context` key starting with `plan` (for example `plan_path`, `plan`, `plan_content`) is rejected. `run()` passes `plan_sha256` explicitly to the preflight.
  - Executor: `executorPreflight` calls `deliverPlan` with the canonical graph row and returns the result; in `run()`, after the executor prompt is set (`:310-312`), append the delivered contract and files in the same delimited form as the Claude workflows.
  - Drift-check, ci-fix and review-fix (routed through this host, `deliver.md:1176`): `run()` resolves the ticket row through `graphFile` (which today has one caller, `:199`) and `deliverPlan`, and appends the delivered contract to `context.prompt` the same way. T-40-09's task-file relay then carries them for every role.
- `workflows/executors.mjs`, `workflows/drift-gate.mjs`, `workflows/fix-round.mjs`: when the entry's `planDelivery.mode` is `delivered`, the prompt embeds the plan as the ticket contract and each delivered file as a delimited block labelled with its path and sha256, lists `not_delivered` paths as unavailable (the agent must not try to read them), and the anti-injection line names the embedded contract. With `mode: 'in-worktree'` or no delivery, the prompt is byte-identical to today's. `no-contract` is returned only when the embedded contract is empty.
- The agent's permissions are not widened: no `--add-dir`, no read exception outside the worktree, nothing written into the worktree.
- Comment policy on added lines.

## Acceptance criteria

- In a target-project fixture with untracked `.planning/`, same-repo and cross-repo executor, drift-check and repair launches on both runtimes put the contract in the agent's prompt; no read outside the worktree is needed.
- A graph copy inside a non-main worktree is refused by both hosts, whether it arrives through `SHIPYARD_GRAPH_DIR`, a flag or the request.
- In the Shipyard repository the built prompts are byte-identical to today's.
- An optional planning reference never refuses a launch; only the plan itself is mandatory.
