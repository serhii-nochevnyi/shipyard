## Goal

This is the core of D-07 for target projects.

- A deterministic gate, `pr-hygiene.cjs`, rejects a PR before publication when its title, body, head branch, commit subjects (D-19) or diff paths carry conveyor or GSD internals.
- A single applicability predicate exempts the Shipyard repository (D-26).
- The title format is the target repository's own convention, read from project configuration, with Conventional Commits as the default (D-45). The gate forbids internals; it does not impose one format on every repository.
- `planning-untrack.cjs` is the explicit, confirmed, one-time migration that makes `.planning/` untracked in a target project (D-16). The conveyor never writes `.gitignore` on its own.

## Scope

- NEW `pr-hygiene.cjs`:
  - `applies({root, ref})` per D-26. When `ref` is given, read the manifest with `git -C <root> show <ref>:plugins/delivery-pipeline/.claude-plugin/plugin.json`, a committed base that an agent cannot edit from its worktree. Without `ref`, read the file from `root`, which is only for trusted checkouts. It is fail-closed: any read or parse error means hygiene applies. A target-project worktree that adds a `shipyard` manifest does not become exempt when `ref` is the base.
  - `conventionalType(ticketType)`: the D-27 map (GSD ticket `type` → conventional type). T-40-18 and T-40-20 import it, so there is one map.
  - `titleFormat({root, repo})` (D-45): reads `loadConfig(root).pr_title_format` from `pipeline-config.cjs` (the merged `pipeline.*` / `delivery_pipeline.*` view, `:924-926`), where `root` is the project root, never a ticket worktree. The value is either one pattern or a map `{<owner/repo>: <pattern>}`, with `default` for unlisted repositories. A pattern is a template over exactly `{type}`, `{scope}`, `{jira}` and `{subject}`, with optional segments written `{[`…`]}` (every other character, including `[`, `]`, `(` and `)`, is literal), for example `[{jira}] {type}: {subject}` or `{type}{[({scope})]}: {[[{jira}] ]}{subject}`. An optional segment with placeholders renders only when every placeholder inside it has a value; an optional segment without placeholders (for example `{[!]}`) is match-only: `check` accepts it, `formatTitle` never renders it. Nested optional segments and a literal `]}` are invalid. Without configuration the format is Conventional Commits `{type}{[({scope})]}{[!]}: {subject}`. An unknown placeholder or an unparseable template refuses `TITLE_FORMAT_INVALID`, naming the key. The template compiles to one anchored regular expression.
  - `formatTitle({type, scope, jira, subject}, format)`: renders a title in that format. A required placeholder with no value (for example `{jira}` for a ticket or epic without a Jira key) refuses `TITLE_FORMAT_UNRENDERABLE`, naming the field. The PR publication path (T-40-24) and the epic PR (T-40-20) build titles through it, so the generator and the gate share one definition.
  - Commit subjects are not held to the title format: ticket PRs squash into the epic under their PR title, so only the title carries the repository convention. `check` still applies the internals rules to every commit subject (D-45).
  - `NEUTRAL_PR_BODY_GUIDE`: the one-line body guide for target projects (summary, changes, tests; no ticket, phase, ADR, plan or tool names). T-40-15 passes it to executors through the existing `prBodyGuide` argument.
  - `NEUTRAL_DELIVERY_RULES_HINT`: the one-line rules hint for target projects (work only within files_modified; conventional-commit subjects with no ticket id). T-40-15 passes it through the existing `deliveryRulesHint` argument. Both strings pass `check` themselves.
  - `check({title, body, head, base, paths, commits, jiraKeys, titleFormat})` returns `{ok, violations: [{field, rule, excerpt}]}`:
    - title matches the compiled `titleFormat` for the PR's repository (D-45); `{type}` is one of `feat|fix|docs|refactor|test|perf|build|ci|chore|revert`, and neither the scope nor the subject is a ticket id;
    - head matches `<type>/<slug>` or `<type>/<JIRA-KEY>-<slug>` with the same type list (D-18 epic `feat/…` included);
    - title, body, head and every commit subject contain none of: `T-\d{2}-\d{2}`, `Ticket:`, `\bPhase \d+`, `ADR-\d+`, `PLAN.md`, `ticket/`, `epic/`, `.planning/`, `.shipyard/`, `gate_status:`, and the words `shipyard`, `gsd`, `conveyor` (case-insensitive, word-bounded);
    - no added, modified, copied or renamed path starts with `.planning/` or `.shipyard/`. Deleting such a path is allowed, because it removes internals: the one-time untrack migration below consists of those deletions and must pass this gate;
    - a Jira key is allowed in the title, head and body only when it is in `jiraKeys` from the graph; in the title it is allowed only where the format places `{jira}`.
  - CLI: `check --project-root <r> [--repo <owner/name>] --base <b> --head <h> --title <t> --body-file <f> [--json]`; `--repo` selects the title format; without it the repository is the project's own slug, parsed from `git -C <root> remote get-url origin`. When a map format is configured and no slug can be determined, it refuses `TITLE_FORMAT_INVALID`. It collects `paths` with their status from `git diff --name-status <b>...<h>` and `commits` from `git log --format=%s <b>..<h>` using argument arrays. It exits 0 when `applies` is false (printing `exempt`), and exits 2 with the violations otherwise.
  - CLI: `format --project-root <r> [--repo <owner/name>] --type <t> [--scope <s>] [--jira <KEY>] --subject <text>` prints the rendered title, or exits 2 with `TITLE_FORMAT_UNRENDERABLE` / `TITLE_FORMAT_INVALID`. `epic-branch.sh` (T-40-20) and the `deliver.md` publication steps (T-40-24) call it.
- `pipeline-config.cjs`: register `pr_title_format` (default `null`) so it is a known key, and validate its shape at load (a string, or an object of strings keyed by `owner/repo` or `default`); a bad shape is a warning that names the key and falls back to the default format. Template compilation stays in `pr-hygiene.cjs`.
- `tests/unit/pipeline-config.test.cjs`: `pr_title_format` produces no unknown-key warning; a non-string map value warns and is ignored.
- NEW `planning-untrack.cjs`:
  - CLI `--project-root <r>` is a dry run that prints the planned `.gitignore` line and `git rm -r --cached .planning`.
  - `--apply --confirm untrack-planning` refuses when `applies` is false (Shipyard), the tree is dirty, the current branch is the default branch, or `.planning/` is already untracked. Otherwise it appends `/.planning/` to `.gitignore` if absent, runs `git rm -r --cached --quiet .planning`, and commits with the subject `chore: stop tracking local planning files` on the current branch, for a normal PR.

- A repository with a configured title format accepts titles in that format only, and the conveyor's own rendered titles pass the gate in every configured format.
- The Shipyard repository is always `exempt`.
