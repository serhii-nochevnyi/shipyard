## Goal

The seam that stops consumer-authored fixtures (D-01, D-02). This ticket delivers three things:

- A capture tool that runs a real producer, scrubs private data, records the CLI version, and writes a provenance-stamped fixture.
- A registry of producer ↔ consumer boundaries, one JSON file per boundary under `tests/fixtures/captured/boundaries/`.
- A contract test that fails when a registered consumer test fabricates the producer's output inline instead of loading the registered fixture, or when a registered fixture is unscrubbed.

It registers the Codex agent stream boundary using the real Codex captures already in the repository. The Claude stream boundary is added by T-40-08, and the Codex re-capture for task-by-file by T-40-09. The `make capture-fixtures` target is added by T-40-26.

## Scope

- NEW `scripts/capture-boundary-fixtures.cjs`: CLI `--boundary <id> [--variant <name>] [--out-dir tests/fixtures/captured] [--dry-run --input <file>]`. For each boundary it knows (`claude-stream`: `claude --print --output-format stream-json --json-schema …` on the base-rung model through the host's argv builder; `codex-agent-stream`: the Codex parent/child `codex exec` pair through `codex-runtime-host.cjs`), it:
  - records `<cli> --version`;
  - runs the producer with a fixed tiny prompt in an `os.tmpdir()` scratch repo;
  - scrubs the output: home directory and `os.tmpdir()` prefixes become `<HOME>` and `<TMP>`, token-shaped strings (`sk-…`, bearer values, `ghp_…`) become `<TOKEN>`, UUID and session ids are consistently renamed `<SESSION-n>`, and absolute user paths become `<PATH-n>`;
  - writes `<out-dir>/<boundary>[-<variant>].jsonl` (a stable name, so plans can list it; the version lives in the provenance line and the registry entry) with a first provenance line `{"shipyard_fixture":{"boundary","cli","cli_version","captured_at","scrubbed":true}}`;
  - prints the registry entry to update.
  Export `scrub(text, context)` and `provenanceLine(meta)` for tests. `--dry-run` scrubs a given `--input <file>` without running any CLI.
- NEW `tests/fixtures/captured/boundaries/codex-agent-stream.json`: `{boundary, producer: 'codex exec (parent/child)', cli: 'codex', cli_version: '0.155.1', fixtures: [the two existing paths], consumers: ['tests/unit/codex-runtime-host.test.cjs', 'tests/unit/codex-decompose-host.test.cjs'], inline_shapes: [list of forbidden source patterns]}`.
- NEW `tests/unit/boundary-fixtures.test.cjs`:
  - (1) Every `boundaries/*.json` parses and its fixtures exist.
  - (2) Scrub check: no fixture contains `/Users/`, `/home/`, `/var/folders/`, token shapes, or an unplaceholdered UUID, except the pre-provenance Codex 0.155.1 files. Those carry no provenance line and must pass the path and token rules. If they fail, stop and escalate: they are outside this ticket's `files_modified`, and T-40-09 re-captures them.
  - (3) Inline-shape check: every consumer test file reads at least one registered fixture path, and contains none of the boundary's `inline_shapes` patterns (for Codex: a literal `"type":"thread.started"` / `turn.completed` JSON line built in source).
  - (4) When the CLI is on `PATH`, a version differing from `cli_version` prints a warning line. It is not a failure, because CI has no CLI.
  - (5) `scrub()` unit cases over a synthetic input: home path, token, repeated session id mapped to the same placeholder.
- Comment policy on added lines.
