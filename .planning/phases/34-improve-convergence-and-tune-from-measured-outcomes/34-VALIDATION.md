# Phase 34 validation contract

## Required evidence

1. Review signatures distinguish reposted, new, oscillating, unidentified, and infrastructure findings. A resource limit returns a checkpoint or inconclusive state and leaves the retry verdict unchanged.
2. Adaptive model changes require a runtime capability snapshot; repair model changes additionally require an authenticated completed predecessor. Unknown capability falls back to the preceding rung; omitted effort does not promote a route.
3. Carry accepts only a real same-tree descendant merge with matching live PR identity and base tree. Changed trees, rewritten ancestry, missing refs, or a race refuse without editing the trailer.
4. Concurrent projects share leases only inside the same declared provider/account scope. Store failures, unknown scope, expiry, release, and nested launches are observable.
5. Reports are idempotent, preserve failed/parked/interrupted samples, mark partial coverage inconclusive, append rollback history, and create a linked candidate without auto-launch.
