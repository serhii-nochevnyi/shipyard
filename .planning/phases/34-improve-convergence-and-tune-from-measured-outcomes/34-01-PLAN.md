## Objective

Give review findings stable identities and expose resource exhaustion as accounting evidence without changing the retry backstop or inventing a plan defect.

## Interfaces

- `review-signature.cjs` provides normalization, stable finding signatures, snapshot comparison, and explicit unknown coverage.
- `reviewers.cjs` decorates live findings with signatures and provenance.
- `sentinel.cjs` carries review progress into the actionable duty item.
- `failure-signature.cjs` and `attempt-history.cjs` report resource state independently of verdict classification.

## Tasks

1. Add pure signature and snapshot functions, preserving thread IDs as provenance and treating missing rule/path/location as unknown.
2. Connect live reviewer and sentinel output; distinguish unchanged, resolved, new, oscillating, infrastructure, and unknown findings.
3. Add budget/checkpoint accounting and tests proving missing or exhausted resources never become `plan_defect` or bypass a retry.

## Verification

`node tests/unit/review-signature.test.cjs && node tests/unit/failure-signature.test.cjs && node tests/unit/attempt-history.test.cjs`

## Done when

Every review retry has inspectable evidence, and a budget signal can only checkpoint or remain inconclusive.
