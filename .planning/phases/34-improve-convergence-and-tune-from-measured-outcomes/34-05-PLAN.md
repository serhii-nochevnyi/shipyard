## Objective

Turn measured treatment runs into an idempotent report with explicit quality and rollback decisions and a linked backlog candidate.

## Interfaces

`optimization-report.cjs` defines the versioned baseline/treatment schema, coverage, metrics, verdict, rollback history, and candidate input. Stats supplies usage/outcome facts; backlog-index persists only a triage candidate and never launches it.

## Tasks

1. Add report creation, validation, idempotent persistence, sample/coverage evaluation, and rollback history for completed, failed, parked, and interrupted runs.
2. Extend stats output with the fields required to attribute provider/account/treatment usage and quality outcomes.
3. Add candidate persistence and delivery/decompose instructions, with tests proving partial data is inconclusive and no policy rewrite occurs.

## Verification

`node tests/unit/optimization-report.test.cjs && node tests/unit/pipeline-stats.test.cjs && node tests/unit/backlog-index.test.cjs`

## Done when

One treatment can be promoted, continued, or rolled back from a reproducible report, and every unproven result remains visible as a linked candidate.
