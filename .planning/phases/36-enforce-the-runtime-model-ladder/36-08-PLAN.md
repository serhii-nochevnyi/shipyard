## Goal

Make dispatch telemetry prove what was resolved, applied, and observed, rather
than treating an intended model as evidence of execution.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-record.cjs`
- `.planning/architecture/ADR-014-DATA-MODEL.md`
- `plugins/delivery-pipeline/scripts/pipeline-stats.cjs`

## Scope

Persist policy fingerprint, role, logical rung, signals, requested/applied/
observed model and effort, runtime, backend, launch identity, agent file or
arguments, and application receipt. Validate contradictions and missing fields.
Require compliant prior receipts for repair escalation, while retaining
historical rows as legacy/unverifiable.

## Acceptance criteria

- `applied_*` values come only from the adapter receipt.
- Missing, contradictory, stale-policy, or absent receipt fields fail closed.
- Repeated repairs cannot escalate from a decision without evidence that the
  previous rung was actually applied.
- Existing historical records are not rewritten as compliant.
