## Goal

Consume the canonical decision in Claude Code while keeping the existing
Claude model palette and provider configuration byte-for-byte unchanged.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/model-policy.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/workflows/executors.mjs`
- `plugins/delivery-pipeline/workflows/fix-round.mjs`
- `plugins/delivery-pipeline/workflows/drift-gate.mjs`
- Existing Claude palette/provider files (read-only compatibility surface)

## Scope

Map logical rungs through the current Claude aliases in a dedicated adapter.
Require resolved launch input in workflow arguments, remove literal fallback
model/effort defaults, return adapter-originated application evidence, and
refuse unsupported application. Do not edit Claude palette/provider files.

## Acceptance criteria

- Claude receives the same role/signal decision as Codex through its existing
  palette, without changing palette IDs, aliases, or provider configuration.
- Workflow paths cannot silently use a literal default, inline backend, or
  inherited session selection.
- Successful launches expose an application receipt and unsupported selections
  block before dispatch recording.

- `node tests/unit/workflows-args.test.cjs`
- Palette/provider hashes before and after are identical.
