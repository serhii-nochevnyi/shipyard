## Goal

Make research, planning, and checking launches in GSD decomposition use the
mandatory runtime/model boundary.

## Context (Reads)

- `plugins/delivery-pipeline/commands/decompose.md`
- `plugins/delivery-pipeline/scripts/pipeline-config.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/scripts/codex-dispatch-adapter.cjs`
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs`
- `tests/unit/pipeline-config.test.cjs`
- `tests/unit/source-contract.test.cjs`

## Scope

Route planner, researcher, and checker launches through `decomposition` or
`research`, pass explicit Codex model/effort or the existing Claude alias and
supported effort, and record receipts. Refuse generic-agent, inline, or
inherited-session paths that cannot apply the resolution. Ensure the canonical
decomposition role vocabulary validates both planner and checker override
keys, so no checker-specific conflict can bypass the routed resolver.

## Acceptance criteria

- Research starts at Astra/low and escalates to Astra/medium only for its
  declared `very-complex` signal; decomposition starts at Astra/low and can
  escalate to Astra/medium.
- No decomposition launch occurs without an explicit runtime selection and
  successful application receipt.
- `gsd-planner` and `gsd-plan-checker` model and effort overrides are both
  validated as decomposition conflicts for Codex and Claude.
- Source-contract tests cover both runtime paths and all refusal cases.
