## Goal

Create the single versioned dispatch contract and the immutable
resolve/validate/launch/receipt tracer that every later adapter will consume.
Keep the Codex and Claude role/rung grids independent: Codex uses its own
logical model vocabulary, while Claude names its existing native aliases
directly. The Claude palette itself remains runtime-adapter-owned and unchanged.

## Scope

Implement all nine roles and both runtime-specific rung grids, signal
evaluation, policy fingerprinting, and a boundary with injected adapters for
tests. Resolution must retain every fired signal, distinguish requested from
applied values, and require the immediately preceding boundary-verified receipt
from the same runtime before repair escalation; a committed successor must make
its predecessor non-replayable across restart recovery. Static Codex dispatch
must validate generated agent existence, content, policy binding, and digest
before launch.

## Acceptance criteria

- `research`, `decomposition`, `executor`, `pr-sentinel`, `integrator`,
  `drift-check`, `arch-review`, `ci-fix`, and `review-fix` resolve exactly as
  their runtime-specific ADR-014 grid specifies.
- Codex executor resolves Luna/max by default and escalates to Astra/medium
  only on explicit critical or checkpoint evidence.
- Claude executor resolves Sonnet/max by default and escalates to Opus/high
  only on explicit critical or checkpoint evidence; Claude's PR sentinel is
  Sonnet/high, integrator is Opus/medium → Opus/high, architecture review is
  Opus/medium → Opus/max → Fable/medium, and CI/review fixes are Opus/medium
  → Opus/max.
- Fixed mechanical roles (PR sentinel and drift-check) do not promote from
  global risk, checkpoint, or window signals; judgement and repair roles do.
- Claude role selection names `sonnet`, `opus`, and `fable` directly and never
  aliases Codex's Terra/Sol/Luna/Astra grid.
- Unknown runtime, conflicting override, unsupported selection, or missing
  receipt fails closed.
- Resolution contains policy version/hash, runtime, role, logical rung,
  concrete model/effort, route, backend, mechanism, and signal reasons.
