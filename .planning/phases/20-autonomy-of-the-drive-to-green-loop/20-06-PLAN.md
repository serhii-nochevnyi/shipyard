## Goal

The babysit loop (deliver.md Step 4 and its mirror in pr-sentinel.md) stops
reasoning about attempts and starts consuming the phase's verdicts: every
failure is signed (`failure-signature.cjs compute`), every dispatch is gated by
the signature-history verdict, a flake is re-run and never charged, a
plan_defect parks with its evidence while the cascade continues, and every
fixer receives the prior-attempt record as input. Every new decision is written
by a script and read back from a file; the loop text only sequences the calls
(the standing rule: prose rules get skipped, mechanical gates hold).

## Scope

**`commands/deliver.md`:**
- Babysit step a (failing checks), rewritten around the verdict:
  1. `gh run view --log-failed` → pipe to
     `failure-signature.cjs compute --job <check> --json` → the signature.
  2. `failure-signature.cjs verdict <T> --signature <sig> --head <head sha>
     --k <pipeline.plan_defect_signatures> --json` → branch on the verdict:
     - `flake` — quarantined: do NOT dispatch a fixer, do NOT charge the
       attempt; log the attempt event with `outcome=flake` (n unchanged);
       re-run the job (`gh run rerun <id> --failed`) or leave it to the next
       round; continue the front.
     - `flake_candidate` — re-run the failed job ONCE before any dispatch,
       then record it: `failure-signature.cjs rerun <T> --signature <sig>
       --head <sha> --outcome green|red`. Green → quarantined, nothing
       charged; red → deterministic, proceed as `repeat`.
     - `plan_defect` — `escalation-record.cjs mark-plan-defect <T> <plan-path>
       "<what the plan got wrong>" --signature <s1> --signature <s2> ...`
       (the distinct signatures from the verdict), then CONTINUE the front:
       the ticket needs a person in the morning, not now; the cascade goes on.
     - `first | progress | repeat` — dispatch ci-fix with model+effort from
       `pipeline-config.cjs model ci-fix --json --risk <r>
       --signature-state <verdict>`; include the returned `strategy` and the
       output of `attempt-history.cjs <T>` in the fixer's input. On `repeat`
       the strategy is `rethink` — same tier, changed approach.
- Step d (after each push): the attempt event gains the new keys —
  `log-event.cjs attempt ticket=<T> pr=<N> n=<n> role=<role> model=<tier>
  outcome=<...> signature=<sig> head=<sha> hypothesis="<from the fixer's
  report>"`. The attempt counter STAYS, as telemetry AND as the backstop:
  `attempts > MAX → escalation-record.cjs mark` remains, because a signature
  oscillating between two values dodges both the repeat rule and the
  K-distinct rule — state this in the text so a future edit does not remove
  it as dead code.
- Workflow round (fix-round): each `prs[]` entry gains
  `attemptHistory: <output of attempt-history.cjs <T>>` and model/effort from
  `--signature-state`; after the round, log each result's `hypothesis` on its
  attempt event. The FALLBACK path (no Workflow tool) gets the same inputs
  inline — the references are the shared channel, the args are this file's.
- Model policy section: repair-role rows (`ci-fix`, `pr-sentinel`) lose the
  attempt-based escalation lines and gain the signature-state column
  (`repeat → same tier, strategy rethink, effort xhigh`); note that
  `--attempt` is still accepted for compatibility but no longer routes repair
  tiers, and that `plan_defect_signatures` (default 3) is the K.
- Telemetry section: document the new attempt-event keys and the four
  script-owned events (`plan_defect`, `flake`, `flake_rerun`, `flake_lift` —
  never logged by hand; log-event refuses them).

**`references/pr-sentinel.md`:** mirror the same contract for the guard: sign
the failure, gate the dispatch on the verdict, never charge a flake, park a
plan_defect via `mark-plan-defect` (the guard's parked set already inherits it
through `activeEscalations`), keep `attempts > maxAttempts` as the backstop
park, log the new attempt-event keys.
