## Goal

`plan_defect` becomes a durable verdict kind in the EXISTING escalation store —
no third store (D2). It is not `failed`: the ticket parks with its reason and
the observed signatures, is flagged for re-decomposition, and the cascade
continues. Park and journal stay ONE act (escalation-record's founding rule);
the verdict expires when the PLAN changes (drift-record's `plan_hash` rule,
reused — a human answering the PR does NOT lift a plan defect; only re-planning
does).

## Scope

**`escalation-record.cjs`:**
- New subcommand
  `mark-plan-defect <ticket> <plan-path> <reason...> [--signature <sig>]... [--graph <dir>]`:
  - Reason mandatory, same guard as `mark` but with a tailored message: the
    morning human inherits ONLY this string plus the signatures — say what the
    plan got wrong, not "plan defect".
  - Repeatable `--signature <sig>` flags collect the distinct signatures that
    triggered the verdict (evidence from `failure-signature.cjs verdict`,
    T-20-01); stored as `signatures: []`.
  - Refuse when the plan file is unreadable (`planHash` null) — a verdict with
    no plan to bind to would never expire (drift-record's exact rule and a
    matching message).
  - Record shape: `{kind:'plan_defect', reason, plan:<abs>, plan_hash,
    signatures, pr, at}`. Store the plan path absolute (drift-record's
    reasoning: mark runs anywhere, reads happen at the project root).
  - Journal event in the SAME locked `mutate`: `{ts, event:'plan_defect',
    ticket, pr, reason, signatures, plan_hash, by:'escalation-record'}`.
- `activeEscalations()` branches by kind:
  - `kind === 'plan_defect'` → in force while `planHash(rec.plan) ===
    rec.plan_hash`; a changed or missing plan means it was re-decomposed — the
    park lifts by itself. The PR fingerprint is IGNORED for this kind: a push
    or review answer must NOT lift it.
  - Missing `kind` or `kind === 'escalation'` → today's fingerprint rule,
    byte-for-byte (back-compat: every pre-phase record is kind-less and must
    keep its exact expiry behavior).
  - Merged tickets stay excluded for both kinds.
  - A plan_defect reason is returned prefixed
    `plan_defect — re-decompose: <reason>` so the front's why-message and the
    sentinel's PARKED_WHY tell the morning human what to do, for free.
- `list` shows the kind; `clear <ticket>` works for both kinds unchanged.

**`log-event.cjs`:** `OWNED_BY_SCRIPTS` gains four entries with messages in the
existing style (name the owning command and the half-act harm):
- `plan_defect` → `escalation-record.cjs mark-plan-defect` (journalling by hand
  records the conclusion without PARKING the ticket — same defect as
  `escalation`).
- `flake`, `flake_rerun`, `flake_lift` → `failure-signature.cjs rerun` / `lift`
  (a hand-written quarantine event skips the lock and the (ticket, signature)
  bookkeeping the verdict reads back).

## Out of scope

- `front.cjs` and `sentinel.cjs` — propagation is free via `activeEscalations`
  (cited above); T-20-04 owns front.cjs in this phase.
- Deciding WHEN plan_defect is reached — that is `failure-signature.cjs
  verdict` (T-20-01); this ticket records what it is told.
- Calling `mark-plan-defect` from the loop — T-20-06.
- Re-decomposition itself (`/shipyard:decompose`) — the park message points at
  it; nothing here invokes it.

## Acceptance criteria

- `mark-plan-defect` in one invocation: escalations.json gains the
  kind-tagged record AND delivery-log.jsonl gains the `plan_defect` event —
  never one without the other, including under concurrent marks.
- With the plan file byte-identical, the park holds even when the PR moves
  (push, review answered, undraft — fingerprint change does NOT lift it).
- Editing the plan file lifts the park on the next `activeEscalations()` read;
  so does deleting it.
- A kind-less legacy record still expires by PR fingerprint exactly as today.
- Reason-less `mark-plan-defect` refuses with a message telling the caller what
  the morning human needs; unreadable plan path refuses.
- `log-event.cjs plan_defect ...` (and `flake`, `flake_rerun`, `flake_lift`)
  exit 1 with a message naming the owning script.
- `--graph` accepted in any position; the sentinel's parked set contains a
  plan_defect ticket without any sentinel.cjs change (assert via
  `activeEscalations` output shape — `{ticket: reason}` — unchanged).
