## Goal

The model ladder loses `attempt` (and `previousFailed`) as tier inputs for the
repair roles and gains a signature-history input; `role x risk` remains (D1,
ADR Consequences). Escalating tier on repeat failure is the rejected "try
harder"; the ladder's new job on a repeat is to change STRATEGY at the held
tier, and to say so mechanically in its `--json` output.

## Scope

All in `plugins/delivery-pipeline/scripts/pipeline-config.cjs`:

- **Tier inputs.** Repair roles are `ci-fix`, `review-fix`, `pr-sentinel`.
  Remove `attempt`/`previousFailed` from their tier decisions:
  - `ci-fix`: `risk === 'high'` → `opus`, else `sonnet`.
  - `pr-sentinel`: `risk === 'high' || signals.checkpoint` → `opus`, else `sonnet`.
  - `review-fix`: unchanged (`codeChange === false` → `sonnet`, else `opus` —
    that signal is about the work's nature, not about attempts).
  - `executor`, `research`, `drift-check`, judgment roles: untouched.
  - The `premium` profile short-circuit stays as is.
- **New signal.** `signals.signatureState`, CLI flag
  `--signature-state <first|progress|repeat|flake_candidate|flake|plan_defect>`
  (exact enum from T-20-01). An unknown value produces a warning on stderr and
  is ignored — same posture as every other invalid config value in this file.
- **Strategy output.** `model <role> --json` gains a `strategy` field when
  `--signature-state` was passed (omitted otherwise, so existing consumers see
  no shape change): `first` → `fix`, `progress` → `continue`, `repeat` →
  `rethink` (re-read the plan, widen the context, raise the hypothesis above
  the symptom), `flake_candidate` → `rerun`, `flake` → `quarantine`,
  `plan_defect` → `park`. The last three mean "do not dispatch a fixer";
  the loop (T-20-06) acts on the string, so pin these six values exactly.
- **Effort.** In `resolveEffort`, a repair role with `signatureState ===
  'repeat'` gets `xhigh` (tier holds, effort deepens — the same
  effort-expresses-depth pattern the capped-runtime rule already uses).
  Mechanical roles and overrides keep their precedence. Simplify or remove the
  now-unreachable `escalated` branch for repair roles as appropriate — but do
  not disturb its behavior for non-repair roles.
- **Config key.** `DEFAULTS` gains `plan_defect_signatures: 3` (the K of the
  k-distinct rule; the same default as `failure-signature.cjs verdict --k`).
  Validate it in the existing positive-number loop. It becomes GSD-visible
  later via the capability if desired — out of scope here.
- **Back-compat.** `--attempt <n>` and `--previous-failed` remain ACCEPTED
  (deliver.md still documents them until T-20-06 lands, and telemetry callers
  pass `--attempt`) but no longer affect repair-role tiers. State this in the
  file's header comment and the usage line; no warning when passed.

Update `tests/unit/pipeline-config.test.cjs` (TDD: adjust/add expectations
first, watch them fail, then change the ladder).

## Acceptance criteria

- `model ci-fix --json --attempt 3 --previous-failed` resolves the SAME tier as
  with no flags (attempt is inert for repair roles); risk high still raises it.
- `model ci-fix --json --signature-state repeat` → `{model:'sonnet',
  effort:'xhigh', strategy:'rethink'}` on default config (claude runtime
  unset); `--signature-state first` → `strategy:'fix'`, effort `high`.
- `model pr-sentinel --json --signature-state plan_defect` → `strategy:'park'`.
- `--signature-state bogus` warns on stderr and omits `strategy`; exit 0.
- Without `--signature-state`, the `--json` shape is unchanged from today
  (`{model, effort}` only).
- `resolve` reports `plan_defect_signatures: 3` by default; a non-positive
  configured value warns and falls back to 3.
- Judgment roles (`arch-review`, `integrator`) still resolve the top tier under
  every profile; `drift-check` stays `sonnet`/light; the Codex runtime cap
  behavior is unchanged.
- No output anywhere is a full model ID or suffixed alias — tier aliases only.
