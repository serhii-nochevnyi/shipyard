## Goal

Prior attempts become an INPUT, not a memory (D5): a deterministic per-ticket
record — signature, hypothesis, diff summary, outcome — rendered from the
journal and handed to the next fixer as data, so a fresh subagent (correct for
context hygiene) can no longer re-propose attempt 1's failed fix on attempt 3.
The fixer, in turn, must REPORT its hypothesis, or the record has nothing to
carry forward.

## Scope

**New `plugins/delivery-pipeline/scripts/attempt-history.cjs`:**
- `attempt-history.cjs <ticket> [--json] [--limit <n>] [--graph <dir>]`.
- Reads `delivery-log.jsonl`, filters events for the ticket among: `attempt`,
  `fix_round`, `escalation`, `plan_defect`, `flake`, `flake_rerun`,
  `flake_lift`. Renders a compact chronological digest, one line per event,
  e.g. `attempt n=2 role=ci-fix model=sonnet signature=ab12cd34
  outcome=pushed hypothesis="off-by-one in the pagination cursor"` — fields
  rendered only when present. `--limit` keeps the most recent n events
  (default: all). `--json` prints the raw filtered events.
- No events / no journal → prints `no prior attempts recorded for <ticket>`
  and exits 0 (a fresh ticket is the normal case, not a failure).
- Graph resolution: log-event's convention verbatim, including the refusal
  when `tickets.json` is absent and `--graph` was not given.

**`workflows/fix-round.mjs`:**
- args contract: each `prs[]` entry gains optional **`attemptHistory`** (exact
  name — T-20-06 writes the matching side in deliver.md) — a pre-rendered
  string from `attempt-history.cjs`, produced by the ORCHESTRATOR (the Workflow
  script builds prompts deterministically and must not shell out).
- When present, the prompt gains a section: prior attempts on this PR are a
  deterministic record of what already failed; the fixer MUST NOT re-propose a
  fix a prior attempt already tried — if its best hypothesis matches a failed
  one, it forms a different hypothesis (re-read the plan, widen the context)
  or returns status `escalate`.
- OUT schema: new required field **`hypothesis`** (string; one sentence — what
  you believed was wrong and what the fix targets; for `no-op`/`escalate`, why).
  Both `fixFallback` constructions include a `hypothesis` value.
- Update the args-contract comment block at the top of the file to match.

**`references/ci-fix.md` and `references/review-fix.md`:**
- Input section: add the prior-attempt record (when any exists): per attempt —
  signature, hypothesis, outcome.
- Procedure: before proposing a fix, check the record; a hypothesis that
  already failed is excluded — repeating it is the defect this record exists
  to prevent; when every plausible hypothesis is exhausted, escalate rather
  than cycle.
- Output section: add a `hypothesis:` line (one sentence, as above) — the
  orchestrator records it on the attempt event, which is what makes the next
  attempt's input exist.
- Wording caution: these files ship through the Codex generator, which
  rewrites the word "Claude" in prose — name mechanisms (the record, the
  orchestrator), never runtimes.

## Acceptance criteria

- `attempt-history.cjs T-XX-YY` over a fixture journal renders only that
  ticket's events, in ts order, with `hypothesis`/`signature` shown when
  present and omitted when absent; `--json` returns the raw events; a fresh
  ticket exits 0 with the no-history line; a missing graph without `--graph`
  refuses.
- `fix-round.mjs` args comment, prompt assembly, and OUT schema all name
  `attemptHistory` and `hypothesis` (exact strings — they are the cross-ticket
  contract with T-20-06); a `prs[]` entry WITHOUT `attemptHistory` builds the
  same prompt as today.
- OUT schema `required` includes `hypothesis`; both fallback objects carry it.
- Both references gain the input, the do-not-repeat rule, and the
  `hypothesis:` output line; neither names a runtime by name.
- `fix-round.mjs` still passes the runtime wrap check (top-level return is the
  DSL, bare `node --check` failing is expected).
