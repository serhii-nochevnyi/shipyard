## Goal

One module answers "does this `files_modified` entry own this path", and Gate 2
overlap, the scope gate and base-merge's conflict resolution all ask it. A
declaration the matcher cannot answer exactly is rejected at Gate 2; two
unordered tickets whose declarations can intersect are an error; base-merge
resolves a conflict mechanically only when ownership is certain.

## Context (Reads)

- ADR-004 D1 (audit F01, reproduced 2026-09-07).
- `validate-graph.cjs globPrefix` (~line 313): `g.slice(0, firstWildcard)`,
  trailing slash trimmed; `overlaps(a, b)` compares the stumps as prefixes. So
  `src/foo*.ts` → stump `src/foo` and `src/*.ts` → stump `src`. Two unordered
  tickets declaring `src/foo*.ts` and `src/fooBar.ts` pass Gate 2 (stump
  `src/foo` vs path `src/fooBar.ts`: not equal, not `src/foo/…`).
- `scope-gate.cjs` ~83 and `base-merge.cjs` ~73: `covered(p) = prefixes.some(pre
  => p === pre || p.startsWith(pre + '/'))` over the same stumps. The first
  ticket's legitimate edit to `src/fooBar.ts` is REJECTED by the scope gate;
  worse, on a conflict base-merge classifies that file as "not mine" and takes
  the base's edition — the ticket's own change is overwritten, committed, and
  the script exits 0 with `result: resolved mechanically`. That is the one
  mechanical conflict resolver the conveyor has, deciding from a wrong owner.
- `CLAUDE.md` on base-merge: "keying on `files_modified` rather than on 'not
  my file' is what protects a child that legitimately edits a file its parent
  also touched". The protection holds only if the matcher is exact.
- Existing plans in `.planning/phases/2*/` declare exact paths, directories
  (`tests/fixtures`) and nothing with a wildcard — the accepted grammar below
  covers every declaration in this repo; run the validator over them as the
  regression.
- `tests/smoke/graph-validator-smoke.sh` runs Gate 2 over fixture projects in
  `tests/fixtures/`; `worktree-gates-smoke.sh` drives scope-gate and base-merge
  against real local git repos. Both gain the F01 fixtures.

## Scope

- New `path-owner.cjs`: `parse(decl) → {kind: 'file'|'dir'|'glob', …}` accepting
  exactly: an exact path; a directory as `dir`, `dir/` or `dir/**`; a single
  `*` within ONE segment (`src/foo*.ts`, `src/*.ts`) — `*` never crosses `/`.
  Anything else (`**` mid-pattern, `?`, `[…]`, `{…}`) → `{error}`. Exports
  `owns(decl, path)` and `mayIntersect(a, b)` (true when any path could satisfy
  both — e.g. `src/*.ts` vs `src/fooBar.ts`, `src/` vs anything under it).
- `validate-graph.cjs`: a declaration `parse` rejects is a Gate 2 ERROR naming
  the ticket and the entry; overlap between unordered tickets uses
  `mayIntersect`.
- `scope-gate.cjs`, `base-merge.cjs`: `owns` replaces the prefix test.
  base-merge additionally: when a conflicted path is owned by the ticket AND
  matched by any wildcard declaration of a sibling ticket in the graph, it does
  NOT auto-resolve — leaves the conflict for an agent with a reason.
- Fixtures + smoke cases for: the F01 pair (Gate 2 now rejects), a legitimate
  `src/fooBar.ts` edit under `src/foo*.ts` (scope gate now accepts), and the
  base-merge overwrite (now left for an agent, ticket's edition preserved).

## Out of scope

Any change to the cascade or to what base-merge does on an unambiguous
conflict. Widening the grammar beyond the three forms.

## Acceptance criteria

- `owns('src/foo*.ts','src/fooBar.ts') === true`; `owns('src/*.ts','src/a/b.ts') === false`;
  `owns('src/*.ts','src/x.md') === false`; `owns('tests/fixtures','tests/fixtures/a/b') === true`.
- `parse('src/**/x.ts')` and `parse('a?.ts')` return an error; Gate 2 fails
  on a fixture declaring one, naming the entry.
- Gate 2 fails on two unordered tickets declaring `src/foo*.ts` and
  `src/fooBar.ts` (today it passes — the smoke fails on current code).
- The scope gate accepts a `src/fooBar.ts` edit under `src/foo*.ts` (today
  rejects).
- base-merge on a conflict in `src/fooBar.ts` where the ticket declares
  `src/foo*.ts` keeps the TICKET's edition (today it takes the base's; assert
  file CONTENT, per `CLAUDE.md`).
- `node validate-graph.cjs` over this repo's real `.planning` still exits 0.
