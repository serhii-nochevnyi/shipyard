## Goal

A `gh pr checks` call that failed or returned unparseable output is recorded as
`checks.unavailable: true` with the error — a state distinct from an observed
empty list. The front keeps such a ticket in `waiting.ci`, the merge refuses
naming the error, and the next sync looks again.

## Context (Reads)

- ADR-004 D11 (audit F02 remainder; the P1 half — unknown states as green — is
  T-24-02's, landed).
- `state-sync.cjs ghChecks` ~109–122: stdout empty or unparseable and any
  non-zero exit all return `{rows: [], none: true, note}`; `state-sync` writes
  `none_reported: true`. T-24-05 routes `none_reported` to `waiting.merge_human`
  ("confirm the repo has no CI") — the right answer for a repo with no CI and
  the WRONG answer for a 503: nobody should be asked to confirm anything about a
  reading that did not happen.
- `check-state.cjs classify` (T-24-02) is the one vocabulary; add the fourth
  state there so every consumer gets it from the same place. `sentinel.cjs
  ghChecks` (~128) is the merge path's live read.
- Chain: T-26-10 → … → T-24-11 own the shared files before this.

## Scope

- `ghChecks` (both scripts) returns `{rows, none, unavailable, note}` where
  `unavailable` is true iff the call errored or stdout was not a JSON array
  (`gh` exit 1 with a valid `[]` is an observed empty list, per the
  exit-code-is-data rule in `CLAUDE.md`).
- `state-sync` writes `checks.unavailable` + `checks.note`; `front.cjs`:
  `unavailable` → `waiting.ci` with `why` "checks unreadable: <note> — retried
  next sync"; `sentinel merge` refuses with the note; `escalation-record`'s
  fingerprint is unchanged (T-24-08 owns lifting).
- `ci-wait.cjs` already distinguishes an outage (T-24-10); no change.

## Out of scope

The `merge_without_ci` policy (T-24-05).

## Acceptance criteria

- Stubbed `gh pr checks` exiting 1 with an HTTP 503 body → state carries
  `unavailable: true`, front `waiting.ci`, merge refused naming the note. Today:
  `none_reported`, `merge_human` (after T-24-05) or merge (before) — fails on
  current code.
- Stubbed `gh` exit 1 with stdout `[]` → `none_reported`, unchanged route.
- `classify` on `null` rows → `unavailable`, not `none_reported`.
