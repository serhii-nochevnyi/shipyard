## Goal

The Jira export's idempotency labels carry the repository, so two repositories
exporting `T-01-01` to one Jira project never find-and-update each other's
issue; the old label is searched as a fallback and migrated with a comment.

## Context (Reads)

- ADR-004 D8 (audit F24; deterministic by construction, not exercised against
  a live Jira).
- `decompose.md` ~346–360: label `shipyard-<ticket-id>` on issues,
  `shipyard-epic-<phase>` on epics; JQL `project = <KEY> AND labels =
  "shipyard-<id>"`. Ticket ids restart at `T-01-01` in every repository.
- The repository identity is available at export time from `gh repo view
  --json nameWithOwner`; sanitize `owner/name` to a label-safe slug
  (lowercase, `/` → `-`).
- The Codex skill is GENERATED from this command (`gen-codex-shipyard.cjs`);
  editing the Claude command is the whole change — do not touch generated
  files.

## Scope

- New labels: `shipyard-<owner>-<repo>-T-<phase>-<plan>` and
  `shipyard-epic-<owner>-<repo>-<phase>`; lookup order: new label, then the
  legacy label ONLY when the issue's description carries this repo's plan path
  in its "Source of truth" line; on a legacy match, add the new label and
  comment "label migrated". Never update an issue whose source-of-truth line
  names another repository.
- The persisted `pipeline.jira` block gains nothing; the slug is derived each
  run.

## Out of scope

Any script; the export stays a prompt-driven MCP procedure.

## Acceptance criteria

- `decompose.md` no longer contains a bare `shipyard-<ticket-id>` label rule;
  the JQL example carries the repo slug; the migration rule and the
  "never update another repository's issue" sentence are present.
- `make test-docs` passes (README/plugin.json command surface unchanged).
