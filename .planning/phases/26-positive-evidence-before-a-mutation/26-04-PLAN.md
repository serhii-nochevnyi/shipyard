## Goal

`ticket-worktree.sh gc` classifies a worktree `landed` only on positive
evidence — the ticket's delivery state says `merged` — never on the absence of
a remote branch. A clean worktree on a local-only branch is `review`: reported,
kept. Cleanliness is re-checked under the git lock immediately before
`--force` removal.

## Context (Reads)

- ADR-004 D4 (audit F08, reproduced: create worktree, commit, do not push,
  `gc --prune` → removed).
- `ticket-worktree.sh` ~244–252: `landed` when the graph knows the ticket, the
  tree is clean and `refs/remotes/origin/<branch>` is absent, with the comment
  "the conveyor deletes a ticket's remote branch only after it has landed". The
  same three facts describe an executor that has committed and not yet pushed
  — the NORMAL state between Phase B and Phase C of every ticket. `--prune`
  then removes it with `git worktree remove --force`.
- `CLAUDE.md` Step 0/2c: `dirty` and `review` are never removed; "gc refuses to
  guess". The `landed` rule guessed.
- Evidence available to the script: `.planning/graph/delivery-state.json`
  (`state[id].status === 'merged'`, and `reapable`), and `git branch --merged`
  is useless after a squash. Use the delivery state; when it is absent, nothing
  is `landed`.
- `tests/smoke/worktree-smoke.sh` drives `ticket-worktree.sh` against real
  local repos (`make test-worktree`).

## Scope

- `landed` ⇔ delivery-state `status: merged` for the ticket (or `reapable`),
  AND clean. Graph-known + clean + no remote ⇒ `review` with reason "committed
  work not on origin — push or remove by hand".
- `--prune`: re-run the porcelain check under the repo's git lock right before
  each removal; a tree that became dirty is skipped and reported.
- `gone` unchanged.

## Out of scope

The reaper (Step 2b — already keyed on `reapable`).

## Acceptance criteria

- Smoke: worktree with one unpushed commit → `gc` says `review`, `gc --prune`
  leaves it in place (today: `landed`, removed — fails on current code).
- Worktree whose ticket is `merged` in a fixture delivery-state and whose
  origin branch is gone → `landed`, pruned.
- No delivery-state file → nothing `landed`, nothing pruned.
- A file created in the worktree between classification and removal → skipped
  with a reason.
