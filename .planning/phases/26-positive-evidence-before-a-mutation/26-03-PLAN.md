## Goal

A cross-phase parent is `landed` only when the comparison SAID so: a failed or
unparseable `gh api compare` is `unknown`, parks the dependents with that
reason, and is retried on the next sync. Repository availability and
`unreachable_paths` block a ticket in BOTH integration modes.

## Context (Reads)

- ADR-004 D3 (audit F07 reproduced with a rate-limited compare; F27 by source).
- `state-sync.cjs` ~311–319: `let ahead = 0; if (exists) { cmp = gh([...],
  {tolerate: true}); ahead = cmp ? parseInt(cmp) || 0 : 0; } … landed: !exists
  || ahead === 0`. A `null` from a failed call, an empty string and a real `0`
  are the same number; `landed: true` follows, and every phase-N+1 child of a
  merged phase-N parent becomes `ready` on a base that does not contain it.
- `state-sync.cjs` readiness (~360–400): the epic-stacked branch checks
  `unreachable_paths` (~368) and `repoData.get(repo).available`; the
  direct-to-main `else` (~396) checks only `status !== 'merged'` of parents.
- Cross-phase parents: T-24-11 (phase 24's last toucher of `state-sync.cjs`
  and `sentinel-smoke.sh`) and T-24-10 (`ci-wait.cjs`, which T-26-10 down this
  chain edits — T-24-10 is a sibling branch in phase 24, not T-24-11's
  ancestor, so it is named explicitly). Both land with phase 24's epic.

## Scope

- `epicInfo[…].landed` becomes `landed: true | false | null` with
  `landed_reason`; `null` when `exists` and the compare failed/unparseable.
  Readiness: a cross-phase parent whose epic is `null` → blocker with reason
  `integration state unknown (gh compare failed: …) — retried next sync`.
  The board prints those under `blocked:` with the reason.
- Move the availability and `unreachable_paths` checks ABOVE the mode split so
  both modes apply them.
- `front.cjs`: no bucket change; verify a `null`-landed parent's child is
  `parked`, not `execute`.
