## Goal

`gsd-tune.cjs --apply` adds the delivery-rules skill to `agent_skills.gsd-planner`
and `.gsd-executor` and removes only a stale shipyard alias; every other entry a
project put there survives. A missing `~/.gsd/` directory is created for
`--global`, not crashed on.

## Context (Reads)

- ADR-004 D7 (audit F22, reproduced: executor skills `[custom-test-contract,
  custom-quality]` became `[global:shipyard-delivery-rules]` after a
  successful apply).
- `gsd-tune.cjs` ~214–220: the desired values are one-element arrays; ~315
  `for (const d of drift) set(raw, d.key, d.want)` replaces the whole array.
  `staleGlobalOverrides` (~316) already knows how to remove only shipyard's own
  entries for `model_overrides` — the same discipline for `agent_skills`.
- ~321: `fs.writeFileSync(tmp…)` then `renameSync` — with `--global` on a
  machine that never ran GSD, `~/.gsd/` does not exist and the write throws.
- Drift detection must match the merge: "drifted" iff the array lacks the
  delivery-rules entry in the form this runtime resolves, or carries the OTHER
  runtime's form (which is silently skipped — `CLAUDE.md`).

## Scope

- Desired value for `agent_skills.*` becomes a MERGE rule: present-entries ∪
  {delivery-rules-for-runtime} − {delivery-rules-for-other-runtime}; order
  preserved, ours appended last.
- `mkdirSync(dirname, {recursive: true})` before the temp write.
- Report lines say what was ADDED/REMOVED, never "set".

## Out of scope

Any other tuned key.

## Acceptance criteria

- Fixture `agent_skills.gsd-executor: [a, b]` → after apply `[a, b,
  global:shipyard:delivery-rules]` on claude; today `[global:shipyard:delivery-rules]`
  — the test fails on current code.
- Fixture with the codex form on a claude runtime → codex form removed, claude
  form added, other entries kept.
- `--global` with a non-existent `~/.gsd` (HOME pointed at a temp dir) → file
  created, exit 0.

Extend `gsd-tune.test.cjs` (it already runs the script against temp configs).
