## Goal

An unparseable `.planning/config.json` never turns into the permissive
defaults for a mutating decision: `sentinel.cjs merge`/`duty`, the waiter's
escalation and state-sync's retarget refuse, naming the file and the parse
error. Defaults apply only when the file is ABSENT.

## Context (Reads)

- ADR-004 D2 (audit F03, reproduced: a truncated config that contained
  `auto_merge: off` resolved to `auto_merge: epic` with only a warning).
- `pipeline-config.cjs loadConfig` (~150–160): `JSON.parse` failure →
  `warnings.push(…)`, `raw = {}`, and the function returns `{config: DEFAULTS…,
  warnings, exists: true}`. `sentinel.cjs` (~86) reads `config` and ignores
  `warnings`; `auto_merge` defaults to `epic`.
- Every mutating caller: `sentinel.cjs` (merge, duty's dispatch decisions),
  `ci-wait.cjs` (escalation via `escalation-record.cjs mark`), `state-sync.cjs`
  (it writes state and prints the `auto-merge:` policy the loop acts on).
  `front.cjs` is a reader — it may render with a loud warning.
- Parents: T-26-11 (end of this phase's state-sync/sentinel chain) and the
  cross-phase T-25-04 (last toucher of `pipeline-config.cjs`, after T-25-03 and
  phase 24's T-24-05). This ticket is last on purpose: it touches every shared file and
  waits for both other epics.

## Scope

- `loadConfig` returns `valid: false` plus `error: {file, message}` when the
  file exists and does not parse (or is not an object). `config` is still the
  defaults for readers, but `valid` is the field every writer checks.
- `sentinel.cjs`: `merge` refuses ("config unreadable: <file>: <error> — fix
  it before any merge"), `duty` emits a single `config-invalid` line and no
  actions; `ci-wait.cjs`: never escalates on an invalid config (returns 0 with
  the reason); `state-sync.cjs`: prints `⚠ config: … INVALID — no policy in
  effect` and sets `auto_merge: off` in the board it prints.
- A `--allow-defaults` flag exists nowhere; the fix is the file.

## Out of scope

Config schema validation beyond parseability (unknown keys already warn).

## Acceptance criteria

- Fixture config `{"pipeline": {"auto_merge": "off"` (truncated) → `sentinel
  merge --dry-run` refuses naming the file; today it reports `would_merge:
  true` with `auto_merge: epic` — the test fails on current code.
- Absent config → unchanged behaviour (defaults, no refusal).
- `ci-wait.cjs` with an invalid config and three empty windows does NOT write
  an escalation.
- `make test-sentinel` passes with a new "corrupt config" case.
