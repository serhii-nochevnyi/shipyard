## Goal

An executor's PR body and its evidence are written to a file in the ticket's
worktree; the workflow returns the PATH and a short status. The orchestrator's
context stops carrying documents it will re-send on every later turn.

## Context (Reads)

- Measured on the same session, 2026-09-07: the orchestrator's transcript
  reached 8.8 MB, and **the twenty largest tool results account for 38% of all
  tool-result bytes in context**, the biggest being 37k, 36k and 30k characters.
  Every one is a workflow completion carrying `prBody` and `evidence` inline.
- The cost is not the single result; it is that context is re-sent on every
  subsequent turn. A 30k-character result read once is paid for once by the
  agent that produced it and then again by the orchestrator on every turn for
  the rest of the run.
- The orchestrator does not need the document. It needs to know the ticket
  committed, what to gate, and where the body is: it passes the body to
  `gh pr create --body-file` and never reads it. This session proved that by
  accident — every PR body was written to a scratchpad file and passed by path
  anyway, after arriving inline first.
- `executors.mjs` returns `{id, branch, status, evidence, prBody}` and
  `fix-round.mjs` returns `{id, pr, pushed, status, notes, hypothesis}`. The
  short fields are what the loop acts on; the long ones are what it forwards.
- `drift-gate.mjs` is NOT in scope: its `reuse_candidates` are short, and the
  loop must read them to build the next executor's prompt.

## Scope

- `executors.mjs`: write `prBody` to `<worktreePath>/.shipyard-pr-body.md` and
  `evidence` to `<worktreePath>/.shipyard-evidence.md`; return
  `{id, branch, status, prBodyPath, evidencePath, summary}` where `summary` is
  the agent's own one-line account, capped. The agent still produces both
  documents; only the transport changes.
- **`fix-round.mjs` and `deliver.md` are deliberately out of scope, and that is
  what lets this ship now.** `fix-round.mjs` belongs to T-24-06, which is in
  flight, and every owner of `deliver.md` is in flight or blocked behind an
  epic; waiting for either would put this fifteen waves out, while the context
  it saves is being paid for on every turn of the session that measured it.
  `executors.mjs` alone carries the largest results — the 37k, 36k and 30k
  outliers are all PR bodies — so it is most of the saving. The same treatment
  for `fix-round.mjs`'s `notes`, and the `deliver.md` sentence, follow in a
  ticket that can own those files.
- Both paths are inside the worktree, so `ticket-worktree.sh remove` cleans them
  up and nothing new needs reaping. Add them to `.gitignore` handling in the
  same way the worktree treats other untracked scratch, and confirm the scope
  gate ignores untracked files (it reads `git diff`, so it does).
- `deliver.md` Phase C: read the body from `prBodyPath` when creating the PR,
  and say why — the orchestrator forwards it and never reads it.

## Out of scope

`drift-gate.mjs`. The size of what agents READ (that is their own context, paid
once). Any change to what the agent produces.

## Acceptance criteria

- The wrapped `executors.mjs` with a stubbed `agent` returns no field longer
  than 500 characters, and the files exist at the returned paths with the full
  content. Today `prBody` comes back inline at up to 11k characters.
- A ticket that returns `blocked` still returns its reason inline: a blocked
  ticket's reason is short and the loop must act on it without a file read.
- The returned `prBodyPath` is an absolute path inside the worktree and the
  file at it is byte-identical to what `prBody` used to carry, so the loop's
  `gh pr create --body-file` needs no other change.
- `make test-fast` passes.

## Test strategy

Extend `workflows-args.test.cjs`, which already evaluates both sources through
the runtime's async wrap with stubs. Assert on field lengths and on file
contents, so the test measures the property (nothing long crosses the boundary)
rather than the shape.
