## Goal

`state-sync.cjs` writes the three fields `computeFront`'s newest predicates
read, so the board and the guard stop disagreeing about a stale base and about
a review verdict with no threads behind it.

## Context (Reads)

- **Found by the integrator on phase 24's epic (2026-09-07, head `35de683`),
  verdict `needs-fix`.** Two of the four predicates T-24-06 shared between
  `front.cjs` and `sentinel.cjs` are dead on the board: `front.cjs:448` calls
  `baseMoved(s)` on `s.merge_state`/`s.behind_by`, `front.cjs:484` calls
  `reviewStandsAlone(…, s.unresolved_count)`, and **`state-sync.cjs` writes none
  of those three fields.** The integrator enumerated its complete entry key set
  and reproduced both branches with a state object carrying only those keys.
- The consequence is the exact disagreement ADR-002 D4 exists to remove, running
  the wrong way: a stale-base PR is offered as `merge` while `sentinel.cjs
  mergeOne` refuses it, and a `CHANGES_REQUESTED`-with-no-threads PR sits in
  `actionable.finalize` while the guard answers `wait-human` and dispatches
  nobody. The guard is right and the board is optimistic.
- **Why the tests passed anyway, which is the part worth keeping:**
  `front.test.cjs` injects the three fields by hand, and `sentinel-smoke.sh`
  asserts board-versus-duty agreement through a REAL `state-sync` run only for
  `waiting.parent` (T-24-03), never for these two. So the acceptance below must
  assert against a `delivery-front.json` written by an actual `state-sync` under
  the stubbed `gh` — hand-built state is how this passed eleven reviews.
- **Root cause is the decomposition, not the ticket.** `24-06-PLAN.md`'s
  `files_modified` does not list `state-sync.cjs`, because Gate 2's overlap rule
  had already given that file to T-24-02/04/05/11 — so the ticket that added two
  board predicates could not add the facts they read. T-24-04 got this right for
  `head_sha` precisely because it did declare the file. This ticket lives in
  phase 26 for the same reason: every file it needs is claimed by phase 26's
  chain, so a phase-24 fix ticket would be a cross-phase contest Gate 2 refuses.
- **The design fork this must decide rather than assume.** ADR-002 forbids new
  `gh` calls in the sync window — `CLAUDE.md` records `reviewDecision` costing
  41s against 7s on a monorepo. `merge_state` can ride the existing OPEN-ONLY
  pass as one more scalar, but that must be MEASURED with `SHIPYARD_TIME=1`
  before and after, not assumed. `unresolved_count` cannot ride it at all (it
  needs a per-PR thread query), so it should not become a sync field: the guard
  already knows it live, and the durable form is a `parkFingerprint`-bound park
  the guard writes, which the board then reads like any other park.
- Cost of leaving it is bounded, not unbounded: T-24-09's ledger caps a
  disagreeing board at twelve blocked rounds. On the Workflow path it combines
  with the missing `needsBaseMerge` dispatch into a genuine stall.

## Scope

- `state-sync.cjs`: add `merge_state` (and `behind_by` when the same response
  carries it) to the OPEN-ONLY pass, never to the bulk `gh pr list` window.
  Print the `SHIPYARD_TIME=1` before/after in the PR body; if the measurement
  shows a material regression, stop and report rather than shipping it.
- `unresolved_count`: NOT a sync field. `front.cjs`'s `reviewStandsAlone` branch
  reads the guard's durable park instead, so the board learns it the way it
  learns every other fact a live query owns.
- `sentinel-smoke.sh`: two cases driven through a REAL `state-sync`, one per
  predicate, asserting the written `delivery-front.json` and `sentinel duty`
  agree. That is the regression this ticket is really about.

## Out of scope

The predicates themselves (correct as shipped). `deliver.md`. The stop gate.

## Acceptance criteria

- A stubbed `gh` reporting `mergeStateStatus: BEHIND` on an otherwise green PR:
  the front written by `state-sync` files it under `fix` with a `base-merge`
  reason, and `sentinel duty` answers `base-merge`. Today the front says
  `merge`; the smoke fails on current code.
- A stubbed PR with `CHANGES_REQUESTED` and zero threads: front and duty both
  route it to a human. Today the front says `finalize`.
- `SHIPYARD_TIME=1 state-sync` shows no material regression against the same
  fixture before the change; the numbers are in the PR body.
- `make test-sentinel` and `make test-fast` pass.

## Test strategy

The smoke is the test, and it must go through a real `state-sync`: a unit test
that injects the fields would reproduce exactly the blind spot that let this
ship. Write the BEHIND case first.
