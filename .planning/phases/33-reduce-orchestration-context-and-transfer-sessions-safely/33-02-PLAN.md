## Test strategy

- A valid committed result yields a capped envelope and validated evidence references; wrong dispatch/head/digest, escaped paths, missing files and agent-forged receipts refuse acceptance.
- Commit/scope checks alone cannot publish tampered evidence; duplicate result delivery is idempotent; missing/surplus result IDs fail; generated delivery uses the same validation command.
The tracer is an end-to-end local fixture of the real command/host/consumer, not only a helper unit test. Create its test file as the first RED action using the existing harness. New slices use fake time and bounded subprocess fixtures, targeting less than 30 seconds. Record RED command/exit/assertion and GREEN evidence; missing import or syntax error is not valid RED. Negative tests match the intended refusal code/reason and assert that launch, publication, acknowledgment or verdict mutation did not occur; a generic thrown error is insufficient. Call the harness done() and assert at least one registered scenario so a no-op test cannot pass. Run each verification command from repository root. Existing integration suites can run longer and must not be substituted for quick checks.
