## Goal

The `gate_status:` trailer carries the head SHA the verdicts were rendered
against; `state-sync` records the PR's current head; a trailer whose head is
not the current head is ABSENT for `sentinel duty`, `sentinel merge` and the
front alike — so a push after the verdict re-owes the verdict instead of
inheriting it.

## Context (Reads)

- ADR-002 D5.
- The trailer today: `gate_status: arch-review=conform, drift-check=…,
  degenerate-green=…, checks=green`, appended by hand via `gh pr edit --body`
  in `deliver.md` (~line 1084) and `pr-sentinel.md` (~line 152). Read by
  `state-sync.cjs parseGate` (line 233), `sentinel.cjs parseGate/gateConform`
  (159/169), `front.cjs gateConform` (457). None of them knows WHICH diff was
  judged. The sequence that breaks it: verdict → undraft → a bot review lands
  on the undrafted PR → review-fix pushes → the PR is green again → `merge`
  reads the old trailer as conform → lands a diff arch-review never saw.
- `state-sync.cjs` `PR_FIELDS` (line 72) is the bulk `gh pr list` window;
  adding `headRefOid` is one scalar and does not carry the `reviewDecision`
  cost `CLAUDE.md` warns about. Record it as `state[id].head_sha`.
- `sentinel.cjs mergeOne` (line 468) already views the PR live; add
  `headRefOid` to that view — the live head is the one the merge must compare.
- `tests/unit/trailer.test.cjs` pins that the reader takes the LAST
  `gate_status:` line and that unknown keys pass through. Keep both
  properties; add `head=`.
- Backwards compatibility: a trailer WITHOUT `head=` is a trailer written by the
  previous release. Treat it as conform ONLY when `state[id].head_sha` is
  absent too (no way to compare — old board); when the board carries a head and
  the trailer does not, the verdict is absent and the `why` says the trailer
  predates head binding. This is the fail-closed direction and it only bites a
  PR that was verdicted under v0.45 and not merged before the upgrade.

## Scope

- New `gate-trailer.cjs`: `write <pr> [--repo o/n] --arch-review conform
  --drift-check <v> --degenerate-green <v> [--checks green]` — reads the live
  body and `headRefOid`, appends ONE `gate_status:` line with `head=<sha>`, and
  refuses to write while `reviewers.cjs unresolved` reports threads (the rule
  `pr-sentinel.md` states in prose: "writing it while a thread is open is
  falsifying the gate"). Also exports `parseGate(body)` and
  `gateConform(gate, headSha)` so the three readers share one implementation.
- `state-sync.cjs`: `headRefOid` in `PR_FIELDS`, `head_sha` in state; import
  `parseGate` from the new module.
- `sentinel.cjs`, `front.cjs`: `gateConform(s)` → conform iff
  `gate['arch-review'] === 'conform'` AND (`gate.head === s.head_sha` OR both
  absent). `why` strings say `conform trailer is for <short-sha>, head is
  <short-sha> — arch-review owed again`.
- `deliver.md` and `pr-sentinel.md`: replace the hand-assembled `gh pr edit`
  trailer block with the `gate-trailer.cjs write …` call (exact invocation
  pinned by the test's usage string). No other edits in those files.

## Out of scope

The arch-review reference itself (it emits a verdict, it does not write the
trailer). Reviewer thread semantics (T-24-06). Merge-side verification beyond
the trailer (T-24-05).

## Acceptance criteria

- `parseGate('gate_status: arch-review=conform, head=abc123')` →
  `{ 'arch-review': 'conform', head: 'abc123' }`; the last-line rule and
  passthrough cases in `trailer.test.cjs` still pass.
- State with `head_sha: 'def456'` and gate head `abc123` → `front.cjs` puts the
  ticket in `finalize` (arch-review owed), `sentinel duty` answers
  `arch-review`, `sentinel merge` refuses naming both SHAs. Today all three say
  conform; the test fails on current code.
- Same head → conform everywhere (unchanged behaviour).
- Trailer without `head` + state without `head_sha` → conform (old board);
  trailer without `head` + state with `head_sha` → absent.
- `gate-trailer.cjs write` against a stubbed `gh` with one unresolved thread
  exits non-zero and writes nothing.
- `deliver.md` and `pr-sentinel.md` contain `gate-trailer.cjs write` and no
  longer contain a hand-written `gate_status:` inside a `gh pr edit` block.

## Test strategy
