## Goal

One module classifies `gh pr checks` rows into failing / pending / passing,
from gh's own `bucket` field; `state-sync.cjs`, `sentinel.cjs` and
`ci-wait.cjs` all import it, and a state none of them has heard of is PENDING,
never green.

## Context (Reads)

- ADR-002 D3.
- Three hand-written lists today, and they disagree:
  - `state-sync.cjs` ~line 281: failing = `FAILURE, ERROR, CANCELLED, TIMED_OUT`;
    pending = `PENDING, QUEUED, IN_PROGRESS, EXPECTED`.
  - `sentinel.cjs` `ghChecks` lines 134–135: the same two lists.
  - `ci-wait.cjs` lines ~211–212: failing additionally includes `ACTION_REQUIRED`.
  Everything else — `WAITING`, `REQUESTED`, `STALE`, `STARTUP_FAILURE`,
  `ACTION_REQUIRED` in two of three — falls into neither list and therefore
  counts as passed: `failing === 0 && pending === 0` is the green test in
  `state-sync.cjs` line 455 and `front.cjs`.
- `gh pr checks --json bucket,state,name` — `bucket` is gh's own
  classification: `pass | fail | pending | skipping | cancel`. It exists so
  callers do not maintain this list. `cancel` and `fail` are failing;
  `skipping` is neither failing nor pending (it counts towards `total` only);
  `pending` is pending; anything else — including a missing bucket on an old gh
  — is PENDING (fail closed: an unreadable check cannot be green).
- `gh pr checks` exit code is data (8 = pending, 1 = failing/no checks), not an
  error — `state-sync.cjs` lines 103–122 already handle this; preserve it.
- T-24-01 is the parent for stacking only: it and T-24-07 both edit
  `deliver.md`, so everything between them is one chain, and every
  `sentinel.cjs`/`front.cjs` edit in this phase rides that chain.

## Scope

- New `plugins/delivery-pipeline/scripts/check-state.cjs` exporting
  `classify(rows) → { total, failing, pending, passing, skipped, none_reported }`
  and `CHECK_FIELDS = 'name,state,bucket'`. Unknown bucket → pending, and the
  module says why in a comment. Also export `stateBucket(row)` for callers that
  need one row.
- `state-sync.cjs`, `sentinel.cjs`, `ci-wait.cjs`: request `CHECK_FIELDS`, call
  `classify`, delete the local lists. The `checks` object written to
  `delivery-state.json` keeps its current keys (`total, failing, pending,
  none_reported, note`) so `front.cjs`, `escalation-record.fingerprint` and
  the stop gate read exactly what they read today.
- `tests/unit/check-state.test.cjs`: the vocabulary table, and the fail-closed
  case for an unknown bucket and for a row with no bucket.

## Out of scope

`front.cjs` (it reads tallies, it does not classify — T-24-03 onward touch it).
The `none_reported → green` rule (T-24-05). Any change to which `gh` calls run.

## Acceptance criteria

- `classify([{bucket:'fail'},{bucket:'cancel'},{bucket:'pending'},{bucket:'pass'},{bucket:'skipping'}])`
  → failing 2, pending 1, passing 1, skipped 1, total 5.
- `classify([{bucket:'weird'}])` and `classify([{state:'STARTUP_FAILURE'}])`
  → pending 1, failing 0 — NOT green.
- `ACTION_REQUIRED` (bucket `fail`) counts as failing in all three consumers.
  In `sentinel.cjs` the only live `gh pr checks` call is on the MERGE path
  (`ghChecks` at ~line 535, inside `mergeOne`; `duty` reads state-sync's cached
  tallies) — so the sentinel test drives `sentinel.cjs merge <T> --json` with a
  stubbed `gh` returning `[{"name":"x","state":"ACTION_REQUIRED","bucket":"fail"}]`
  and asserts the refusal names `1 failing check(s)`. Today that row is in
  neither hand-written list, the gate sees 0 failing / 0 pending, and the merge
  PROCEEDS — the test fails on current code.
- Every `gh pr checks` stub in the repo emits `bucket` on its rows, because a
  row without one is PENDING by this ticket's own rule: `tests/smoke/
  sentinel-smoke.sh` (lines ~66 and ~70) and `tests/unit/trailer.test.cjs`
  (line ~63) both stub `[{"name":"build","state":"SUCCESS"}]` and assert green /
  `would_merge`; add `"bucket":"pass"` to those rows. They are in
  `files_modified` for exactly this reason.
- No literal `'FAILURE'`/`'IN_PROGRESS'` list remains in `state-sync.cjs`,
  `sentinel.cjs` or `ci-wait.cjs` (grep in the verification commands).
- `make test-sentinel` still passes (it stubs `gh pr checks`; update the stub's
  JSON to carry `bucket` where the fixture emits rows).

## Test strategy

TDD: the vocabulary table first, then the fail-closed row. For the consumers,
extend the existing stubbed-`gh` fixtures in `sentinel.test.cjs` and
`ci-wait.test.cjs` with one `ACTION_REQUIRED`/`fail` row each and assert the
verdict changes. Then add `bucket` to the two existing stubs named in the
acceptance criteria (`sentinel-smoke.sh`, `trailer.test.cjs`) — a bucket-less
row is pending under the new rule, so those fixtures go red until they carry
it. Those are the ONLY two other `gh` stubs in the repo (`grep -rln "pr checks"
tests/`).
