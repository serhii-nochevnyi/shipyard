## Goal

The guard's `wait-parent` and the front's buckets agree: a child whose parent
is still moving is `waiting.parent`, not `finalize`; the CI waiter waits on the
parent's checks when that is what the child waits for; and `front.cjs` stops
recommending `gh pr checks --watch`.

## Context (Reads)

- ADR-002 D4; `CLAUDE.md` on `front.cjs` ("the front must never offer what the
  guard refuses" — written for `checkpointParent`, which already lives in both
  files; this ticket does the same for the OTHER shared test).
- `sentinel.cjs` `parentIsMoving(id)` (line 243) and its use in `duty` (line
  286 → action `wait-parent`). `front.cjs` has no counterpart: the child lands
  in `finalize` (or `fix`), the loop dispatches nothing because the guard owns
  the bucket, the guard answers `wait-parent`, `ci-wait.cjs` refuses because
  something is "actionable", and the stop gate blocks over it. Measured on the
  proving ground as the guard "declining the work the front offered" round
  after round.
- `deliver.md` documents `waiting.parent` in its bucket table ALREADY. The
  prose is ahead of the code; this ticket makes the code catch up, so
  `deliver.md` needs no edit here.
- The `checkpointParent` sharing in `front.cjs`/`sentinel.cjs` is the pattern:
  one function, both callers, one test that drives both with the same state.
  The comment at `sentinel.cjs` line 505 explains why `parentIsMoving`'s
  checkpoint exception must stay as it is — preserve the semantics exactly
  while moving the function.
- `ci-wait.cjs` watches the PRs in `waiting.ci`. A child in `waiting.parent`
  is waiting on its PARENT's CI; if the waiter ignores it, the board reads as
  "nothing in CI" while a parent's pipeline is the only thing that will ever
  move it — and the stop gate's CI-only branch (which reads `waiting.ci`) then
  allows the stop. So the waiter must include the parent PR of every
  `waiting.parent` child in its watch set (deduplicated).
- `front.cjs` line 627 prints `(watch is legal here — they are the only thing
  left)`. `deliver.md` item 5 and `ci-wait.cjs` say the opposite; the message
  must name `ci-wait.cjs` instead.

## Scope

- New `parent-moving.cjs` exporting `parentIsMoving(id, { tickets, state })`
  with the exact semantics of the sentinel's function (including the
  checkpoint exception). `sentinel.cjs` imports it; the local copy is deleted.
- `front.cjs`: new bucket `waiting.parent` (with a `why` naming the parent and
  what it is doing); counted in `counts`; excluded from `actionable`; included
  in the `fixpoint: NO` reasoning (a parent moving is not a fixpoint); rendered
  by `formatFront`. `sentinel.duty`/`sentinel.clear` treat it like `waiting_ci`.
- `ci-wait.cjs`: watch set = `waiting.ci` ∪ parents of `waiting.parent`; the
  refusal rule ("anything actionable or dispatched") is unchanged; the empty
  board test ("nothing to wait for") must consider both buckets.
- `front.cjs` line 627 wording → `(run ci-wait.cjs — it waits in the foreground
  and returns on the first PR to settle)`.
- Stop gate: NO change to `stop-gate.cjs` (T-24-09 owns it). Verify in the
  front test that a board with only `waiting.parent` produces
  `actionable_count: 0` and non-empty `waiting.parent`, and note in a comment
  in `front.cjs` that the stop gate's CI-only branch reads `waiting.ci`
  only — T-24-09 extends it.

## Out of scope

owned by T-24-07); the checkpoint exception's semantics.

## Acceptance criteria

- One state fixture (parent PR open with pending checks, child PR green and
  conform) → `sentinel duty` says `wait-parent` for the child AND
  `computeFront` puts the child in `waiting.parent`. Today the front puts it in
  `finalize`/`merge`; the test fails on current code.
- `parentIsMoving` from the new module returns the same answer as the deleted
  sentinel function for every case `sentinel.test.cjs` already covers
  (including the checkpoint parent).
- `ci-wait.cjs --json` on a board with an empty `waiting.ci` and one
  `waiting.parent` child reports the PARENT's PR in its watch set and does not
  refuse with "nothing to wait for".
- `formatFront` renders `parent: <ids>` under waiting.
- `grep -n "watch is legal" plugins/delivery-pipeline/scripts/front.cjs` is empty.
