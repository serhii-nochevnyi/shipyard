## Goal

`plan_defect` is reached only from K distinct failure signatures with NO green
between them, `unknown` signatures never count towards K, and the attempt
counter the ladder and the `attempts > max` backstop read is derived from the
journal — so a resumed session continues at attempt N+1 instead of restarting
at 1.

## Context (Reads)

- ADR-002 D8; ADR-001 D1/D2 for what the verdict is FOR.
- `plugins/delivery-pipeline/scripts/failure-signature.cjs` — the file header
  (line 27) states `K distinct, no green → plan_defect`. `computeVerdict`
  (line ~258) implements `distinct >= k → plan_defect` (line ~292) with no
  green check at all: `priorSignatures` is every signature the ticket ever
  journalled. Three sequential failures — each FIXED, each followed by a green
  push — therefore park a healthy ticket as a plan defect on the third. Prose
  asserting a behaviour the code does not have, in the same file; the same
  class `CLAUDE.md` records for `BEHIND` in `sentinel.cjs`.
- `unknown` is the signature `computeSignature` emits when no error class can
  be extracted. Two `unknown`s are not "two distinct failures" — they are two
  failures nobody could read — yet the `Set` counts the string once and any
  real signature beside it as a second.
- `plugins/delivery-pipeline/scripts/attempt-history.cjs` — renders prior
  attempts for a fixer as INPUT (ADR-001 D5). It never says how MANY there
  were, so `deliver.md` keeps `attempts` in the session and the backstop
  `attempts > max_attempts` resets on every resume. The journal already holds
  every `attempt` event; the number is one count away.
- `tests/unit/failure-signature.test.cjs`, `tests/unit/attempt-history.test.cjs`
  — extend, keep the harness (`tests/unit/assert-harness.cjs`).
- `deliver.md` Step 4 babysit loop — where `attempts` is read and where the
  signature verdict branches are listed. This ticket edits ONLY the sentences
  that name the attempt counter's source; the rest of the file is T-24-07's.

## Scope

- `computeVerdict`: the distinct window is the set of signatures journalled
  since the last event that proves a green for this ticket — a `merge`, or a
  standing `flake` quarantine (`failure-signature.cjs rerun --outcome green`
  writes `flake`, not a `flake_rerun … green`; no writer produces the latter,
  and `attempt … outcome=green` has no writer either — the first draft of this
  plan named both and the executor rightly departed from it, see PR #27). A
  `flake_lift` retracts the reset it introduced. A green RESETS the window.
  *(Amended 2026-09-07 after delivery: the shipped code is the contract; this
  text now matches it.)* `unknown` is excluded from the distinct set (it
  still participates in `first`/`repeat`/`flake_candidate` for the current
  signature). Update the header comment so it describes what the code does.
- `attempt-history.cjs --json` gains `next_n` (count of journalled `attempt`
  events for the ticket + 1) and `attempts` (the count). The human rendering
  prints the same number once, at the top.
- `deliver.md`: the babysit loop reads the attempt number from
  `attempt-history.cjs --json` → `next_n` (exact string, pinned by the test),
  never from a session variable; the `attempts > max_attempts` backstop reads
  the same number.

## Out of scope

Any other change to `deliver.md` (T-24-07). The verdict vocabulary itself
(first/progress/repeat/flake_candidate/flake/plan_defect) is unchanged.

## Acceptance criteria

- Journal: sig A red → green → sig B red → green → sig C red. `computeVerdict`
  with k=3 returns `first` (or `progress`), NOT `plan_defect`. Today it returns
  `plan_defect`; the test must fail on the current code.
- Journal: sig A, B, C red with no green between → `plan_defect` (unchanged).
- Journal: `unknown`, `unknown`, sig A → distinct is 1, not 2 or 3.
- `attempt-history.cjs <T> --json` for a ticket with two journalled attempts
  returns `{ attempts: 2, next_n: 3, … }`; with none, `{ attempts: 0, next_n: 1 }`.
- `deliver.md` contains the literal `next_n` and no longer instructs the loop
  to keep the counter in the session.
