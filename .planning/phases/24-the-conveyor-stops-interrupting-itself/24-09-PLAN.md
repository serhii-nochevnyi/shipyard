## Goal

The stop gate blocks once per ROUND of a live cascade — not once per turn —
under a hard cap; it never blocks a fresh session over a journal event from a
run that ended; and a dispatch that has outlived a plausible launch no longer
counts as "an agent is working" for the CI-only hatch.

## Context (Reads)

- ADR-002 D2. `CLAUDE.md`'s three `stop-gate.cjs` paragraphs — read all of
  them; every hatch listed there is load-bearing and this ticket adds a ledger
  without removing one. "A stop gate that traps a session gets uninstalled,
  after which it enforces nothing" is the constraint every change below is
  measured against; that is why the risk is HIGH and the checkpoint is set.
- **A2** line 168: `if (payload.stop_hook_active) allow();` — one block per
  turn. A stacked cascade with N children needs N rounds (merge → child goes
  BEHIND → base-merge → CI → merge …), and each round the loop legitimately
  tries to end the turn after dispatching. The gate blocks once, the loop
  resumes, dispatches, tries to stop again — and this time `stop_hook_active`
  lets it through with three tickets still to land. The hatch was written to
  bound the cost of a FALSE block; it must not also bound the number of TRUE
  ones. Replace it with a per-session ledger beside the front:
  `stop-gate-ledger.json` `{ session_id, blocks, last_generated_at,
  last_moved_at }`. Re-block only when the board ADVANCED since the last block
  (`generated_at` newer, or a qualifying journal event newer than
  `last_moved_at`); otherwise the stale-board rule already holds. Hard cap
  `SHIPYARD_STOP_GATE_MAX_BLOCKS` (default 12 — a cascade deeper than that is a
  phase nobody should run in one turn). Above the cap: allow, and print why.
  The session id comes from the hook payload (`session_id`); a payload without
  one falls back to the old one-block rule.
- **A3** `movedSince` (line 196) counts any journal event with `at >
  generated_at`. A run that ended on a sentinel merge leaves such an event
  forever; the hook is GLOBAL, so the first stop of every later session in
  that repository is blocked with "the board is behind reality". Bound the
  event's age by `SHIPYARD_STOP_GATE_RESYNC_MS` (the same ceiling the
  stale-board rule uses): an event older than that is a run that ended.
- **A5** line 346–348: `if (!ci.length || dispatched.length) allow();` — any
  `waiting.dispatched` entry opens the CI-only hatch. A dispatch marked before a
  launch that never happened (T-24-07 fixes the order in prose) is 90 minutes
  of silence. Read `dispatches.json` beside the chosen front; a dispatch older
  than `SHIPYARD_STOP_GATE_DISPATCH_SUSPECT_MS` (default 45 min — longer than
  any fix round the proving ground has measured, shorter than the TTL) does not
  open the hatch, and the block message names the ticket and says
  `dispatch-record.cjs clear <T>` if the agent is gone. A hook has ~75ms; one
  small JSON read is within budget — measure it in the test the way the journal
  tail read is measured.
- The front is chosen across worktrees by newest `generated_at` (the
  proving-ground lesson); the ledger and `dispatches.json` are read from the
  SAME directory as the chosen front, never from cwd.
- `.planning/graph/` is tracked in this repository (see `.gitignore`); the
  ledger is session state and must be ignored like `delivery-front.json`.

## Scope

- The three changes above, in `stop-gate.cjs` only, plus the ledger's
  `.gitignore` entry. Every existing hatch and every existing test stays
  green. The ledger write is wrapped like `ci-wait.cjs`'s store write: a
  read-only dir or a corrupt file never turns into a non-zero exit.
- The installer (`make install-shipyard-claude-hook`) copies this file to
  `~/.claude/hooks/`; the PR body must say the hook needs re-installing.

## Out of scope

`front.cjs`, `dispatch-record.cjs`, the installer script, `deliver.md`.

## Acceptance criteria

- Sequence: front A (actionable 2) → block; `stop_hook_active: true`, same
  front → allow (unchanged). Then front B (`generated_at` newer, actionable 1) →
  BLOCK again even with `stop_hook_active: true`. Today the second is allowed;
  the test fails on current code.
- Twelve advancing fronts → twelve blocks; the thirteenth allows and prints the
  cap.
- A journal `merge` event 5 hours old against a front 6 hours old → allow
  (run ended). The same event 5 minutes old → block (unchanged).
- CI-only front with one `waiting.dispatched` ticket whose `dispatches.json`
  record is 10 minutes old → allow (agent working). 60 minutes old → BLOCK,
  message names the ticket and `dispatch-record.cjs clear`.
- No `session_id` in the payload → old one-block behaviour.
- Ledger dir read-only → exit 0, decision unchanged, one stderr line.
- All existing `stop-gate.test.cjs` cases pass unchanged.
