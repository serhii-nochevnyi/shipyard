## Goal

`deliver.md` and `pr-sentinel.md` describe the conveyor this phase ships: no
`--watch` for the guard, the dispatch mark AFTER the launch, the `base-merge`
duty and `waiting.parent`/`waiting.human` routes named as the scripts name
them, the attempt number read from `attempt-history.cjs`, and both manifests
bumped together.

## Context (Reads)

- ADR-002 D10. `CLAUDE.md`: "prose rules get skipped, mechanical gates hold" —
  and the corollary this phase keeps hitting: prose that contradicts the gate
  teaches the reader to ignore the gate.
- This ticket is LAST in the chain on purpose: its checkout contains every
  script change of T-24-01…06, so every name it pins is read from shipped code
  in the same worktree, not from a sibling PLAN. `.planning/backlog/
  diamond-child-base-is-materially-incomplete.md` is the record of why that
  matters. Verify each pinned string with `grep` against the scripts in THIS
  checkout and quote `file:line` in the PR body.
- **pr-sentinel.md step 4** (~line 45) tells the guard to run `gh pr checks
  <pr> --watch`. The guard is one agent serving every open PR; a watch
  serializes it on one PR — the exact opportunity cost `ci-wait.cjs` was
  written to avoid. The guard's loop is: duty → act → re-sync → duty; when
  nothing is actionable it RETURNS, and the main loop's `ci-wait.cjs` waits.
  Lines ~176 and ~247 use "watch" in the sense of "guard duty" — keep those,
  change the command.
- **A5 — mark after launch.** `deliver.md` Step 3 (4a) and `pr-sentinel.md`
  mark `dispatch-record.cjs mark` BEFORE the Workflow/Agent call. A launch that
  fails (tool refused, Workflow unavailable on Codex and the Agent fallback
  not taken) leaves a 90-minute dispatch that the front reports as
  `waiting.dispatched` and the stop gate honours. Reorder: launch (the
  Workflow tool returns immediately with a task id; the Agent tool returns an
  agent id) → THEN mark, passing the id in the record's `note`. Say why in one
  sentence. T-24-09 adds the mechanical half (an over-aged dispatch is not an
  agent at work).
- **Attempt number**: T-24-01 shipped `attempt-history.cjs --json` → `next_n`.
  Check every place `deliver.md` still speaks of a session-held `attempts`
  counter and point it at `next_n` (T-24-01 edited only the sentences it had
  to; this ticket finishes the file).
- **Bucket table** in `deliver.md`: `waiting.parent` is now real (T-24-03);
  `waiting.human` gains the CHANGES_REQUESTED-without-threads case (T-24-06);
  the duty actions gain `base-merge` and `wait-human` (T-24-06); the trailer is
  written by `gate-trailer.cjs` (T-24-04, already edited there — verify, do not
  duplicate).
- **Sweep items the wave-1 guard reported (2026-09-07)**: `pr-sentinel.md`
  ~187/~199 still tell the guard to keep a session attempt counter (read
  `attempt-history.cjs --json` → `next_n` instead — T-24-01 shipped it);
  `CLAUDE.md`'s two "one block per turn" sentences and `README.md`'s "already
  blocked once" describe the stop gate before T-24-09 (now: one block per
  ROUND under a ledger and a cap); `deliver.md`/`pr-sentinel.md` "lifts when the
  ticket's state moves" is imprecise for a `pr-sentinel` dispatch after
  T-24-08 (it lifts on the guard's OUTPUT — merge, base move, draft change).
  ADR-002 D8's "attempt … outcome=green" has no writer: say "a merge or a
  standing flake" wherever the reset is described.
- **Manifests**: `plugin.json` and `capability.json` bump together (0.45.0 →
  0.46.0); `make test-overlay` checks the drift, `tests/unit/files-contract.test.cjs`
  is where a pinned-string test for command docs belongs if one is added.
