## Issues found in cycle 1, and the changes made

### Blockers (fixed)

**1. [context_compliance / key_links] An implicit (bare `arm`) binding must never select a board that silences a live sibling board.**
- Plan: 45-01, Scope 1.
- Evidence:
  - The production caller still runs a bare `arm` (`commands/deliver.md:1233`), and its line change is second pass.
  - Scope 1 bound the cwd board whenever `<cwd>/.planning/graph` held a front. A session in a stale main checkout would therefore bind main's stale board, and the bound hook would stop enforcing the live phase-worktree board that the `:749` regression and backlog acceptance 2/3 ("ambiguous scope cannot silently select an unrelated board", backlog :21, :26-27) protect.
- Change:
  - Explicit `--graph-dir` / `SHIPYARD_GRAPH_DIR` always binds.
  - The implicit cwd board binds only when the cwd is a linked worktree, or when no other worktree carries a front. Otherwise the marker is unbound (legacy, bounded) and the CLI names the competing boards.
  - Added the acceptance case "bare `arm` from stale main next to a live worktree stays unbound and blocks", and a mutation check.

**2. [key_links] Every dogfood provenance writer path can record `source_root`.**
- Plans: 45-02, 45-03.
- Evidence:
  - The R16 marketplace path passes only `SHIPYARD_INSTALL_KIND/SOURCE_SHA/SOURCE_DIRTY` (`install-shipyard-marketplace.cjs:35-40`) into `fromEnv`.
  - `fromEnv` never sees a checkout (`host-provenance.cjs:60-66`).
  - As written, "the writer records `source_root`" could not reach that record. The marketplace dogfood cache would stay legacy, so the doctor would still report `error`, and REQ-187/188 would fail for the very scenario that motivated R16.
- Change:
  - 45-02: `derive` records the toplevel, and `fromEnv` reads `SHIPYARD_SOURCE_ROOT`. Tests and acceptance were added for both.
  - 45-03: `installKindEnv` returns `SHIPYARD_SOURCE_ROOT` for dogfood, with a unit assertion.

**3. [verification_derivation] Every verification command runs under the trusted host allowlist.**
- Plans: 45-04, 45-05.
- Evidence: the bullets `bash -c 'for i in $(seq 50); do …; done'` contain `' $ ( ) ; |`. The Codex host refuses them with `VERIFICATION_SPEC_UNSUPPORTED` (`codex-delivery-host.cjs:351-354`), so executor verification could never pass.
- Change: the loops were removed from `## Verification commands`. They are now recorded acceptance evidence, with the exact command and the requirement to record its exit status. The single-run commands stay.

**4. [nyquist 8e] VALIDATION.md exists when nyquist is enabled and RESEARCH has a Validation Architecture.**
- Plan: phase level.
- Evidence: `.planning/config.json:24` sets `nyquist_validation: true`, and `45-RESEARCH.md` has a `## Validation Architecture` section, but there was no `45-VALIDATION.md`.
- Change: created `45-VALIDATION.md`, with a per-ticket map using the final ROADMAP ids, the Wave 0 files and the extra evidence.

**5. [research_resolution] RESEARCH has no unresolved open question.**
- Plan: phase level.
- Evidence: `45-RESEARCH.md` "## Open Questions" listed 4 questions without resolutions.
- Change: the heading is now "## Open Questions (RESOLVED)", and each question carries its disposition.

- Evidence:

- Change: the variants use a test-only monkeypatch in the child, plus a second IPC barrier between check and write. 45-07 no longer cites T-45-05 as the source of its pattern (it is not a dependency).

**7. [key_links] A detached decomposition refusal is never reported `exited-ok`.**
- Plan: 45-11.
- Evidence: `statusOnce` reports `exited-ok` for any JSON last line (`deliver-dispatch.cjs:393-396`), and the plan did not pin the invariant that refusals never print JSON on stdout (today they do not: `codex-decompose-host.cjs:381-399`, `:417-419`).
- Change: added the `@invariant`, an acceptance case and a mutation check.

- Plan: RESEARCH.
- Evidence: the RESEARCH tables are off by one from ROADMAP (for example, RESEARCH REQ-188 is concurrency, while ROADMAP REQ-188 is the dogfood home).
- Change: added a supersession note. VALIDATION.md uses the ROADMAP ids.
