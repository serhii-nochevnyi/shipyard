## Two distinct phase-43 failures

**T-43-03, PR #338 — reviewer sandbox.** Earlier authenticated architecture reviews found three source defects and then a renamed-file pre-image defect; those findings required real repairs. After the fixes, head `494f63875dedbc926507ec5b43a847a7dd5c5ede` against epic base `bf89a93fb9f4c89017f7e680511dad45bc9098de` had green exact-head `test-fast` CI (run `36426661162`) and local comment-policy 33/33 plus publish-gate 8/8. The next sealed Sol/xhigh review artifact (`8f5eeb726ce58b9e26f05a03808135d77f9362f39f86a0cc6e4b260216b3519c`) reported `violation` with two remaining blockers: both test commands received `EPERM` while creating temporary files in the reviewer's read-only sandbox, before assertions ran. That review used 2,726,387 input tokens (2,554,880 cached) and 18,877 output tokens. The observed failure is about execution environment, not a demonstrated source-test failure; it also does not itself prove the architecture conforms.

The installed gate accepts only an exact-live-head `arch-review=conform` trailer. The earlier immutable artifact is a valid `violation`; it cannot be edited or carried into conform, and green CI alone cannot change it. There is no supported non-model adjudication or appeal command. Launching a full new Sol/xhigh review merely to classify the two sandbox failures would consume another model turn. Manually writing a conform trailer from the CI result would misstate the current reviewer verdict. This is a missing **typed environment-failure resolution contract**, distinct from phase-44 WP-E's exact-input reuse of an already valid verdict.

**T-43-14 — lost executor publication payload.** An authenticated Luna/max executor finalized signed source commit `fbd71f5bc10fd12206965b201de135b3136a0e33`, changing exactly four PLAN paths and passing verification, but did not leave the required PR body, evidence and bounded result for `role-artifact seal → validate → read`. A second Luna/max turn produced body/evidence and passed all four PLAN verification commands, yet the host refused `NO_PUBLISHABLE_DELTA` because the source was already committed. The two turns consumed 5,605,276 plus 464,776 input tokens respectively; these are processing counters, not subscription quota debits. The second turn's unsealed files cannot be rebound to the first dispatch/commit. The signed commit, receipts and patch are preserved locally, but no PR was opened.

Phase-42 `--resume-finalization` recovers the signed commit metadata, not the producer body/evidence/result. The installed ticket-worktree lifecycle has no supported way to re-cut the existing unmerged canonical T-43-14 branch from the epic for a clean executor replay; `create` reuses the branch, while `remove` only removes its worktree. A manual reset/deletion or a fabricated artifact would bypass that lifecycle. The evidence is therefore a **producer-payload durability and recovery gap**, separate from already completed commit-finalization recovery. A future fix cannot retroactively reconstruct bytes that the original host never persisted.

## Proposed safe treatments for formal investigation

1. Extend R10 with a typed reviewer/host environment-failure classification. Record command, phase of failure (setup versus assertion), sandbox capability, exact ticket/base/head, receipt and immutable findings. If a review has any source or architecture blocker, it remains blocking. Define a policy-reviewed, separately auditable adjudication path for *only* environment-only findings on an unchanged governing input. It must verify exact-head CI or trusted host execution of the same checks, preserve the original `violation`, and require explicit human authority or an accepted deterministic policy before a replacement gate record can be issued. Unknown cause, missing evidence, changed head/base/ADR/instructions, or test assertion failure refuses. Do not forge a model `conform` verdict or silently bypass the merge gate.
2. Add R12 for executor producer-payload persistence. The host must durably bind bounded result, PR body and evidence digests to the authenticated dispatch and finalization candidate before a signed commit becomes publishable. A crash or lost scratch file should recover those **same bytes** with receipt/scope/head/tree verification and then use normal `seal → validate → read`, without a second model turn. If the payload was never persisted, fail explicitly; do not synthesize or cross-bind another dispatch. Test crash points before/after payload persistence and commit finalization, as well as no-delta retries.
3. Treat both as measured pipeline overhead, not a reason to downgrade native reviewer or executor models. Count all failed/replayed turns, elapsed work, quota-window observations where attributable, real missed defects and human adjudications. Compare verified completions and false-green rate after rollout. Phase 44 still owns provider-specific quota collection and exact-input review reuse; Phase 42 keeps signed-commit recovery, while R12 covers the missing producer payload.

## Questions for INV-008 and the ADR

- Can a deterministic or human-signed adjudication safely resolve only environment findings while preserving the independent review's source judgment? Which authority and audit trail may issue the new gate record?
- What exact-head CI provenance proves the same test command and input ran, rather than merely showing an unrelated green check?
- Where should the host persist producer payload so that recovery is atomic with dispatch/finalization identity and private bounded storage?
- How does the ticket-worktree lifecycle recover a signed but unpublished unmerged branch when original producer bytes are absent, without silently replacing its history?
