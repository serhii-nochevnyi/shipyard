## Goal

R16, install half (D-03). `node scripts/install-shipyard-marketplace.cjs codex --source "$PWD"` currently writes a dogfood cache into the shared `CODEX_HOME || ~/.codex` (`scripts/install-shipyard-marketplace.cjs:131-145` `setupCodexHost`; `:35-40` marks an untagged or dirty checkout `dogfood`). Another session on the same machine then sees a foreign cache. The `make install-shipyard-dogfood-*` targets refuse outright without `DOGFOOD_ROOT` (`Makefile:128-134`). After this ticket, a dogfood install targets a dedicated home by default: `${XDG_STATE_HOME:-$HOME/.local/state}/shipyard/dogfood/<runtime>/<first 16 hex of sha256(realpath of the checkout toplevel)>`. An explicitly set `CODEX_HOME` or `DOGFOOD_ROOT` still wins. The install records `source_root` (from T-45-02).

## Scope

1. `install-shipyard-marketplace.cjs`: `installKindEnv` (`:35-40`) also returns `SHIPYARD_SOURCE_ROOT` = the realpath of the source checkout's toplevel whenever it returns a dogfood kind. When the install kind is `dogfood` and `CODEX_HOME` is unset, `setupCodexHost` targets the dedicated home and prints the path plus the `CODEX_HOME=` export needed to use it. When `CODEX_HOME` is set and equals the default shared home, it refuses a dogfood source there (mirroring the Claude refusal) unless the target is the dedicated path. A release install is unchanged.
2. `install-shipyard-codex.sh`: when `--dogfood-root` is omitted in dogfood mode, compute the same dedicated root (`set -euo pipefail`; validate early). The existing refusal of a root inside the Codex home is kept.
3. `Makefile`: `install-shipyard-dogfood-claude` / `-codex` default `DOGFOOD_ROOT` to the dedicated path instead of erroring. The target names stay the same, because `docs-smoke.sh` checks them.
4. `README.md:147-160` and `CLAUDE.md:51-52`: document the default dedicated home, the explicit override, and the doctor's `foreign` status.

## Acceptance criteria

- A dogfood Codex install with `CODEX_HOME` unset writes only under the dedicated home, and a second checkout gets a different home.
- A dogfood install aimed at the shared default Codex home is refused, and the message names the dedicated path.
- A release install still targets `CODEX_HOME || ~/.codex`.
- `make install-shipyard-dogfood-codex` without `DOGFOOD_ROOT` no longer errors on the missing variable. The Makefile target names are unchanged.
- The provenance record written by a marketplace dogfood install carries `source_root` equal to the realpath of the source checkout. A unit test asserts `installKindEnv` returns `SHIPYARD_SOURCE_ROOT` for a dogfood checkout and omits it for a tagged release.
