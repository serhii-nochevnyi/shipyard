## Goal

D5, advisory only (D-04, ADR-023). `capacity-lease.cjs` has per-provider slot leases (`createCapacityCoordinator`, `plugins/delivery-pipeline/scripts/capacity-lease.cjs:39-216`), but nothing bounds how many launches a run or phase makes in total. This ticket adds an aggregate admission ledger in **shadow mode**. `reserve` records `would_admit` / `would_refuse` for a launch against a run/phase budget. Verification and checkpoint reservations are always admitted and never count against the launch budget, and `reconcile` records observed usage when it is known. The ledger never changes any admission result. It is wired into no launch path and adds no config key. Missing quota data yields conservative counts, never a percentage.

## Scope

1. Add `createAdmissionLedger({ storeDir, now, launchBudget, lockWaitMs })` to `capacity-lease.cjs`. `launchBudget` comes only from the constructor, and its default is a conservative constant: 12 launches per run/phase, recorded in the ledger record as `budget_source: 'default'`.
   - Ledger file: `<storeDir>/admission-ledger.json`, with a separate schema string `shipyard.admission-ledger.v1` and 0600 permissions. Updates run under `withLock`.
2. `reserve({ run_id, phase, kind: 'launch' | 'verification' | 'checkpoint', dispatch_id })` → `{ decision: 'would_admit' | 'would_refuse', mode: 'shadow', launches_reserved, launch_budget }`. Verification and checkpoint reservations always return `would_admit` and are excluded from `launches_reserved`. A duplicate `dispatch_id` is idempotent.
3. `reconcile({ dispatch_id, observed })` stores the observed usage verbatim, or `observed: 'unknown'` when absent. `report({ run_id, phase })` returns counts and `quota: 'unknown'` unless observed data exists. It never emits a percentage.
4. `readCapacitySnapshot` and the existing coordinator are unchanged. An existing test asserts the snapshot's key set is unchanged.

## Acceptance criteria

- **Concurrent reservers.** 8 child processes each reserve a launch against budget 4 through one IPC barrier. The ledger records exactly 4 `would_admit` and 4 `would_refuse`, with no lost or duplicated entry. A non-atomic variant must fail.
- **Verification and checkpoint.** After the launch budget is exhausted, `verification` and `checkpoint` reservations are still `would_admit`.
- **Shadow only.** No function returns or throws a refusal that a caller could act on. The mode is always `shadow`.
- **Quota.** A missing observation reports `quota: 'unknown'` and conservative counts.
- **Compatibility.** `readCapacitySnapshot` output and `SCHEMA_VERSION` are byte-identical to before for the existing fixtures.
