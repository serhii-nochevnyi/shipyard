## Goal

R13, N48 part only. `usage-report` reports zero observations for a Codex host-stream transcript (`codex exec --json`). Its Codex branch accepts only `event_msg`/`token_count` and `token_usage_record` (`plugins/delivery-pipeline/scripts/usage-report.cjs:479-482`), requires a timestamp (`:501-503`), and treats the value as a cumulative thread total (`:486-493`). The stream shape (`tests/fixtures/captured/codex-agent-stream-exec.jsonl`) is `thread.started{thread_id}` → `turn.started` → `turn.completed{usage}`. It has no timestamp and no model or effort, and its usage is **per turn**. After this ticket, such a transcript produces a per-session sum. A report of zero observations on a stream transcript fails a test.

## Scope

1. Recognise `thread.started` (sets the stream session) and `turn.completed` with an object `usage`, as a third Codex schema: `stream`.
2. Stream usage is **summed** per session across turns in source order, never max-merged.
3. One schema per session: if a session already has `current` or `legacy` records, its stream rows are skipped with a warning. The reverse also holds, so a thread that appears both as a stream and as a native rollout is counted once.
4. Missing timestamps: stream entries are marked `untimed`. They count toward the session total and are excluded from any time-windowed aggregate, instead of being refused at `:501-503`. They are never given a fabricated time.
5. Model and effort come only from `metadataFor` attribution. A stream session without attribution is reported `unattributed`.
