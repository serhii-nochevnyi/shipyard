## Goal

R8, capture-tool part only (intake N28, N29). `scrub` (`scripts/capture-boundary-fixtures.cjs:55-65`) replaces home and tmp paths, token shapes and UUIDs, but it has no rule for Codex account fields. The committed fixtures show hand replacements: `"creator_user_id":"<USER-ID>"`, and `"creator_account_id"` mis-placeholdered as `<SESSION-1>` because its value is a UUID (`grep -oh '"creator_[a-z_]*":"[^"]*"' tests/fixtures/captured/*.jsonl`). After this ticket:
- the scrubber replaces account identifier fields with stable placeholders before the UUID pass;
- the live-capture scratch directory is `git init`-ed, so the CLIs see a real repository (R7/N10 lesson);
- the fixture scan rejects any account field whose value is not a placeholder.

## Scope

1. Add `replaceAccountIds(input, context)` before `replaceSessionIds` in `scrub`. JSON string values of the keys `creator_user_id`, `user_id`, `account_id`, `creator_account_id`, `chatgpt_account_id` and `organization_id` become `<USER-ID>` for user keys and `<ACCOUNT-ID>` for account/organization keys. Each distinct value gets a stable index (`<ACCOUNT-ID-1>`, …) only when more than one distinct value appears. The placeholders already committed (`<USER-ID>`) keep their spelling.
2. Live capture: after `mkdtemp`, run `git init -q` in the realpath scratch dir, and one empty commit with a fixed author and date passed through `-c user.name/user.email` and the commit environment (no global config). The dry-run path is unchanged.
3. `checkFixtureScrub` fails a fixture in which any of those keys holds a value that is not a `<…>` placeholder. The committed fixtures pass as they are: the existing `<SESSION-1>` account placeholder is a placeholder, and is left as is.

## Acceptance criteria

- **Scrub.** A scrub input carrying a raw `creator_user_id` and a UUID `creator_account_id` comes out as `<USER-ID>` and `<ACCOUNT-ID>`, and the account UUID never becomes `<SESSION-n>`. Session UUIDs elsewhere keep their `<SESSION-n>` numbering.
- **Scan.** A fixture containing a raw account id fails `checkFixtureScrub` and names the key. Every committed fixture still passes, byte-unchanged.
- **Git scratch.** A capture run (with the boundary runner stubbed) receives a `scratchDir` where `git -C <scratchDir> rev-parse --is-inside-work-tree` prints `true`.
