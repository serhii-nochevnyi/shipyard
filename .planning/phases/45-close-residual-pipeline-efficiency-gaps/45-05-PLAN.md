## Goal

R9, harness part (intake N7, N14). Two flaky concurrency tests become deterministic, and the guards they cover still fail when removed:
- "two successor processes race through acknowledgement, then the winner dispatches at the real boundary" (`tests/unit/session-handoff.test.cjs:188`);
- "file-backed reservation is atomic across concurrent Node processes" (`tests/unit/dispatch-boundary.test.cjs:1871`).

Both use `tests/unit/assert-harness.cjs`. That harness starts an async body immediately and keeps running the file's later synchronous tests on the same event loop until `done()` (`assert-harness.cjs:76-99`, `:112-125`), so these child-process races share time and CPU with unrelated work. The root cause is not reproduced yet (research confidence LOW), so a Wave 0 reproduction comes first.

## Scope

1. **Wave 0.** Loop each suite 50 times and capture the failing assertion and child stderr. Record in the RED commit whether the cause is test scheduling (A4) or production code.
2. **Tests.**
   - Both tests start their children only after every child reports `ready` over IPC, and release them with one `go` message.
   - The authority key is created once in the parent before the children start, so the race exercises only `reserve`/`ack`.
   - Both race tests move to the end of their file, after every synchronous test, so no later synchronous test competes with them.
3. **Production (only if Wave 0 shows a production race).**
   - `session-handoff.cjs`: the grace check uses the lock's own recorded creation time, not the directory mtime.
   - `dispatch-boundary.cjs`: `loadAuthorityKey` tolerates a concurrent `EEXIST` by re-reading the published key.
   - Each such change keeps its refusal semantics and gets its own unit test.
   - If Wave 0 shows no production cause, these two files stay untouched.
4. **Guard-removal checks.** For each race, a test variant replaces the guard with a non-atomic check-then-write and must observe more than one winner.
   - The replacement is test-only. The child script monkeypatches the atomic primitive (the `fs` call behind `atomicCreateBuffer` / the ownership `mkdir`) before it requires the module, so no production seam is added.
   - The variant is deterministic: every child completes its check, then waits at a second IPC barrier before it writes, so the duplicate winner does not depend on scheduling luck.

## Out of scope

- Changing `assert-harness.cjs` or any other suite.
- Widening `LOCK_GRACE_MS` or timeouts as the fix.
- The recovery query that P2 adds to `dispatch-boundary.cjs` (T-45-09 depends on this ticket).

## Acceptance criteria

- Each of the two suites passes 50 consecutive runs.
- The non-atomic variant of each race observes a duplicate winner, which proves the test still detects the defect it covers.
- Exactly one successor wins the handoff, and the loser is `HANDOFF_LOST` or `OWNERSHIP_LOCKED`. Exactly one of 8 reservers gets `{reserved: true}`.
