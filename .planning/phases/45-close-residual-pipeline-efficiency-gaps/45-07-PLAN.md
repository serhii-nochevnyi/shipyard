## Goal

P1 lease primitive (D-05, ADR-023). Today nothing prevents two sessions from launching a planner into the same phase directory at once. `claude-decompose-host.cjs:180-258` creates a fresh run per call, and `codex-decompose-host.cjs:314-400` uses the caller's `run_id`. This ticket adds a host-internal writer lease keyed by the realpath of the worktree plus the phase directory. It holds an owner (session and run), the base revision, a monotonic fencing epoch and a secret token. A stale or expired holder cannot overwrite a live owner. Wiring it into the hosts is T-45-08.

## Scope

New `plugins/delivery-pipeline/scripts/planning-writer-lease.cjs`, built only from built-ins, `lock.cjs` and `run-controller.cjs`. Exports:
- `createPlanningWriterLease({ stateRoot, worktree, phaseDir, now, ttlMs })`, which refuses a `stateRoot` inside the worktree.
- `acquire({ owner, base_revision })` → `{ token, epoch, expires_at }`. The epoch increments on every successful acquire and takeover. It refuses `WRITER_LEASED` (naming the live owner and `expires_at`) while another live owner holds the lease.
- `heartbeat({ token, epoch })`.
- `assertFence({ token, epoch, base_revision })`. It refuses `WRITER_FENCED` for a superseded epoch or wrong token, `LEASE_EXPIRED` after the TTL, and `BASE_MOVED` when the base revision differs.
- `release({ token, epoch })`.
- `recover({ owner, reason })`: an explicit, bounded crash-recovery path. It succeeds only when the prior lease has expired, or its recorded pid is not alive on this host. It bumps the epoch and records the reason.
- `snapshotTree()` / `changedSince(snapshot)`: sha256 digests of the phase-directory files. They report each path whose digest changed between acquire and seal, together with the lease record (writer evidence), so a caller can mark the affected receipts stale.

State lives in `<stateRoot>/<sha256(realpath worktree + '\n' + phaseDir)>/lease.json` (0600; directories 0700). All record updates run under `withLock`. Only one-line `@invariant:`/`@security:` comments are added.

## Out of scope

- Wiring into the decompose hosts (T-45-08) and the `decompose.md` text (T-43-11/12/15, second pass).
- Any global lease. Different worktrees or phase directories never contend.

## Acceptance criteria

- Two owners racing to acquire the same key: exactly one gets a token, and the other gets `WRITER_LEASED`.
- Different worktrees, or different phases in one worktree, never contend.
- After a takeover, the old `{token, epoch}` fails `assertFence` with `WRITER_FENCED`. An expired lease alone does not let a second writer seal while the first owner still heartbeats.
- `recover` refuses while the owner is live and unexpired, and succeeds after expiry or when the owner pid is dead. Its epoch is strictly greater.
- A file changed in the phase directory between `snapshotTree` and `changedSince` is reported with its path. Unchanged files are not reported.
- A `stateRoot` inside the worktree is refused.
- All time comes from the injected `now`. There is no wall-clock sleep in the tests.

## Threat model

|---|---|---|---|---|---|
| TH-45-14 | Tampering | a stale planning writer overwriting a live owner | high | mitigate | Epoch plus token fencing (`assertFence`), with takeover only via expiry or a dead pid. |
| TH-45-15 | Spoofing | a guessed token | medium | mitigate | 32 random bytes from `crypto.randomBytes`; the lease file is 0600 in private state. |
