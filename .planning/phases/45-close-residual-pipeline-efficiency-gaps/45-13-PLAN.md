## Goal

R6, Claude drift workflow only (intake N23). A drift-check judge sometimes returns a verdict that contradicts itself: "fresh" with moved findings. The trusted artifact validator rejects it with `INVALID_RESULT 'fresh drift verdict cannot contain moved findings'` (`plugins/delivery-pipeline/scripts/role-artifact.cjs:1118`, raised through the seal in `plugins/delivery-pipeline/scripts/claude-workflow-host.cjs:285-294`). Today `drift-gate.mjs` rethrows (`plugins/delivery-pipeline/workflows/drift-gate.mjs:256-258`), and the launch is lost. After this ticket, exactly that contradiction gets one bounded repair dispatch in the same round. The repair has a new `dispatch_id`, `previousDispatchId` set to the first dispatch, and the validation error as fenced data in the prompt. A second invalid result refuses with both errors and both dispatch ids. The validator is unchanged.

## Scope

1. **Wave 0.** Pin, in a test, the exact error shape that reaches the `.catch`: the code, the message, and whether it is wrapped as `DispatchBoundaryError` with a `cause`. The match below uses that shape.
2. `isDriftContradiction(e)` is true only when the error (or its `cause`) has code `INVALID_RESULT` and the exact message `fresh drift verdict cannot contain moved findings`. Every other error still rethrows unchanged.
3. On a match, dispatch once more with the same `role`, `model`, `effort`, `signals`, `risk` and `artifact`, with `previousDispatchId` = the first dispatch id and a fresh `dispatchId` (omitted, so the boundary assigns one). The prompt gets one appended fenced block quoting the validation error as data. There is at most one repair per ticket per run.
4. A second failure of any kind rejects with an `Error` whose message contains both error messages and both dispatch ids (code `DRIFT_REPAIR_EXHAUSTED`). The one-result-per-ticket accounting is unchanged.
5. The result of a successful repair carries `repaired_from: <first dispatch id>` and the first error text, so a host can journal it later. Adding a `log-event.cjs` type (T-43-07/08/18/19) is second pass.

## Acceptance criteria

- **One repair.** A stub judge that first returns fresh-with-moved-findings and then a valid fresh verdict produces one result for the ticket, with `repaired_from` set, and exactly two dispatches whose ids differ. The second dispatch's `previousDispatchId` is the first dispatch id.
- **Two refuse.** Two contradictory results in a row reject with `DRIFT_REPAIR_EXHAUSTED`, and the message contains both errors and both dispatch ids. There is no third dispatch.
- **Other errors.** Any other error (a throwing judge, another `INVALID_RESULT` message, a receipt failure) is not retried. The existing tests at `:361-372` and `:873` pass unchanged.
- **Routing.** The repair dispatch carries identical model, effort and signals.
