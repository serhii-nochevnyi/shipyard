## Goal

P2, Claude (D-05). This is the Claude counterpart of T-45-09. A completed Claude judgment role (researcher, planner or checker) whose host timed out or died before `record` is recovered into its original receipt, for its original `dispatch_id`, without a second launch. Recovery uses the durable reservation (`recorder.getReservation`, from T-45-09), the transcripts the host already saved under `<privateStore>/transcripts`, and the host-private launch snapshot. All of it goes through the same Claude verification functions a live launch uses. Anything missing, incomplete, altered or still live refuses, and no receipt is synthesized.

This ticket depends on T-45-09, which owns `dispatch-boundary.cjs`, the read-only `getReservation` query, and the boundary's `createDispatchBoundary({ recoverReserved: true })` mode. The current `origin/ticket/T-45-09-codex-decompose-host-recovers-a-complete` ref already has that mode in `reserveDispatchId`; T-45-09 must retain and test it as the authorized route to `record`. T-45-10 consumes it without editing the boundary or using recorder authority directly. The dependency on T-45-08 (the `claude-decompose-host.cjs` lease wiring) is transitive through T-45-09.

## Scope

1. **`claude-runtime-host.cjs`.** Export `verifyCompletedClaudeLaunch({ session_id, start_evidence_file, transcript_path, saved_native_transcript, model, effort, gsd_role, worktree })`. For typed judgment launches, write SessionStart hook evidence directly to a retained 0600 file under `<privateStore>/launches/<dispatch_id>/` rather than the launcher’s temporary directory; keep the temporary cleanup for other callers. Validate that file with `readSessionStartEvidence`, validate its original `transcript_path` against the existing project/session path rules, and save the complete native assistant JSONL (distinct from `writeTranscript`'s CLI stdout) in the same private store with byte count and SHA-256 before treating the launch as completed. Extend `readSessionEvidence` with a recovery-only saved-transcript input: keep the original path/session validation and the same `parseAssistantTranscript` model, effort and role checks, but read the authenticated private bytes when the original native file is gone. A missing, altered or incomplete saved copy refuses; CLI stdout alone is insufficient. Live launch verification remains unchanged.
2. **`claude-decompose-host.cjs` live path.**
   - Persist `launch.json` (`{dispatch_id, run_id, session_id once known, child_pid once spawned, lease_epoch, tree_snapshot, start_evidence_file, start_evidence_sha256, transcript_path, saved_native_transcript, saved_native_transcript_sha256}`, 0600) under `privateStore(scope)` before the launch. Bind every evidence path and digest to this record and its `dispatch_id`, which must match `recorder.getReservation(dispatchId)`; keep the saved files in a 0700 launch directory. Record the actual `session_id` when generated, then record the actual positive child PID via a synchronous, durable update immediately after `spawn` and before writing stdin or waiting. Expose a synchronous `onChildSpawn` seam through `createClaudeRuntimeHost` / `createClaudeCliLauncher` for that update. If PID is missing or invalid, or the update fails, terminate the spawned child and refuse before sending the prompt; never record a receipt. Persist the SessionStart digest and saved native transcript reference/digest before `record`.
   - Include `dispatch_id` and `run_id` in the thrown refusal on failure, so that recovery can name them.
   - Bind the original repository/worktree, phase, ticket, run identity, typed GSD role, request digest and resolved model/effort/policy to the private launch record and original reservation. Recovery checks these retained bindings against the original request; substituted scope, selection, request or policy refuses before any receipt.
   - Before the runtime completion callback returns, persist the authenticated final output declaration, the exact planning-artifact changed set and a SHA-256 for every completed artifact. Recovery compares current paths and bytes with both the authenticated child declaration and the completed digest checkpoint; recomputing digests from changed current files alone is not proof.
3. **`claude-decompose-host.cjs recover --dispatch <id>`** (a CLI entry beside `main`, plus an exported `recoverDecomposition`).
   - Recover the writer lease through its fenced dead-owner recovery API; an unexpired live owner refuses with `WRITER_LEASED`.
   - Require the reservation to exist and not be recorded.
   - Require a valid positive `child_pid` from the original launch record and check it is no longer live before parsing evidence. Missing or invalid PID refuses with `RECOVERY_EVIDENCE_INCOMPLETE`; a live PID or any process-probe error that cannot prove the process stopped refuses with `RECOVERY_UNKNOWN_LIVE`. Neither case calls a launcher or records a receipt. Run `verifyCompletedClaudeLaunch` on the launch-bound retained SessionStart evidence and saved native assistant transcript, matching their digests and original transcript reference; the original native transcript may be gone.
   - Take the result only from the transcript's final assistant result.
   - Require `changedSince(tree_snapshot)` to equal the paths the result declares.
   - Re-run the existing receipt compliance checks unchanged, seal via `decompositionEnvelope`, and dispatch through T-45-09's `createDispatchBoundary({ recoverReserved: true })` mode under the original `dispatch_id`. The boundary checks the durable unrecorded reservation and calls its normal authorized `record`; the Claude host neither invokes private recorder authority nor reserves the dispatch again. Assert this path succeeds with the T-45-09 boundary API and refuses on missing or recorded reservations.
   - It never calls the runtime launcher.
4. **Refusal codes are identical to T-45-09.** Unknown-live applies when the recorded Claude child pid is alive.

## Acceptance criteria

- **Recovery per role.** For each of `gsd-phase-researcher`, `gsd-planner` and `gsd-plan-checker`, a completed saved transcript recovers to one verified receipt with the original `dispatch_id`, and the injected launcher records zero calls.
- **Refusals.** Each of the following refuses with its code and records nothing: no reservation; already recorded; retained SessionStart evidence or saved native transcript missing or altered; transcript without a complete model-and-effort record (`claude-runtime-host.cjs:325`); a model or effort mismatch; tree changed outside the declared paths; missing completion-time artifact checkpoint; missing or invalid child PID; live or unknown-liveness PID; original scope/request/selection/policy mismatch; bytes changed on an originally declared artifact path. Recovery never invokes the launcher for these cases.
- **Crash boundary.** A kill after reservation and completion but before `record` recovers. A kill before completion refuses.
- **Durable evidence.** Recovery succeeds when the original Claude project transcript has been removed after the private native transcript snapshot was saved. The retained SessionStart evidence, its native transcript reference and both digests remain bound to the original reservation/launch record. A host-dead/child-live fixture refuses while the child is alive with no second launch; a completed saved-evidence fixture recovers with the original transcript gone. A failed synchronous PID write kills the child before stdin and leaves no receipt.
- **Live path.** Live-path tests pass unchanged.
- **Human checkpoint.** An operator compares one recovered receipt with a live receipt, field by field, before merge.
