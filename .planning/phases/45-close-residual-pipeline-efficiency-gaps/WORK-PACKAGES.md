# Phase 45 — Residual pipeline efficiency work packages

**Status:** queued phase scope, not an accepted ADR, executable GSD PLAN, or ticket graph. 2026-09-26.

**Goal:** fix armed Stop-gate board ownership and remove repeated model work and uncontrolled launches that remain outside phase 44, without weakening native role receipts, independent review, required instructions, tests, approval, or merge gates. Measure Claude and Codex subscription consumption independently; token totals and API prices are not quota units. The Stop-gate fix is a correctness gate, not an efficiency treatment.

**Evidence:** [static efficiency audit](../../../docs/audits/2026-09-25-pipeline-subscription-efficiency.md), [Claude session audit](../../../docs/audits/2026-09-25-claude-session-efficiency.md), [Codex planning session audit](../../../docs/audits/2026-09-25-codex-phase41-pipeline-behavior.md), [phase-43 outer-agent model-routing research](MODEL-ROUTING-RESEARCH.md), [phase-43 environment/recovery research](ENVIRONMENT-RECOVERY-RESEARCH.md), and [phase 44 scope](../44-optimize-subscription-efficiency-per-runtime/CONTEXT.md) with its [work packages](../44-optimize-subscription-efficiency-per-runtime/WORK-PACKAGES.md). Recheck these observations against the installed release before implementation; dispatch counts alone are not quota measurements. Workstream R's evidence is the [phase-40 delivery findings](../../investigations/INV-008-residual-pipeline-efficiency/intake/phase40-delivery-findings.md) (N1–N28, 2026-09-26/27).

## Boundary and sequencing

Keep phase 44's delivered subscription observation, rotation advice and effort experiment with phase 44. Exact arch-review reuse, required-rule coverage, the research fact index and checkpoint reasons are carried here as workstream C, under the ADR-021 contracts. Keep phases 40–42's planning host, delivery dispatch/preflight, handoff/wake, prompt measurement, and executor finalization recovery with theirs. This plan owns only the residual behaviors below; a shared file must have one serialized owner when formal tickets are created.

Phase 45 has five separately owned workstreams. **Carried subscription-efficiency items** (workstream C, moved from phase 44 on 2026-09-28) keep their ADR-021 contracts and wait for the phase-43 epic. **Stacked-delivery reliability** (workstream R, added 2026-09-27 from the phase-40 delivery run) builds on the phase-40 delivery seams and the ADR-020 host verification and verdict carry, and owns only what neither covers. **Stop-gate correctness** depends on phase-39 arming and phase-41 scoped-run behavior, but can be implemented and released independently after its own gates. **Planning reliability** needs the phase-40 authenticated planning host and phase-42 recovery boundary installed and verified. **Delivery efficiency** uses phase-44 outcome/quota observations before activating behavior changes. Global REQ/ticket IDs remain unassigned until the supported investigation, ADR, typed researcher/planner/checker, and graph gates accept this scope. The phase-44 queue entry is preparation, not an executable dependency receipt.

| ID | Deliverable and dependency | Acceptance and refusal cases |

| R4 | Hosts run the publish gates before they push or finalize (N9, N24, N26, N13). ## Decision gates and rollout

1. Plan and verify S1 as its own correctness ticket. Reproduce the armed A/B-session failure on the installed hook, prove both opposite board states and the stale-main/owned-phase regression, then check the installed copied bundle after the fix. A human checkpoint is required before activation. S1 can ship independently of quota baselines.
2. Baseline the installed Claude and Codex hosts with phase-44 provider-specific observations and phase-41 outcome joins. Record parent, child, failed, interrupted, and recovery work; identify account/window changes and concurrent uncontrolled usage as inconclusive.
3. Prove P1/P2 first, then P3/P4; P5 follows the C3 fact-index identity. Preserve all original receipts and run the native host contract tests plus end-to-end planning fixtures. An observed false green, lost ownership, or duplicate role launch blocks rollout.
4. Pilot D1/D2 separately on equivalent delivery work, after S1 is installed for D1. Roll out D3/D4 only with exact input and quality follow-up. Activate D5 in advisory/shadow mode before enforcement, with a tested pause/resume path. Evaluate D6 only after an approved model experiment and comparable parent-plus-child baselines; preserve native role routing throughout.
5. Evaluate one efficiency treatment at a time against verified completions, total account-window consumption when attributable, attempts, p90 work, reopens, escaped defects, and gate integrity. Missing evidence means inconclusive; a quality regression rolls back the treatment. Do not promise a numeric subscription saving from static estimates.

**Deferred, not implementation packages:** reducing four independent investigation lines to one/two workers conflicts with phase-44's explicit four-line quality contract and needs a separately accepted design with blind-spot evaluation. Automatic rotation/ownership transfer and quota-based cross-provider scheduling are also outside phase 44's authorized shadow/advisory mode; each needs capability proof and a separate policy decision. No automatic provider fallback or model downgrade is implied here.

**Formalization checkpoint:** reconcile phase 44's queued but non-executable preparation and current phase-40/42 installed state; run the supported authenticated investigation and ADR review; assign global requirements and ticket ownership through GSD; verify typed planning artifacts and validate the graph. Until then, this file is the reviewable scope and execution order, not permission to dispatch model work.
