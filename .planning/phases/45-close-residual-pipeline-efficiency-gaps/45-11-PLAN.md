## Goal

P4, first-pass part (D-05). The Codex model parent that drives decomposition currently spends model turns waiting on a long `codex-decompose-host.cjs` call. A supported blocking wait already exists: `deliver-dispatch.cjs wait --dispatch <id>` (`waitOnce` → `statusOnce` → `readRecord` / `readResult`, reading `<stateDir>/<id>/record.json`). This ticket gives the Codex decompose host a detached mode whose record and result can be read by that existing wait, and attributes the detached child's model use separately from an explicitly supplied parent wait observation. The typed native child and receipt contract stay intact. The production caller that invokes the wait and emits the parent observation is explicitly deferred by CONTEXT.md's first-pass ownership rule; this ticket alone therefore does **not** complete the parent attribution clause of REQ-193. Any efficiency effect is `inconclusive` until matched cohorts exist (ADR-023 Consequences).

This ticket depends on T-45-09: it edits `codex-decompose-host.cjs` after P2, and WORK-PACKAGES P4 requires P2. Read the integration base from `origin/ticket/T-45-09-codex-decompose-host-recovers-a-complete`; this planning checkout precedes that unmerged dependency.

## Acceptance criteria

- **Waiting.** `node plugins/delivery-pipeline/scripts/deliver-dispatch.cjs wait --dispatch <id>` returns `exited-ok` with the decomposition result for a detached host that succeeds. It returns `exited-failed` for one that refuses, and exit code 3 on a timeout, with no edit to `deliver-dispatch.cjs`.
- **Receipt.** The detached child produces the same verified receipt as a foreground `runCli` for the same stub fixture. Tests cover both explicit and caller-omitted dispatch IDs; the parent wait record, child reservation and authenticated receipt all identify the same dispatch.
- **Refusal is not ok.** A detached host refusal leaves no JSON line in `result.jsonl`, and `statusOnce` reports `exited-failed`. A mutation that prints the refusal as JSON on stdout must fail the contract test.
- **Attribution in this ticket.** An explicitly supplied observation with `actor: 'parent'` and the detached child's `actor: 'child'` observation are reported in separate sums. An invalid `actor` is refused. Rows without `actor` are unchanged. Full REQ-193 remains pending until a production parent wait emits its own row through the phase-43-owned caller linkage; this test does not prove that linkage.
- **Efficiency.** Any efficiency report is marked `inconclusive`, and no percentage is emitted.
