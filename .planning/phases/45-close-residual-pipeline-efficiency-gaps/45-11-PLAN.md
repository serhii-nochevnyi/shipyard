## Goal

P4, first-pass part (D-05). The Codex model parent that drives decomposition currently spends model turns waiting on a long `codex-decompose-host.cjs` call. A supported blocking wait already exists: `deliver-dispatch.cjs wait --dispatch <id>` (`plugins/delivery-pipeline/scripts/deliver-dispatch.cjs:404-432` `waitOnce`, `:384-402` `statusOnce`, reading `<stateDir>/<id>/record.json` via `:365-368`). After this ticket, the Codex decompose host has a detached mode. It writes a `record.json` and a result file in **exactly** that format, so the existing `wait` blocks in a host process with no model turns. Parent wait time and child model usage are then recorded as separate attribution rows. The typed native child and its receipt contract are unchanged. Any efficiency effect is reported `inconclusive` until matched cohorts exist (ADR-023 Consequences), and no saving is claimed.

This ticket depends on T-45-09: it edits `codex-decompose-host.cjs` after P2, and WORK-PACKAGES P4 requires P2.

## Scope

1. **`codex-decompose-host.cjs --detach --args-file <f>`.**
   - Validate the request exactly as `runCli` does, and resolve `dispatch_id`.
   - Create `<dispatchStateDir>/<dispatch_id>/` (0700). `dispatchStateDir` is imported from `deliver-dispatch.cjs`, which exports it at `:492`. An override is possible only through the in-process options.
   - Spawn itself detached (`--args-file`, stdout → `result.jsonl`, stderr → `log`).
   - Write `record.json` with the nine fields above (`ticket` = scope ticket or `decomposition`, `role` = the GSD role, `runtime: 'codex'`).
   - Print `{dispatch_id, wait: 'node <plugin>/scripts/deliver-dispatch.cjs wait --dispatch <id>'}` and exit 0.
   The child runs the normal `runCli`, including the writer lease and receipt verification.
2. **Attribution.** `orchestration-overhead.cjs` gains an optional `actor` field (`parent` | `child` | `host`; default `null`) in `normalizeObservation`, and the report splits sums by actor. The detached child records its model evidence with `actor: 'child'`. A `wait_poll` row with `actor: 'parent'` is recorded by whoever waits; this ticket provides the helper and the test only, not the `deliver-dispatch` call site. Requested and observed model/effort stay on the child row.
3. **Contract test** `tests/unit/decompose-dispatch-wait-contract.test.cjs`. It launches the detached host with a stub runtime, then calls the imported `waitOnce`/`statusOnce` with an injected `clock`/`sleep`. It asserts `exited-ok` with the host's result, `exited-failed` on a host refusal, and `running` while the pid is live. It fails loudly if `record.json` loses a field `statusOnce` reads.

## Acceptance criteria

- **Waiting.** `node plugins/delivery-pipeline/scripts/deliver-dispatch.cjs wait --dispatch <id>` returns `exited-ok` with the decomposition result for a detached host that succeeds. It returns `exited-failed` for one that refuses, and exit code 3 on a timeout, with no edit to `deliver-dispatch.cjs`.
- **Receipt.** The detached child produces the same verified receipt as a foreground `runCli` for the same stub fixture.
- **Attribution.** An observation with `actor: 'parent'` and one with `actor: 'child'` are reported in separate sums. An invalid `actor` is refused. Rows without `actor` are unchanged.
- **Efficiency.** Any efficiency report is marked `inconclusive`, and no percentage is emitted.
