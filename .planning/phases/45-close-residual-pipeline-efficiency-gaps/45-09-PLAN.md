## Goal

P2, Codex (D-05). Sometimes the native parent's wait times out, or the host dies, after the typed child (researcher, planner or checker) has already completed. The dispatch then has a durable reservation but no record, so today the only path is a second launch. After this ticket, `codex-decompose-host.cjs recover --dispatch <id>` rebuilds the **original** receipt for the **original** `dispatch_id`. It uses the reservation, the saved parent and child native transcripts, and the digest of the artifact the child wrote, and it runs them through the same verification functions a live launch uses. Missing, incomplete, altered, or still-live evidence refuses. No receipt is ever synthesized, and model use is counted once. The risk is high because this adds a second path to a verified receipt, so a human checkpoint reviews the refusal matrix before merge.

This ticket depends on T-45-08 (it edits `codex-decompose-host.cjs` after the lease wiring, and recovery must hold the writer lease) and on T-45-05 (it edits `dispatch-boundary.cjs` and its test after the barrier rewrite).

## Scope

1. **`dispatch-boundary.cjs`.** Add the read-only `recorder.getReservation(dispatchId)`. It returns `{dispatch_id, reserved_at, recorded: boolean}`, or `null`, and never writes.
2. **`codex-runtime-host.cjs`.** Extract the existing post-exit verification sequence (`:1090-1100`: `readNativeCodexSession` → `readNativeParentRaw` → `readNativeCodexChild`) into an exported `verifyCompletedNativeLaunch({ session_id, selection, agent, env, allowTimedOutWait })`. The live `launch` calls it with `allowTimedOutWait: false`, so its behaviour is unchanged. In recovery mode (`true`), a parent wait with `timed_out: true` is accepted only if the child transcript proves exactly one `task_complete` bound to the parent and role. Every other check stays.
3. **`codex-decompose-host.cjs recover --dispatch <id> --args-file <f>`.**
   - Acquire the writer lease (a live owner → `WRITER_LEASED`).
   - Require `getReservation` → reserved and not recorded.
   - Locate the parent session from the host's own transcript directory for that dispatch. The child's `pid`, if recorded, must not be alive (otherwise `RECOVERY_UNKNOWN_LIVE`).
   - Run `verifyCompletedNativeLaunch`.
   - Take the output only from the authenticated child transcript's single `task_complete.last_agent_message`. The captured shape `tests/fixtures/captured/codex-agent-stream-child.jsonl` carries no digest field, so none is assumed.
   - Artifact binding: at live launch the host now persists a private `launch.json` beside its receipts (`{dispatch_id, parent_session_id, lease_epoch, tree_snapshot}` from `snapshotTree`, 0600). At recovery, `changedSince(tree_snapshot)` must equal exactly the paths the recovered output declares, and each file is sealed with its sha256. Otherwise the result is `RECOVERY_ARTIFACT_ALTERED` (a missing `launch.json` gives `RECOVERY_EVIDENCE_MISSING`).
   - Seal through the same `sealResearchArtifact`/`sealPlans`, then `record` through the recorder with the original `dispatch_id`.
   - No runtime process is spawned (the `spawn` option is asserted unused).
4. **Refusals.** Refusal codes: `RECOVERY_NO_RESERVATION`, `RECOVERY_ALREADY_RECORDED`, `RECOVERY_EVIDENCE_MISSING`, `RECOVERY_EVIDENCE_INCOMPLETE`, `RECOVERY_UNKNOWN_LIVE`, `RECOVERY_ARTIFACT_ALTERED`. None of them writes a receipt.
5. **No task-text proof.** The proof never relies on the child's first user message (Codex task text arrives encrypted in `agent_message`, intake N27).

## Acceptance criteria

- **Recovery per role.** For each of `gsd-phase-researcher`, `gsd-planner` and `gsd-plan-checker`, a completed child with a timed-out parent wait recovers to exactly one verified receipt with the original `dispatch_id`. There is no spawn, and usage is attributed once.
- **Refusals.** Each of the following refuses with its code and records nothing: no reservation; already recorded; missing child transcript; child without `task_complete`; parent transcript digest changed; artifact digest changed; live child pid.
- **Crash boundary.** A host killed after `reserve` and after the child completes, but before `record`, recovers. A host killed before the child completes refuses with `RECOVERY_EVIDENCE_INCOMPLETE`.
- **Live path.** Live-path behaviour is unchanged: a timed-out wait in a live launch still refuses, and all existing suites pass.
- **Human checkpoint.** An operator reviews the refusal matrix and one recovered receipt against its live-launch counterpart (same verification function, same fields) before merge.

## Threat model

| Threat ID | STRIDE | Component | Severity | Disposition | Mitigation |
|---|---|---|---|---|---|
| TH-45-20 | Spoofing / Repudiation | a synthesized recovery receipt | critical | mitigate | Recovery goes only through `verifyCompletedNativeLaunch` and the recorder MAC. No reservation or no evidence → refusal. |
| TH-45-21 | Tampering | an altered artifact adopted under an original receipt | high | mitigate | The launch-time tree snapshot must match the changed paths the output declares, and every file is sealed with its sha256. Plus the parent transcript digest re-check (`readNativeParentRaw`). |
| TH-45-22 | Elevation | a double receipt / double count | high | mitigate | `RECOVERY_ALREADY_RECORDED`, `DUPLICATE_DISPATCH_ID`, and the writer lease held during recovery. |
| TH-45-23 | Tampering | recovery racing a still-running child | medium | mitigate | `RECOVERY_UNKNOWN_LIVE` when the recorded pid is alive. |
