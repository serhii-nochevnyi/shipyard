## Goal

P2, Codex (D-05). Sometimes the native parent's wait times out, or the host dies, after the typed child (researcher, planner or checker) has already completed. The dispatch then has a durable reservation but no record, so today the only path is a second launch. After this ticket, `codex-decompose-host.cjs recover --dispatch <id>` rebuilds the **original** receipt for the **original** `dispatch_id`. It uses the reservation, the saved parent and child native transcripts, and the digest of the artifact the child wrote, and it runs them through the same verification functions a live launch uses. Missing, incomplete, altered, or still-live evidence refuses. No receipt is ever synthesized, and model use is counted once. The risk is high because this adds a second path to a verified receipt, so a human checkpoint reviews the refusal matrix before merge.

This ticket depends on T-45-08 (it edits `codex-decompose-host.cjs` after the lease wiring, and recovery must hold the writer lease) and on T-45-05 (it edits `dispatch-boundary.cjs` and its test after the barrier rewrite).

## Scope

1. **`dispatch-boundary.cjs`.** Add the read-only `recorder.getReservation(dispatchId)`. It returns `{dispatch_id, reserved_at, recorded: boolean}`, or `null`, and never writes. Expose reserved recovery only through `createDispatchBoundary({ recoverReserved: true, ... })`: its `reserveDispatchId` branch must require this durable, unrecorded original reservation, refuse a duplicate, and then pass the normal verified result through boundary `record`. This is the authorized seam T-45-10 consumes; neither host calls private recorder authority or creates a new reservation. On the current `origin/ticket/T-45-09-codex-decompose-host-recovers-a-complete` ref, `getReservation` and this `recoverReserved` branch already exist; preserve and test that behavior rather than adding a second operation.
2. **`codex-runtime-host.cjs`.** Extract the existing post-exit verification sequence (`:1090-1100`: `readNativeCodexSession` → `readNativeParentRaw` → `readNativeCodexChild`) into an exported `verifyCompletedNativeLaunch({ session_id, selection, agent, env, allowTimedOutWait })`. Both live launch and recovery preserve the established completed-child contract: a parent wait with `timed_out: true` is accepted only if the authenticated child transcript proves exactly one `task_complete` bound to the original parent and typed role. A parent wait timeout alone is never completion evidence. Incomplete, duplicate, altered or substituted child evidence refuses in both paths; every other check stays.
3. **`codex-decompose-host.cjs recover --dispatch <id> --args-file <f>`.**
   - Acquire the writer lease (a live owner → `WRITER_LEASED`).
   - Require `getReservation` → reserved and not recorded.
   - Locate the parent session from the host's own transcript directory for that dispatch. Persist a valid positive original native process ID synchronously in the launch-bound session-start record before the child can run or wait. Recovery requires that ID and reliable stopped-process evidence before parsing completion; missing, invalid, inaccessible or otherwise unknown liveness refuses, and a live process refuses with `RECOVERY_UNKNOWN_LIVE`. A dead host alone is not proof that its native child stopped.
   - Run `verifyCompletedNativeLaunch`.
   - Take the output only from the authenticated child transcript's single `task_complete.last_agent_message`. The captured shape `tests/fixtures/captured/codex-agent-stream-child.jsonl` carries no digest field, so none is assumed.
   - Artifact binding: at live launch the host persists a private `launch.json` beside its receipts with original reservation identity, parent session/process ID, lease epoch and `tree_snapshot` from `snapshotTree` (0600). The runtime completion callback must durably write the authenticated final output declaration, exact changed-path set and SHA-256 of every completed artifact **before** returning to the receipt path. At recovery, require that original completion checkpoint, compare `changedSince(tree_snapshot)` to the authenticated declaration and compare each current byte digest to its completion-time digest before sealing. Missing completion checkpoint or digest refuses; never reconstruct the missing checkpoint from current files after a crash. Changed paths with altered bytes refuse `RECOVERY_ARTIFACT_ALTERED` (a missing launch record gives `RECOVERY_EVIDENCE_MISSING`).
   - Seal through the same `sealResearchArtifact`/`sealPlans`, then `record` through the recorder with the original `dispatch_id`.
   - No runtime process is spawned (the `spawn` option is asserted unused).
4. **Refusals.** Refusal codes: `RECOVERY_NO_RESERVATION`, `RECOVERY_ALREADY_RECORDED`, `RECOVERY_EVIDENCE_MISSING`, `RECOVERY_EVIDENCE_INCOMPLETE`, `RECOVERY_UNKNOWN_LIVE`, `RECOVERY_ARTIFACT_ALTERED`. None of them writes a receipt.
5. **No task-text proof.** The proof never relies on the child's first user message (Codex task text arrives encrypted in `agent_message`, intake N27).

## Acceptance criteria

- **Recovery per role.** For each of `gsd-phase-researcher`, `gsd-planner` and `gsd-plan-checker`, a completed child with a timed-out parent wait recovers to exactly one verified receipt with the original `dispatch_id`. There is no spawn, and usage is attributed once.
- **Refusals.** Each of the following refuses with its code and records nothing: no reservation; already recorded; missing child transcript; child without `task_complete`; parent transcript digest changed; completion-time artifact checkpoint missing; artifact bytes changed on the same declared path; missing or invalid original process ID; child still live or liveness unknown.
- **Crash boundary.** A host killed after `reserve`, authenticated child completion and the durable completion-time artifact checkpoint, but before `record`, recovers. A host killed before the completion checkpoint refuses with `RECOVERY_EVIDENCE_INCOMPLETE`, even if current paths appear to match a final message.
- **Live path.** Live-path behaviour is unchanged: a timed-out parent wait is accepted only with exactly one authenticated completed child bound to the original parent and typed role; incomplete or duplicate child completion refuses. All existing suites pass under their documented test environment.
- **Human checkpoint.** An operator reviews the refusal matrix and one recovered receipt against its live-launch counterpart (same verification function, same fields) before merge.
