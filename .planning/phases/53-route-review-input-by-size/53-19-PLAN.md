<objective>Let the producer side of the trust boundary seal and validate the new artifacts, so the hosts of the following tickets can produce unit and hybrid judgments that the archive accepts and the PR-level consumers ignore.</objective>

## Goal

ADR-033 R-5 (D-05) and R-4: "one dispatch = one launch = one receipt = one sealed judgment" (research `constraints.md` TC-4); each unit and reducer dispatch is an ordinary receipt-verified dispatch whose judgment must be sealable. The hosts seal through `roleArtifact.sealJudgment` and `validateJudgmentManifest` (`claude-role-host.cjs:1418-1430`). Consumption of hybrid verdicts is T-53-27; this ticket only makes sealing and manifest validation accept the new contract strings and subject family and records what the consumer will need.

## Scope

When a judgment's subject parses as `review-part` (role `arch-review` or `integrator`), seal and validate it as an ordinary judgment of that role without requiring a ticket-row, PR or phase-binding lookup the unit does not have; its manifest records `subject_kind: "review-part"`.

Evidence path. `judgmentEvidenceName(role, phase)` and `judgmentEvidencePath` (`role-artifact.cjs:4712-4738`) fix the integrator's evidence to `.planning/phases/<phase>/INTEGRATION.md`, and `validateJudgmentManifest` compares `manifest.source_evidence_path` with that name (`:5567-5574`), so a unit's judgment sealed from the scratch file would be refused. `prepareRoleArtifact`, `sealJudgment` and `validateJudgmentManifest` therefore accept an explicit `evidenceKind: "part"` input, which selects `INTEGRATION_PART_EVIDENCE_NAME` (T-53-18) for the role `integrator` and is refused for any other role; the sealer derives the kind from the trusted record's ticket (a review-part ticket requires `part`, any other integrator ticket requires the phase file) and refuses a mismatch with `ARTIFACT_IDENTITY_MISMATCH`, so the name and the subject must agree. The archive name inside `.shipyard-role-artifacts/<dispatch>/` stays `INTEGRATION.md` for both. The architecture review's evidence is already the scratch `.shipyard-arch-review-evidence.md` and is unchanged. When a result carries `review_contract` equal to either hybrid string, validate it with `isSupportedIntegrationContract` or `isSupportedArchContract`, require `review_route`, `route_record_digest`, `review_completeness`, `limitations` and `unresolved_sources`, and write `{ contract, route, route_record_digest, review_completeness, manifest_digest?, plan_digest?, ledger_digest? }` into `current_review` of the sealed manifest (aggregate and pull as appropriate); a result with an unsupported contract string, or a partitioned aggregate without `ledger_digest`, refuses with `REVIEW_CONTRACT_INVALID`. Results without a hybrid contract string follow today's paths unchanged. The selectors that choose current candidates (`:3745-3752`, `:3843-3847`) are left as they are and covered by a test that a sealed review-part record is not selected.

Contract sites owned here (the `CONTRACT_SITES` table of T-53-17): `role-artifact.cjs:5629`, where `validateJudgmentManifest` runs the Codex sealed-context check when `result.review_contract` equals the legacy focused string, adopts the family predicate so a hybrid architecture result takes the same check; and the `current_review` record written at seal and compared at validate (`:5624-5627`). Every consumer-side site (`:3165`, `:3224`, `:3252`, `:3278`, `:3282-3283`, `:3314`, `:3443`, `:3545-3549`, `:3564`, `:3585-3586`, `:3878` and the integrator sites `:3331`, `:3333`, `:3467`, `:3798`) belongs to T-53-27.

## Out of scope

## Acceptance criteria

- A judgment sealed under a review-part subject for each role validates and archives; its manifest has `subject_kind: "review-part"` and carries the unit's contract and route fields.
- `currentArchitectureVerdict` and `currentIntegrationVerdict` return null (do not select) when the only sealed record of the head is a review-part judgment with a passing verdict.
- A hybrid aggregate judgment seals with `current_review` carrying contract, route and digests; a hybrid result with a v4 string, with a partitioned route and no ledger digest, or without `route_record_digest` refuses with `REVIEW_CONTRACT_INVALID`.
- An integrator judgment under a review-part subject prepares, seals and validates with `evidenceKind: "part"` from `.shipyard-integration-part-evidence.md`; the same judgment with the phase file, a phase integrator judgment with the part file, `evidenceKind: "part"` for another role, and a manifest whose `source_evidence_path` disagrees with its subject each refuse; two consecutive part judgments sealed in one worktree leave `statusIgnoringScratch(worktree, { untracked: 'all', forJudge: false })` empty, the call every hybrid request makes (the aggregate flag of T-53-20): each seal leaves the archive directory `.shipyard-role-artifacts/<digest>/` in the worktree, which that option ignores, and the same call with the default `forJudge` lists the archive directory as the only dirty path, so the case documents why the option is required.
- All existing seal and validate cases in `tests/unit/role-artifact.test.cjs` pass unchanged.
