<objective>Measure the one R-10 obligation that is pure computation: how large the partitions of the real phase 50 review diff are, so the partitioned route is sized from data.</objective>

## Goal

ADR-033 R-10 "seam-aware partition sizes for the phase 50 diff" (research spike S5, `alternatives.md` §8). Research estimated about two to four units for a byte-budget partition and 29 units of about 23 KB for per-ticket units (`alternatives.md` Option C); those are derived estimates, not measurements. After T-53-01 the review diff excludes the mirror, so the sizes must be taken from the review change set.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/review-diff-scope.cjs` from T-53-01 (rows, per-file diff via `reviewDiff` with `contextLines`).
- `plugins/delivery-pipeline/scripts/path-owner.cjs` (the one ownership matcher: `parse` and the match function used by Gate 2) and `.planning/graph/tickets.json` rows (`files`, `phase`, `epic`).
- `.planning/investigations/INV-019-review-diff-size-independence/research/alternatives.md` §1.5 (the measured phase 50 sizes: 2,043,597 B today, 1,400,771 B without the mirror, 815,389 B at `--unified=10`, 679,800 B at `--unified=3`; epic head `f80dfea7`, merge-base `be7ab4f3`) and §2 Option C unit definitions.
- `plugins/delivery-pipeline/references/review-routing-measurements.json` and the validator from T-53-07.

## Scope

Add the subcommand `partition-sizes --base <rev> --head <rev> [--graph <dir>] [--role integrator|arch-review] [--context-lines N] [--budget-tokens N] [--record] [--json]`. It builds the review change set, takes each included row's diff size at the given context, and reports: totals (files, additions, deletions, diff bytes, estimated tokens as ceil(bytes/4)); per-ticket ownership groups using path-owner.cjs over the graph rows of the head's phase (unowned rows in an `unowned` group) with per-group bytes; per top-level and second-level directory bytes; the byte-budget packing count (next-fit in path order over directory groups against the budget minus a stated overhead, with oversize files counted as split); and cross-owner static import edges between changed files (relative `require` or `import` literals resolved with the impact builder's extension and index rules against the changed paths). It states in its output that the packing is an estimate with the rule used. With `--record` it writes the observed values into the `partition-sizes-phase50` item with the command line, ISO time and git HEAD, only when both revisions resolve; otherwise it exits 2 and the item becomes a `limitation` stating the revisions were unavailable. The item is left without a sign-off: an executor never signs, a later operator `signoff` binds to the recorded content, and rerunning `--record` changes the content and so makes any earlier entry stale (T-53-07); until the operator signs it, the knobs that name `partition-sizes-phase50` stay locked at their conservative defaults.

## Out of scope

The production partitioner and seam inventory (T-53-14, which later replaces this tool's local import scan with the shared one); any model call; thresholds.

## Acceptance criteria

- On a synthetic repository with three tickets, mirror and planning changes and a cross-ticket import, the sums of ownership groups, of directory groups and the total agree, excluded rows appear nowhere, the unowned group collects unowned paths, and the cross-owner edge is counted once.
- The byte-budget packing count is at least `ceil(total_tokens / capacity)` and never below the largest single group when that group fits.
- Run against the phase 50 epic (`be7ab4f3`...`f80dfea7`) at the integrator role with `--context-lines 10` the observed total diff bytes are within 1% of the 815,389 bytes research measured for the product pathspec without the mirror at that context (`alternatives.md` §1.5), the difference being per-file rename handling, or the item is a limitation naming the missing revision.
- The record validates after `--record`.
- Usage: `partition-sizes` is registered through the table of T-53-07, so `review-measure.cjs --help` lists it with each of `--base`, `--head`, `--graph`, `--role`, `--context-lines`, `--budget-tokens`, `--record` and `--json`, and the usage case of T-53-07 still passes.
