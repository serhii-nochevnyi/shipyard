## Scope

`parseCli` accepts `--graph-dir <path>` once with the same value checks as `--args-file` (non-empty, not starting with `--`), refuses it together with `--capability-only`, and `runClaudeRoleCli` merges it into `hostOptions.graphDir` (an explicit option still wins). The value must be absolute, resolve to a real directory (no symlink), be named `graph` under a `.planning` directory, and belong to a checkout of the same repository as the reviewed worktree (same git common directory), the rule the verdict consumers already apply; a violation refuses with a named `INVALID_INPUT`. `canonicalWorktree` and `assertEvidenceOnlyChanges` are unchanged.

## Out of scope

Any change to the request schema (`graph_dir` stays a non-request field), `deliver-dispatch.cjs`, the Codex hosts, and the partitioned route. The other source of dirt between consecutive role launches, the integrator's `INTEGRATION.md` evidence file, is handled by the scratch evidence name of T-53-18, T-53-19 and T-53-22; the flag here removes only the tracked graph-file dirt, and both are needed for a partitioned run.

## Acceptance criteria

- `--graph-dir` outside the reviewed worktree (another checkout of the same repository) lets two consecutive launches run with `git status --porcelain` empty between them.
- Without the flag on a repository that tracks its graph files, the first launch leaves them modified and the second launch refuses with the dirty-tree message (documented behaviour, asserted).
- A relative path, a symlink, a directory not named `.planning/graph`, a directory of a different repository, a repeated flag and the flag with `--capability-only` each refuse with a named code.
