## Scope

New `review-partition.cjs` exporting `planPartition`, `seamInventory`, `planDigest`, `verifyCoverage` and `unitEmbeddedDigest`. `planPartition({ rows, budgetTokens, overheadTokens, identity, contextLines })`: `identity` is the opaque object the coordinator builds, `{ repository, subject, role, runtime, head, base }` (the runtime and role are part of it so that a plan, and the ledger run derived from it, belongs to one runtime and one role, T-53-15), and `contextLines` is the context the row sizes were measured at; both are recorded in the plan so a host-side recompute from git runs the same recipe. Capacity = budget minus overhead (refuse with `REVIEW_UNIT_BUDGET_TOO_SMALL`, naming both numbers, when capacity is below 2000 tokens). Each row becomes one or more segments: a row whose diff tokens fit the capacity is one segment; a larger row is split at hunk boundaries (`@@` lines) into the fewest ordered parts that each fit, and a single hunk larger than the capacity is split at line boundaries; segments carry `{ path, part, parts, byte_start, byte_end, sha256 }` and the parts of one path concatenate to the manifest's `diff_sha256`. Segments are grouped by directory (first two path segments, then deeper segments for a group above capacity) and packed next-fit in path order, so rows of one directory stay together whenever they fit. Units are `{ id, index, count, paths, segments, diff_bytes, estimated_tokens, directories }` with ids `u01`, `u02`, …; the plan is `{ schema: "shipyard.review-partition.v1", identity, context_lines, budget_tokens, overhead_tokens, capacity_tokens, units, rows_digest, digest }`. `seamInventory({ plan, readBlob })` scans the new-side blob of each changed JS or TS path for relative `require` and `import` literals, resolves them against the changed paths with the impact builder's rules, and returns edges `{ from_unit, to_unit, from_path, to_path, specifier }` for pairs in different units (deduplicated, sorted, bounded at 5000 with an explicit `truncated` count and per-unit-pair counts) plus per-unit `uncertain` counts for dynamic dependency forms. `verifyCoverage({ plan, rows, readSegment })` proves every measured row is covered exactly once and that segment digests reproduce each file's `diff_sha256`. `rows` and `readSegment` are mandatory and the function has no mode that skips them: a call whose `rows` is not an array or whose `readSegment` is not a function refuses with `REVIEW_PARTITION_COVERAGE_INPUT` before looking at the plan. The rows are the review rows as git reports them for the plan's identity, supplied by the caller from `gitCoverageSource` of T-53-15 and never taken from the plan; the function compares them with the plan, and returns a frozen `{ ok, problems, coverage_digest }` whose problems carry the codes `row-uncovered` (a row of `rows` in no unit), `row-duplicated` (in two units), `extra-row` (a unit row not in `rows`), `segment-gap` (the parts of a split file do not tile its diff), `segment-digest-mismatch` (bytes from `readSegment` differ from the plan's segment sha256 or the parts do not concatenate to the file's `diff_sha256`) and `rows-digest-mismatch` (the plan's `rows_digest` differs from the digest of the supplied rows), each naming the path; `coverage_digest` is the sha256 of the canonical `{ rows_digest, plan_digest, segment digests }`.

`unitEmbeddedDigest(unit, readSegment)` (fourth round) returns the sha256, as 64 lowercase hex, of the bytes of the unit's segments in plan order, each obtained from `readSegment(segment)` and concatenated with no separator. This is the definition of "the unit packet embeds its planned bytes": a host builds a unit packet's diff content as exactly that concatenation (T-53-22, T-53-24; the Codex integrator through the shared preparation, T-53-26), and every later check compares the digest of the diff content of the authenticated, sealed packet with this function's result over bytes `readSegment` took from git (T-53-15 `verifyLedger`, T-53-27, T-53-29), so planned bytes, embedded bytes and verified bytes are one definition. It refuses a unit with no segments or a `readSegment` result that is not a Buffer or string with `REVIEW_PARTITION_COVERAGE_INPUT`.

`review-measure.cjs` partition-sizes now calls `seamInventory` instead of its local scan and keeps its output shape.

## Acceptance criteria

- For random row sets (seeded) every unit's tokens are at most the capacity, units are disjoint, the union of segments covers every row exactly once, and the plan is identical on a second run.
- Two rows in one directory that fit together always share a unit; a plan over a phase-50-shaped fixture (about 80 files and 800 KB at the default capacity) has a unit count between `ceil(total/capacity)` and `ceil(total/capacity) + number of top-level directories`.
- A single 700 KB file diff at capacity 80 KB is split into ordered parts each at most the capacity whose concatenation digest equals the file's `diff_sha256`; a single hunk larger than the capacity splits at line boundaries.
- A test file importing a source file in another unit yields a seam edge; an import within one unit yields none; a dynamic `require(variable)` increments `uncertain` for its unit.
- `planPartition` with capacity below 2000 tokens refuses naming the budget and overhead.
- `verifyCoverage` is mandatory-input: a call without `rows`, with a non-array `rows` and without `readSegment` each refuse with `REVIEW_PARTITION_COVERAGE_INPUT`. Against a row set of 12 rows, a plan built from the same rows minus one is refused `row-uncovered` naming the omitted path (the omitted-row case that T-53-15, T-53-22, T-53-24, T-53-26, T-53-27, T-53-29 and T-53-30 each repeat at their own caller), a plan with one row placed in two units is refused `row-duplicated`, a plan with an extra unit row is refused `extra-row`, a `readSegment` that returns one altered byte for one segment is refused `segment-digest-mismatch`, a plan whose rows came from another head is refused `rows-digest-mismatch`; the unaltered plan returns `ok: true` and a 64-hex `coverage_digest` that is stable across two calls.
- The measurement tool's partition-sizes output keeps its shape and its cross-owner edge count equals the seam inventory's count for the same fixture.
- `unitEmbeddedDigest` of a unit equals an independently computed sha256 of the concatenated segment bytes, is stable across two calls, changes when one byte of one segment changes or when two segments are swapped, differs between two units of one plan, and refuses an empty unit and a non-bytes `readSegment` result with `REVIEW_PARTITION_COVERAGE_INPUT`; for a unit that holds exactly one part of a split oversize file it equals the segment's recorded sha256.
