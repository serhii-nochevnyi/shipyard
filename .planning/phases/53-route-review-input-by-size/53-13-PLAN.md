## Scope

New `review-manifest.cjs` exporting `measureRows({ root, base, head, mergeBase, rows, contextLines, exec })`, `buildManifest({ root, base, head, mergeBase, rows, contextLines, exec, limits })`, `manifestDigest`, `coverageInventory(manifest)` and `validateCoverage(...)`. `measureRows` runs each included row's recipe once and returns `{ rows: [{ path, old_path, status, old_blob, new_blob, additions, deletions, diff_bytes, diff_sha256 }], totals }` without the pull-route bounds, so the host can size an epic of any diff size before choosing a route (bounded only at 20000 rows and 64 MiB per file diff, refusing with `REVIEW_SCOPE_OVER_BOUND`); the partition planner and the work estimate use it. `buildManifest` calls `measureRows` and then applies the pull-route bounds. `buildManifest` returns `{ ok: true, manifest }` or `{ ok: false, blocker, detail }`. The manifest is `{ schema: "shipyard.review-manifest.v1", base, merge_base, head, head_tree, context_lines, rows: [{ path, old_path, status, old_blob, new_blob, size_bytes, additions, deletions, diff_bytes, diff_sha256, recipe }], totals: { files, additions, deletions, diff_bytes }, digest }` sorted by path. `diff_sha256` is the sha256 of the exact stdout bytes of the recipe and `recipe` is the argv array `git diff --no-ext-diff --no-textconv --unified=N <merge_base>...<head> -- :(literal)<path>` with both paths of a rename or copy row; `size_bytes` is the new blob size (zero for a deletion). A row whose diff exceeds 2 MiB yields blocker `oversize-file`; a serialized manifest above the manifest limit yields `manifest-over-bound`. `validateCoverage({ manifest, declared, review_completeness, limitations, unresolved_sources })` returns `{ ok, problems }` where problems name missing paths, extra paths, hash mismatches, duplicates and the completeness rule; `declared` is a list of `{ path, diff_sha256 }`.

## Out of scope

Prompting, packet shape, host wiring and result schemas (T-53-17, T-53-21, T-53-23, T-53-25); proving the reviewer read anything.

## Acceptance criteria

- On a throwaway repository with add, modify, delete, rename, binary and mode-change rows, every row's `diff_sha256` equals the sha256 of running its recipe, rename rows carry both paths in the recipe, deletions have `size_bytes` 0, and the manifest digest is stable across two builds.
- `measureRows` returns sizes and digests for a row whose diff exceeds 2 MiB (no blocker) and refuses with `REVIEW_SCOPE_OVER_BOUND` only past 20000 rows or 64 MiB for one file diff.
- A row with a diff above 2 MiB gives `{ ok: false, blocker: "oversize-file" }` from `buildManifest`; enough rows to exceed 512 KiB give `manifest-over-bound`; both blockers are the codes `review-route.nextRoute` accepts.
- `validateCoverage` accepts an exact inventory and refuses a missing path, an extra path, a wrong hash, a duplicate and a `complete` review with any limitation or unresolved source; an `incomplete` review with a full inventory is accepted as incomplete and never reported ok-as-complete.
