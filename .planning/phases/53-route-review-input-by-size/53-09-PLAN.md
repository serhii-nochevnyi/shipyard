## Scope

New `review-measure-claude.cjs`, registered as subcommands of `review-measure.cjs`:
- `synth-prompt --tokens N [--seed S] --out <file>` writes deterministic unified-diff-like text whose JSON-escaped packet form has `ceil(bytes/4)` equal to N within one token, and prints its byte count and sha256.
- `probe-claude-window --model <id> --effort <e> --tokens <N,...> --out <dir> [--live]`: default is a dry run that prints the planned launches; with `--live` and `SHIPYARD_REVIEW_MEASURE_LIVE=1` it launches each size through `createClaudeRuntimeHost` with the host's own options in a scratch git repository outside the checkout, one child per size with an injectable spawn for tests, saves each stream and session transcript into `<dir>` and writes a summary of largest accepted and smallest refused estimated sizes and the observed usage per run.
- `probe-claude-reach --model <id> --effort <e> --out <dir> [--live]`: same opt-in; launches one child in a linked worktree with a fixed prompt that asks it to run `git diff` in the worktree, to `Read` a file under a host-private directory outside the worktree and to run `git diff` against a manifest-listed path, saving the stream and transcript.
- `ingest-claude-usage --stream <file> --prompt-bytes N`: reports observed input tokens from the stream usage fields against `ceil(promptBytes/4)`, the ratio, and the stream's terminal reason.
- `ingest-claude-transcript --transcript <file>`: counts `tool_use` and `tool_result` pairs, flags results whose recorded length is shorter than the declared output or that carry a truncation marker, detects compaction by the record kinds Claude Code uses for a compact boundary or summary, and lists every unrecognized record kind in `unrecognized_record_types`.
- `ingest-claude-reach --stream <file> --probe outside-read|git-diff`: reports whether the matching `tool_use` has a non-error `tool_result` (`reachable` true, false or unknown) with a bounded excerpt.
Each ingest accepts `--record` to write the observed values into the matching item with the command line, ISO time and git HEAD; `--item <id>` names the item when more than one fits. The record keys pinned by T-53-07 are written exactly: `ingest-claude-usage --record --item estimator-undercount` writes `observed.ratio` (observed input tokens divided by `ceil(promptBytes/4)`), and with `--item window.claude-sonnet-5-5` or `--item window.claude-opus-5-5` it writes `observed.usable_input_tokens` equal to `ceil(promptBytes/4)` only when the stream's terminal reason is not a refusal and no compaction was seen, otherwise it records the refusal under `observed.refused_at_estimated_tokens` and leaves the item unmeasured (`validate` would refuse a measured window item without the usable key). All subcommands are registered through the table of T-53-07, so each appears in `review-measure.cjs --help`. The seven Claude items listed in the first must-have change from tooling-pending to `owed` with these exact commands (and stay without a sign-off), and the markdown Runbook gains the Claude steps (what to run, which evidence file to pass to which ingest).

## Acceptance criteria

- `synth-prompt` is deterministic for a seed, hits the requested estimate within one token and its output has no secrets or host paths.
- Without both opt-ins `probe-claude-window` and `probe-claude-reach` print a plan, exit 0 and never call spawn; with both opt-ins and a fake spawn emitting fixture stream lines they save evidence and a summary.
- `ingest-claude-usage` on the captured executor stream yields observed token fields and a ratio; a stream ending in `terminal_reason: prompt_too_long` is reported as refused.
- `ingest-claude-transcript` reports counts for a hand-built transcript with a truncated result and a compact-boundary record, and lists an unknown record kind.
- `ingest-claude-reach` distinguishes a successful, an errored and an absent result for both probes.
- Record keys and usage: on a scratch record, `ingest-claude-usage --record --item estimator-undercount` on the captured executor stream writes a positive `observed.ratio`, `--item window.claude-sonnet-5-5` on a completed stream writes `observed.usable_input_tokens` and a stream ending in `prompt_too_long` writes only `refused_at_estimated_tokens`; the resulting records pass the T-53-07 validator when the item is measured; every subcommand of this ticket appears in `review-measure.cjs --help`.
- After this ticket the seven Claude items (`window.claude-sonnet-5-5`, `window.claude-opus-5-5`, `estimator-undercount`, `claude-compaction`, `claude-tool-result-bodies`, `claude-outside-worktree-read`, `claude-linked-worktree-git-diff`) are `owed` with non-empty commands and `validate` passes; `validate --final` still lists the four Codex-owned items (`window.gpt-6.1-sol`, `codex-batch-reader-2.6mb`, `phase50-integrator-model-effort`, `codex-integrator-sandbox`) as tooling-pending, so `--final` names exactly those four.

## Test strategy

New `tests/unit/review-measure-claude.test.cjs`, beginning with the guard of T-53-01 before it requires a plugin script, driven by the captured fixtures and small hand-written streams; fake spawn for the probes. The probe cases pass an explicit scratch `HOME`, `CLAUDE_CONFIG_DIR` and output directory, create their scratch git repository and linked worktree under `os.tmpdir()`, and run through the isolated environment of T-53-01. The live gate does not rest on that runner alone, because the guard of T-53-01 deliberately accepts `SHIPYARD_REVIEW_MEASURE_LIVE` (`tests/unit/run.sh` does not unset it): the probe entry points read the variable only from an `env` option (default `process.env`), and every probe case passes an explicit environment that lacks it, or sets it on purpose for the opt-in cases, so an exported variable in the operator's shell, whether the file runs through the runner, `make test-fast` or `node --test`, cannot start a live launch; a case sets the variable in `process.env` and calls a probe with an explicit `env` lacking it and asserts spawn is never called. No run needs a Claude account. Name cases with the prefix `review-routing:`.
