<objective>Prove the phase goal end to end at the level the repository can without live models: one test that drives a phase-50-shaped epic through the coordinator and asserts the properties ADR-033 promises across all three routes and the rollback.</objective>

## Goal

ADR-033 Decision and Consequences: a review runs for any epic size; coverage is proven mechanically on the inline and partitioned routes and by declaration on the pull route; rollback is that each route is additive and selectable, that selecting a legacy contract or raising a threshold restores the previous behaviour (the contract selection unconditionally, a raised threshold only through the signed-record gate that R-9 implies), and that no sealed artifact becomes invalid. The phase 50 shape: 2.04 MB combined diff, 33% changed lines, 31% generated mirror, 1.3 MB planning noise, 29 tickets, 107 files (research `alternatives.md` §1.5). Each prior ticket proves its own part; this ticket proves the properties across them.

(10) The mutation table below.

Mutation table (the automated failing-first evidence). The test file resolves every plugin module through one function that honours `SHIPYARD_ACCEPTANCE_PLUGIN` (a path to a plugin directory, default the repository's `plugins/delivery-pipeline`) and runs only the scenario named by `SHIPYARD_ACCEPTANCE_ONLY` when it is set. One test, `review-routing: each pinned property fails when broken`, copies the plugin directory to a scratch directory under `os.tmpdir()` once per row, applies the row's literal replacement to the copy, runs `node --test` on this same file in a child process with `SHIPYARD_ACCEPTANCE_PLUGIN` pointing at the copy, `SHIPYARD_ACCEPTANCE_ONLY` naming the row's scenario and `SHIPYARD_ACCEPTANCE_MUTATING=1` (which disables this test inside the child, so it cannot recurse), and asserts the child exits non-zero and names that scenario. A row is `{ property, file, anchor, replacement, scenario }` and the anchor is a literal string that must occur exactly once in that file of the copy, otherwise the test fails loudly with the row and file (a drifted anchor is a defect of this table, never a silent pass). The eight rows break: the mirror exclusion (the classification predicate of `review-diff-scope.cjs`), the unit budget (the capacity check of `review-partition.cjs`), the once-coverage invariant (the exactly-once check of `verifyCoverage`), the ceiling (the ceiling function of `review-ledger.cjs`), the work-size signal (the signal selection in `review-route.cjs` or the host call site the coordinator tests exercise), the default-thresholds pin (a default in `pipeline-config.cjs`), the signed-record lock (the sign-off check of `knobGate` in `review-measure.cjs`) and the mandatory coverage proof (the coverage requirement or the `verifyCoverage` call inside `verifyLedger`). The executor chooses each anchor by reading the merged modules and records it in the table; nothing in the repository is modified, the scratch copies are deleted, and this is the only test of the phase that spawns a child test process.

## Out of scope

Live model behaviour; host-internal cases already proven in T-53-20…T-53-27; package regeneration and CI parity.

## Acceptance criteria

- Scenarios (1) to (9) pass deterministically in a bare worktree in under 60 seconds without network, a live model or the host evidence directory; scenario (10), the mutation table, runs one scenario per child process and is expected to take a few minutes in total (stated here so a slow run is not mistaken for a hang).
- The test fails when any one of the following eight properties is broken, and that is checked by the suite on every run through the mutation table (one child test process per row against a scratch copy of the plugin directory, each row's anchor required to occur exactly once, each child required to fail on the named scenario), not by a one-off recorded in a comment: the mirror exclusion, the unit budget, the once-coverage invariant, the ceiling, the work-size signal, the default-thresholds pin, the signed-record lock (a raise honoured without a measured, current sign-off) and the mandatory coverage proof (a verifyLedger that no longer runs the set-cover over git rows).
- A partitioned run of the phase-50-shaped fixture completes all its launches in one worktree with the fake hosts leaving their sealed archive directories (scenario 1), which shows the coordinator's clean-worktree check accepts the archive directory a real seal leaves while still refusing a modified tracked graph file or a leftover phase evidence file.
- Scenario 8 (omitted row and swapped unit artifact) and scenario 9 (ticket-level refusal and runtime binding) pass as described in Scope, and a scratch run of the acceptance file against a plugin copy in which the coverage requirement has been removed fails scenario 8.
- The test and its commands pass whatever the state of the shipped record's items and sign-offs, in a bare worktree with no account, no network and no operator action; the test calls no probe and spawns none, and the isolated runner also removes `SHIPYARD_REVIEW_MEASURE_LIVE` (the guard accepts it, as `tests/unit/run.sh` does not unset it), so it cannot start a live probe either way.

## Test strategy

One test file, beginning with the guard of T-53-01 and the `os.homedir` override header before it requires a plugin script; names prefixed `review-routing:`; fixtures built once per file under `os.tmpdir()`, with explicit scratch `storageRoot` and `graphDir` for every host and adapter, and records injected through `reviewRoutingRecord` (`lockedRecord()` and `unlockedRecord()` of T-53-11) wherever a scenario needs a raised threshold; it runs through the isolated environment, and the isolation test of T-53-01 is run with it as the last test gate of the phase's code tickets (T-53-31, the prose ticket, runs beside it).
