<objective>Add what unit and reducer dispatches need before any host can launch one: the subject family they are sealed under, the dispatch-boundary subject kind that admits it, and a scratch evidence name that keeps the worktree clean between launches, so partitioned-route artifacts exist beside the phase-level ones and cannot stand in for them.</objective>

## Goal

ADR-033 R-4 (D-04): "each unit is an ordinary receipt-verified dispatch" while the PR-level gate must be satisfied only by the aggregate. Research `alternatives.md` Option C: "a new unit/ledger artifact kind that cannot satisfy the PR-level gate (today any sealed `arch-review` record with a matching PR/head/base and `verdict:'conform'` can, `role-artifact.cjs:3844-3849`, `:3868-3879`)". The current consumers select candidates by subject pattern (`PHASE_SUBJECT.exec` at `role-artifact.cjs:3845`, `parseSubject('integrator', ...)` at `:3750`), so a subject that matches neither pattern is ignored by them.

Decomposition verified two further facts that would have stopped every unit launch.

- The dispatch boundary refuses a review-part architecture-review subject and, depending on the repository path, an integrator one. `subjectKindFromContext` (`dispatch-boundary.cjs:1071-1093`) accepts kind `phase` only for an exact `PHASE_SUBJECT`, refuses kind `ticket` for an architecture-review ticket that begins `phase=` (and a review-part subject begins `phase=`), and refuses every other kind except `round`; `ticketFromContext` (`:1050-1069`) refuses whitespace unless `isSubjectTicket` parses the ticket as planning-input, decomposition-seal, integrator or architecture-review, and a repository path with a space is allowed in the subject grammar. An integrator review-part ticket without whitespace therefore passes today as an ordinary `ticket`, so its receipt would be recorded as a plain ticket receipt rather than as a unit. `reconcile` (`:2325-2360`) already compares the recorded kind and `dispatch` already records `subject_kind` when it is not `ticket` (`:2501`), so only the admission functions need the new kind.
- The Claude integrator's evidence file is `.planning/phases/<phase>/INTEGRATION.md` (`claude-role-host.cjs:656`), an untracked file that is not scratch, so after one launch the next is refused with "worktree has local changes before role dispatch" (`canonicalWorktree` `:174`); the Codex host writes the same file after its launch (`codex-delivery-host.cjs:948-951`). The architecture review's evidence is already a scratch file. A partitioned run launches N units, reducers and an aggregate in one worktree, so unit and reducer integrator launches need a scratch evidence name.

## Scope

- `architecture-target.cjs`: add family `review-part` to `FAMILIES` with keys `phase`, `repository`, `tickets`, `head`, `base`, `plan`, `part` and pattern `^phase=(\d+-[A-Za-z0-9][A-Za-z0-9._-]*);repository=(<REPOSITORY_CLASS>);tickets=([a-f0-9]{64});head=([a-f0-9]{40});base=([a-f0-9]{40});plan=([a-f0-9]{64});part=((?:unit|node):[a-z0-9]{1,16})$`. Export it through the existing `buildSubject`/`parseSubject`; add `REVIEW_PART_SUBJECT` as a named export of the pattern. No other family changes.
- `dispatch-boundary.cjs`: `isSubjectTicket` also parses `review-part`; `subjectKindFromContext` gains kind `review-part`, valid only when the role is `arch-review` or `integrator` and `parseSubject('review-part', ticket)` is not null; a ticket that parses as review-part is refused with `INVALID_INPUT` ("review-part subjects require subject_kind review-part") under kind `ticket` for both roles and under kind `phase` (already refused because it does not match `PHASE_SUBJECT`); kind `review-part` with any other ticket or role is refused with `INVALID_INPUT`. Every other input resolves exactly as today. `dispatch` and `reconcile` need no change beyond that function: the recorded kind is compared at reconciliation.
- `conveyor-scratch.cjs`: add `INTEGRATION_PART_EVIDENCE_NAME = '.shipyard-integration-part-evidence.md'`, append it as the last entry of `SCRATCH_FILES` and export it; `isScratch` and `statusIgnoringScratch` need no change because they read the list. This name is used only for integrator unit and reducer launches (T-53-19 accepts it for review-part integrator judgments, T-53-22 and T-53-26 prepare those launches with it); the aggregate integrator launch keeps `.planning/phases/<phase>/INTEGRATION.md` because `gsd-sync` and the conveyor read that file and the aggregate is the last launch of a run.

## Acceptance criteria

- `buildSubject("review-part", …)` and `parseSubject` round-trip for a repository containing a space and a non-ASCII character; a repository with a semicolon refuses at `buildSubject` and `parseSubject` returns null for a subject with the repository replaced by one; a bad head, base, plan or part string does not build.
- For a representative set of review-part subjects `PHASE_SUBJECT` and the `integrator` and `architecture-review` family patterns do not match, and for representative integrator and architecture-review subjects the new pattern does not match.
- Boundary: a review-part subject (with a space in the repository) dispatched with `subject_kind: "review-part"` for role `arch-review` and for role `integrator` through the fake adapter produces a verified record whose `subject_kind` is `review-part`, and `reconcile` with the same kind and ticket returns it; the same subject with no kind (ticket) and with kind `phase` is refused `INVALID_INPUT`; a phase subject, an integrator subject and a plain ticket under kind `review-part` are refused; roles `executor` and `pr-sentinel` with kind `review-part` are refused; `reconcile` with a different kind than the recorded one is refused `NONCOMPLIANT_RECEIPT`; every existing case in `dispatch-boundary.test.cjs` passes unchanged.
- Scratch: `SCRATCH_FILES` equals the previous seven names followed by `.shipyard-integration-part-evidence.md`; `isScratch` is true for it with `forJudge` true and false and false for the same name in a subdirectory; `statusIgnoringScratch` ignores an untracked file with that name and still reports `INTEGRATION.md` under `.planning/phases/` as dirty; the `list` CLI prints it.
- Existing families and tests are unchanged apart from the exact-list pin in `conveyor-scratch.test.cjs`, which is updated as stated, not loosened.
