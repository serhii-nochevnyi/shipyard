<objective>Create the ledger authority of the partitioned route: an immutable plan and HMAC-protected unit records in the protected authority directory, with the set-cover verification and the verdict ceiling that make a partial partitioned review unable to pass.</objective>

## Goal

ADR-033 R-4 (D-04): "The host proves coverage as a set-cover over git data (every changed row belongs to exactly one unit whose packet embeds it and whose result is receipt-verified) plus a ledger authority outside the worktree; a phase verdict is `passed` only when the ledger is complete and every unit is complete and passing." Research `constraints.md` TC-7 and TC-11: roster authority is HMAC-protected, unreadable to both children and bounded; a ledger over many units cannot ride in the 8,192-byte envelope or the 128 KiB result and needs its own immutable, digest-bound store; packets cannot carry receipts (`rejectAuthorityKeys`), so unit records live host-side.

This ticket carries a merge checkpoint (`human_checkpoint: merge`, which the operator may pre-authorize at Gate 2) because it introduces a new authority store.

## Scope

New `review-ledger.cjs` (the module name is only a file name; on disk the store is a partition run store) storing under `path.join(archiveAuthorityDirectory(worktree, true), "partition-runs", <run id>)` where the run id is the sha256 of the canonical ledger identity `{ repository, subject, role, runtime, head, base }` (the object the plan records, T-53-14) and the plan digest; `runtime` is `claude` or `codex` and `role` is `integrator` or `arch-review`, so the same head, base and plan under the other runtime or role is a different run in a different directory. The only entry the store adds to the authority directory is the directory `partition-runs`, which matches none of the reserved names of `protectedRecordsWithoutKey` (see Context): the former layout `review-ledger/` and `review-ledger.key` started with `review-`, so a ledger created before the worktree's `hmac.key` existed would have made the next role launch refuse with "existing protected records require their original authority key". Files: `partition-runs/ledger.key` (32 random bytes, 0600, published atomically with temp file plus link; the ledger's own key, not `hmac.key`), and per run `plan.json` (the partition plan, mode 0400, written once) and `ledger.json` (HMAC envelope updated by temp file plus link or atomic rename); directories 0700. Key custody follows the role-artifact invariant for its own protected records: when `partition-runs/` holds a run directory but `ledger.key` is absent, every operation refuses with `REVIEW_LEDGER_INVALID` and no new key is published. The existing Codex all-attempt ledger and the PR ledger are different stores; error codes `REVIEW_LEDGER_*` and the `ledger_digest` contract field are names of this store only. API: `createLedger({ worktree, identity, plan })` (idempotent for an identical plan, `REVIEW_LEDGER_CONFLICT` for a different plan under the same identity), `openLedger({ worktree, run, runtime })` returning the handle of an existing run (verified like a read, `REVIEW_LEDGER_INVALID` when absent or altered; hosts open a ledger by run id and always name their own runtime: a run whose recorded identity runtime differs refuses with `REVIEW_LEDGER_RUNTIME` and none of its records is read as evidence), `readPlan(handle)` returning the verified immutable plan, `readLedger(handle)` (verifies mode bits, HMAC, plan digest and identity, `REVIEW_LEDGER_INVALID` otherwise), `recordUnit(handle, record)` with record `{ unit_id, attempt, runtime, dispatch_id, receipt_digest, artifact_ref, artifact_digest, outcome, review_completeness, summary, findings_count, blocking_count, packet_digest }` (summary at most 500 characters; `runtime` must equal the ledger identity's, else `REVIEW_LEDGER_RUNTIME`), `recordFailure(handle, { unit_id, attempt, code })`, `gitCoverageSource({ worktree, handle, exec })`, the one production source of the set-cover input: it reads the verified plan of `handle` and recomputes from git, at the ledger identity's `base` and `head` (commit objects that exist whatever the live head is) and the plan's `context_lines`, the review rows with `review-diff-scope.reviewChangeSet` for the identity's role and their sizes and digests with `review-manifest.measureRows`, and returns a frozen `{ rows, rows_digest, readSegment }` where `readSegment(segment)` re-runs `reviewDiff` for the segment's path (both sides of a rename) and returns the bytes `byte_start` to `byte_end`; it reads git only, never the plan's own rows, and refuses with `REVIEW_COVERAGE_UNAVAILABLE` when the objects are missing. `verifyLedger(handle, { identity, rereadArtifact, coverage })` has a mandatory `coverage` input, the object `gitCoverageSource` returns: a call without it, or with one lacking `rows` or `readSegment`, refuses with `REVIEW_LEDGER_COVERAGE_REQUIRED` and computes nothing. It requires exactly one counted record per plan unit and calls the host-supplied `rereadArtifact(record)` for each counted record, which must return a frozen `{ artifact_digest, packet_digest, unit: { id, plan_digest }, embedded_sha256 }` read from that unit's sealed artifact and its authenticated original packet (the runtime's own re-extraction of the packet the model was shown, the extraction the consumers use, T-53-27), never from the record or from the model's result; `embedded_sha256` is the sha256 of the diff content of that packet. For every unit record `verifyLedger` compares `artifact_digest` and `packet_digest` with the record, `unit.id` with `record.unit_id`, `unit.plan_digest` with the plan digest and `embedded_sha256` with `review-partition.unitEmbeddedDigest(planUnit, coverage.readSegment)` (T-53-14), the digest of the unit's planned segment bytes taken from git; any difference is a `unit-packet-mismatch` problem naming the unit and the field (`artifact_digest`, `packet_digest`, `unit_id`, `plan_digest` or `embedded_sha256`), and a callback result without `embedded_sha256` is `unit-packet-unproven` and is never skipped, so `ok` is false. This is the verification-time proof that each counted unit's packet embedded its planned bytes, as opposed to the dispatch-time check the host makes before launch: a record that points at another unit's sealed artifact, or at one sealed under another plan, fails it, and so does a packet that embedded anything but the planned bytes. Reducer node records (T-53-16) have no segments and are not subject to the embedded check. It then runs `review-partition.verifyCoverage({ plan, rows, readSegment })` over the git-recomputed rows, and returns a frozen `{ ok, problems, complete, all_passing, counted_units, ledger_digest, coverage_digest }` where `ok` is true only when units, artifacts, unit packets and coverage all hold; evidence problems (a missing unit, a re-read digest mismatch, `unit-packet-mismatch`, `unit-packet-unproven`, `row-uncovered`, `row-duplicated`, `extra-row`, `segment-gap`, `segment-digest-mismatch`, `rows-digest-mismatch`) give `ok: false` with the named problems and do not throw, so a caller can report them. `ledgerVerdictCeiling(handle, role, options)` takes the same options as `verifyLedger` and runs it itself, returning `{ complete, all_passing, ceiling }` with ceiling `passed` (integrator) or `conform` (arch-review) only when `ok`, complete and all passing, `needs-fix`/`violation` when `ok` and complete with a failing unit, and `incomplete` otherwise (every `ok: false` included); there is no code path to `passed` or `conform` that does not run the set-cover over rows recomputed from git, and the hybrid result validator of T-53-17 accepts only the frozen `verifyLedger` result as its `ledger` input. The hosts (T-53-22, T-53-24, T-53-26), the consumers (T-53-27) and the coordinator (T-53-29) are the production callers: each builds `coverage` with `gitCoverageSource` at its own call and each has its own omitted-row case. A unit counts through its latest verified attempt; a verified record is immutable; a later attempt is accepted only after the earlier attempt was recorded as a failure. `ledgerDigest(handle)` is the sha256 of the canonical plan digest and counted records. A head or base different from the ledger identity raises `REVIEW_LEDGER_STALE`.

## Out of scope

Reducer-node records (T-53-16 extends this module); dispatching, sealing and consuming (T-53-22…T-53-29), including the omitted-row cases of those callers; any edit of `role-artifact.cjs` (only its exported directory function is used).

## Acceptance criteria

- Create, read, record and verify round-trip; the ledger directory is under the authority namespace (not under the worktree), directories are 0700, the key 0600 and the plan 0400; a file with group or world access, a symlink or a wrong size refuses with `REVIEW_LEDGER_INVALID`.
- Name collision: after `createLedger` in a worktree whose authority directory has no `hmac.key` yet, the authority directory's only new entry is `partition-runs`, and a role-artifact entry point that creates authority state (the sealing or roster-registration helper the role-artifact tests already use) still succeeds and publishes `hmac.key`; a case that plants an entry named `review-ledger` in a fresh authority directory shows the same call refusing with the protected-records message, which documents why the store avoids that prefix; with run directories present and `ledger.key` deleted every operation refuses and no key file appears.
- Flipping a byte of a record, replacing the MAC, swapping the plan or changing the identity each refuses; recording the same unit and attempt twice refuses; recording a second attempt before a failure refuses; recording an unknown unit refuses.
- Ceiling table: no records is incomplete; all units complete and passing is passed (integrator) or conform (arch-review); one unit incomplete is incomplete; one complete unit failing is needs-fix or violation; a record whose artifact digest no longer matches the re-read artifact makes `verifyLedger` fail.
- Coverage is mandatory: `verifyLedger` and `ledgerVerdictCeiling` called without `coverage`, or with a `coverage` that lacks `rows` or `readSegment`, refuse with `REVIEW_LEDGER_COVERAGE_REQUIRED` and compute nothing; passing rows recomputed for a different head (their digest differs from the plan's `rows_digest`) returns `ok: false` with `rows-digest-mismatch`.
- Omitted row, on a throwaway repository with 12 changed paths under real git: `gitCoverageSource` rows equal an independent `git diff --raw` classification of the same range at the plan's role; a plan built with `planPartition` from those rows minus one row is accepted by `createLedger` (it is internally consistent), every unit is then recorded complete and passing with authentic artifact digests, and `verifyLedger` returns `ok: false` with `row-uncovered` naming the omitted path while `ledgerVerdictCeiling` returns `incomplete` and never `passed` or `conform`; the same fixture planned from the full rows returns `ok: true` and `passed`; a plan with one row in two units returns `row-duplicated`; a `readSegment` that alters one byte returns `segment-digest-mismatch`; `readSegment` bytes digest to the plan's segment sha256 for a split oversize file.
- Unit packets at verification time: on the same twelve-path fixture with an authentic `rereadArtifact` (it returns each unit's recorded digests, its own id and plan digest and `embedded_sha256` equal to `unitEmbeddedDigest` over `readSegment`) `verifyLedger` returns `ok: true`; a callback that returns for unit `u02` a changed `embedded_sha256`, or the digest of `u01`'s bytes, returns `ok: false` with `unit-packet-mismatch` naming `u02` and the field `embedded_sha256` while every artifact digest still matches and `ledgerVerdictCeiling` returns `incomplete`; a callback that returns `u01`'s `unit.id` for the record of `u02`, a different `plan_digest` or a different `packet_digest` each gives `unit-packet-mismatch` naming that field; a callback that omits `embedded_sha256` gives `unit-packet-unproven`; a reducer node record is not subject to the check.
- Runtime binding: the same plan, head and base under identity runtime `claude` and `codex` give two different run ids and two directories; `openLedger({ run, runtime: 'codex' })` on a run created for `claude` refuses with `REVIEW_LEDGER_RUNTIME` and returns no handle; `recordUnit` with a record whose `runtime` differs from the identity's refuses with `REVIEW_LEDGER_RUNTIME`.
- A changed head or base gives `REVIEW_LEDGER_STALE` for every operation.
- Two concurrent `recordUnit` calls on different units both land; two on the same unit and attempt leave exactly one.
