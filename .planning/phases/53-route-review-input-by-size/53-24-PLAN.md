## Scope

- Request path. `requestValue` (`codex-delivery-host.cjs:119-121`, extended by T-53-23 for `review_contract` and `review_min_route`) now also admits, for role `arch-review` with the hybrid architecture string only, `context.review_unit` (`{ run, unit, plan_digest }`) and `context.review_aggregate` (`{ run, node }`), validated through `parseSelectors(context, 'arch-review')`; it refuses them together, without the hybrid string, with the legacy focused string, and for role `integrator` (until T-53-26); every other context key is still refused as before. Without this the unit and aggregate selectors never reach `prepare`.
- `prepare` accepts `review_unit` and `review_aggregate` through `parseSelectors` (valid only with the hybrid contract, never together); the host's call site passes them through and still refuses anything else. Because `requestValue` sees no subject, `prepare` also checks the subject: a `scope.ticket` that matches neither `PHASE_SUBJECT` nor a review-part subject (a ticket-level architecture review) refuses either selector with `REVIEW_PARTITION_UNSUPPORTED` (`partitionSupported` of T-53-17).
- Unit launch: `scope.ticket` is a `review-part` subject; open the ledger by run id (`openLedger` with `runtime: "codex"`; a ledger recorded for the other runtime or role refuses with `REVIEW_LEDGER_RUNTIME`), read and verify the plan, compare the plan identity (repository, head, base, ticket-set digest, phase, pull request) with live inputs (`STALE_CONTEXT`), compare the plan digest with the request, re-run `reviewDiff` per segment path, slice the recorded range, verify each sha256 and embed the segments as the packet diff content, concatenated in plan order with no separator, so that the sha256 of that content is `review-partition.unitEmbeddedDigest` of the unit (T-53-14); the packet adds `review_unit` (its `segments_digest` equal to that digest), `unit_seams`, `review_route` (the plan's partitioned record) and `review_scope`, keeps the architecture records of an ordinary review, omits retained roster evidence; `signals.inputTokens` is the whole-review work stored in the plan; `finish` validates the unit branch of `validateHybridResult` and seals under the review-part subject.
- Aggregate and reducer launches: the aggregate uses the normal phase subject and the phase binding with the retained roster and evidence as today; the packet has identity-only `diff`, the change inventory rows, per-input outcome and bounded summary and artifact digest from the ledger, seams for aggregate inputs, reduction levels and `ledger_digest`; `verifyLedger` runs before launch with the host's artifact validator, satisfying the `rereadArtifact` contract of T-53-15 (the artifact digest, packet digest, unit id and plan digest and `embedded_sha256`, the sha256 of the diff content of the authenticated original packet re-extracted from the unit's pinned archive, never from the ledger record; exported from `codex-arch-review-context.cjs` as `unitArtifactReader(options)`, which the coordinator's Codex adapter passes to its final check, T-53-29), and with `coverage: gitCoverageSource({ worktree, handle })` (T-53-15), which recomputes the review rows and segment bytes from git at the ledger identity, is mandatory and refuses the launch with `REVIEW_COVERAGE_INVALID` naming the first problem when `ok` is false (a plan that omits or duplicates a row, whose rows differ from git, or in which a counted unit's sealed packet did not embed its planned bytes, `unit-packet-mismatch`); the change inventory rows of the packet are the rows `gitCoverageSource` returned; the frozen `verifyLedger` result is the `ledger` input of the aggregate branch of `validateHybridResult`, so the result is validated against a coverage-verified ledger and its ceiling; a reducer uses a `review-part` node subject and is validated like a unit with its inputs echoed.
- The single evidence file and the read-only sandbox with one write grant are unchanged.
- Subject kind through the Codex path. `codex-delivery-host.cjs:3036` sets `context.subject_kind = 'phase'` for every architecture-review ticket that begins `phase=`, and a review-part subject begins `phase=`; the call becomes: kind `review-part` when the ticket parses as a review-part subject (for either role, because the Codex integrator's unit and reducer dispatches reach the same line and T-53-26 relies on it), `phase` when it matches `PHASE_SUBJECT` for the architecture review, as today otherwise. `readerSubjectKind(manifest)` in `codex-runtime-host.cjs:1001` (used at `:981`, `:1018`, `:3389`, `:3604` for the reader capacity probe and file-input custody) returns `review-part` for a manifest whose ticket parses as a review-part subject, so a unit relayed as host files is reconciled under the kind it was dispatched with; every other manifest resolves as today. The boundary admits the kind since T-53-18.

The collector tolerates untracked files under `.shipyard-role-artifacts/` only for a phase binding (`codex-arch-review-context.cjs:1080-1082`, `archiveBookkeeping`) or for pinned archives, so a second unit collection in the same worktree would be refused with "review worktree has local changes" because of the first unit's sealed archive. For a review-part subject the same allowance as for a phase binding applies, limited to untracked entries under that archive directory; any other untracked or modified path still refuses. ## Acceptance criteria

- A unit launch embeds only that unit's segments, refuses a segment whose sha256 differs, a changed head or base, a different ticket set and a plan digest different from the request; its `signals.inputTokens` equals the plan's whole-review work; its result with a wrong `review_unit` echo is refused and a correct one seals under a review-part subject that `currentArchitectureVerdict` ignores.
- An aggregate launch refuses a ledger with a missing unit, a tampered record or a re-read artifact digest mismatch; with a complete passing ledger its packet has no diff text and carries unit summaries, seams and the ledger digest; a `conform` result over a failing or incomplete unit is refused with `REVIEW_VERDICT_EXCEEDS_LEDGER`; a correct aggregate seals under the phase subject with the hybrid contract and ledger digest.
- Omitted row: on the three-unit fixture over a real repository, an aggregate launch whose ledger plan was built from the git rows minus one row (every unit recorded complete and passing) refuses before launch with `REVIEW_COVERAGE_INVALID` naming `row-uncovered` and the path, the fake dispatch is never called, and the same fixture planned from the full rows launches with a change inventory equal to an independently computed `git diff --raw` classification.
- Unit packet at verification time: an honest Codex-sealed unit's `unitArtifactReader` result carries `embedded_sha256` equal to `unitEmbeddedDigest` over bytes read from git and the aggregate launches; a ledger in which the record of unit `u02` was planted with the sealed artifact of `u01`, or of a `u02` sealed under another plan of the same head and base, refuses the aggregate before launch with `REVIEW_COVERAGE_INVALID` naming `unit-packet-mismatch` and `u02`, and the fake dispatch is never called, the same code, problem and unit as the Claude host gives the same fixture (T-53-22).
- Runtime and subject: a unit or aggregate launch against a ledger created for runtime `claude` refuses with `REVIEW_LEDGER_RUNTIME`; a ticket-level architecture review (ticket subject) carrying `review_unit` or `review_aggregate` refuses in `prepare` with `REVIEW_PARTITION_UNSUPPORTED`, while a phase-bound request is unaffected; every unit and aggregate launch's `signals.inputTokens` equals the plan's whole-review work.
- A reducer launch echoes its inputs and seals under its node subject.
- Two consecutive unit collections in one worktree (the first unit's judgment sealed and archived) both succeed, the second is not refused as dirty, an untracked non-archive file between them still refuses, and a unit relayed as host files is reconciled under kind `review-part` (the reader custody path accepts it and refuses a mismatched kind); the host passes `subject_kind` `review-part` for a review-part ticket and `phase` for a phase ticket.
- Inline, pull and legacy launches are unchanged.
- Request path: `validateArgs` accepts `review_unit` and `review_aggregate` for role `arch-review` with the hybrid architecture string, and refuses with `INVALID_INPUT` each of: both together, either without the contract, either with the legacy focused string, either for role `integrator`, a unit with a malformed run id or plan digest, and an aggregate with an unknown node form.
