<objective>Add the tree reduction that lets an epic with more units than one aggregation step can hold still be judged completely, with every reducer node part of the host-verified ledger.</objective>

## Goal

Research `alternatives.md` Option C and `risks.md`: "an epic larger than any aggregation step can hold" and chunked review losing cross-chunk judgement; the aggregator receives per-unit verdict summaries (at most 500 characters each, `role-artifact.cjs:32-33`), so the input grows with the unit count.

## Scope

New `review-reduction.cjs` with `planReduction({ unitIds, fanout, maxDepth })` returning `{ schema: "shipyard.review-reduction.v1", fanout, levels: [{ level, nodes: [{ id, inputs }] }], aggregator: { inputs }, depth, digest }`: with at most `fanout` units the plan has no levels and the aggregator takes the units; otherwise consecutive groups of at most `fanout` units in unit order become level-one nodes `l1n01…`, then groups of nodes become level-two nodes, until at most `fanout` nodes remain for the aggregator. Depth above 8 (the `maxDepth` default) refuses with `REVIEW_REDUCTION_TOO_LARGE`. `verifyReduction(plan, unitIds)` proves each unit is in exactly one level-one node and every node is consumed exactly once. `review-ledger.cjs` gains `recordNode(handle, record)` with the unit-record shape plus `level` and `node_id`, the node set from the reduction plan stored in the ledger, node outcomes taken into `verifyLedger` and `ledgerVerdictCeiling` (a missing, incomplete or failing node lowers the ceiling exactly like a unit), and `ledgerDigest` covering nodes. The node-aware `verifyLedger` and `ledgerVerdictCeiling` keep the mandatory `coverage` input and the runtime binding of T-53-15 unchanged: nodes add records to what is counted, they never replace the set-cover over rows recomputed from git, and a ledger with reducer nodes whose plan omits a row still returns `ok: false`.

Risk is high, not medium: the ticket edits the ledger module of T-53-15, the authority store whose verdict ceiling decides whether a partitioned review may pass, and extends that ceiling and the ledger digest with the reducer nodes (T-53-57); it carries a merge checkpoint (`human_checkpoint: merge`), which the operator may pre-authorize at Gate 2.

## Out of scope

Reducer dispatch and prompts (T-53-22, T-53-24, T-53-26); the coordinator's level loop (T-53-29).

## Acceptance criteria

- For 1…256 units and fan-outs 2, 4 and 8 the reduction is deterministic, every node has at most `fanout` inputs, every unit is covered once, the final aggregator input is at most `fanout`, and the depth equals `ceil(log_fanout(units))` minus one for more than `fanout` units.
- 8 units at fan-out 8 produce no levels; 9 units produce one level of two nodes (8 and 1).
- A unit count needing depth 9 (fan-out 2 with 513 units) refuses with `REVIEW_REDUCTION_TOO_LARGE`.
- A ledger whose reduction nodes are missing or one failing yields a lowered ceiling; recordNode refuses an unknown node and a replay; node records are covered by tamper detection and by `ledgerDigest`.
- With reducer nodes recorded, `verifyLedger` without `coverage` still refuses with `REVIEW_LEDGER_COVERAGE_REQUIRED`, and a 20-unit plan built from the git rows minus one row with every unit and node complete and passing returns `ok: false` with `row-uncovered` and a ceiling of `incomplete`.
- The existing ledger tests still pass.
