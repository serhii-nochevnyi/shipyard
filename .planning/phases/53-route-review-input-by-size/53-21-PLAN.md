<objective>Implement the pull route on the Claude host so a mid-size epic is reviewed in one session without embedding its diff, with the proof limited to what the decision says it is: a declared inventory equal to a host-built, digest-bound manifest.</objective>

## Goal

ADR-033 R-3 (D-03) and R-1. The pull packet "carries a host-built manifest of changed paths (status, blob ids, size, per-file diff hash, recipe) bound into the context digest; the reviewer pulls each file's diff"; "its coverage proof is declarative: the host checks that the reviewer's declared coverage inventory equals the manifest and that `complete` implies empty limitations; it does not prove the reading." The upper threshold is configurable; under the conservative defaults the pull band is empty, so operators opt in by lowering `review_inline_max_tokens` (tightening, always honoured by the gate of T-53-11) or, once the shipped record unlocks the knob (every informing item measured and operator-signed), by raising `review_pull_max_tokens`. The Claude child already runs `Bash,Read,Edit,Write,Glob,Grep` in the worktree (`claude-runtime-host.cjs:781-782`); whether `git diff` works for it in a linked worktree is the measurement item `claude-linked-worktree-git-diff`, and a reviewer that cannot read reports a limitation and is escalated.

## Scope

When the selected route is `pull`: build the manifest with `buildManifest` at the configured context; put it in `role_context.review_manifest`; keep `exact_diff` (architecture) or `combined_diff` (integrator) as an object with `base`, `merge_base`, head and tree identities and `manifest_digest` but no `content`; size the integrator packet bound from the manifest and metadata instead of the diff text; replace the inline-diff sentences of the instruction with the pull instruction: for every manifest row run its recipe from the worktree with `git` through `Bash`, review the output, never modify the worktree, and return `coverage_inventory` (one `{ path, diff_sha256 }` per row, the sha256 of the exact output read), `review_completeness`, `limitations` and `unresolved_sources`; the result is validated with the pull branch of `validateHybridResult`; a result with an `incomplete` completeness is sealed but cannot carry a passing or conform authority (the consumer gate in T-53-27 reads `review_completeness`). If `buildManifest` returns a blocker the host refuses with `REVIEW_PARTITION_REQUIRED` and a route record whose `escalated_from` is `pull`.

## Out of scope

Proving the reviewer read any diff (declared by decision; a transcript-derived proof is a separate later change that needs its own spike); units and aggregates (T-53-22); Codex (T-53-23, T-53-25).

## Acceptance criteria

- With thresholds that select pull, the packet has `review_manifest` with the digest in the context digest, no `content` under `exact_diff` or `combined_diff`, and a prompt whose size grows only with the manifest: a fixture with ten times the diff bytes and the same row count produces a prompt within 5% of the original size.
- A correct inventory seals as complete; a missing path, an extra path, a wrong hash, a duplicate, or `complete` with a limitation is refused with `REVIEW_COVERAGE_MISMATCH` or `REVIEW_CONTRACT_INVALID`; an `incomplete` result with a full inventory seals with `review_completeness: "incomplete"`.
- A file diff above 2 MiB, or a manifest above 512 KiB, escalates to `REVIEW_PARTITION_REQUIRED` with `escalated_from: "pull"`.
- A reviewer that modifies the worktree is refused by the existing `WORKTREE_MUTATED` guard (asserted with a fake runtime that writes a file).
- The inline route and all legacy cases are unchanged.
