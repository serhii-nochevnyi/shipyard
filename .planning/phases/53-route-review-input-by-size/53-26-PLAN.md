## Scope

`requestValue` (`codex-delivery-host.cjs:119-121`, extended for the integrator by T-53-25) and `prepareIntegratorInput` accept `review_unit` and `review_aggregate` for role `integrator` under the hybrid integrator string only, validated through `parseSelectors(context, 'integrator')` (the four hybrid keys `review_contract`, `review_min_route`, `review_unit` and `review_aggregate`, and no others; a unit with an aggregate, either without the hybrid string, either with a legacy string and either for the architecture review's string are refused with `INVALID_INPUT`); the hybrid branch calls the shared preparation with the selector and builds the Codex input from the returned unit or aggregate packet through the inline transport only, as T-53-25 does for the inline route (material plus generated instructions at most 1 MiB; above it the launch is refused with `REVIEW_ROUTE_UNAVAILABLE` and `blocker: "transport-limit"`, never routed through host files, the reader transport or the v2-only completed-source restoration), with a binding carrying the hybrid contract, route record digest, plan digest and, for an aggregate, the ledger digest; the dispatch subject for a unit or reducer is the review-part subject and for the aggregate the normal phase subject; `request.signals.inputTokens` is the whole-review work from the plan; `finishIntegrationReview` validates unit and aggregate results with `validateHybridResult` (unit echo, ledger digest, ceiling) and seals them under their subjects. A stale identity, plan mismatch, altered segment or ledger problem refuses before launch because the shared preparation refuses.

Unit packets at verification time (fourth round). The ledger of a Codex integrator run holds Codex-sealed unit artifacts, so the shared aggregate preparation (T-53-22) must read them with the Codex reader: `codex-delivery-host.cjs` exports `unitArtifactReader(options)`, which satisfies the `rereadArtifact` contract of T-53-15 for Codex-sealed integrator artifacts (the artifact digest, packet digest, unit id and plan digest and `embedded_sha256`, the sha256 of the diff content of the authenticated original packet re-extracted from the unit's pinned input binding by the extraction the Codex consumer branch of T-53-27 uses, never from the ledger record), passes it to the shared preparation as `options.unitArtifactReader`, and hands it to the coordinator's Codex adapter (T-53-29) for its final check. The unit input is built from the shared preparation's unit packet, so its diff content is the concatenation of the unit's verified segments and its sha256 is `unitEmbeddedDigest` (T-53-14, T-53-22).

Subject kind and evidence file. The unit and reducer dispatch carries `subject_kind: "review-part"` (set at `codex-delivery-host.cjs:3036` by T-53-24 for either role; the boundary admits it since T-53-18). `finishIntegrationReview` writes the host's evidence markdown to `review.prepared.evidencePath` (`:948-951`) and seals from it: for a unit or reducer that path is `.shipyard-integration-part-evidence.md` (the shared preparation sets it, T-53-22) and `prepareRoleArtifact` and `sealJudgment` receive `evidenceKind: "part"` (T-53-19), so the worktree stays clean for the next launch; the aggregate writes `.planning/phases/<phase>/INTEGRATION.md`. The Codex integrator's launch cleanliness checks already ignore the archive directory (`isScratch(..., { forJudge: false })` at `:1390`, `:2200`, `:2515`, `:3250`) and the new scratch name through `SCRATCH_FILES`.

## Acceptance criteria

- A unit request embeds only the unit's segments and carries the unit echo requirement; the `signals.inputTokens` equals the plan's whole-review work; the result with a wrong echo is refused; a correct one seals under a review-part subject that `currentIntegrationVerdict` ignores.
- An aggregate request refuses a missing, tampered or incomplete ledger; with a complete passing ledger the input has no diff text and carries unit summaries, seams and the ledger digest; a `passed` result over a failing or incomplete unit is refused with `REVIEW_VERDICT_EXCEEDS_LEDGER`; a correct aggregate seals under the phase integrator subject with the hybrid contract and ledger digest; a reducer echoes its inputs.
- Omitted row and runtime, through the shared preparation: an aggregate request whose ledger plan was built from the git rows minus one row (every unit recorded complete and passing) refuses before launch with `REVIEW_COVERAGE_INVALID` naming `row-uncovered` and the omitted path, with the same code, problem and path as the Claude host refuses the same fixture (asserted against the T-53-22 helper), and the fake native runtime is never called; a unit or aggregate request against a ledger created for runtime `claude` refuses with `REVIEW_LEDGER_RUNTIME`; every unit and aggregate request's `signals.inputTokens` equals the plan's whole-review work.
- Unit packet at verification time: an honest Codex-sealed integrator unit's `unitArtifactReader` result carries `embedded_sha256` equal to `unitEmbeddedDigest` over bytes read from git and the aggregate launches; a ledger in which the record of unit `u02` was planted with the sealed artifact of `u01`, or of a `u02` sealed under another plan of the same head and base, refuses the aggregate before launch with `REVIEW_COVERAGE_INVALID` naming `unit-packet-mismatch` and `u02`, and the fake native runtime is never called, the same code, problem and unit as the Claude host and the Codex architecture review give the same fixture (T-53-22, T-53-24).
- A unit or aggregate input above 1 MiB is refused with `REVIEW_ROUTE_UNAVAILABLE` and `blocker: "transport-limit"` and a spy on `prepareFileInput` shows it was never called; inline, pull and legacy requests are unchanged.
- Two consecutive integrator unit dispatches in one worktree both pass preparation (the part evidence file and the sealed archive directory are ignorable), each unit receipt records `subject_kind: "review-part"`, and the aggregate's evidence is `.planning/phases/<phase>/INTEGRATION.md`.
- Request path: `validateArgs` accepts `review_unit` and `review_aggregate` for role `integrator` with the hybrid integrator string, and refuses with `INVALID_INPUT` both together, either without the contract, either with the v1 or v2 string, either with the architecture hybrid string, a unit with a malformed run id or plan digest, and an aggregate with an unknown node form; a v1 or v2 request carrying either selector is refused, so a legacy caller cannot reach a unit or aggregate dispatch.
