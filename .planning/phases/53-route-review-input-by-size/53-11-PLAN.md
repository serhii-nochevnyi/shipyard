<objective>Make the thresholds configurable and conservative, make the conservatism mechanical by reading the signed measurement record at run time, and build the pure router that every host and the coordinator will ask for a route, so route choice is one tested function with a recorded decision and recorded threshold sources.</objective>

## Goal

ADR-033 R-1, R-7 and R-9 (D-01, D-07, D-09). Decisions: the host chooses the route from measured work; thresholds are configurable and "default to conservative values until measured" (DECISIONS: until measured the defaults "keep every review on the safest route (partitioned above the inline bound)"); the work counts diff plus required material, not the prompt. Research: no model window is recorded anywhere; `WINDOW_THRESHOLD_TOKENS` (250000) is a rung selector only. A merge checkpoint can be pre-authorized by the operator at Gate 2, after which no person sees the merge, so "until measured" cannot rest on a merge approval whether or not the operator pre-authorizes: this ticket makes the router itself refuse a configured threshold above its default until the record carries a measured, operator-signed entry for every obligation that informs it.

## Scope

`pipeline-config.cjs`: add flat knobs to `DEFAULTS` and `NUMERIC_KNOBS`: `review_inline_max_tokens` 150000, `review_pull_max_tokens` 150000, `review_unit_budget_tokens` 100000, `review_context_lines` 10, `review_reduction_fanout` 8, `review_max_units` 64. After the shared rule, normalize: `review_context_lines` of 50 or more falls back to the default with a warning (the allowed range is 1 to 49: D-02 says fewer than 50 surrounding lines, and 50 is the legacy context the hybrid contract replaces, so a hybrid review can never run at the legacy context); `review_pull_max_tokens` below `review_inline_max_tokens` is raised to it with a warning; `review_reduction_fanout` below 2 falls back to the default. `pipeline-config.cjs` stays a compatibility reader that cannot authorize a routed dispatch and does not read the record; nothing here touches model policy.

New `review-route.cjs`: `ROUTES` (`inline`, `pull`, `partitioned`); `thresholdsFrom(cfg, options)`; `estimateTokens(bytes)` (`ceil(bytes/4)`); `measureWork({ diffBytes, requiredBytes, metadataBytes })` returning `{ schema: "shipyard.review-work.v1", diff_bytes, required_bytes, metadata_bytes, estimated_tokens, estimator }`; `selectRoute({ role, runtime, work, thresholds, floor })` returning `{ schema: "shipyard.review-route.v1", route, reason, work, thresholds, threshold_sources, floor, escalated_from }` where work at or below the inline threshold selects inline, at or below the pull threshold pull, else partitioned, a floor raises the route and a floor never lowers it (a request to route below the natural route refuses with `REVIEW_ROUTE_DOWNGRADE`); `nextRoute(route, blocker)` returning the next route or `{ exhausted: true }` for partitioned, with blocker codes `manifest-over-bound`, `oversize-file`, `incomplete-coverage`, `route-proof-missing` and `transport-limit` (a host whose transport cannot carry the route's packet, for example the Codex 1 MiB inline limit, reports it so the coordinator escalates instead of failing); `calibrate(record)` returning `{ schema: "shipyard.review-calibration.v1", calibrated, reason, thresholds, owed, knobs: [{ knob, calibrated, blocked_by, unlocked, unlock_blocked_by }] }`.

The gate. `thresholdsFrom(cfg = {}, { record, recordPath } = {})` takes the configuration object `pipeline-config` returns (defaults already merged and normalized) and returns `Object.freeze({ values, sources, locked, record_state })`. `values` holds the six numbers `selectRoute` takes as `thresholds`. The record is `options.record` when given (a test or host injection, never a request field), else read through `loadRecord(options.recordPath || path.join(__dirname, '..', 'references', 'review-routing-measurements.json'))`, the shipped record beside the plugin's references in the checkout, the installed Claude plugin and the Codex bundle; a record in the working directory or the project is never read. `record_state` is `loaded`, `absent` or `invalid`. For each knob: a configured value equal to the default has source `default`; a configured value below the default of one of the three token knobs (`review_inline_max_tokens`, `review_pull_max_tokens`, `review_unit_budget_tokens`) is honoured with source `config-tightened` because tightening can only send more work to a safer route; any other configured value is honoured, with source `config-unlocked`, only when `knobGate(record)` reports that knob unlocked, that is every item in its `informed_by` list is `measured` with a current operator sign-off; otherwise the value is the default, the source is `default-locked`, and `locked` gains `{ knob, requested, blocked_by }` with the reasons `knobGate` returned (`owed`, `limitation`, `documented`, `tooling-pending`, `unsigned`, `stale-signoff`, `record-invalid`). An absent, unreadable or invalid record unlocks nothing and never throws. After resolution the invariants of `pipeline-config` are applied again (pull not below inline, context lines at most 49). `selectRoute` records `threshold_sources` (the `sources` object) beside `thresholds`, so every artifact shows which thresholds were in force and why. `calibrate` prints a proposal for the operator's config and never writes files: a knob is calibrated only when every item in its `informed_by` list in the record is `measured` (proposal possible), is `unlocked` only when each is also signed and current, and lists the blocking item ids in `blocked_by` and `unlock_blocked_by`; for a calibrated knob the proposal is inline = 40%, pull = 60% and unit budget = 30% of the smallest measured usable input window (the least `observed.usable_input_tokens` among the three window items) divided by the measured estimator ratio (`observed.ratio` of `estimator-undercount`), rounded down; `review_context_lines`, `review_reduction_fanout` and `review_max_units` have no formula and are never proposed. Overall `calibrated` is true only when the three window-derived knobs are all calibrated; otherwise it is false with reason `measurements-owed` and `owed` the sorted union of blocking ids.

Shared fixture helper `tests/unit/helpers/review-routing-fixtures.cjs` (test code only): `lockedRecord()` returns a deep copy of the shipped record with every sign-off removed, and `unlockedRecord()` returns a deep copy with every item forced to `measured` (plausible observed values that carry the keys T-53-07 pins, `observed.usable_input_tokens` for the three window items and `observed.ratio` for the estimator item, so the record passes `validateRecord`; in memory only, never written to the shipped file) and a current sign-off built with `itemDigest`, so host, coordinator and acceptance tests that must raise a threshold inject `{ record: unlockedRecord() }` instead of editing anything; its header says so.

## Acceptance criteria

- `DEFAULTS` carry exactly the six values above; a config with a non-number, a non-positive value, a context of 50 (the boundary) or more, or a pull threshold below inline normalizes with a warning naming the key, and a context of 49 is accepted as given (through an unlocked record, since changing the knob is locked without one).
- `selectRoute` boundaries: work equal to the inline threshold is inline, one token over is partitioned under the defaults (pull band empty), and with an explicit pull threshold above inline the band selects pull; a floor of pull on small work yields pull; a request that asks for a lower route than the natural one refuses; `nextRoute` chains inline, pull, partitioned, then exhausted, and accepts each of the five blocker codes including `transport-limit`; the route record carries `threshold_sources`.
- `measureWork` of the same diff and material gives the same estimate whatever prompt text surrounds it.
- `calibrate` on an in-memory record derived from the shipped one with the window, estimator, compaction, tool-result, reach, linked-worktree and Codex reader items forced to `owed` returns `calibrated: false`, reason `measurements-owed`, every window-derived knob uncalibrated with its informing items listed (`owed`, `tooling-pending` and `limitation` all block); on the shipped file itself the test asserts only the rule, computed independently from the record (a knob is calibrated exactly when every one of its informing items is `measured`), so the operator measuring items later does not break the suite; on an in-memory record whose informing items are all measured it returns deterministic integer proposals for the three window-derived knobs and none for the other three, with `unlocked` false for a knob whose items are measured but unsigned and true once they are signed; a record where only the windows are measured but `claude-tool-result-bodies` is owed calibrates inline and unit budget and blocks pull; it writes nothing.
- Gate, on in-memory records (`lockedRecord()`, `unlockedRecord()` and edits of them): `thresholdsFrom({})` returns `values` equal to the six defaults with every source `default` in every record state (locked, unlocked, absent, invalid); with `lockedRecord()` a config raising `review_inline_max_tokens` to 300000 returns 150000 with source `default-locked` and `locked` naming the knob, the requested value and the blocking items, a config lowering it to 100000 returns 100000 with source `config-tightened`, and a config changing `review_context_lines` to 20, `review_reduction_fanout` to 4 or `review_max_units` to 128 (or lowering it to 32) returns the default with source `default-locked`; with `unlockedRecord()` the same raises return the requested values with source `config-unlocked`; removing one informing item's sign-off, editing a signed item's observed values, or setting one item back to `owed` re-locks exactly the knobs that item informs with reason `unsigned`, `stale-signoff` or `owed`; a `recordPath` naming a missing file gives `record_state: "absent"` and a malformed file `invalid`, both locking every raise without throwing; pull raised above its default while inline stays at the default is honoured only when pull is unlocked, and the pull-not-below-inline invariant holds in every combination.
- A test places `unlockedRecord()` as a file in the working directory and beside the project configuration without passing it and asserts `thresholdsFrom` still reads only the shipped path (so a project cannot unlock its own thresholds); on the shipped record the test computes independently which knobs are unlocked (every informing item `measured` with a current digest-matching entry) and asserts that a configuration setting all six knobs to twice their default is honoured for exactly those knobs, so measuring and signing later cannot break the suite and the suite never requires either, and no test of this ticket needs a live account or an operator action.
- A test asserts the defaults in `DEFAULTS` equal the `value` of the six thresholds in the shipped measurement record and equal the validator's exported `CONSERVATIVE_DEFAULTS`, and that every record threshold with basis `conservative-unmeasured` has no measured evidence.
