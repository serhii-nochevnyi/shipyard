## Goal

## Scope

- `parseRequest` and the exported `prepareIntegratorContext` (called by the Codex host in T-53-26, so it returns the prepared unit or aggregate context for the integrator role exactly as it does for the inline route) accept the hybrid selectors `review_unit` (`{ run, unit, plan_digest }`) and `review_aggregate` (`{ run, node }`) for both roles; they are valid only with the hybrid contract and never together, and for the architecture review only with a phase binding (a request without `phase` is a ticket-level review and refuses either selector with `REVIEW_PARTITION_UNSUPPORTED`, `partitionSupported` of T-53-17).
- Unit dispatch: open the ledger by run id (`openLedger` with `runtime: "claude"`; a ledger recorded for the other runtime or another role refuses with `REVIEW_LEDGER_RUNTIME`), read and verify the plan, compare the plan identity (repository, head, base, ticket-set digest, phase and pull request for the architecture review) with the live inputs (`STALE_CONTEXT` on any difference) and the plan digest with the request; for each segment of the unit re-run `reviewDiff` for its path and slice the recorded byte range, verify its sha256 against the plan and embed the segments in plan order, concatenated with no separator, as the diff content of `exact_diff` or `combined_diff`, so that the sha256 of that content is `review-partition.unitEmbeddedDigest` of the unit (T-53-14); add `role_context.review_unit` (id, index, count, plan digest, `segments_digest` equal to that digest), `unit_seams` (the seam edges touching this unit), `review_route` (the partitioned record from the plan) and `review_scope`; the unit instruction says to judge only the supplied unit, to use the seam list for cross-unit concerns and to leave other units to their own dispatches; the packet carries the same plans and architecture records as an inline review so each unit's overhead is the plan's recorded overhead; `signals.inputTokens` is the whole review's work estimate stored in the plan; the dispatch subject is a `review-part` subject; the result echoes `review_unit` and is validated by the unit branch of `validateHybridResult`; the sealed manifest records the subject kind.
- Aggregate and reducer dispatches: build the packet without diff content (identity-only `exact_diff` or `combined_diff` objects) and with `review_aggregate` data: the complete change inventory rows (path, status, blob ids, sizes, additions, deletions) without text, for each input unit or node its outcome, completeness, bounded summary and artifact digest read from the ledger, the seam inventory for aggregate inputs, the reduction levels and `ledger_digest`; `verifyLedger` runs before launch with `rereadArtifact` implemented through the host's own artifact validator and satisfying the contract of T-53-15 (for each unit record it returns the artifact digest, the packet digest, the unit id and plan digest, and `embedded_sha256`, the sha256 of the diff content of the authenticated original packet the unit's reviewer was shown, re-extracted from the unit's pinned archive by the original-packet extraction the consumers use, never from the ledger record or the model's result; the host exports it as `unitArtifactReader(options)` so the coordinator's adapter, T-53-29, passes the same reader to its final check; the exported `prepareIntegratorContext` takes the reader as `options.unitArtifactReader`, defaulting to the Claude reader, so the Codex host, which calls it as the shared preparation, passes the reader of its own sealed artifacts, T-53-26) and with `coverage: gitCoverageSource({ worktree, handle })` (T-53-15), which recomputes the review rows and segment bytes from git at the ledger identity; the coverage is mandatory, and a result with `ok: false` (a plan that omits a row, duplicates one, does not tile a split file, whose rows differ from git, or in which a counted unit's sealed packet did not embed its planned bytes, `unit-packet-mismatch`) refuses the dispatch before launch with `REVIEW_COVERAGE_INVALID` naming the first problem and path or unit; the change inventory rows of the packet are the rows `gitCoverageSource` returned, never a copy from the plan, so the aggregator is shown exactly the set the proof covered; the frozen `verifyLedger` result is the `ledger` input of the aggregate branch of `validateHybridResult`, so the result is validated against a coverage-verified ledger; the aggregate dispatch uses the normal phase subject of the role (so it is the artifact the PR-level gate reads) with the hybrid contract and the ledger digest and its result is validated by the aggregate branch including the ledger ceiling; a reducer node uses a `review-part` subject with `part=node:<id>` and is validated like a unit with its inputs echoed.
- Dispatch subject kind. The unit and reducer dispatch passes the review-part subject as `context.ticket` with `subject_kind: "review-part"`, which the boundary admits since T-53-18 (it refuses a review-part ticket under every other kind, so this is required, not optional); the launch adapter's own context check (`claude-role-host.cjs:1147-1150`) accepts `review-part` for a unit or reducer launch and keeps requiring `phase` for a phase binding and `round` for the sentinel; the aggregate keeps `subject_kind: "phase"` for the architecture review and the plain integrator subject for the integrator. The receipt of a unit therefore records `subject_kind: "review-part"`.
- Evidence file, so consecutive launches stay clean. The integrator's phase evidence file is not scratch, so a unit that wrote it would make the next launch refuse as a dirty worktree. Unit and reducer integrator launches set `prepared.evidencePath` to `.shipyard-integration-part-evidence.md` (T-53-18), pass `evidenceKind: "part"` to `prepareRoleArtifact` and to sealing (T-53-19), and the unit instruction names that file as the only file the reviewer may write; the aggregate integrator launch keeps `.planning/phases/<phase>/INTEGRATION.md`, the file `gsd-sync` and the conveyor read, and it is the last launch. A unit reviewer that writes `INTEGRATION.md` is refused by `assertEvidenceOnlyChanges` as `WORKTREE_MUTATED`. The phase evidence file left by a launch that is not the accepted last one (an escalated inline or pull integrator launch, T-53-20 and T-53-21, or a failed aggregate attempt) is never scratch and this ticket does not make it so: the coordinator rotates it between attempts of one run through `prepareRoleArtifact` (T-53-29), and the host-level contract that makes this necessary and sufficient is pinned by the T-53-20 case. The architecture review keeps `.shipyard-arch-review-evidence.md` for units, reducers and the aggregate. Every hybrid request already runs `canonicalWorktree` with the aggregate flag (T-53-20), which ignores the archive directory the previous launch's seal left behind.

## Acceptance criteria

- A unit request on a fixture with three units embeds only that unit's segments (a path of another unit does not appear), refuses a segment whose recomputed sha256 differs, refuses a different head, base or ticket set and a plan digest that differs from the request, and its `signals.inputTokens` equals the plan's whole-review work estimate.
- A unit result with the wrong `review_unit` echo is refused; a correct one seals under a `review-part` subject, is ignored by `currentArchitectureVerdict` and `currentIntegrationVerdict`, and the manifest records its subject kind.
- An aggregate request refuses when the ledger is missing a unit, has a tampered record or an artifact whose re-read digest differs; with a complete passing ledger its packet has no diff text, lists every unit's summary and the seam inventory and carries the ledger digest; a result of `passed` (or `conform`) with a failing or incomplete unit in the ledger is refused with `REVIEW_VERDICT_EXCEEDS_LEDGER`; a correct aggregate seals under the normal phase subject with the hybrid contract and ledger digest.
- Omitted row: on a three-unit fixture over a real repository, an aggregate request whose ledger plan was built from the git rows minus one row (every unit recorded complete and passing with authentic artifact digests) refuses before launch with `REVIEW_COVERAGE_INVALID` naming `row-uncovered` and the omitted path, and the fake runtime is never called; the same fixture planned from the full rows launches and its packet's change inventory equals an independently computed `git diff --raw` classification of the range.
- Runtime and subject: a unit or aggregate request against a ledger created for runtime `codex` (the same plan, head and base) refuses with `REVIEW_LEDGER_RUNTIME`; a ticket-level architecture review (no `phase`) carrying `review_unit` or `review_aggregate` refuses with `REVIEW_PARTITION_UNSUPPORTED` and an integrator or phase architecture request is unaffected.
- A reducer node dispatch echoes its inputs and seals under its `review-part` node subject.
- Unit packet at verification time: on the three-unit fixture an honest unit's `unitArtifactReader` result carries `embedded_sha256` equal to `unitEmbeddedDigest` over bytes read from git and the aggregate launches; a ledger in which the record of unit `u02` was planted (through the real `recordUnit`, with an otherwise valid receipt and artifact digest) with the sealed artifact of `u01`, or of a `u02` sealed under another plan of the same head and base, refuses the aggregate before launch with `REVIEW_COVERAGE_INVALID` naming `unit-packet-mismatch` and `u02`, and the fake runtime is never called.
- Clean worktree between launches: two consecutive integrator unit launches in one worktree (the fake runtime writes the part evidence file each time and the host seals each judgment, which leaves the sealed archive directory `.shipyard-role-artifacts/<digest>/` in the worktree) both pass preparation, the second is not refused as dirty, and `statusIgnoringScratch(worktree, { untracked: 'all', forJudge: false })`, the call every hybrid request makes through the aggregate flag (T-53-20), is empty between them while the same call with the default `forJudge` lists that archive directory as the only dirty path, so the case fails if the flag is dropped; an integrator unit whose reviewer writes `.planning/phases/<phase>/INTEGRATION.md` is refused `WORKTREE_MUTATED`; the aggregate integrator's evidence path is the phase file; a unit receipt records `subject_kind: "review-part"` and the launch adapter accepts it.
- Inline, pull and legacy cases are unchanged.
