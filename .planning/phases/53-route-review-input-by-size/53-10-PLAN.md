## Scope

New `review-measure-codex.cjs`, registered in `review-measure.cjs`:
- `synth-codex-packet --bytes N --out <file>`: a deterministic semantic-content packet of N bytes (default 2,600,000) for the batch reader.
- `probe-codex-batch --bytes N --model <id> --effort <e> --out <dir> [--live]`: default dry run; with `--live` and `SHIPYARD_REVIEW_MEASURE_LIVE=1` it prepares host-file input from the synthetic packet with the automatic reader profile and launches one Codex child through the existing capacity-probe path with an injectable spawn, saving the native session and the host's consumption summary.
- `ingest-codex-session --session <file>`: reports whether a turn completed, whether a compaction record is present, the physical and logical read counts, any truncation flag and the usage input tokens, listing unrecognized record kinds.
- `ingest-receipt --receipt <file> --kind claude-integrator|codex-integrator`: extracts `applied_model`, `applied_effort` and, for Codex, `sandbox_evidence.base_profile` and the generated agent file name, from a dispatch receipt file the operator copies out of the evidence store; refuses a file that is not a receipt and never searches for one.
Each ingest accepts `--record`. Update the items `window.gpt-6.1-sol`, `codex-batch-reader-2.6mb`, `phase50-integrator-model-effort` and `codex-integrator-sandbox` from tooling-pending to `owed` with exact commands; the markdown Runbook gains the Codex steps and the evidence-store steps (copy the receipt out, then ingest).

`show --gate` is added to the `show` subcommand of T-53-07: it prints the six knobs, each `unlocked` or `locked` with its blocking items and reasons, calling `knobGate` on the record at `--record` (default the shipped one).

Operator checkpoint (where the operator measures and signs; this ticket carries `human_checkpoint: merge`, which Gate 2 lets the operator pre-authorize ticket by ticket and which then stops waiting for a person, so the checkpoint is not what keeps thresholds conservative whichever way the operator decides: the signed record read by the router is). After this ticket every Claude, Codex and evidence-store item that needs a live account is `owed`, so the Runbook gains an `Operator checkpoint` section that lists each owed item (id, exact command, evidence file to pass to which ingest, the threshold knobs it informs from the record's `informed_by` lists) and the three steps the operator takes, at any time and in any merge order: run any of the owed commands they choose and ingest each result with `--record` (which turns that item `measured` and, because it changes the item's content, leaves it unsigned); run `review-measure.cjs signoff --operator <name> --item <ids>` for each item whose current content they accept (measured evidence, or an owed item or limitation they accept leaving as it is); confirm with `review-measure.cjs show --gate` which knobs are now unlocked and with `review-measure.cjs validate --signed` that every item carries a current entry. Until the operator does so, `validate --signed` exits 1 naming the items without a current entry, which is expected and is not a defect, and every knob that has an unmeasured or unsigned informing item stays at its conservative default because the router enforces it (T-53-11), whatever this pull request's approval says. No CI job and no test needs the operator to have acted. Record keys: `ingest-codex-session --record --item window.gpt-6.1-sol` writes `observed.usable_input_tokens` (the T-53-07 key) only for a session that completed with no compaction record, from the estimator tokens of the supplied probe input, and otherwise records the refusal or compaction under other keys and leaves the item unmeasured. Every subcommand of this ticket is registered through the table of T-53-07 and so appears in `review-measure.cjs --help`.

## Acceptance criteria

- `synth-codex-packet` is deterministic and exactly N bytes; the dry-run probe never calls spawn; with both opt-ins and a fake spawn it saves evidence.
- `ingest-codex-session` on the captured Codex streams reports completion, counts and usage; a hand-built session with a compaction record reports `compacted: true`; an unknown record kind is listed.
- `ingest-receipt` extracts the model, effort and sandbox profile from a hand-built receipt of each kind, and refuses a non-receipt file with a named error.
- `validate --final` exits 0 after this ticket. On a scratch copy of the shipped record with no sign-offs, `validate --signed` exits 1 and names every item that lacks a current entry (asserted by a test on the copy and never on the shipped file, so the operator's later measurements or sign-offs cannot break the suite); on the shipped record itself it exits 1 until the operator acts, which the executor reports in its summary and does not "fix".
- `show --gate`: on a scratch copy built in memory with the window, estimator and reader items measured and signed it prints `review_inline_max_tokens` unlocked and `review_pull_max_tokens` locked naming the remaining owed items; on a copy with nothing signed it prints all six locked; its output agrees with `knobGate` for each knob.
- Record keys and usage: on a scratch record, `ingest-codex-session --record --item window.gpt-6.1-sol` on a completed captured session writes a positive integer `observed.usable_input_tokens`, a session with a compaction record writes none and leaves the item unmeasured, and the result passes the T-53-07 validator; `review-measure.cjs --help` lists `synth-codex-packet`, `probe-codex-batch`, `ingest-codex-session`, `ingest-receipt` and the `show --gate` option with their options.
- Every item whose status is `owed` in the shipped record appears in the Runbook's `Operator checkpoint` section with its exact command and the knobs it informs (a test asserts that inclusion, so items the operator has since measured may remain listed), and the section carries the three operator steps; no executor step runs a live probe or the signoff command.
