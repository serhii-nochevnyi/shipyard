<objective>Add the runtime-neutral coordinator that turns a single review request into the right sequence of ordinary host dispatches and returns one verified result, so deliver's integrator and architecture-review steps call one entry for every size.</objective>

## Goal

ADR-033 R-1 and R-4 (D-01, D-04). One host instance performs one launch (research `constraints.md` TC-4), so the hybrid's multi-launch route needs an orchestrator above the hosts. The ADR: "a route that cannot close its proof escalates to the next route and never accepts a partial review"; "each unit is an ordinary receipt-verified dispatch"; "the graph-directory fix is a hard dependency" because N launches each rewrite tracked graph files; the unit count multiplies launches and receipts. The coordinator is a library like the hosts (`deliver.md` calls the host libraries); its tests inject fake hosts.

`depends_on` is `[T-53-26]` (fourth round; it was T-53-27). The coordinator imports the hosts and their exported readers (T-53-20 to T-53-26), the router, partition, ledger, reduction and contract modules (T-53-11 to T-53-17, all ancestors of T-53-26 through the host chain) and the existing `prepareRoleArtifact` export; it uses no code from the consumer branches of T-53-27 (it proves the ledger itself with `verifyLedger`, and the consumers stay an independent re-derivation at consumption time) and shares no file with T-53-27 or T-53-28, whose files are `role-artifact.cjs`, `codex-arch-review-context.cjs` and their tests. So it runs beside them, and T-53-30 and T-53-31 still follow it.

## Scope

New `review-coordinator.cjs` exporting `runReview({ runtime, role, request, hosts, options })`, `claudeHosts(options)` and `codexHosts(options)`. `hosts` is `{ measure(request), run(request), rereadArtifact(record) }`; the adapters build them from each runtime's real host (a fresh host instance per `run`), with `rereadArtifact` the unit artifact reader the same runtime's aggregate preparation uses (`unitArtifactReader` of `claude-role-host.cjs` T-53-22, of `codex-arch-review-context.cjs` T-53-24 and of `codex-delivery-host.cjs` T-53-26), so the final check below proves each counted unit's sealed packet embedded its planned bytes with the same reader the host used before the aggregate launch, pass `options.reviewRouting` and `options.reviewRoutingRecord` through to the host so thresholds always come from `thresholdsFrom` and the signed-record gate (T-53-11), and build only requests the host's own request parser admits (the Claude `parseRequest`, the Codex `requestValue` as extended by T-53-23 to T-53-26). `runReview` refuses a request whose `review_contract` is not one of the two hybrid strings with `REVIEW_CONTRACT_NOT_HYBRID`, naming that legacy contracts, including a Codex v1 caller's own-diff request, are served by calling the host directly and are never routed, and that the coordinator applies no pathspec to a caller-supplied diff. Flow: `measure` returns the route record and work; inline or pull: `run` the request with the hybrid contract; if the result is `incomplete`, if validation refuses with a route-proof code, or if the host raises `REVIEW_PARTITION_REQUIRED` or `REVIEW_ROUTE_UNAVAILABLE` carrying a `blocker` (the Codex hosts raise it with `transport-limit` when the packet does not fit the 1 MiB inline transport, T-53-25), re-run with `review_min_route` set to `nextRoute(...)` for that blocker; a `transport-limit` raised by a unit, reducer or aggregate launch is not escalated (there is no higher route) and fails the run with `REVIEW_UNIT_FAILED` naming the blocker and the knob to lower (`review_unit_budget_tokens`); partitioned: refuse with `REVIEW_UNIT_LIMIT` (naming the plan count, `review_max_units` and the knob to raise) when the plan has more units than `review_max_units`; build rows with `measureRows`, the plan with `planPartition` (budget and overhead from the thresholds and measured material), the seam inventory, the ledger identity (repository, subject, head, base, plan digest) and `createLedger`; for each unit not yet counted run `{ review_unit }` through `hosts.run`, verify the returned receipt and artifact fields, `recordUnit` (or `recordFailure` and one retry, then `REVIEW_UNIT_FAILED` naming unit and cause); before the first launch and after each launch require a clean worktree (the one status call named in Scratch and archive handling below) and refuse with `REVIEW_WORKTREE_DIRTY` naming the dirty paths, `--graph-dir` and the `graphDir` option when they are tracked graph files, and the file and the remedy (rotate the role-owned file with `node ${CLAUDE_PLUGIN_ROOT}/scripts/role-artifact.cjs prepare --worktree <worktree> --role integrator --phase <phase>`, then rerun, which resumes from the ledger) when the dirty path is the integrator's `.planning/phases/<phase>/INTEGRATION.md` left by an earlier call, for example by an aggregate attempt that failed after writing it (the coordinator cannot prove who wrote a file it did not see written, so across calls it never deletes it; unit and reducer launches write the scratch part evidence file instead, T-53-18); within one call the rotation of that file between attempts is the escalation rule below; before every launch compare head and base with the ledger identity and, if moved, abandon the run and start a new one (all units re-owed); plan the reduction with `planReduction`, run each node as `{ review_aggregate: { run, node } }` and `recordNode`; run the aggregate; `verifyLedger` and return `{ route: "partitioned", result, ledger_digest, units }` only if the aggregate's verdict is within `ledgerVerdictCeiling`; a rerun with the same run id resumes from the ledger without relaunching counted units. Every dispatch result, route record and escalation is returned in an ordered `trace`.

Request shape (fourth round; this is how a built request reaches `runReview`, and T-53-31 prescribes it). `request` is the host's own request object with the hybrid fields added and nothing else changed. Claude: the `shipyard.claude-role-request.v1` object, which for the phase architecture review is exactly what `deliver-dispatch.cjs build arch-review <phase-directory> --phase <N> --pr <N> --runtime claude` prints (`{ schema, role: "arch-review", worktree, phase, pr, repo }`) and for the integrator the object `deliver.md` builds (`{ schema, role: "integrator", worktree, phase }`), plus the top-level field `review_contract` (the hybrid string of the role) and optionally `review_min_route`. Codex: the object the same builder prints for the phase architecture review (`{ scope, graph_dir, role, signals, context }`) or the integrator call of `deliver.md` (`scope` plus `{ role, dispatch_id, context }`), plus `context.review_contract` and optionally `context.review_min_route`; the adapter takes `scope` and `graph_dir` out of it, passes them to the host constructor (`graph_dir` as the `graphDir` option) and passes the rest to `run`, and for a unit or reducer launch sets `scope.ticket` to the review-part subject of that unit (T-53-18, T-53-24, T-53-26) while the aggregate keeps the phase subject. The coordinator adds only `review_contract`-family fields it was not given (`review_min_route` on escalation, `review_unit`, `review_aggregate`); it never rewrites the identity fields of the built request, and a request whose identity the host's parser refuses is refused by that parser. A ticket-level architecture request (no `phase`) built by `deliver-dispatch.cjs build arch-review <ticket> --runtime claude --pr <N>` reaches the coordinator the same way and is refused by name where its work needs the partitioned route (below).

Scratch and archive handling (fourth round). Every check of this ticket that asks whether the worktree is clean, the check before and after each launch and the eligibility test for the rotation below, is the one call `statusIgnoringScratch(worktree, { untracked: 'all', forJudge: false })` of `conveyor-scratch.cjs`, which is the call the hosts make for every hybrid request (`canonicalWorktree` with the aggregate flag, `forJudge: !aggregate`, T-53-20; the function's default is `forJudge: true`, under which the archive directory counts as dirt). It matters because every launch seals its judgment and the seal (`ensureArchiveDirectory` of `role-artifact.cjs`) leaves an untracked directory `.shipyard-role-artifacts/<sha256 of the dispatch id>/` in the worktree; nothing hides it (no `.gitignore` entry), so under the default option the second launch of every run, and every rotation, would be refused as dirty although only the host's own sealed archive is present. The accepted scratch is therefore exactly: the files of `SCRATCH_FILES` (including `.shipyard-integration-part-evidence.md`, T-53-18) and untracked entries under `.shipyard-role-artifacts/`; nothing else is ignored. Every other untracked or modified path, a tracked graph file and the phase evidence file included, is dirt that is named in `REVIEW_WORKTREE_DIRTY`. The archive directory is never listed in that error, never deleted and never rotated by the coordinator (it is the host's retained evidence, pinned by the ledger records). The rotation condition "that one path is the only dirty path" is evaluated on this call's entries, so it holds after a real launch that sealed a judgment (entries: `?? .planning/phases/<phase>/INTEGRATION.md` alone) and fails when a tracked graph file is also modified.

Escalation and the phase evidence file (within one call). An inline or pull integrator launch that is about to be escalated (its result is `incomplete`, validation refused it with a route-proof code, or the host raised `REVIEW_PARTITION_REQUIRED` or `REVIEW_ROUTE_UNAVAILABLE` after the launch) leaves `.planning/phases/<phase>/INTEGRATION.md` untracked and not scratch, so the next launch's `canonicalWorktree` refuses it as a dirty worktree (the contract pinned by the T-53-20 and T-53-25 cases). Before re-running with the higher floor the coordinator rotates that one file through `role-artifact.cjs` `prepareRoleArtifact({ worktreePath, role: "integrator", phase })`, the exported function behind the `role-artifact.cjs prepare` command that `deliver.md` already runs before every integrator prompt, so the sanctioned owner of that role-owned file clears it and the coordinator performs no ad hoc deletion. It does so only when all of these hold: this same `runReview` call launched the attempt (the trace records it) after its own clean-worktree check passed, so the file did not exist or was clean then; after the launch the scratch-aware status call above (`forJudge: false`, so the sealed archive directory the launch left is not dirt) shows exactly that one path as the only dirty path (a tracked graph file or any other path still refuses with `REVIEW_WORKTREE_DIRTY` and its remedy and nothing is rotated); and it first records the file's sha256 and byte length in the attempt's trace entry (the host's sealed archive keeps the content). An architecture-review attempt needs no rotation (its evidence file is scratch). Escalating from an incomplete inline or pull integrator review therefore needs no manual deletion.

Runtime and role binding. The ledger identity the coordinator builds is `{ repository, subject, role, runtime, head, base }` (T-53-14, T-53-15), `runtime` being the runtime of the adapter in use, so the run id a Claude coordinator created is never the run id a Codex coordinator computes for the same head, base and plan, and a resume by run id passes `runtime` to `openLedger`, which refuses another runtime's run with `REVIEW_LEDGER_RUNTIME`; the hosts check it again at every dispatch (T-53-22, T-53-24, T-53-26). The adapters stay provider-pure: no fallback to the other runtime exists and a failed run is never completed by the other.

Set-cover callers. The coordinator is one of the three production callers of the coverage proof, with the hosts' aggregate preparation and the consumers. After `planPartition` and before any launch it recomputes the rows from git with `gitCoverageSource` (never from the rows it planned with) and runs `review-partition.verifyCoverage` on the plan: a plan that omits or duplicates a row, whose rows differ from git or whose segments do not tile a split file refuses with `REVIEW_COVERAGE_INVALID` naming the problem and path before any launch; the planner is replaceable only through the test dependency object `options.deps.planPartition`, which production code never sets. A resume gets the same check on the stored plan of the opened ledger. The final check is `verifyLedger` with a freshly built `gitCoverageSource` and `hosts.rereadArtifact`, so it covers the unit packet proof of T-53-15 (a record planted with another unit's or plan's sealed artifact gives `unit-packet-mismatch`) as well as the row coverage: `runReview` returns `{ route: "partitioned", ... }` only when the frozen result is `ok: true` and the aggregate's verdict is within the ceiling of that coverage-verified ledger, and no code path of the coordinator calls `verifyLedger` or `ledgerVerdictCeiling` without the coverage input.

Ticket-level architecture reviews. The partitioned route exists for a phase subject only (`partitionSupported` of T-53-17, R-4 "judges the phase"). For a ticket-level architecture review (a request without `phase`) whose measured or floored route is `partitioned`, `runReview` refuses before any launch with `REVIEW_PARTITION_UNSUPPORTED`, naming the subject kind and the remedy (review that ticket on the legacy focused contract, or split the ticket), and a host that raises the code mid-flow has it propagated unchanged; inline and pull escalation for such a review proceeds as for any other and ends in that refusal rather than in a partial review. The integrator and the phase architecture review are unaffected.

## Out of scope

Choosing thresholds; host internals; `deliver.md` text (T-53-31); parallel unit execution (units run sequentially because each host instance and the single role evidence file are exclusive).

## Acceptance criteria

- Inline small review: one `run`, route inline, trace has one entry; the coordinator adds nothing to the host request except the hybrid contract and any floor.
- A pull review whose result is incomplete, and one whose host raises `REVIEW_PARTITION_REQUIRED`, escalate to partitioned with the original dispatch kept in the trace as history; an inline request on a partitioned-size epic never launches a single over-window dispatch.
- Partitioned happy path with 5 units and fan-out 8: five unit runs in order, then the aggregate; the final result is returned with the ledger digest. With fan-out 2: reduction levels run before the aggregate and every node is recorded.
- A unit that fails once is retried once; failing twice raises `REVIEW_UNIT_FAILED`; killing the coordinator after unit 3 and rerunning resumes with units 4 and 5 and launches nothing for units 1 to 3.
- A head or base move between units starts a new run with no counted units; a tampered ledger refuses; a dirty worktree after a launch refuses with the remedy; a plan above `review_max_units` refuses before any launch.
- A host raising `REVIEW_ROUTE_UNAVAILABLE` with `blocker: "transport-limit"` on an inline request escalates to pull and then partitioned with the original dispatch in the trace; the same blocker from a unit run fails with `REVIEW_UNIT_FAILED` naming `review_unit_budget_tokens`.
- Scratch and archive: every fake host leaves, after each launch, what a real launch leaves: the sealed archive directory `.shipyard-role-artifacts/<sha256 of the dispatch id>/` with one file in it (created through the real `ensureArchiveDirectory` path or a directory of exactly that shape), beside the evidence file the real host writes (the part evidence name for units and reducers, the phase file for inline, pull and aggregate integrator launches). A five-unit run completes, so the second and later launches are not refused as dirty; the coordinator's checks use the real `statusIgnoringScratch` on the real throwaway repository with `forJudge: false` (a mutation of the case that makes the coordinator call it with the default `forJudge` refuses the second launch with `REVIEW_WORKTREE_DIRTY` naming the archive directory, so the case fails if the option is dropped); `REVIEW_WORKTREE_DIRTY` never names the archive directory and the archive directory is never deleted or rotated; a modified tracked graph file or an untracked file that is neither a scratch name nor under the archive directory is still named and still refuses, with the archive directory present beside it.
- An aggregate attempt that fails after leaving `.planning/phases/<phase>/INTEGRATION.md` (the fake host writes the file where the real host does) makes a rerun in a new call refuse with `REVIEW_WORKTREE_DIRTY` naming that file and the `role-artifact.cjs prepare` command as the remedy, and nothing is deleted; after the test runs that command the rerun launches only the aggregate and no unit; a tracked graph file left modified is reported with the `--graph-dir` remedy.
- Escalation after an incomplete integrator launch (the fake host also leaves its sealed archive directory, as above, so the rotation condition "that one path is the only dirty path" is exercised against a realistic status): a fake inline integrator host that writes `INTEGRATION.md` and returns `incomplete` is followed, in the same call, by a pull or partitioned launch that passes the clean-worktree check because the coordinator rotated the file through `prepareRoleArtifact` first; the trace entry of the first attempt carries the file's sha256 and byte length, no manual deletion happens, and the second launch does not see the first one's file; when a tracked graph file is also modified after the first launch the coordinator refuses with `REVIEW_WORKTREE_DIRTY` and its `--graph-dir` remedy and rotates nothing; an architecture-review escalation needs no rotation; the same escalation with an `INTEGRATION.md` that existed and was clean before the first launch (the coordinator's own pre-launch check) is refused rather than rotated.
- Coverage callers: with a faulty planner injected through `options.deps.planPartition` that drops one row, `runReview` refuses with `REVIEW_COVERAGE_INVALID` naming `row-uncovered` and the path before any host `run` call; with a ledger created directly by `createLedger` from a plan that omits a row and resumed by run id, the resume refuses before any launch with the same code; when every unit and the aggregate are complete and passing but the stored plan omits a row (planted after the pre-launch check by writing the ledger through the test's own handle), the final `verifyLedger` returns `ok: false` and `runReview` raises `REVIEW_COVERAGE_INVALID` instead of returning a result; the same inputs with the full row set return the result. Unit packet proof: with the fake hosts' `rereadArtifact` implemented from their recorded packets (it returns the digest of the diff content each fake host really embedded, computed through `unitEmbeddedDigest`), the honest run returns its result; a ledger in which the record of unit `u02` was planted with the artifact of `u01` makes the final check raise `REVIEW_COVERAGE_INVALID` naming `unit-packet-mismatch` and `u02` instead of returning a result.
- Runtime binding: a run id created by the Claude coordinator passed to the Codex coordinator for the same head, base and plan refuses with `REVIEW_LEDGER_RUNTIME` before any launch; the Codex coordinator given the same head, base and plan without a run id creates a different run with a different id and launches every unit; neither adapter constructs the other runtime's host (the existing spy cases) and the ledger records of one runtime never appear in the other's trace.
- Ticket-level architecture review: a request without `phase` whose measured route is `partitioned` refuses with `REVIEW_PARTITION_UNSUPPORTED` before any launch, naming the subject kind and the legacy-contract remedy; the same review at inline or pull size runs normally; a host that raises `REVIEW_PARTITION_UNSUPPORTED` has it propagated unchanged; an integrator and a phase architecture review of the same size partition normally.
- An aggregate verdict above the ceiling is not returned (the host refuses and the coordinator raises).
- Legacy contract requests are not routed: `runReview` refuses a request with no contract string, with `shipyard.integration-review.v1`, with `shipyard.integration-review.v2` and with `shipyard.focused-architecture-review.v1` (or any other non-hybrid string) with `REVIEW_CONTRACT_NOT_HYBRID` before any measure or run call, so a Codex v1 caller supplying its own `diff` can neither reach a route nor be mistaken for a host-scoped review.
- Threshold gate in the coordinator: the cases that set `review_reduction_fanout` (fan-out 2) or `review_max_units` below their defaults inject `reviewRoutingRecord: unlockedRecord()`, because only the three token knobs honour tightening without a signed record; a companion case shows that the same configuration with `lockedRecord()` yields fan-out 8 and 64 units (source `default-locked`) and that the coordinator then plans with those values; the cases that shrink `review_unit_budget_tokens` to force several units need no record.
- Request path: every request the Codex adapter builds (inline, pull floor, partitioned floor, unit, reducer node, aggregate, for both roles) passes the exported `validateArgs` of `codex-delivery-host.cjs` (which calls `requestValue`), and every request the Claude adapter builds passes `parseRequest`; a request with a hybrid selector but a legacy string is refused by the real parser, not only by the coordinator.
