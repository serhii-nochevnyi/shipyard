## Scope

In `authenticateCurrentCoverage` and the two current-verdict functions add hybrid branches (both roles, Claude and Codex originals): re-extract the original packet or runtime binding as today; require the hybrid contract in the sealed `current_review`; compare the route record digest of the packet with the result's and the sealed manifest's; by route: inline checks the embedded-diff identity as the focused branch does; pull requires the manifest in the original packet to hash to the bound manifest digest and `validateCoverage` of the result's inventory against it; partitioned aggregate requires the original packet's ledger digest to equal the result's, opens the ledger by run id (`openLedger` with the runtime the artifact's receipt records, so a ledger created for the other runtime or role refuses), and runs `verifyLedger` with `rereadArtifact` implemented through the existing artifact validation of each unit record's pinned archive and satisfying the contract of T-53-15 (the artifact digest, packet digest, unit id and plan digest and `embedded_sha256`, the sha256 of the diff content of the authenticated original packet the consumer re-extracts from that archive, by the Claude or the Codex original-packet extraction it already uses for the aggregate's own packet, never from the ledger record or from fields the artifact declares about itself) and with `coverage: gitCoverageSource({ worktree, handle })` (T-53-15), which recomputes the review rows and segment bytes from git at the ledger identity; `coverage` is mandatory here and is never taken from the artifact or the plan, so the consumer itself proves that every changed row sits in exactly one counted unit and that each counted unit's sealed packet embedded exactly its planned segment bytes, and a plan that omits or duplicates a row, whose rows differ from git, or in which a counted unit's packet embedded other bytes or belongs to another unit or plan (`unit-packet-mismatch`) refuses with `REVIEW_COVERAGE_INVALID` naming `coverage` and the first problem and path or unit. The verdict must be within the ceiling of that coverage-verified ledger and the frozen `verifyLedger` result is the `ledger` input of `validateHybridResult`. A hybrid candidate whose route is `partitioned` and whose subject fails `partitionSupported` (T-53-17: a non-phase architecture subject) refuses with `REVIEW_COVERAGE_INVALID` naming `partition-unsupported`. The producer pin loop applies to the hybrid Claude architecture review exactly as to the focused one (the pinned file list is unchanged). A hybrid candidate whose `review_completeness` is not `complete` is skipped; a hybrid candidate with a string other than the two hybrid strings, or whose route proof fails, refuses with `REVIEW_COVERAGE_INVALID` naming the failing check. Candidate selection still ignores `review-part` subjects. Legacy contracts follow their existing branches byte for byte.

Contract sites owned here (the `CONTRACT_SITES` table of T-53-17, v0.73.0 anchors; each is re-read first and gets either a hybrid branch ahead of the legacy one or the family predicate, never a loosened comparison): focused string, original packet and response extraction `:3165`, `:3224`, `:3443`, `:3545-3549`, `:3564`; the Claude and Codex focused branches of `authenticateCurrentCoverage` `:3252`, `:3278`, `:3282-3283`, `:3314`; the focused membership check of current admission `:3585-3586`; the completeness gate of `currentArchitectureVerdict` `:3878`, which skips a hybrid candidate whose `review_completeness` is not `complete` exactly as it skips a focused one; integrator contract `:3331` (expected `shipyard.integration-review.v2`) and `:3333` (legacy v1) which gain the hybrid branch before them, `:3467` (the inline v2 identity check, unchanged for v2) and `:3798` (the default contract recorded for a legacy candidate, which a hybrid candidate overrides with its own). `:5629` and the sealed `current_review` record belong to T-53-19. The v2-only sites that a hybrid integrator never reaches (`codex-arch-review-context.cjs:643`, `codex-runtime-host.cjs:3455`) are not touched.

## Acceptance criteria

- A host-sealed hybrid inline architecture review and integrator verdict are accepted as current authority; a pull verdict is accepted when its inventory equals the manifest and refused when the sealed inventory or manifest digest differs, when `complete` was declared with a limitation, or when the original packet's manifest was altered; an `incomplete` pull verdict is not authority.
- A host-sealed aggregate over a complete passing ledger is accepted; it is refused when the ledger is missing, a unit record or its artifact digest was altered, a unit is missing or failing, the ledger digest differs, or the verdict exceeds the ceiling; a sealed passing review-part judgment alone is never returned.
- Omitted row at the consumer: a host-sealed aggregate over a ledger whose plan was built from the git rows minus one row (every unit and its artifact intact, a complete passing ledger by every other measure) is refused by both current-verdict functions with `REVIEW_COVERAGE_INVALID` naming `coverage`, `row-uncovered` and the omitted path, and is accepted when the plan was built from the full rows; an aggregate over a ledger created for the other runtime, and a partitioned hybrid artifact under a ticket-level architecture subject, are each refused with the named check.
- Unit packet at the consumer: a host-sealed aggregate over a ledger in which the record of unit `u02` was planted (through the real `recordUnit`, every receipt and artifact digest intact) with the sealed artifact of `u01`, or of a `u02` sealed under another plan of the same head and base, is refused by both current-verdict functions with `REVIEW_COVERAGE_INVALID` naming `coverage`, `unit-packet-mismatch` and `u02`, and the honest ledger is accepted; the same two plantings are refused for Codex-sealed architecture-review and integrator aggregates in the new Codex consumer file.
- Codex originals (new file `tests/unit/review-routing-consumers-codex.test.cjs`, which begins with the isolation guard): hybrid artifacts sealed by the Codex hosts, the architecture review through `codex-arch-review-context` `prepare` and `finish` on the shared collector fixture (inline, pull, aggregate) and the integrator through `createCodexDeliveryHost` with the fake native runtime and the fixtures of T-53-25 and T-53-26 (inline, pull, aggregate), are read through `currentArchitectureVerdict` and `currentIntegrationVerdict` and `gate-trailer.verifyArchitectureTarget`: accepted when every proof holds and each refused for the same separate tamperings as the Claude cases (manifest digest, declared inventory, ledger digest, a unit record, a unit artifact digest, the verdict, the omitted-row plan, the swapped unit artifact), with a legacy Codex focused verdict and a legacy v2 integrator verdict accepted unchanged beside them.
- `gate-trailer.cjs verifyArchitectureTarget` accepts the accepted aggregate and refuses the refused ones in the same fixtures.
- A hybrid candidate with an unknown contract string refuses; legacy focused, legacy integrator and lineage cases in the existing tests pass unchanged; changing a pinned producer file refuses a hybrid Claude architecture verdict as it does a focused one.
