## Scope

- `parseRequest` and the exported `prepareIntegratorContext` (which the Codex host calls, `:670-676`): the integrator accepts `review_contract` of the legacy two or the hybrid string and the new optional `review_min_route`; the architecture review accepts `review_contract` equal to the hybrid string and `review_min_route`; selectors are parsed with `review-contract-v3.parseSelectors`. A request without a contract string, or with a legacy one, takes today's path unchanged.
- New exported `measureReview(options, request)`: performs the same preflight as a run (clean tree, graph, live PR or merged-PR identity) and returns `{ route_record, work, review_scope }` without building the embedded packet, launching or writing; the work is `measureWork` over the `measureRows` diff bytes at the configured context, the required material bytes (plans, selected architecture records, selected backlog, reference text) and the metadata bytes (change inventory and `review_scope`); thresholds are `thresholdsFrom(config, { record: options.reviewRoutingRecord })` (T-53-11), where `config` is `loadConfig` for the project root overlaid with `options.reviewRouting` (a test and embedding override that is itself subject to the signed-record gate: a raise above a default takes effect only through an unlocked record), and the route record carries `thresholds` and `threshold_sources`.
- Hybrid `prepareIntegrator` and `prepareArch`: obtain the route record first; the inline route builds the packet with `reviewDiff` at `review_context_lines`, adds `role_context.review_contract`, `review_route` and `review_scope`, and sets `signals.inputTokens` to the work estimate; the instruction text states the contract and route; `roleOutputSchema` allows the hybrid result fields; `validateResult` uses `review-contract-v3.validateHybridResult` for hybrid requests, with identity echoes from the host's own binding, and the sealed `host_context` carries the route record.
- A hybrid selection of `pull` is refused with `REVIEW_ROUTE_UNAVAILABLE` naming the route (T-53-21 adds the pull handler) and of `partitioned` with `REVIEW_PARTITION_REQUIRED` carrying the route record, which is the permanent behaviour of a single-launch host; a `review_min_route` above the natural route raises the selection. A ticket-level (non-phase) architecture review, one whose request has no `phase` binding so `partitionSupported` of T-53-17 is false, never takes the partitioned route: where the measured or floored route would be `partitioned` the host raises `REVIEW_PARTITION_UNSUPPORTED` (route record and subject kind attached, naming the remedy: review that ticket on the legacy contract or split it) instead of `REVIEW_PARTITION_REQUIRED`, so no coordinator is invited to partition it. The integrator and the phase architecture review are unaffected.
- Contract sites owned here (the `CONTRACT_SITES` table of T-53-17, v0.73.0 anchors): the allow-lists at `:96` and `:673` (the hybrid integrator string joins the legacy two, through `isSupportedIntegrationContract`); the focused emission at `:527-528` (the packet's `review_contract` and `focused.review_contract` carry the hybrid architecture string for a hybrid request and the legacy string otherwise) and the file-relay binding at `:1453`, which carries the same string as the packet; the `roleOutputSchema` constant at `:992` (`const` for a legacy request, an `enum` of the legacy and hybrid strings otherwise, chosen per request); the aggregate flag at `:915`; and the `:658` v2 lineage branch, which stays v2-only because a hybrid review never inherits a baseline.
- Aggregate worktree flag. `prepareInvocation` calls `canonicalWorktree(..., aggregate)` with `aggregate` true for a phase architecture review and a v2 integrator (`:914-915`), which makes the scratch archive directory `.shipyard-role-artifacts/` ignorable (`forJudge: false`). Every launch seals a judgment into that directory, so a partitioned run's second launch would be refused as dirty for either role without it. For any hybrid request of either role `aggregate` is true, exactly as for those two cases; a legacy request keeps today's value. The graph-dir flag (T-53-03) and the part evidence name (T-53-18, T-53-19, T-53-22) are the other two halves of keeping the tree clean between launches.

## Acceptance criteria

- Legacy requests (no contract string, the two legacy strings) produce the same packets, prompts and signals as before this ticket (the review pathspec of T-53-01 already scopes the host-built diff of every contract, so "as before" means as after T-53-01, with the 50-line context and the prompt-size signal unchanged by this ticket); all existing tests in `claude-role-host.test.cjs` and the legacy 50-line pins pass.
- A hybrid integrator and a hybrid architecture review on a small fixture select `inline`; the diff contains at most `review_context_lines` unchanged lines around each change (asserted at the default without a record, and with the knob at 3 through `reviewRoutingRecord: unlockedRecord()`, because changing that knob is locked without a signed record); no `plugins/shipyard/` path appears; `review_route` and `review_scope` are in the packet and `host_context`.
- The gate holds in the host: with `options.reviewRouting = { review_context_lines: 20 }` and no record the packet's route record shows `thresholds.review_context_lines` 10 with source `default-locked` and the diff carries at most 10 unchanged lines of context; with `reviewRoutingRecord: unlockedRecord()` it shows 20 with source `config-unlocked`.
- `signals.inputTokens` of a hybrid request equals the work estimate computed independently in the test from the measured diff and material bytes, and differs from `ceil(promptBytes/4)` on a fixture where they diverge.
- With both thresholds lowered (tightened, which needs no record) to the same value below the work, a hybrid request is refused with `REVIEW_PARTITION_REQUIRED`; with only the inline threshold lowered below the work (the pull band opens under the default pull threshold) it is refused with `REVIEW_ROUTE_UNAVAILABLE`, because this ticket does not handle the pull route; `review_min_route: "partitioned"` on small work refuses with `REVIEW_PARTITION_REQUIRED`; no route below the natural one is ever selected. The same two settings on a ticket-level architecture review (request without `phase`) refuse with `REVIEW_PARTITION_UNSUPPORTED` carrying the route record and the subject kind, and on an integrator and a phase architecture review still refuse with `REVIEW_PARTITION_REQUIRED`.
- `measureReview` returns the route record without launching or changing the worktree; a hybrid result with a wrong route echo, a missing completeness field or a mismatched identity is refused; an unknown contract string is refused with the existing unsupported-contract error.
- Two consecutive hybrid inline launches of the architecture review in one worktree (the fake runtime seals a judgment each time) both pass preparation, because its evidence file is scratch and the sealed archive directory is ignorable under the aggregate flag, while two consecutive legacy launches behave as they do today.
- The integrator's evidence file is not scratch: after a hybrid inline integrator launch whose fake runtime wrote `.planning/phases/<phase>/INTEGRATION.md` and returned `incomplete`, the next hybrid launch in that worktree is refused with `worktree has local changes before role dispatch` (the behaviour the coordinator must handle, T-53-29), and after `role-artifact.prepareRoleArtifact({ worktreePath, role: "integrator", phase })` (the function behind `role-artifact.cjs prepare`, which `deliver.md` runs before every integrator prompt) has rotated that one file the same launch passes preparation. The case documents the contract the coordinator relies on and changes no host behaviour.
- The packet, the relay binding and the output schema of a hybrid architecture request carry the hybrid architecture string and those of a legacy request still carry the legacy string.
