## Scope

New `review-contract-v3.cjs` exporting: `INTEGRATION_V3`, `FOCUSED_V3`; `isSupportedIntegrationContract(value)` (legacy one, legacy two, hybrid) and `isSupportedArchContract(value)` (focused legacy and hybrid), both false for anything else; `ROUTE_PROOF` (`inline` embedded-diff, `pull` declared-manifest-coverage, `partitioned` ledger-set-cover); `routeRecordDigest(record)`; `buildBinding({ role, subject, route, routeRecord, manifestDigest, planDigest, ledgerDigest })` returning `{ review_contract, route, route_record_digest, proof, manifest_digest, plan_digest, ledger_digest }` and refusing a partitioned route without a plan and ledger digest, a pull route without a manifest digest, and a partitioned route whose `subject` fails `partitionSupported` with `REVIEW_PARTITION_UNSUPPORTED`; `partitionSupported({ role, subject })`, true for role `integrator` (always a phase subject) and for role `arch-review` only when the subject matches `PHASE_SUBJECT` (imported from `architecture-target.cjs`), false for an architecture-review ticket subject, so a ticket-level (non-phase) architecture review, which R-4's aggregator ("judges the phase") does not cover, stays on inline and pull and is refused by name when its work needs the partitioned route; `hybridContractFor(role)` (`INTEGRATION_V3` for `integrator`, `FOCUSED_V3` for `arch-review`, an error for any other role); `parseSelectors(value, role)` validating `review_contract` (only the hybrid string of that role, so the integrator string for role `arch-review` and the reverse are refused; the Claude `parseRequest` and the Codex `requestValue` both call it), `review_min_route` (one of the three routes), `review_unit` (`{ run, unit, plan_digest }`, run a 64-hex id, unit `u` followed by digits, digest 64 hex) and `review_aggregate` (`{ run, node }` with node `aggregate` or a reducer node id), refusing a unit selector together with an aggregate selector and either without the hybrid contract; `validateHybridResult({ role, route, binding, result, manifest, ledger })` with the field rules: common `review_contract`, `review_route`, `route_record_digest`, `review_completeness` (`complete` or `incomplete`), `limitations`, `unresolved_sources` (bounded string lists of at most 128 entries and 1024 bytes each, `complete` requires both empty), and the identity echo the legacy validators require, supplied by the caller in `binding.identity`: for the architecture review `repository`, `id`, `pr`, `head`, `base_commit`, `merge_base`, `base_tree`, `ticket_set_digest`, `context_digest` equal to the binding's and a 64-hex `launch_digest` (the checks of `validateFocusedResult`, whose contract string it hard-codes, so it cannot be reused), and for the integrator `phase`, `head`, `head_tree`, `base`, `base_tree`, `ticket_set` and `ticket_set_digest` (the checks of `validateResult`); pull adds `coverage_inventory` equal to the manifest through `validateCoverage`; unit adds `review_unit` echo equal to the request; aggregate adds `ledger_digest` equal to the ledger's and a verdict (`passed`, or `conform`) permitted only when the ceiling allows it, else the result must declare `incomplete` or the failing verdict. For the aggregate the `ledger` argument is the frozen result `review-ledger.verifyLedger` returned (T-53-15), never a handle or a bare digest: the validator requires `ledger.ok === true`, a 64-hex `ledger_digest` equal to the binding's and a 64-hex `coverage_digest`, derives the ceiling from that result (`ledgerVerdictCeiling` over the same verification), and refuses any other shape, an `ok: false` result included, with `REVIEW_ROUTE_PROOF_MISSING`; so the set-cover over rows recomputed from git has necessarily run before an aggregate can be validated. Errors carry codes `REVIEW_CONTRACT_INVALID`, `REVIEW_ROUTE_PROOF_MISSING`, `REVIEW_COVERAGE_MISMATCH`, `REVIEW_LEDGER_MISMATCH`, `REVIEW_VERDICT_EXCEEDS_LEDGER`, `REVIEW_COVERAGE_INVALID` (the host and consumer refusal that names a failed coverage problem) and `REVIEW_PARTITION_UNSUPPORTED`, held as exported constants so no other module repeats them.

## Acceptance criteria

- The support predicates accept exactly the strings above; `shipyard.integration-review.v4` and any other value are refused.
- `buildBinding` refuses missing digests by route; the binding for each route has the proof named in `ROUTE_PROOF`.
- Selector parsing accepts the valid shapes and refuses a bad run id, a unit with an aggregate, a selector without the hybrid contract, an unknown route name, the integrator hybrid string for role `arch-review` and the architecture hybrid string for role `integrator`; `hybridContractFor` returns the right string per role and refuses any other role.
- For each route the validator accepts a correct result and refuses: a wrong route echo, a coverage inventory that differs from the manifest, a `complete` review with a limitation, a mismatched unit echo, a mismatched ledger digest, an aggregate verdict above the ledger ceiling, and a result whose identity echo differs from `binding.identity` in any field for either role.
- Aggregate input: `validateHybridResult` for a partitioned aggregate accepts the frozen `verifyLedger` result of an `ok: true` verification and refuses with `REVIEW_ROUTE_PROOF_MISSING` a ledger handle, a record-only object without `coverage_digest`, and an `ok: false` verification (built in the test from a plan that omits a row), so an aggregate cannot be validated against an unproven ledger.
- Partition support: `partitionSupported` is true for the integrator with a phase integrator subject and for `arch-review` with a `PHASE_SUBJECT`, false for an architecture-review ticket subject and for a malformed subject; `buildBinding` for a partitioned route with a ticket subject refuses with `REVIEW_PARTITION_UNSUPPORTED`, while inline and pull bindings for the same ticket subject build.
- The legacy contract strings stay exactly as they are in their owning modules: the legacy focused string is read from the exported `FOCUSED_CONTRACT` of `codex-arch-review-context.cjs` at call time, and the two legacy integrator strings, which have no exported constant anywhere, are held once as literals in this module; a test proves `isSupportedIntegrationContract` agrees with the Claude host's `parseRequest` and the Codex host's `requestValue` for each legacy value, the hybrid value and an unknown value, so the copies cannot drift. No other new module of this phase repeats a contract literal; they import `INTEGRATION_V3`, `FOCUSED_V3` and the predicates.
- A census test scans `plugins/delivery-pipeline/scripts/*.cjs`, `references/*.md` and `commands/*.md` for `FOCUSED_CONTRACT`, `shipyard.focused-architecture-review` and `shipyard.integration-review.v`, and asserts the set of files found equals the file set of `CONTRACT_SITES`, so a new reference site in a new file fails until it is listed with its owner.
