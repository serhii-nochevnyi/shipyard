## Scope

- Request path first. `requestValue` (`codex-delivery-host.cjs:119-121`) runs before `prepare` can see the context and today refuses `context.review_contract` for every role but the integrator and for every string but the two legacy ones, so a hybrid architecture request would never reach `prepare`. This ticket extends it, per role: for `arch-review` it accepts `context.review_contract` only when it equals `hybridContractFor('arch-review')` (the hybrid architecture string) and `context.review_min_route`, both validated through `parseSelectors(context, 'arch-review')`; for `integrator` it stays as it is (the two legacy strings; the hybrid integrator string is T-53-25's); for every other role, the hybrid string of the other role, a legacy string together with a hybrid selector, `review_min_route` without the hybrid string, an unknown string and an unknown route name it refuses with `INVALID_INPUT`; `review_unit` and `review_aggregate` stay refused until T-53-24 admits them.
- `prepare` accepts `launch.context.review_contract` (hybrid architecture string only) and `review_min_route` beside `repo`; selectors are parsed by `review-contract-v3.parseSelectors`; every other context key is still refused.
- New exported `measureReview(scope, launch, options)` returning the route record and work without launching or writing: the work is `measureWork` over `measureRows` diff bytes at `review_context_lines`, the required material bytes and the metadata bytes; thresholds come from `options.reviewRouting` or `loadConfig`.
- Hybrid `collect`: obtains the route first; inline builds `diff` with `reviewDiff` at the configured context and adds `review_contract`, `review_route`, `review_scope` to the packet; pull builds `review_manifest` and leaves the packet's `diff` as identity-only (no `content`), with the file relay unaffected; a manifest blocker or a work size above the pull threshold refuses with `REVIEW_PARTITION_REQUIRED` carrying the route record (`escalated_from` set when the blocker came from pull), because a single launch cannot perform the partitioned route; for a ticket-level architecture review (`scope.ticket` does not match `PHASE_SUBJECT`, so `partitionSupported` of T-53-17 is false) the same condition refuses with `REVIEW_PARTITION_UNSUPPORTED` carrying the route record and the subject kind and naming the remedy (review that ticket on the legacy contract or split it), so no coordinator is invited to partition it.
- The prompt names the hybrid contract and route; for pull it instructs the reviewer to run each manifest recipe with read-only `git` commands and return `coverage_inventory`, `review_completeness`, `limitations`, `unresolved_sources`.
- `focusedBinding` carries the hybrid contract string for hybrid contexts; `finish` validates hybrid results with `validateHybridResult` (identity fields from the binding) in place of `validateFocusedResult`, records the route record in `host_context`, and the original receipt custody comparison uses the same binding.
- `admitArchitectureInput` keeps the work-size `inputTokens` for hybrid contexts instead of the file-input count.
- Contract sites owned here (the `CONTRACT_SITES` table of T-53-17, v0.73.0 anchors): in `codex-arch-review-context.cjs` the focused-contract comparisons and emissions at `:419`, `:461`, `:528` (file-input prompt, material and bundle selection), `:905-906` (`verifyFileInput` focused branch), `:1169` (`collect` packet), `:1390-1391` and `:1408` (`validateFocusedResult` stays the legacy validator, `focusedBinding` chooses the string), `:1571` (prompt text), `:1600` and `:1688` (launch binding), `:1701` and `:1712` (reader capacity and variant transport, which a focused context bypasses), `:1812` and `:1827` (`finish`) all accept the legacy or the hybrid architecture string through one family predicate and emit the string the context was prepared with; in `codex-runtime-host.cjs` the focused file-transport custody check at `:2631` accepts the same family, which is why this ticket lists that file (without it a hybrid review that is relayed as host files, possible once an operator raises `review_inline_max_tokens` above the relay limit, is refused with "focused files differ from private launch custody"). The integrator-string sites `:643` of the collector and `:3455` of the runtime host are T-53-25's.

## Acceptance criteria

- Legacy launches (no `review_contract`) behave exactly as before, including the context-key refusal for any key other than `repo`.
- Request path: `validateArgs` (which calls `requestValue`) accepts `{ role: 'arch-review', context: { review_contract: <hybrid architecture string>, review_min_route: 'pull' } }` and the same without a floor, and refuses with `INVALID_INPUT` the hybrid architecture string for role `integrator`, the legacy focused string together with `review_min_route`, `review_min_route` without the contract, `review_unit` and `review_aggregate` (until T-53-24), an unknown contract string and an unknown route name; every request the existing `codex-delivery-host.test.cjs` cases send is accepted or refused exactly as before.
- A hybrid launch on a small fixture records `inline`, embeds the diff with at most `review_context_lines` unchanged lines around changes, has no mirror path, carries `review_route` and `review_scope`, and its launch `signals.inputTokens` equals the independently computed work estimate even when a file relay is used.
- With the pull band enabled the packet has `review_manifest` and no diff content and a correct declared inventory seals as complete; a wrong inventory, a `complete` result with a limitation or a mismatched identity is refused; an `incomplete` result seals as non-authoritative.
- Work above the pull threshold, an oversize file or an oversize manifest refuses with `REVIEW_PARTITION_REQUIRED` for a phase-bound review; the same inputs on a ticket-level review (ticket subject, no phase binding) refuse with `REVIEW_PARTITION_UNSUPPORTED` carrying the route record and subject kind; a `review_min_route` above the natural route raises it and a lower request is refused.
- `measureReview` writes nothing and launches nothing; the hybrid contract string is in the receipt custody comparison.
- A hybrid review whose prompt exceeds the relay limit (the test injects `reviewRoutingRecord: unlockedRecord()` and sets `review_inline_max_tokens` above it, because a raise takes effect only through an unlocked record; without the record the same setting returns the default with source `default-locked` and the review is not relayed) is relayed as host files, passes `codex-runtime-host.cjs:2631`'s custody check and carries the hybrid string in its manifest binding; the same relay with a legacy string still passes as before and a binding with any other string is refused.
