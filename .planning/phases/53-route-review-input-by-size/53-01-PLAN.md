## Scope

New `review-diff-scope.cjs` exporting: `MIRROR_PREFIX` (`plugins/shipyard/`); `classifyReviewPath(path, role)` returning `{ included, reason }` with reason `null`, `mirror`, `planning` or `development`; `parseRawDiff` for `git diff --raw -z --no-abbrev --find-renames` output; `reviewChangeSet({ root, base, head, role, exec, maxBuffer })` returning included rows, excluded rows by reason and the `review_scope` record; `reviewDiff({ root, base, head, rows, contextLines, exec, maxBuffer, maxArgBytes })`; `reviewListings(...)` returning `name_status`, `numstat` (same NUL-separated formats as `git diff --name-status -z --find-renames` and `--numstat -z --find-renames`, restricted to included rows) and `changedPaths`; `LEGACY_CONTEXT_LINES` (50) and `DEFAULT_CONTEXT_LINES` (10); a small CLI `diff --role --base --head [--context-lines]` and `scope --role --base --head --json` for callers that build a diff outside a host. The CLI owns its usage text, because T-53-31's documentation test checks the prose against it: `--help` or `-h` prints a `usage:` block to stdout that lists both subcommands and every option they accept and exits 0, and no arguments, an unknown subcommand or an unknown option print the same block to stderr and exit 2 without running git.

Rules: role `integrator` excludes every `isDevelopmentArtifact` path plus the mirror; role `arch-review` excludes the mirror and `.planning/` except `.planning/architecture/**` and any `.planning/**/DECISIONS.md`, and keeps other development artifacts (`docs/audits/`, `.shipyard*`, `AGENTS.md`, `CLAUDE.md`). A row is excluded only when every path it names is excluded; a rename or copy whose two sides classify differently becomes a plain add or delete of the included side. The mirror prefix matches only `plugins/shipyard/` (`plugins/shipyard-other/` stays).

Git mechanism (verified on the installed git 2.54 while decomposing): `git diff` has no `--pathspec-from-file` (it is a usage error, exit 129), and `:(exclude)` magic cannot re-include `.planning/architecture/**` once `.planning/` is excluded, so exclusion is computed on rows and the diff is built from explicit paths. `reviewChangeSet` runs one `git diff --raw -z --no-abbrev --find-renames <range>` and classifies each row. `reviewDiff` and `reviewListings` then run: (a) when no row is excluded, the plain unfiltered command with no pathspec (so the output is byte-identical to today's); (b) otherwise the same command with `-- :(literal)<path> …` appended as argv entries, one `:(literal)` entry per included path (both sides of an included rename), never through a shell, split into consecutive chunks of at most `maxArgBytes` argv bytes (default 65536, a parameter so tests can force one path per call) with a rename or copy pair always inside one chunk, and the chunk outputs concatenated in raw-row order; (c) an empty included set returns an empty result without calling git, because an empty list after `--` selects the whole diff and would put the mirror back. Every call passes `--no-ext-diff --no-textconv --find-renames` explicitly (the integrator's legacy `diffText` omitted `--no-textconv` and relied on the default for renames; explicit flags remove the dependence on user git configuration and change nothing on a repository without textconv drivers), then `--unified=<N>`. `changedPaths` is derived from the included rows (both sides of an included rename, the `--no-renames` semantics the old call had) without another git call. `review_scope` is `{ schema: "shipyard.review-scope.v1", role, mirror: { count, digest, paths: [{ path, status, old_blob, new_blob }], listed, omitted }, planning: { count, digest }, development: { count, digest }, digest }` with the mirror list capped at 1000 entries and the omitted count and a digest of the complete list recorded. Row count is bounded at 20000 and raw output at `FILE_LIMITS.material`; over-bound input refuses with `REVIEW_SCOPE_OVER_BOUND`.

Claude host: `prepareIntegrator` and `prepareArch` obtain their rows from `reviewChangeSet` and build the diff, `changedPaths`, `name_status` and `numstat` from it; the context stays `LEGACY_CONTEXT_LINES` and the existing 2 MiB and 16 MiB bounds apply to the included content; `role_context.review_scope` is added for both roles. The existing assertion at `tests/unit/claude-role-host.test.cjs:641` (the phase architecture review diff contains `SUMMARY.md`, a file under `.planning/phases/`) pins the old unscoped diff; it changes to assert that the diff keeps the changed product and architecture files, that `SUMMARY.md` is absent, and that `review_scope.planning.count` counts it, which is a stricter assertion, not a looser one.

Caller-built diffs (the Codex v1 caller). The CLI `diff --role --base --head [--context-lines]` exists for the one review diff no host builds: a Codex `shipyard.integration-review.v1` caller supplies its own diff (`deliver.md` legacy full-input compatibility), so the host can neither scope nor verify it and the pathspec is not applied by any host there; T-53-31 tells such callers to build it with this command. The CLI's `--role integrator` output is byte-identical to what `reviewDiff` returns for the same rows, asserted in the module tests.

Isolated test environment (phase test rule; no decision change). New `tests/unit/helpers/isolated-environment.cjs`. As a library it exports `ISOLATED_KEYS`, `UNSET_KEYS` (the four keys `tests/unit/run.sh` unsets), `RUNNER_ONLY_UNSET_KEYS` (`SHIPYARD_GRAPH_DIR` and `SHIPYARD_REVIEW_MEASURE_LIVE`, which only the helper's own runner removes), `isolatedEnvironment(baseEnv, root)`, `assertIsolatedEnvironment(env = process.env)` and `runIsolated(files, options)`. As a CLI, `node tests/unit/helpers/isolated-environment.cjs <tests/unit/NAME.test.cjs>...` refuses with exit 2 and a usage line an argument that is not an existing `tests/unit/*.test.cjs` file, and otherwise creates one scratch root under `os.tmpdir()` and runs `node --test <files>` with the environment `tests/unit/run.sh` gives its CI workers: private `HOME`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `TMPDIR`, `TMP`, `TEMP`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` and `XDG_RUNTIME_DIR` (mode 0700), and a private git configuration (`user.name` and `user.email` set, `commit.gpgsign` and `tag.gpgsign` false, `init.defaultBranch` main, `GIT_CONFIG_GLOBAL` pointing at it, `GIT_CONFIG_NOSYSTEM=1`). It removes `UNSET_KEYS` (`CLAUDE_PLUGIN_ROOT`, `CLAUDE_CODE_ENTRYPOINT`, `CODEX_SANDBOX`, `CODEX_SANDBOX_NETWORK_DISABLED`) and `RUNNER_ONLY_UNSET_KEYS` (`SHIPYARD_GRAPH_DIR`, `SHIPYARD_REVIEW_MEASURE_LIVE`) from the child's environment, deletes the scratch root afterwards and exits with the child's status. `assertIsolatedEnvironment` throws an error with code `TEST_ENVIRONMENT_NOT_ISOLATED`, naming the key and the runner command, when any of `HOME`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME` or `XDG_DATA_HOME` is unset, equals the real home (`os.userInfo().homedir`, which does not follow `$HOME`) or lies inside its `.local/state`, `.codex`, `.claude`, `.config`, `.cache` or `.local/share`; when `os.homedir()` does; or when one of the four `UNSET_KEYS` is present.

The guard agrees with `tests/unit/run.sh` (fourth round; the guard is the file this ticket changes, `run.sh` stays unchanged). `run.sh` unsets exactly the four `UNSET_KEYS` on its line 10 and gives each worker the private variables above, so a worker started by `make test-unit` or `make test-fast` passes the guard in every shell. It does not unset `SHIPYARD_GRAPH_DIR`, which a worktree session exports on purpose (`deliver.md:584`, `graph-dir.cjs:15,49`), or `SHIPYARD_REVIEW_MEASURE_LIVE`, so the guard must not reject either, or every new test file would fail under `make test-fast` in such a shell while CI passed. The runner still removes both from its child (stricter than `run.sh`, harmless), and the two effects are closed in the tests instead of in the guard: every host call passes an explicit scratch `graphDir`, which wins over the variable wherever a host reads both (`options.graphDir || process.env.SHIPYARD_GRAPH_DIR`, `codex-delivery-host.cjs:142,178`, `codex-arch-review-context.cjs:991,1758,1778`), and the live-probe gate of T-53-09 and T-53-10 reads the variable only from an `env` option that every one of their cases passes explicitly, so an exported variable in the operator's shell cannot start a probe through a unit test. Node's `os.homedir()` follows `$HOME` on POSIX, so the private `HOME` also isolates the modules that call it: `claude-role-host.cjs:1118` and `codex-delivery-host.cjs:304` default their state root to `~/.local/state/shipyard/...`, `role-artifact.cjs:997` derives the authority home from it, `claude-runtime-host.cjs:366,374,418` and `role-artifact.cjs:3110` read `process.env.HOME` first. The `os.homedir` override headers that existing test files carry stay as they are. Every new test file of this phase that requires a plugin script begins with `require('./helpers/isolated-environment.cjs').assertIsolatedEnvironment()` before that first require, and tests always pass explicit scratch `storageRoot` and `graphDir` options to a host.
