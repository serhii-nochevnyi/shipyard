## Scope

- Request path. `requestValue` (`codex-delivery-host.cjs:119-121`) accepts `context.review_contract` for the integrator only when it is one of the legacy two strings or `hybridContractFor('integrator')`, and accepts `context.review_min_route` only together with the hybrid string; the context is validated through `parseSelectors(context, 'integrator')` when the hybrid string or a selector is present. It refuses with `INVALID_INPUT` the architecture hybrid string for the integrator, `review_min_route` with a legacy string or no contract, `review_unit` and `review_aggregate` (until T-53-26), an unknown string and an unknown route name, and, for a hybrid context, every other key except `plan_sha256` (the one other context key `requestValue` validates today): a caller-supplied `input_transport`, `input_bundle`, `prompt` or `diff` is refused. `prepareIntegratorInput` accepts the hybrid string and `review_min_route`; the legacy-two allow-list and the lineage branch are unchanged; any other string still refuses.
- Legacy and v1 callers. A Codex `shipyard.integration-review.v1` caller supplies its own diff (the `diff` field of the dispatch context, `deliver.md` legacy full-input compatibility) and the caller-material tail of `prepareIntegratorInput` (`:1024-1088`) carries it exactly as given. No host builds that diff, so the review pathspec of T-53-01 is explicitly not applied by this host there, and the host neither verifies nor rewrites it; the caller is told to build it with `node ${CLAUDE_PLUGIN_ROOT}/scripts/review-diff-scope.cjs diff --role integrator` (T-53-31), which returns the bytes a host would build. Such a caller never reaches a new route: `requestValue` refuses a route selector without the hybrid string, so a v1 or v2 request cannot ask for inline, pull or partitioned handling, and the coordinator refuses non-hybrid requests (T-53-29). A v2 request goes through the shared Claude-host preparation and so already receives the scoped diff (T-53-01); choosing the hybrid contract, whose diff the host builds, is the way to a host-enforced pathspec on Codex.
- Hybrid branch (before the lineage branch): call the shared `prepareIntegratorContext` with the hybrid request to obtain the route record, the packet (inline: embedded diff at `review_context_lines` with `review_scope`; pull: `review_manifest` with identity-only `combined_diff`) and the work estimate; when the route is partitioned, or a blocker escalated it, refuse with `REVIEW_PARTITION_REQUIRED` carrying the route record. Otherwise the packet is carried by the inline transport only, exactly as the legacy caller-material tail does it (`:1024-1052`: material plus generated instruction bytes at most 1 MiB, recorded in `inlineIntegratorInputs` and re-checked by `recheckInlineIntegrator`); the instruction stabilization loop over the selected agent file is kept and `request.signals.inputTokens` is the work estimate. A hybrid packet whose material plus instructions exceeds the 1 MiB inline limit is refused with `REVIEW_ROUTE_UNAVAILABLE` carrying the route record and `blocker: "transport-limit"` (a code `review-route.nextRoute` accepts and the coordinator escalates on); `prepareFileInput`, the reader transport and the completed-source machinery are never used for a hybrid integrator, so the v2-only restoration sites (`codex-runtime-host.cjs:3455`, `codex-arch-review-context.cjs:643`) and the `:3087-3094` completed-source check stay unreachable from it and unchanged. Under the conservative defaults the inline threshold (150000 tokens, about 600 KB) is below the limit, and a unit (T-53-26) is sized by `review_unit_budget_tokens` (default 100000 tokens), so the refusal only fires when an operator raises a threshold above what the Codex inline transport carries.
- `finishIntegrationReview`: hybrid results are validated with `validateHybridResult` (identity echoes from the host binding); the sealed result records the route record.
- The pull instruction tells the reviewer to run each manifest recipe with read-only git commands from the worktree, never to modify it, and to return the coverage inventory and completeness fields.

## Acceptance criteria

- Legacy requests (no contract, legacy one, legacy two) behave as before; the existing pins in `phase49-incremental-integration.test.cjs` pass unchanged.
- A hybrid integrator on a small fixture records `inline`, has no mirror path in its packet, uses at most `review_context_lines` of context, and its `request.signals.inputTokens` equals the independently computed work estimate (not `ceil(promptBytes/4)`, asserted on a fixture where they differ).
- A hybrid packet above the 1 MiB inline limit (the test injects `reviewRoutingRecord: unlockedRecord()` and raises `review_inline_max_tokens` above it, because a raise takes effect only through an unlocked record) is refused with `REVIEW_ROUTE_UNAVAILABLE` and `blocker: "transport-limit"`, and a spy on `prepareFileInput` shows it was never called; a hybrid request context carrying any key other than `review_contract` and `review_min_route` (this ticket admits those two; T-53-26 adds `review_unit` and `review_aggregate`), for example `input_transport`, `input_bundle`, a prompt or a diff, is refused by `requestValue`.
- Request path: `validateArgs` accepts `{ role: 'integrator', context: { review_contract: <hybrid integrator string>, review_min_route: 'partitioned' } }` and the same without a floor, still accepts the two legacy strings, and refuses with `INVALID_INPUT` the architecture hybrid string for the integrator, `review_min_route` with the v1 string, the v2 string or no contract, `review_unit` and `review_aggregate` (until T-53-26), an unknown string and an unknown route name.
- A v1 request carrying a caller-supplied `diff` behaves byte-identically to before this ticket (the diff is carried as given and no route selector is read), a v1 request carrying any route selector is refused, and a v2 request's packet contains no `plugins/shipyard/` path (shared preparation); the test pins both statements of the Legacy and v1 callers paragraph.
- With the pull band enabled the packet has the manifest and no diff content; a correct inventory seals as complete; a wrong inventory, a `complete` result with a limitation or a mismatched identity is refused; an incomplete result is non-authoritative.
- A work size above the pull threshold, an oversize file or manifest refuses with `REVIEW_PARTITION_REQUIRED`; a lower `review_min_route` than natural refuses; an unknown contract string refuses with the existing unsupported-contract error.
- Evidence file between attempts (the case the coordinator relies on, T-53-29): a hybrid Codex integrator inline launch whose fake native runtime wrote `.planning/phases/<phase>/INTEGRATION.md` and returned an `incomplete` result leaves that untracked file, and the next hybrid launch in the same worktree is refused by the host's own clean-worktree preflight; after `role-artifact.prepareRoleArtifact({ worktreePath, role: "integrator", phase })` has rotated that one file the same launch passes preparation. The case documents the contract and changes no host behaviour.
