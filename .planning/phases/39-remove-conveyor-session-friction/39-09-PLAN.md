## Goal

`adr-bootstrap.cjs` creates only the missing `.planning/config.json`,
`ROADMAP.md` and `REQUIREMENTS.md` from an accepted ADR: one phase for the ADR,
one requirement id per `## Decision` bullet parsed by `adr-ingest.cjs`, and a
plain-language refusal for an ADR without decisions (D-03).

## Scope

- CLI, run from the project root: `node adr-bootstrap.cjs --adr <path> [--phase <N>] [--json]`. `--phase` defaults to 1.
- Read the ADR and call `decisionEntries`. Zero entries → stderr `<adr> has no bullets under ## Decision; add one bullet per locked decision (see templates/adr/ADR.md) and re-run`, exit 1, no stack trace, no file written.
- Create only missing files with `fs.writeFileSync(file, data, { flag: 'wx' })`; an existing file is never read-modified or truncated, and an `EEXIST` race is reported as skipped.
  - `config.json`: `{"git":{"branching_strategy":"none"}}` plus a trailing newline.
  - `ROADMAP.md`: `### Phase <N>: <ADR title>`, `**Status**: planned (<ADR id>)`, `**Requirements**: REQ-01, …`, and a one-line goal.
  - `REQUIREMENTS.md`: `- [ ] **REQ-NN**: <decision text>` per decision in ADR order, then a traceability table `| REQ-NN | Phase <N> | Pending |`.
- Output a report `{ created: [...], skipped_existing: [...], requirements: [{ id, decision }] }` (JSON with `--json`, else one line per item).
- Partial project: create only the missing file(s) and list the others under `skipped_existing`; never merge into an existing ROADMAP or REQUIREMENTS.
- No explanatory code comments.

## Out of scope

## Acceptance criteria

- An empty project gets all three files, with REQ ids 1:1 and in order with the ADR bullets.
- A pre-existing `ROADMAP.md` stays byte-identical and is reported under `skipped_existing`, while the missing files are created.
- An ADR without decisions exits 1 with the plain message and writes nothing.
- A nested-`###` ADR yields one requirement per `###` decision.
- In a temp project with the generated config, `gsd-tune.cjs --check --runtime claude --json` reports no REQUIRED drift for `git.branching_strategy` (tuning drift may still exit 1).
