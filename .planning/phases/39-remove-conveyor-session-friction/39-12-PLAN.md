## Goal

When a Claude host launch declares an output schema, the host passes it to the
Claude CLI, so the worker's handback returns as `result.structured_output`
matching the schema instead of prose. This extends REQ-135 / D-12 ("research
handbacks receive their bound at launch") to every Claude host launch that
declares a schema: the executor `OUT` schema (`status: "committed"`) and the
research `OUT` schema (`summary` `maxLength: 500`) must reach the CLI. Today
they do not, so finished executors (T-39-01, T-39-02, T-39-04) and the INV-003
research fan-out were reported blocked.

## Defect (verified before planning)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs` `launch()` builds
  `args` (about lines 668-677) with no `--json-schema`, even though
  `launchOptions` carries `schema`.
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs` (about lines
  859-867) builds `launchOptions` with `...agentOptions`. `agentOptions.schema`
  is set by `plugins/delivery-pipeline/workflows/executors.mjs:332` and
  `plugins/delivery-pipeline/workflows/investigation-research.mjs:274`.
- `claude-runtime-host.cjs` (about line 736) uses
  `parsed.result.structured_output` only when it is present, and otherwise
  falls back to `streamText(parsed)`.
- Checked live: `claude --print --output-format stream-json --json-schema <schema>`
  returns `result.structured_output` that matches the schema.

## Scope (per D-01: deterministic script fix plus focused tests; per D-12: bound handed over at launch)

- Add the schema check in `launch()` inside the existing validation block, right after the two `readOnly` checks and before `gsdAgentDefinition` and `fs.mkdtempSync`. If `launchOptions.schema !== undefined` and `object(launchOptions.schema)` is false, call `fail('INVALID_INPUT', 'schema must be a plain JSON object')`. This covers `null`, arrays, strings and numbers. The refusal happens before any temp directory is created and before `spawn` is called.
- Serialize once there: `const schemaJson = schema === undefined ? null : JSON.stringify(schema)`. Wrap it so a serialization error (for example a cyclic object) becomes `fail('INVALID_INPUT', 'schema must be serializable JSON')`, also before launch.
- In `args`, append `...(schemaJson ? ['--json-schema', schemaJson] : [])` as the final elements, after `'--settings', settings`. Leave every existing flag, value and relative order as it is. Without a schema, the argv is byte-identical to today's.
- Keep the `result.output` precedence exactly as it is: `structured_output` first, then `streamText(parsed)`. Do not change `summary`.
- No other file changes. The adapter already spreads `agentOptions`, so both workflows are fixed through this single host change.
- Comment policy: add no explanatory, historical or ticket comments. An optional single-line `@contract:` marker of 120 characters or less is the most allowed.

## Acceptance criteria

- With `schema: { type: 'object', properties: { status: { type: 'string' } }, required: ['status'] }`, the captured argv contains `--json-schema` exactly once, followed by `JSON.stringify(schema)`. These are the last two elements, right after the `--settings` value.
- With no `schema`, the captured argv contains no `--json-schema`, and all existing assertions in the native-launcher and read-only tests still pass unchanged.
- Each of `schema: null`, `schema: []` and `schema: 'x'` rejects with `code === 'INVALID_INPUT'` and a message containing `schema must be a plain JSON object`, and the `spawn` stub is never called.
- When the stream's `result` record carries `structured_output`, `result.output` equals that object. When it is absent, `result.output` is the stream text, as before.

## Amendment (found while delivering)

The workflow dispatch adapter captured the runtime host's wrapper
`{status: "completed", summary, output}` as the agent result, so a workflow
could never read the worker's `status: "committed"` even with a structured
output. `claude-dispatch-adapter.cjs` now passes a plain-object `output` to
the workflow and keeps the wrapper for application evidence; a text output is
unchanged. The runtime-owned adapter baseline digest in
`tests/unit/source-contract.test.cjs` is updated deliberately for this change.
Tests: `tests/unit/claude-workflow-host.test.cjs` (structured output reaches
the workflow; text output unchanged).
