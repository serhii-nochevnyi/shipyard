## Goal

When `.planning/config.json` is missing, `gsd-tune` names the file it looked for
and the command that creates it, still exiting 2 with the `gsd-tune:` prefix
(D-11).

## Context (Reads)

- `plugins/delivery-pipeline/scripts/gsd-tune.cjs:322` (`fail(msg, code = 2)`), `:325-326` (missing-config message), `ROOT = process.cwd()`
- `tests/unit/gsd-tune.test.cjs:356-361` (asserts only non-zero status and no conjured config)
- Existing-implementation check: the message is the single template string at `:326`; `fail` already owns the prefix and exit code, so only the string changes.

## Scope

- Replace only the template string at `:326` with: `no ${CONFIG} — this directory is not a GSD project yet. Create it with /shipyard:decompose (Codex: $shipyard-decompose), which bootstraps .planning/config.json from an accepted ADR, or /gsd-new-project, then re-run gsd-tune from that project root`. `${CONFIG}` must render as the absolute path of the missing file.
- Keep `fail(...)` with the default code 2, the prefix, and `ROOT = process.cwd()` (no upward search).
- No new comments.

- stderr matches `/^gsd-tune: /`, contains `path.join(dir, '.planning', 'config.json')`, contains `/shipyard:decompose`, and contains `$shipyard-decompose` (Codex parity).
- No config file is created.
