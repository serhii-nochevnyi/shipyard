## Goal

`gsd-sync.cjs` accepts the project that `adr-bootstrap.cjs` creates, in both
publication and `--check`, with no manual edits and no `--adopt-native`. This
closes INTEGRATION.md F1, the one blocking seam of phase 39: after
`/shipyard:decompose` bootstraps a project (T-39-09 + T-39-10, ADR-016 D3 /
REQ-126), the `plan:post` capability gate and `state-sync.cjs` then run the
ADR-013 projection and refuse it. The fix keeps the T-39-09 contract: missing
files only, REQ ids 1:1 and in ADR order, `| REQ-NN | Phase N | Pending |` rows,
and pre-existing files never read-modified and reported under
`skipped_existing`.

## Defect (verified before planning)

The integrator reproduced all three causes. I confirmed each one in the source.

- `adr-bootstrap.cjs:48-63` (`requirementsContent`) writes `.planning/REQUIREMENTS.md`
  with no ownership marker. `gsd-sync.cjs:1013-1022` (`generatedFileContent`) throws
  `.planning/REQUIREMENTS.md exists but is not owned by shipyard:gsd-sync generated`.
  It runs this for every generated file in both `--check` and write mode
  (`buildSnapshot`, `:1134`). `hasMarker` (`:139-147`) looks for the marker on
  line 3 of `REQUIREMENTS.md` only.
- `adr-bootstrap.cjs:36-46` (`roadmapContent`) writes only `**Requirements**: REQ-01, …`.
  `gsd-sync.cjs:346-381` (`parseRoadmap`) reads definitions only from
  `- **REQ-NN** — <text>` lines. Without them, `projectRequirements` (`:655-693`)
  regenerates a REQUIREMENTS.md that has no decision text.
- `adr-bootstrap.cjs` never creates `.planning/PROJECT.md`. `checkSource`
  (`gsd-sync.cjs:595`) then reports `PROJECT.md is missing`. `parseProjectCore`
  (`:393-405`) reads the core value from a `## Core Value` heading section. If that
  section is missing, it falls back to a Shipyard-specific sentence.
- `gsd-sync.cjs:135-137` `marker(fingerprint)` is the single source of the marker
  format, but `module.exports` (`:1262-1276`) exports only `FILE_MARKER`, not
  `marker`.

## Scope

- **gsd-sync.cjs:** add `marker` to `module.exports`. Change nothing else in this file.
- **adr-bootstrap.cjs**, `roadmapContent(phase, heading, requirements)`:
  - Keep the `### Phase N: <title>`, `**Status**`, `**Requirements**` and goal lines unchanged.
  - After the goal line and one blank line, add one `- **REQ-NN** — <decision>` line per requirement, in ADR order. Use an em dash (U+2014), the separator `parseRoadmap` matches.
  - Collapse the decision text's internal whitespace to single spaces on this line. A decision wrapped over several ADR lines then stays one `parseRoadmap` description and cannot start a new list item.
- **REQUIREMENTS.md.** In `requirementsContent`, make line 1 `# Requirements`, line 2 blank, and line 3 the gsd-sync marker line built from the imported `marker` with an all-zero fingerprint `'0'.repeat(64)`.
  - Require the helper as `const { marker } = require('./gsd-sync.cjs');`.
  - Leave the rest of the file (checklist, `## Traceability`, rows) unchanged.
  - The marker is truthful. gsd-sync owns this file and regenerates it wholly from the ROADMAP declarations on first publication. The all-zero fingerprint matches no real source, so `--check` before publication reports the file as stale, never as unowned.
- **PROJECT.md.** Add a fourth target, `.planning/PROJECT.md`, written only when missing through the same `writeIfMissing` (`wx`) path, and reported in `created` / `skipped_existing` like the others. Content:

  ```
  # <ADR title>

  ## Core Value
  Implement <ADR id>: <ADR title>.
  ```

  - This uses a `## Core Value` section rather than the `**Core Value:**` line the integrator suggested, because `parseProjectCore` reads only the heading section. With the line form, the projection would fall back to the Shipyard sentence.
- **Target order:** `config.json`, `ROADMAP.md`, `REQUIREMENTS.md`, `PROJECT.md`. The existing files keep their order, so current report assertions only gain one entry.
- **Pre-existing files:** keep the rule that an existing PROJECT.md, ROADMAP.md or REQUIREMENTS.md is never read, modified or truncated, and is listed under `skipped_existing`.
- **Comment policy:** add no explanatory, historical or ticket comments on added code lines. At most one single-line `@contract:` marker of 120 characters or less is allowed.

## Acceptance criteria

1. **Fixture round trip.** A temp project (under `os.tmpdir()`, run with a `testEnv`-style environment) goes through these steps:
   1. `adr-bootstrap.cjs --adr <ADR with 3 decisions> --json`.
   2. Write one delivery PLAN at `.planning/phases/01-<slug>/01-01-PLAN.md`. Its front matter is `phase: 1`, `plan: 1`, `files_modified: [src/example.js]` (the file exists), `requirements: [REQ-01]` and `delivery: { ticket: T-01-01, risk: low }`.
   3. `validate-graph.cjs` (exit 0).
   4. Write `.planning/graph/delivery-state.json` `{"T-01-01":{"status":"pending"}}`.

   Then:
   - `gsd-sync.cjs --json` exits 0 with `ok: true`;
   - `gsd-sync.cjs --check --json` exits 0 with `ok: true` and `blockers: []`;
   - neither output contains `not owned by`, `PROJECT.md is missing` or `has no ### Phase`.
2. **Decision texts survive.** After publication, the regenerated `.planning/REQUIREMENTS.md` contains `- [ ] **REQ-0N**: <decision>` for every ADR decision, in order. Each decision's whitespace is collapsed. The traceability table has `| REQ-0N | Phase 1 | Pending |` for each.
3. **Stale, not unowned.** In a freshly bootstrapped project with the same PLAN, graph and state, and before publication, `gsd-sync.cjs --check --json` exits 1. Its `blockers` contain only `… is missing or stale` entries. It reports no ownership error.
4. **Bootstrap output.**
   - An empty project gets `config.json`, `ROADMAP.md`, `REQUIREMENTS.md` and `PROJECT.md`, reported under `created` in that order.
   - The bootstrapped REQUIREMENTS.md line 3 satisfies the ownership check. Assert it by calling `hasMarker` indirectly, through acceptance 1, and directly with the regex from `gsd-sync.cjs:141`.
   - The ROADMAP has one `- **REQ-NN** — ` line per decision.
   - PROJECT.md has `## Core Value` followed by `Implement <ADR id>: <title>.`.
5. **Pre-existing file.** A pre-existing `PROJECT.md` stays byte-identical and is listed under `skipped_existing`, while the missing files are created.
6. **Existing tests still pass.** All existing `adr-bootstrap` tests pass. Update only the expected `created` list and the printed-lines count to include `PROJECT.md`. This includes the source assertion that `./adr-ingest.cjs` is required, and the `gsd-tune --check` REQUIRED-drift test. `node tests/unit/gsd-sync.test.cjs` stays green.
