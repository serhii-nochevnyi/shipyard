## Goal

A Claude role worker can return an identity that the host accepts on the first
try. The integrator reference example and the launched output schema both
describe `ticket_set` as the exact array of objects the host authenticates
(`id`, `pr`, `head`, `base`, `branch`). A result that echoes `ticket_set` as a
string or as a list of ids is refused with a named remedy, not the generic
identity mismatch. This extends REQ-135 / T-39-12 (the handback receives its
bound at launch) to role judgements, and it closes integrator findings F3
(`roleOutputSchema` describes only `blocking_count`) and the ticket_set
ambiguity seen in this phase's own integrator dispatch.

## Scope

- **Decision:** keep the full `ticket_set` comparison. It is stronger than comparing the digest alone, and the host already owns the array. Make the contract describe that array exactly.
- **Output schema.** In `roleOutputSchema`, define one `TICKET_SET_SCHEMA`:

  ```
  { type: 'array', items: { type: 'object', additionalProperties: false,
    required: ['id','pr','head','base','branch'],
    properties: { id: string, pr: integer >= 1, head: string, base: string, branch: string } } }
  ```

  - `integrator` gets properties `outcome` (enum `passed`, `needs-fix`, `human-review-required`), `phase`, `head`, `head_tree`, `base`, `base_tree`, `ticket_set_digest`, `summary` (strings), `ticket_set`, `blocking_count` and `findings` (array). Required: `outcome`, `phase`, `head`, `head_tree`, `base`, `base_tree`, `ticket_set`, `ticket_set_digest`, `blocking_count`, `summary`, `findings`.
  - `pr-sentinel` gets `outcome` (enum `clear`, `blocked`, `awaiting-human`), `ticket_set`, `ticket_set_digest`, `head`, `head_tree`, `performed`, `refused`, `blocking_count` and `summary`. Required: `outcome`, `ticket_set`, `ticket_set_digest`, `head`, `head_tree`, `blocking_count`.
  - `arch-review` stays byte-identical.
  - The result stays `{ type: 'object', properties, required }`, with `required` omitted for arch-review.
- **Named-remedy refusal.** In `validateResult`, before the integrator and sentinel identity comparisons, run a shape check. When `result.ticket_set` is not an array, or any element is not a plain object with exactly the keys `id`, `pr`, `head`, `base` and `branch`, call `reject(...)` with code `INVALID_RESULT`. The message is `<role> result ticket_set is <a string|an array of non-objects|...>; remedy: copy role_context.ticket_set verbatim, the exact array of {id, pr, head, base, branch} objects in host order, not a string or a list of ids`.
  - The shape check runs after the sentinel outcome check, so an unsupported outcome keeps its existing refusal.
  - A well-shaped array with any differing value still gets the existing `ARTIFACT_IDENTITY_MISMATCH` message, unchanged.
  - A JSON-encoded string is refused, never parsed.
- **Reference.**
  - In `integrator.md`, replace the example's `ticket_set` line with `"ticket_set": [{"id": "T-33-01", "pr": 123, "head": "<40-char PR head sha>", "base": "<PR base branch>", "branch": "<ticket branch>"}]`.
  - After the example, add one sentence: "`ticket_set` is `role_context.ticket_set` copied verbatim, the exact array of `{id, pr, head, base, branch}` objects in host order; a string, a list of ids, a reordered or re-keyed array is refused."
  - Keep the digest sentence and the `## Verification contract` section.
- Comment policy: add no explanatory, historical or ticket comments on added code lines. At most one single-line `@contract:` marker of 120 characters or less is allowed.

## Acceptance criteria

- The integrator launch's `selection.schema` (captured through `onLaunch`) has these properties:
  - `required` includes `ticket_set` and `ticket_set_digest`;
  - `properties.ticket_set.items.required` deep-equals `['id','pr','head','base','branch']`;
  - `additionalProperties === false`.

  The pr-sentinel launch schema has the same `ticket_set` definition and requires `outcome`, `head` and `head_tree`. The arch-review launch schema is unchanged.
- Captured shape: an integrator result whose other fields are correct but whose `ticket_set` is a string (for example `"T-39-01 … T-39-12"`) is refused:
  - the error has `code === 'INVALID_RESULT'`;
  - the message contains `ticket_set` and `remedy: copy role_context.ticket_set verbatim`;
  - the message does not contain `identity differs`;
  - `INTEGRATION.md` is not sealed, and no artifact is returned.
- An integrator result whose `ticket_set` is `['T-01-01']` gets the same refusal. So does a sentinel result whose `ticket_set` is a string.
- A well-shaped `ticket_set` with one changed `head` is still refused with `ARTIFACT_IDENTITY_MISMATCH`.
- The existing integrator, sentinel, read-only smoke and arch-review tests pass unchanged.
- `integrator.md` contains `"ticket_set": [{"id"` and `copied verbatim`. `node tests/unit/source-contract.test.cjs` still passes the verification-contract test.
