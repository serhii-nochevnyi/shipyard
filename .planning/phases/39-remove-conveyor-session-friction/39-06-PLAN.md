## Goal

`validate-graph.cjs` warns, without changing its exit status, when a same-phase
dependency shares no `files_modified` with its parent, and the delivery-rules
skill states the validator's condition: ordering alone is not a `depends_on`
(D-08).

## Scope

- In the `for (const id of order)` loop, for each same-phase, same-repo dependency `d`, when no pair of ownable paths from `t.files` and `tickets[d].files` satisfies `mayIntersect`, push the warning: `${id}: depends_on ${d} shares no files_modified with it — if ${id} does not need ${d}'s code, drop the dependency (ordering alone is not a depends_on; it serializes waves and pr_base)`. Cross-phase and cross-repo dependencies keep only their existing warnings. Exit status is unchanged; the contested-path rule and diamond warning are byte-identical.
- `skills/delivery-rules/SKILL.md` §7: linearize only when the child needs every parent's code at once; an ordering-only relation is not a `depends_on`; mention the new warning and that a real import dependency may legitimately trigger it.
- Regenerate `.shipyard/generated/gsd-delivery-rules/SKILL.md` by the `projectionBody` rule (source bytes plus the managed marker), so gsd-tune does not report `stale-managed`.
- Do not extend the narrative header in `validate-graph.cjs`; no new explanatory comments.
