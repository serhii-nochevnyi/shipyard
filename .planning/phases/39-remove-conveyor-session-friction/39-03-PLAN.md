## Goal

The stop gate enforces a delivery front only in a session that `/shipyard:deliver`
armed with a per-`session_id` marker. A missing, unreadable or foreign marker
allows the stop; armed sessions keep cross-worktree front discovery (D-04).

## Scope

- Human checkpoint first (risk high, Assumption A1): before relying on it, the operator runs a scratch plugin command that echoes `${CLAUDE_SESSION_ID}` on the host and compares it with the `session_id` the Stop hook receives. If it is not substituted, stop and escalate for an alternative arming path; do not ship an inert arm.
- New `plugins/delivery-pipeline/scripts/stop-gate-arm.cjs` exporting `markerPath(cwd, sessionId)`, `arm(cwd, sessionId)`, `isArmed(cwd, sessionId)`, with CLI `node stop-gate-arm.cjs arm --session-id <id>`.
  - `sessionId` must match `/^[A-Za-z0-9_-]{8,128}$/`; anything else, including an unsubstituted `${CLAUDE_SESSION_ID}` literal, makes the CLI exit 1 with a plain message (one `@security:` marker comment is allowed).
  - Marker path: `<git rev-parse --git-common-dir>/shipyard/stop-gate-armed/<id>.json` (spawn with a timeout, like `worktreesOf`); when cwd is not in a git repo, `<cwd>/.planning/graph/stop-gate-armed/<id>.json`.
  - Marker body `{ session_id, armed_at, cwd }`, written with `lock.cjs` `writeAtomic`. `isArmed` is true only for a readable, parseable marker whose `session_id` equals the requested id; any error returns false.
- `stop-gate.cjs`: in the unscoped branch only, before collecting candidates, allow when `!sessionId || !isArmed(cwd, sessionId)`. Scoped mode, the kill switch, the ledger and cross-worktree discovery for armed sessions stay unchanged. Do not extend the existing header comment.
- `deliver.md` Step 0: add the Claude-only arming item `node ${CLAUDE_PLUGIN_ROOT}/scripts/stop-gate-arm.cjs arm --session-id "${CLAUDE_SESSION_ID}"`, stating that a non-zero exit must be reported to the user, that Codex has no stop hook so it skips this, and that a `--fork-session` session must re-arm. Rewrite the self-check sentence to pipe `{"session_id":"<this session id>"}` instead of `{}`.
- `.gitignore`: add `.planning/graph/stop-gate-armed/` next to the ledger entry.
- Test helpers in `stop-gate.test.cjs` arm by default: pass a fixed `session_id` in the payload and arm through the module's own `arm(cwd, id)` (git-common-dir marker inside a git repo such as the `:393`/`:417` sibling-worktree fixtures, fallback marker in non-git temp dirs); never hand-write the fallback path in a git fixture. Rewrite the `:707` test deliberately: without a session id the gate now allows (intended behaviour change).
- `tests/unit/dispatch-record.test.cjs`: the `gate(cwd)` helper passes a fixed `session_id` and arms the scratch project through `arm(cwd, id)` before spawning, so the end-to-end block/silent assertions keep measuring the board, not the arming.

## Acceptance criteria

- An unarmed session next to a fresh live foreign front → allow.
- A marker for another `session_id` → allow; an unreadable or malformed marker → allow; a payload without `session_id` → allow.
- An armed session next to a live sibling worktree → block (the `:393` and `:417` cases stay green).
- An armed session with a stale main checkout and a live worktree front → block.
- Scoped-mode tests are unchanged and green.
- `stop-gate-arm.cjs arm --session-id '${CLAUDE_SESSION_ID}'` and `--session-id ../x` exit 1 without writing; a valid id writes the marker under git-common-dir, or the fallback outside git.
- `stop-gate.cjs` requires `./stop-gate-arm.cjs` by a relative path (source assertion in `stop-gate-arm.test.cjs`), so `copy_stop_bundle` ships it; `stop-gate-arm.cjs` itself requires only built-ins and relative modules.
- `tests/unit/dispatch-record.test.cjs` stays green with the armed `gate` helper (negative control still blocks).
- The host probe confirmed `${CLAUDE_SESSION_ID}` substitution matches the Stop-hook `session_id` (recorded in the evidence).
