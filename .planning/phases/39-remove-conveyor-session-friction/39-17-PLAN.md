## Goal

The three judgement roles (arch-review, integrator and pr-sentinel) receive a context packet that holds only what their plans can act on. After this plan:

- the packet carries only the ADRs that the role's plans reference by id (`ADR-NNN`), and never an ADR whose status is superseded (ADR-005 and ADR-012 today);
- the packet carries no backlog entry unless a plan references it;
- each source file's content appears exactly once in the packet;
- the packet token ceiling is a real bound, in the tens of thousands for arch-review and pr-sentinel, with a larger explicit bound for the integrator derived from its combined diff;
- a packet over its bound is refused before launch, and the refusal names the remedy.

This extends REQ-135 (a role worker receives its bound at launch and is refused deterministically, with a named remedy) from the result to the launch packet. It closes the phase 39 integrator launch refusal measured on 2026-09-25: `claude-role-host: complete role prompt exceeds the bounded launch size`.

## Scope

- **ADR selection (`claude-role-host.cjs`).** Replace `architectureRefs(worktree)` with `architectureRefs(worktree, plans)`:
  - **Referenced ids.** Collect the ids that match `/\bADR-(\d{3})\b/g` in the content of the role's plans: the single ticket plan for arch-review, and every phase plan (`sources.plans`) for the integrator and pr-sentinel. Sort them and remove duplicates.
  - **Decision record.** An id `ADR-NNN` resolves to its decision record: the one `.planning/architecture/ADR-NNN-*.md` file whose name after `ADR-NNN-` is not an all-uppercase companion suffix (`/^[A-Z][A-Z0-9-]*\.md$/`, for example `DATA-MODEL.md`, `ROLLOUT.md`, `BACKLOG.md`).
  - **Other architecture files.** A companion or any other architecture file is included only when a plan names its exact `.planning/architecture/<file>.md` path.
  - **Superseded records.** A record whose first status line matches `/^\s*(?:[-*]\s+)?(?:\*\*)?Status(?:\*\*)?\s*:(?:\*\*)?\s*superseded\b/im` is excluded even when a plan references it.
  - **Metadata only.** Excluded and unresolved ids are recorded in `role_context` without content:
    - `adr_excluded: [{ id, path, reason: 'superseded' }]`;
    - `adr_unresolved: [id]` for an id with no record in the corpus.

    An unresolved id is recorded, not refused, because plans may cite records held in another repository.
  - **Investigation references.** The `.planning/investigations/.../DECISIONS.md` scan runs only over the included records.
  - **Size bounds.** The `SOURCE_MAX_BYTES` checks stay, applied to the included set.
  - **Empty corpus.** A missing `.planning/architecture` directory is still refused. A corpus with no referenced record gives `adr_refs: []`, which satisfies `ROLE_REQUIRED_INPUTS['arch-review']`.
- **One copy of each reference.**
  - ADR content appears only in `required_refs`. `role_context.adr_refs` carries `{ id, path, sha256, bytes }` without content.
  - `sourceReferences` builds `requiredRefs` as the plan paths plus the included architecture paths, each path once.
  - For the integrator and pr-sentinel, the packet-level `acceptance` and `verification` passed to `buildContextPacket` are `[]`. Per-ticket acceptance and verification live only in `phase_contracts` `{ ticket, path, acceptance, verification, sha256 }`, and the plan content lives only in `required_refs`.
  - Arch-review keeps its single plan's `acceptance` / `verification` at packet level.
- **Backlog selection (`claude-role-host.cjs` + `context-packet.cjs`).**
  - **Selection.** The role host reads the backlog inventory with `inventory(root, null, '')` from `backlog-index.cjs` (read only). It selects an item when a role plan contains the item's full id verbatim, or contains the item's source path (the part of `source` after the first `:`, for example `.planning/backlog/notes.md`). An item whose status is `verified_closed`, `deferred` or `superseded` is never selected.
  - **What `buildPacket` passes.** The sorted `selectedBacklogIds`, plus `backlogInventory: 'selected'`.
  - **`context-packet.cjs` `buildBacklog`.** Accept `options.backlogInventory`, either `'all'` (the default, unchanged for the executor and every other caller) or `'selected'`:
    - with `'selected'`, `inventory.items` holds only the compact entries of the selected ids;
    - `inventory.scope` is `'selected'`;
    - `matched_items` equals the number of selected items;
    - `total_items` stays the full inventory count.

    Any other value fails `INVALID_BACKLOG_SELECTION`.
  - **`validateContextPacket`.** Accepts both scopes. When `inventory.scope === 'selected'`, `inventory.items` must be exactly the selected ids; otherwise fail `INVALID_CONTEXT_PACKET` with `packet backlog inventory scope does not match its selection`.
- **Packet bounds (`claude-role-host.cjs`).** Remove `PACKET_MAX_TOKENS`. Add frozen bounds:
  - `ARCH_REVIEW_PACKET_TOKENS = 60000`;
  - `PR_SENTINEL_PACKET_TOKENS = 40000`;
  - `INTEGRATOR_CONTEXT_TOKENS = 60000`;
  - `INTEGRATOR_PACKET_MAX_TOKENS = 320000`.

  How they apply:
  - `buildPacket` takes the ceiling from `packetBound(role, roleContext)`. The integrator's bound is `Math.min(INTEGRATOR_PACKET_MAX_TOKENS, INTEGRATOR_CONTEXT_TOKENS + Math.ceil(Buffer.byteLength(roleContext.combined_diff.content, 'utf8') / 4))`.
  - After `buildContextPacket`, when `packet.accounting.overflow === true`, `buildPacket` calls `reject(message, 'CONTEXT_PACKET_OVER_BOUND')` before `makePrompt` and before any runtime launch.
  - The message is `<role> context packet is <estimated_tokens> tokens, over its bound of <bound>; remedy: <remedy>`. The remedy for each role:
    - **arch-review:** `split the ticket so its PR diff and referenced ADRs fit, or drop ADR and backlog references its plan does not rely on`;
    - **integrator:** `split the phase into smaller ticket sets, or drop ADR and backlog references its plans do not rely on`;
    - **pr-sentinel:** `drop ADR and backlog references the phase plans do not rely on`.
  - `PROMPT_MAX_BYTES` and its check in `makePrompt` stay as the final byte guard.
- **Tests.**
  - `planText()` in `claude-role-host.test.cjs` gains the line `- Follows ADR-014.`, so that the existing arch-review assertion at `:305` keeps its meaning.
  - A fixture helper `writeCorpus(root, { adrs, backlogFiles })` writes the extra ADR records and backlog files before the seed commit. It is added as a `setupRepository` option.
- **Comment policy.** Add no explanatory, historical or ticket comments on added code lines. At most one single-line `@contract:` or `@invariant:` marker of 120 characters or less per file.

## Acceptance criteria

1. **Unreferenced context is dropped.** Build an integrator fixture with:
   - 20 extra accepted ADR records (`ADR-101-*.md` … `ADR-120-*.md`), none referenced by the plan;
   - 30 backlog files, none referenced by the plan.

   It launches, and the packet captured with `onLaunch` + `packetFromPrompt` has:
   - no `required_refs` path starting `.planning/architecture/ADR-1`;
   - `role_context.adr_refs` holding only `ADR-014`;
   - `backlog.selected_ids` deep-equal to `[]`;
   - `backlog.inventory.items.length === 0`;
   - `backlog.inventory.scope === 'selected'`.
2. **A referenced ADR is included once.** A plan that references `ADR-101` twice, and names `.planning/architecture/ADR-101-sample.md`, gives:
   - exactly one `required_refs` entry with that path, holding the full content;
   - one `role_context.adr_refs` entry for `ADR-101`, with no `content` key;
   - a unique marker string from the ADR body that occurs exactly once in the launched prompt.

   Likewise, the plan's full content (JSON-escaped) occurs exactly once in the integrator prompt, and packet-level `acceptance` is `[]` while `phase_contracts[0].acceptance` is non-empty.
3. **A superseded ADR is excluded.** A plan that references `ADR-105` and `ADR-112` gives no `required_refs` entry for either record, and `role_context.adr_excluded` deep-equal to `[{ id: 'ADR-105', path, reason: 'superseded' }, { id: 'ADR-112', path, reason: 'superseded' }]`, when:
   - `ADR-105-*.md` has the status line `- **Status**: superseded for runtime model and effort selection`;
   - `ADR-112-*.md` has the status line `- **Status:** superseded for runtime model and effort selection`.

   This holds for arch-review and for the integrator.
4. **A referenced backlog entry is selected.** A plan that names `.planning/backlog/ref.md` selects exactly that file's non-closed items. `backlog.selected[*].content` is complete, and `inventory.items` lists only those ids. Every other backlog file is absent.
5. **An over-bound packet is refused before launch.** Build an arch-review fixture whose plan references an ADR of about 300 KB. The launch is refused, and:
   - `error.code === 'CONTEXT_PACKET_OVER_BOUND'`;
   - the message contains `arch-review context packet is`, `over its bound of 60000` and `remedy: split the ticket`;
   - `onLaunch` was never called, and no artifact is returned.

   The same fixture for the integrator is refused with `integrator context packet is`, `remedy: split the phase`, and a bound equal to `60000 + ceil(diffBytes / 4)`.
6. **Real bounds.**
   - An arch-review packet that launches has `accounting.soft_ceiling === 60000`.
   - A pr-sentinel packet that launches has `accounting.soft_ceiling === 40000`.
   - An integrator packet has `accounting.soft_ceiling === 60000 + Math.ceil(diffBytes / 4)`, where `diffBytes` is the byte length of `role_context.combined_diff.content`.
   - `claude-role-host.cjs` no longer contains `PACKET_MAX_TOKENS`.
7. **context-packet unit.**
   - With `backlogInventory: 'selected'` and one selected id, `inventory.items` holds exactly that id, `total_items` keeps the full count, and `validateContextPacket` passes.
   - A packet whose `inventory.items` gains an unselected entry after the build fails with `packet backlog inventory scope does not match its selection`.
   - `backlogInventory: 'some'` fails with `INVALID_BACKLOG_SELECTION`.
   - Without the option, the packet is unchanged from today: the existing tests pass unmodified.
8. **Existing tests.** Every existing test in both files passes. The only edit to an existing fixture is the `planText()` ADR-014 reference line.
