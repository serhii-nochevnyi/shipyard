## Goal

Shipyard ships `templates/adr/ADR.md`, and `adr-ingest.cjs --check` validates an
ADR with the existing parser without writing or deleting anything (D-06). The
same module exports `decisionEntries(markdown)` so the bootstrap (T-39-09) uses
one ADR parser (D-03).

## Scope

- `parseArgs`: add `--check` (boolean). `--check` combined with `--output` or `--output-dir` throws a usage error (`--check writes nothing; drop --output/--output-dir`). With `--check`, the output-path requirement does not apply.
- Split `processInput` into a pure `checkInput(input)` (read, `normalizeAdr`, `validateAdr`, return `{ input, decisions }`) and the existing write step. In check mode `main` never calls `prepareOutputDir` or any write; for each input it prints `<input>: OK (<n> decisions)`, or a JSON array with `--json`. Exit 0 when all inputs pass; exit 1 with the existing `validateAdr` message otherwise.
- Add and export `decisionEntries(markdown)`: returns the ordered array of decision texts from `normalizeAdr(markdown).content`, using the same `sectionNodes`/`canonical`/`directEntries`/`childEntry` logic `countDecisionEntries` counts (so `decisionEntries(md).length === countDecisionEntries(...)`). Also export `checkInput`.
- New `plugins/delivery-pipeline/templates/adr/ADR.md`: title line, header bullets `- **Status:**`, `- **Date:**`, `- **Decision owner:**`, `- **Scope:**`, `- **Supersedes:**`, `- **Related:**`, `- **UI design:** none | <design source>`, then `## Context`, `## Decision` (one placeholder bullet per locked decision, at least one bullet), `## Consequences`, `## Out of scope`. No nested `###` under machine-read sections.
- No explanatory code comments.

## Out of scope

- Re-validating existing accepted ADRs.
- The investigate Gate 1 prose (T-39-11) and the bootstrap script (T-39-09).

## Acceptance criteria

- `--check --input` on the FLAT and NESTED fixtures exits 0, prints the decision count, and creates no file.
- `--check` on an ADR with no `## Decision` bullets exits 1 with the existing "no decisions were found" message.
- `--check --output-dir <dir>` exits 1 with a usage error.
- `--check` leaves a pre-existing `*.ingest.md` in a directory byte-identical.
- The shipped template passes `normalizeAdr` + `validateAdr` (the same function `--check` uses).
- `decisionEntries(NESTED)` returns the fixture's two decisions in order; `decisionEntries(FLAT)` returns its bullets in order.
- Existing ingest behaviour (with `--output`/`--output-dir`) is unchanged.
