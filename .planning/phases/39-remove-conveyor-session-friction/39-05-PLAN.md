## Goal

A script turns `tickets.json` and the local PLAN files into a deterministic,
pure-data Jira export plan (issue content, repo-namespaced labels, explicit
`is blocked by` direction) that the agent executes verbatim through MCP, and a
second subcommand records the resulting keys into PLAN frontmatter. The script
has no network code and handles no credential (D-07).

## Scope

- `jira-export.cjs plan --repo <owner/repo> --project <KEY> [--issue-type <t>] [--epic-issue-type <t|none>] [--graph <dir>] [--json]`:
  - reads `tickets.json` and each ticket's PLAN `## Goal`, `## Scope`, `## Acceptance criteria` from local files only;
  - emits steps in a fixed order: one epic per phase (skipped with `--epic-issue-type none`), then issues in topological order (parents first, ties by ticket id), then links;
  - each issue step carries summary, description (sections plus the single-line source-of-truth pointer), labels (namespaced, lowercase, sanitized), epic reference, and an idempotency lookup `{ jql: 'project = KEY AND labels = "<label>"' }` with the legacy-label fallback in the documented order;
  - each link step is `{ type: "Blocks", inward: <dependency ref>, outward: <dependent ref>, phrase: "<dependent> is blocked by <dependency>", required_semantics: "inward description reads is blocked by" }`, one per `depends_on` entry;
  - output is byte-identical across runs (stable key order, no timestamps).
- `jira-export.cjs record <T-NN-MM> <KEY> [--graph <dir>]`: validates the ticket id `^T-\d{2}-\d{2}$` and key `^[A-Z][A-Z0-9]+-\d+$`, refuses a ticket absent from `tickets.json`, then inserts or replaces `jira: <KEY>` inside the PLAN's `delivery:` block as a line edit (all other bytes preserved, atomic write), and prints a reminder to re-run `validate-graph.cjs`. Idempotent.
- No `fetch`, URLs, `mcp`, `gh`, `curl`, `child_process` or network modules in the source.
- No explanatory code comments.

## Acceptance criteria

- For a fixture graph with a diamond and a chain, `plan --json` is byte-identical across two runs, parents precede children, and every `depends_on` yields exactly one link with the dependent on the outward (blocked) side.
- Labels are namespaced by `<owner>-<repo>` and lowercase; the source-of-truth pointer is a single line.
- `--epic-issue-type none` yields no epic steps.
- `record` changes only the `jira:` line (byte diff of the rest is empty), is idempotent, and refuses an unknown ticket or malformed key with exit 1.
- The network-token sweep over `jira-export.cjs` finds nothing.
