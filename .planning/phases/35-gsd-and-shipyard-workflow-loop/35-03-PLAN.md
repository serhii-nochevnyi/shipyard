## Goal

Make the synchronized workflow understandable and healthy from a cold start,
then publish this repository's missing GSD artifacts through the canonical
synchronizer. Documentation must describe the actual boundary and the config
must use the capability's declared namespace so GSD does not warn about ignored
keys.

## Context (Reads)

- `.planning/architecture/ADR-013-gsd-workflow-synchronization.md` and its
  interface/data/rollout companions.
- `.planning/PROJECT.md`, `.planning/ROADMAP.md`, and `.planning/config.json` —
  current GSD project anchor, requirements, roadmap, and warnings.
- `docs/gsd_multilevel_delivery_pipeline.md` — public workflow contract and
  operator entry point.

## Scope

- Normalize the GSD project anchor headings required by the installed health
  validator while preserving the intentional non-duplication with `CLAUDE.md`.
- Move the Shipyard GSD synchronization setting into the declared
  `delivery_pipeline` namespace and remove the ignored ad-hoc key.
- Document the projection command, lifecycle gates, evidence rules, repair path,
  and the native GSD/Shipyard boundary in the delivery documentation.
- Run the synchronizer in write mode against this repository, review every
  generated file, and retain truthful pending/gaps findings for historical
  phases. Do not edit existing integration verdicts.

## Out of scope

- Resolving phase 24/27 integration findings.
- Deleting stale worktrees or changing delivery-state history.
- Inventing summaries or UAT passes for phases without evidence.

## Acceptance criteria

- `validate.health` has no `STATE.md`/PROJECT-heading errors and `init.progress`
  detects the native state/requirements artifacts.
- The project config produces no unknown `pipeline` key warning for the
  synchronization setting.
- The delivery documentation names synchronization after delivery and before
  phase ship, and all claims point to the actual command/gate.
- A write-mode sync creates the required artifacts; a subsequent `--check`
  returns clean; phase 27 remains non-green and phase 29 remains passable from
  its existing evidence.
- `roadmap.analyze`, `stats.json`, `verification.status`, and `phase uat-passed`
  agree with the projected artifact set.
- Existing unrelated worktree/config/code changes remain untouched.
