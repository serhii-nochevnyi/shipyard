## Goal

Build the one local projection command that turns validated Shipyard planning and
delivery evidence into native GSD state without inventing completion. The command
must be usable by both installers and remain safe to rerun after an interrupted
session.

## Context (Reads)

- `.planning/architecture/ADR-013-gsd-workflow-synchronization.md` — locked
  source-of-truth, artifact, and evidence rules.
- `.planning/architecture/INTERFACES-013-gsd-workflow-synchronization.md` — CLI,
  marker, exit-code, and JSON contracts.
- `.planning/architecture/DATA-MODEL-013-gsd-workflow-synchronization.md` —

## Scope

Implement `gsd-sync.cjs` with:

1. applicability and source validation (delivery plans, graph identity, phase
   mapping, and no ambiguous ticket);
2. deterministic source fingerprinting independent of absolute paths/timestamps;
3. generation of `STATE.md`, `REQUIREMENTS.md`, one summary per plan, one UAT
   and verification projection per phase, and a marked roadmap status block;
4. evidence mapping that distinguishes merged plan, passed integration,
   `needs-fix`, missing evidence, and unreadable/malformed sources;
5. `--check`, `--json`, and `--phase` argument handling;
6. ownership-marker conflict refusal, lock-scoped atomic writes, and idempotency.

The generated summary must state that it is a Shipyard delivery projection and
must not claim native executor commits when delivery evidence only identifies a
merged ticket.

## Out of scope

- Capability registration or lifecycle hook wiring (35-02).
- Repository documentation/config cleanup and current-state bootstrap (35-03).
- GitHub/Jira access, PR mutation, worktree cleanup, or historical integration
  remediation.

## Acceptance criteria

- A temporary project with plans, graph, delivery state, and a passed integration
  report generates all required native artifacts and a second run is byte-stable.
- `--check` exits 0 after synchronization and non-zero after a source change or
  deleted generated file, without rewriting anything.
- A merged plan gets `status: complete`; a non-merged or malformed plan is not
  marked complete.
- A phase with no integration evidence is `pending`; a `needs-fix` integration
  is `gaps_found`; only a fully merged phase with explicit passing evidence is
  `passed`.
- Generated UAT has parser-compatible `### N.` blocks and column-zero results;
  `gsd-tools phase uat-passed` produces the expected pass/fail result.
- A conflicting non-generated artifact is refused and named; no partial
  publication remains after a failed write.
- The source fingerprint changes when a plan, graph state, roadmap, or
  integration evidence changes and stays stable across checkout roots.

## Test strategy

Use temporary directories and real CLI invocations. Cover source parsing,
identity mismatch, every status branch, generated-file ownership, idempotency,
check-only no-write behavior, fingerprint stability, lock/atomic publication,
and the installed GSD UAT predicate. Include the repository's 79-plan graph as
an integration fixture through a read-only `--check` run.
