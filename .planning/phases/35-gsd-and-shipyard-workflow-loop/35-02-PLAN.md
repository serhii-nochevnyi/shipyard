## Goal

Make the projection part of the actual GSD lifecycle for Claude and Codex. A
Shipyard project must not proceed from planning, delivery, verification, or
ship with a missing/stale native projection; an ordinary GSD project must remain
unaffected.

## Context (Reads)

- `capabilities/delivery-pipeline/capability.json` — existing Gate 2 and UAT
  gate schema and config namespace.
- `capabilities/delivery-pipeline/checks/graph-gate.cjs` and
  `capabilities/delivery-pipeline/checks/uat-gate.cjs` — applicability and
  fail-closed launcher patterns.
- `scripts/install-shipyard-capability.sh` and
  `scripts/install-shipyard-codex.sh` — both copy plugin scripts into the
  capability/bundle surfaces.
- `scripts/gen-codex-shipyard.cjs` and
  `tests/smoke/codex-shipyard-smoke.sh` — generated Codex payload contract.
- `docs/gsd_multilevel_delivery_pipeline.md` — GSD/Shipyard loop boundaries.

## Scope

Implement the installed `gsd-sync-gate.cjs` launcher and register the
applicability-scoped hooks/gates:

- `plan:post`: write the projection after Gate 2 succeeds;
- `execute:post` and `verify:post`: write it after delivery/verification;
- `ship:pre`: run `--check` as a blocking final consistency gate.

Add `delivery_pipeline.gsd_sync` as a declared boolean, defaulting to true,
with an explicit false opt-out. Preserve the existing `pipeline.*` legacy
compatibility only where the current gates already support it; do not create a
second config namespace for new behavior.

The launcher must resolve its own installed sibling, refuse missing/incomplete
bundles, preserve command exit codes, and report `not applicable` for projects
without a valid Shipyard delivery plan. Smoke coverage must prove the generated
Codex bundle contains and can execute the same synchronizer.

## Out of scope

- Projection implementation (35-01).
- Manual editing of generated GSD files.
- Changes to GitHub state-sync, Jira projection, or stop-gate semantics.

## Acceptance criteria

- Capability manifest validates with the installed GSD capability validator.
- The gate is inert in a non-conveyor temporary project and blocking in a
  conveyor project with missing/stale artifacts.
- The four lifecycle points are registered with the correct write/check mode
  and `onError: halt` for blocking checks.
- `delivery_pipeline.gsd_sync=false` disables only this new synchronization
  gate and leaves Gate 2/UAT behavior unchanged.
- Claude capability install and Codex generation expose one identical canonical
  `gsd-sync.cjs`; no hand-edited generated copy is introduced.
- Smoke tests cover the installed sibling lookup and a stale projection refusal.

## Test strategy

Use temporary project roots for applicability, opt-out, missing sibling, and
stale projection cases. Run the capability validator and the full Codex smoke;
assert the generated bundle's script hash equals the canonical script hash.
