## Goal

ADR-020 adds four project-configuration keys (D-05 comment markers, D-07 remedy workflows, D-09 bot identities, D-01 verification allow-list). They follow the phase-40 D-45 pattern: registered in `pipeline-config.cjs`, keyed by `owner/repo`, the merged `delivery_pipeline.*` view wins, and a bad shape warns and falls back. This ticket registers them once and exports one resolver, so the consumers (T-43-03, T-43-08, T-43-16, T-43-18) never re-parse a map.

## Scope

- `pipeline-config.cjs`: register `comment_markers`, `reviewer_bots`, `repo_remedies` and `verification_commands` with default `null` so none produces an unknown-key warning. Normalize at load:
  - `comment_markers`: object; each key is `owner/repo` (validated with the same slug grammar as `delivery.repo`) or `default`; each value an array of strings, each 1..64 characters, no whitespace, no regular-expression metacharacters other than `@ = - _ . :`. An invalid token is dropped with a warning naming the key and the token; an invalid map warns and becomes `null`.
  - `reviewer_bots`: same map shape; values are logins, optionally ending in one `*` for a prefix match.
  - `repo_remedies`: object keyed by `owner/repo`; each value an array of `{signature: string, workflow: string matching /^[A-Za-z0-9._-]+\.ya?ml$/, inputs?: {string: string}, ref?: string}`. An invalid entry is dropped with a warning.
  - `verification_commands`: map keyed by `owner/repo` or `default`; each value an array of `{argv: non-empty string[], profile?: 'sandbox'|'host', timeout_s?: integer 1..3600}`; `profile` defaults to `sandbox` (P-01). A string instead of `argv` array is refused with a warning (no shell strings).
- Export `repoValue(cfg, key, repo)`: returns the `repo` entry, else `default`, else `null`. It never reads anything but the already-loaded config.
- `tests/unit/pipeline-config.test.cjs` (hermetic temp project roots): no unknown-key warning for the four keys; each invalid shape warns naming the key and falls back; `delivery_pipeline.<key>` wins over `pipeline.<key>`; `repoValue` picks the repository entry, then `default`, then `null`; a `verification_commands` entry given as a string is refused; `profile` defaults to `sandbox`; with none of the keys set, `loadConfig` returns exactly today's warnings for the Shipyard repository's own `.planning/config.json`.
