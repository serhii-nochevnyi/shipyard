## Goal

D-05 (REQ-163). pdffiller's own agents require `@ai-generated model=<model>` on generated tests; the hard-coded markers blocked it, and an ADR-required edit of a stale comment was blocked because a modified comment line scores as added. Target repositories may declare extra exact marker tokens in trusted project config; a changed line whose pre-image was already a comment is not an addition; net-new free comments still block; built-in markers and Shipyard defaults are unchanged.

## Scope

- `comment-policy.cjs`:
  - `extraMarkers({projectRoot, repo})`: `repoValue(loadConfig(projectRoot), 'comment_markers', repo)`; the repository slug comes from `git -C <projectRoot or worktree> remote get-url origin`. Any read failure or no project root returns `[]` (the stricter built-in set, fail closed). The ticket worktree's `.planning/config.json` is never read.
  - A comment body is allowed as a marker when it matches `MARKER_PATTERN` (unchanged) or starts with a configured token followed by whitespace or end of body, and the whole marker line is at most `MAX_MARKER_LENGTH`. Tokens are compared literally (no regex built from config).
  - Pre-image rule: inside each `--unified=0` hunk, pair removed and added lines positionally; an added line whose paired removed line scanned as a comment in the base blob (`git show <base>:<path>`, scanned whole so block-comment state is right) and that is itself a comment is reported as `edited_comment`, not a violation. An added comment line with no paired comment pre-image still blocks.
  - `policy.allowed_markers` in the JSON output lists the built-in markers plus the effective configured tokens.
- `publish-gate.cjs`: pass `projectRoot` and the repository slug to the policy; no other change.
- `tests/unit/comment-policy.test.cjs` (hermetic git fixtures):
  - with `comment_markers: {"acme/app": ["@ai-generated"]}` in a temp project root, `// @ai-generated model=x` passes for `acme/app` and blocks for `acme/other`;
  - a token containing whitespace or `(` is dropped (T-43-01 warns) and does not allow anything;
  - editing the text of an existing comment line passes; turning a code line into a comment blocks; a net-new free comment blocks;
  - a block comment opened above the hunk is recognised through the whole-file scan;
  - no config: exactly today's results and today's `allowed_markers`;
  - a `.planning/config.json` inside the worktree that declares markers is ignored.
- `tests/unit/publish-gate.test.cjs`: a fixture with a configured token passes the gate end to end; the Shipyard-shaped fixture reports the three built-in markers only.
- Comment policy on added lines.
