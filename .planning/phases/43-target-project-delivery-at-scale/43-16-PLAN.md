## Goal

D-01 (REQ-159). The Claude executor sandbox has no docker, php, network or dependencies, so 8 of 13 proving-ground tickets could edit but not verify, and the orchestrator verified and committed them by hand. The trusted host, outside the agent sandbox, runs only the verification commands declared in the approved plan that match the project allow-list, as argument arrays with timeouts and bounded output; records the result as finalization evidence (a sealed artifact referenced by digest); finalizes only on pass; returns failures to the bounded executor or fixer round. The agent sandbox is not widened and the receipt shape does not change. Codex reuses the same host path (T-42-01's producer).

Runner profile (P-01): T-42-01's OS-sandboxed runner is the default; an allow-list entry may declare `profile: host` to run through `runBounded` without the OS sandbox (argv, timeout, bounded output), the profile is recorded in the evidence, and it is never the default.

Risk is high: this is an operator-authority execution path and relaxes T-42-01's "never bare `runBounded`" for declared entries. The checkpoint verifies on an operator host that an undeclared command never runs and that the `host` profile runs only for the declared entry.

## Scope

- NEW `host-verification.cjs` (extracted from T-42-01's producer; `codex-delivery-host.cjs` keeps a re-export of `collectVerificationEvidence` for its callers):
  - `planCommands(pinnedPlanText)`: parse the pinned plan's `## Verification commands` bullets into argv arrays with a strict tokenizer (whitespace split, single/double quotes, no shell operators; any `|`, `;`, `&&`, `>`, `<`, backtick or `$(` refuses the command as unrunnable).
  - `admit(commands, allowList)`: a command is admitted when some allow-list entry's `argv` is a token-wise prefix of it, except that an entry with `profile: host` admits only an exact token-wise match (a `host` entry `["make"]` does not admit `make deploy`); the entry's `profile` (default `sandbox`) and `timeout_s` apply. Unadmitted commands are listed as `not_allowed` and are never run. With no allow-list configured, nothing runs host-side and today's behaviour stands (finalization evidence records `verification: not-configured`).
  - `run(admitted, {worktree, runner})`: `sandbox` entries through `createVerificationRunner` (T-42-01, unchanged); `host` entries through a new `createHostProfileRunner` in `command-runner.cjs`; both return status, signal, timeout flag and bounded output digests.
  - `evidence(results, meta)`: a sealed artifact (durable envelope, host key) stored under the host state root, referenced by digest; it records each argv, profile, runner backend or `host`, status and output digests, and the scoped tree digest before and after. A changed scoped tree refuses.
- `command-runner.cjs`: `createHostProfileRunner({timeoutMs, maxOutput, envAllowList})` wraps `runBounded` with argv only (no shell), the timeout, bounded output and an explicit environment allow-list; it is exported only for `host-verification.cjs`.
- `claude-delivery-host.cjs` and `codex-delivery-host.cjs`: after a verified executor or fixer completion and before `finalizeDeliveryCommit`, call `host-verification`; on any failure return a structured `verification_failed` result naming the failing command, which routes to the existing bounded fixer round and never finalizes; on pass pass the evidence digest to the finalizer as finalization evidence. The receipt is not modified.
- Tests (hermetic; a fake runner is injected where the OS backend is absent, and the real `sandbox-exec`/`bwrap` cases from T-42-01 keep running where available):
  - `tests/unit/host-verification.test.cjs`: parsing of bullets; shell operators refused; prefix admission for sandbox entries and exact-only admission for `host` entries; `not_allowed` never runs (spy runner); `host` profile routed to the host runner and recorded; default profile is sandbox; a command appearing only in agent output is ignored; changed tree refuses; evidence digest stable.
  - `tests/unit/command-runner.test.cjs`: `createHostProfileRunner` enforces timeout and output bound and never invokes a shell.
  - `tests/unit/claude-delivery-host.test.cjs` and `tests/unit/codex-delivery-host.test.cjs`: a failing admitted command blocks finalization and yields `verification_failed`; a passing one finalizes with the evidence digest; the receipt object is byte-identical to today's shape; no allow-list → today's behaviour.
