## Goal

D-02 (REQ-160), recorder half; D-01 (REQ-159) evidence link. Nothing records which commits the conveyor made: the finalizer returns `{commit, …}` and persists nothing, `base_merge` journal lines are written by the model (one covers a hand-resolved conflict), and hand commits were signed with the same key. Before the merge gate can refuse uncovered heads (T-43-19), every conveyor commit needs a sealed coverage record: executor and fixer commits at trusted finalization (with the receipt and verification evidence digests), and base-merges that `base-merge.cjs` committed itself (P-02). The first recorded finalization writes the sealed rollout marker used to decide "opened after release" (P-03).

Same-phase parents: T-43-13 (primary by id on a depth tie; `base-merge.cjs`, shared `files_modified`) and T-43-16 (both hosts and their tests, shared `files_modified`, plus the verification evidence digest this ticket records). T-43-06 (finalizer, scratch set) is an ancestor of both.

Risk is high because the records are the merge gate's evidence; the checkpoint verifies on an operator-owned scratch repository that a hand commit and a hand-resolved merge get no record.

## Scope

- NEW `conveyor-coverage.cjs`:
  - Store: `<host state root>/coverage/<repo-slug>/<commit>.json`, sealed with the durable envelope and a host key created 0600 on first use; the state root is the one the delivery hosts already use outside any worktree, resolved by one exported `coverageRoot()` that both hosts (Claude and Codex) and the sentinel call, so a record written under one runtime is verifiable under the other; `conveyor-coverage.test.cjs` asserts that the helper resolves the same path under Claude and Codex runtime environments (T-43-19's `sentinel.cjs` calls the same helper).
  - `createCoverageWriter({keyPath})` → `{record}`: the only way to write a record; it needs the host key (0600, host state root, never inside a worktree) and is called only from trusted host code paths — the finalizer, `base-merge.cjs` and T-43-18's remedy attribution. It is not exported through any CLI. `record({commit, parents, tree, ticket, repo, kind, dispatch_id?, receipt_digest?, verification_digest?, base_merge?})`: `kind` is `executor|fixer|base-merge|remedy`; executor/fixer require `dispatch_id` and `receipt_digest`; atomic create, an existing identical record is idempotent, a conflicting one refuses.
  - `verify({commit, repo})`: returns `{covered: true, record}` only when the envelope authenticates with the host key, the recorded `commit`, `parents` and `tree` match `git cat-file` of that commit, and — for `executor` and `fixer` — the durable receipt for `dispatch_id` is re-read from the host's receipt store (the same `getVerifiedRecord` path T-42-01 uses), has `compliance: verified`, names the same ticket and repository, and its digest equals `receipt_digest`. A missing, unverified or mismatching receipt, an unreadable store or key, or any other difference returns `{covered: false, reason}`; nothing is inferred.
  - `rolloutMarker({repo?})` / `ensureRolloutMarker({recorded_at})`: a sealed project-level marker written once, at the first `record` of kind executor or fixer; later calls return the existing marker.
  - CLI: `verify <commit> --repo <slug> [--json]` and `marker [--json]` only; there is no `record` subcommand, so an orchestrator cannot cover its own commit.
- `delivery-commit-finalizer.cjs`: accept `coverage: {kind, dispatch_id, receipt_digest, verification_digest}` from the host and, after `update-ref` succeeds, call `record`; a record failure is returned as a named error (the commit exists; the host reports it and the merge gate will refuse until re-finalized).
- Both hosts: pass `kind` (`executor` for executor runs, `fixer` for fix rounds), the dispatch id, the verified receipt digest and T-43-16's evidence digest.
- `base-merge.cjs`: after it commits a clean or mechanically resolved merge (its own `git commit --no-edit`, or a fast-forward with no commit needs no record), call `record` with `kind: 'base-merge'` and `base_merge: {base, requested_base, taken_from_base}`. The `conflicts remain` path records nothing (P-02); a later hand commit of that merge stays uncovered and must go through a fixer round.
- Tests (hermetic: temp state root, temp key, own `GIT_CONFIG_GLOBAL`, `commit.gpgsign=false`):
  - `tests/unit/conveyor-coverage.test.cjs`: record then verify; tampered envelope → uncovered; an executor record whose `dispatch_id` has no verified receipt in the store (or whose receipt digest differs) → uncovered; the CLI offers no `record` subcommand; a record written with a different key → uncovered; record for commit A presented for commit B → uncovered; executor record without receipt digest refuses; idempotent re-record; marker written once at the first executor record and stable afterwards.
  - `tests/unit/delivery-commit-finalizer.test.cjs`: a successful finalization writes one record whose `commit` equals the returned commit; a failed `update-ref` writes none.
  - `tests/unit/claude-delivery-host.test.cjs`, `tests/unit/codex-delivery-host.test.cjs`: executor and fix-round paths pass kind, dispatch id, receipt digest and verification digest; the receipt shape is unchanged.
  - `bash tests/smoke/worktree-gates-smoke.sh` (base-merge regression) plus a coverage case in `conveyor-coverage.test.cjs` driving `base-merge.cjs` on a fixture: mechanical merge recorded, `conflicts remain` not recorded.
