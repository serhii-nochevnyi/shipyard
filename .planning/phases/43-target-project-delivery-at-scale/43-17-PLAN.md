## Goal

D-02 (REQ-160), recorder half; D-01 (REQ-159) evidence link. Nothing records which commits the conveyor made: the finalizer returns `{commit, …}` and persists nothing, `base_merge` journal lines are written by the model (one covers a hand-resolved conflict), and hand commits were signed with the same key. Before the merge gate can refuse uncovered heads (T-43-19), every conveyor commit needs a sealed coverage record: executor and fixer commits at trusted finalization (with the receipt and verification evidence digests), and base-merges that `base-merge.cjs` committed itself (P-02). The first recorded finalization writes the sealed rollout marker used to decide "opened after release" (P-03).

Same-phase parents: T-43-13 (primary by id on a depth tie; `base-merge.cjs`, shared `files_modified`) and T-43-16 (both hosts and their tests, shared `files_modified`, plus the verification evidence digest this ticket records). T-43-06 (finalizer, scratch set) is an ancestor of both.

### Re-plan after T-43-16 landed (2026-09-29)

The drift check against `origin/epic/43-target-project-delivery-at-scale` at `dc6ddcc18e9219a76d960a3bd3f0a2f59e036f72` (tree `92b4475e58921183bef1ce479a02f58c5d5254dd`) found that Claude and Codex keep durable receipts in separate runtime roots and run/worktree stores. The earlier plan assumed one shared host state root and did not give `verify({commit, repo})` a way to reopen a receipt using only its dispatch id. Resolve this without moving either runtime's receipt store: both runtimes use one runtime-independent user coverage root, and each executor/fixer coverage record seals the exact receipt-store directory used by its host. Verification reads that recorded store directly and read-only; it never guesses from the current session or scans runtime directories. This ticket does not edit `dispatch-boundary.cjs`: T45-09 owns that shared file, and a cross-phase edit here would create unordered ownership overlap. The coverage verifier therefore validates the existing durable receipt envelope in place and refuses if its store or authority key is missing, invalid, or unreadable; it must not create or repair receipt state.

Risk is high because the records are the merge gate's evidence; the checkpoint verifies on an operator-owned scratch repository that a hand commit and a hand-resolved merge get no record.

## Scope

- NEW `conveyor-coverage.cjs`:
  - Root: `coverageRoot()` resolves to `~/.local/state/shipyard/coverage`, independent of runtime name, `storageRoot`, run id, worktree, and current repo. Claude, Codex, and sentinel use this same user-level root. Create it with mode 0700 and keep the HMAC key at mode 0600 outside every repo/worktree. Partition records as `<coverage root>/coverage/<repo-slug>/<commit>.json`; `conveyor-coverage.test.cjs` proves both runtimes resolve the same default root (T-43-19's sentinel calls the same helper).
  - `createCoverageWriter({keyPath})` → `{record}` is the only write API; it is called only from trusted host paths — the finalizer, `base-merge.cjs`, and T-43-18's remedy attribution — and is not exported through a CLI. `record({commit, parents, tree, ticket, repo, kind, dispatch_id?, receipt_digest?, verification_digest?, receipt_store?, base_merge?})`: `kind` is `executor|fixer|base-merge|remedy`; executor/fixer require `dispatch_id`, `receipt_digest`, and the absolute `receipt_store` directory actually used by that host. The host supplies this locator; it is part of the HMAC-sealed payload. Base-merge/remedy records do not require a receipt store. Atomic create; an identical record is idempotent, a conflicting one refuses.
  - `verify({commit, repo})` returns `{covered: true, record}` only when the coverage envelope authenticates, commit/parents/tree match `git cat-file`, and an executor/fixer record's `receipt_store` is read directly with no writes. Verify the existing durable dispatch HMAC envelope and require `compliance: verified`, the same ticket/repository, and the sealed `receipt_digest`. Never call `createDurableRecorder` during verification: it creates missing directories and authority keys. A missing/unreadable store or key, unverified/mismatching receipt, or any other mismatch returns `{covered: false, reason}`; verification never infers a path from the current session or scans runtime directories.
  - `rolloutMarker({repo?})` / `ensureRolloutMarker({recorded_at})`: a sealed project-level marker written once, at the first `record` of kind executor or fixer; later calls return the existing marker.
  - CLI: `verify <commit> --repo <slug> [--json]` and `marker [--json]` only; there is no `record` subcommand, so an orchestrator cannot cover its own commit.
- `delivery-commit-finalizer.cjs`: accept `coverage: {kind, dispatch_id, receipt_digest, verification_digest}` from the host and, after `update-ref` succeeds, call `record`; a record failure is returned as a named error (the commit exists; the host reports it and the merge gate will refuse until re-finalized).
- Both hosts: pass `kind` (`executor` for executor runs, `fixer` for fix rounds), the dispatch id, the verified receipt digest and T-43-16's evidence digest.
- `base-merge.cjs`: after it commits a clean or mechanically resolved merge (its own `git commit --no-edit`, or a fast-forward with no commit needs no record), call `record` with `kind: 'base-merge'` and `base_merge: {base, requested_base, taken_from_base}`. The `conflicts remain` path records nothing (P-02); a later hand commit of that merge stays uncovered and must go through a fixer round.
- Tests (hermetic: temp state root, temp key, own `GIT_CONFIG_GLOBAL`, `commit.gpgsign=false`):
  - `tests/unit/conveyor-coverage.test.cjs`: record then verify; tampered envelope → uncovered; executor/fixer entries reopen verified receipts from separate Claude and Codex stores after dispatch ends; missing/unreadable receipt store or key, absent/unverified receipt, or digest mismatch → uncovered; a missing store is not created; no `record` CLI command; different coverage key or commit → uncovered; executor record without receipt digest/store refuses; idempotent re-record; marker written once at first executor record and stable afterwards.
  - `tests/unit/delivery-commit-finalizer.test.cjs`: a successful finalization writes one record whose `commit` equals the returned commit; a failed `update-ref` writes none.
  - `tests/unit/claude-delivery-host.test.cjs`, `tests/unit/codex-delivery-host.test.cjs`: executor and fix-round paths pass kind, dispatch id, receipt digest, verification digest, and the exact durable receipt-store directory used for that dispatch; the receipt shape is unchanged.
  - `bash tests/smoke/worktree-gates-smoke.sh` (base-merge regression) plus a coverage case in `conveyor-coverage.test.cjs` driving `base-merge.cjs` on a fixture: mechanical merge recorded, `conflicts remain` not recorded.
