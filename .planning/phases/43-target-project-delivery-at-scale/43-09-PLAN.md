## Goal

D-15 (REQ-173). On the proving ground state-sync took a 128 s median over 25 syncs because it lists `--state all --limit <pr_fetch_limit>` per repository and re-derives every ticket. It must list PRs by ticket head and open state, and not re-derive tickets whose merge into a landed epic is recorded immutably; `--full` re-derives everything.

## Scope

- `state-sync.cjs`:
  - Per repository: one `gh pr list --state open --json <PR_FIELDS>` pass (bounded by `pr_fetch_limit`, truncation still falls back per branch).
  - For each ticket that is neither in the open list nor immutably landed: look up by the ledger PR number (`gh pr view <n> --json …`), else `gh pr list --state all --head <branch> --limit 50` as today's per-branch path.
  - Immutably landed: the ticket's previous state is `merged` with a recorded merge SHA, it has a ledger entry, and its epic's PR is recorded as merged into the integration branch. Such a ticket keeps its previous row and costs no `gh` call.
  - `--full`: today's full re-derivation (all states, every ticket).
  - The summary line reports `listed_open`, `looked_up`, `skipped_landed`.
- NEW `tests/unit/state-sync-listing.test.cjs` (stub `gh` on `PATH` counting calls; temp graph dir): a landed ticket produces 0 calls; an open ticket appears from the single open listing; a closed-unmerged ticket is found by ledger number; `--full` restores the all-state listing; a ticket merged into an epic whose PR is still open is re-derived (not skipped).
- `tests/smoke/sentinel-smoke.sh`: update every affected fake `gh` fixture to distinguish the primary `pr list --state open --json <PR_FIELDS>` listing from the open review/detail listing by the requested `--json` field set. Return full primary rows including `state` and `headRefName`, while retaining each fixture's review decision, body, merge-state variation and all existing assertions; keep `--state all` and per-head paths accurate for `--full`/fallback.
