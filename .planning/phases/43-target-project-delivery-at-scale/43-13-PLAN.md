## Goal

D-03 (REQ-161). Base-merges that only brought already-judged sibling squashes discarded the verdict seven times (about 23 arch-review launches for 13 tickets). A conform verdict carries across a base-merge when the ticket's own patch is identical (`git patch-id --stable`, or identical blobs for every `files_modified` path) and every other path equals the new base; any other difference, including a merge that duplicated a block, re-owes arch-review. The carry posts the `merge-gate` commit status introduced by T-40-19.

Risk is high because it reuses a verdict; the checkpoint reviews the negative fixtures on an operator-owned scratch repository.

## Scope

- `gate-trailer.cjs` `carry`: keep the tree-equal path. Add the patch-identity proof, used when head trees differ, requiring all of:
  1. `patch-id --stable` of `diff <judgedBase> <judgedHead>` equals that of `diff <newBase> <newHead>`;
  2. `diff --name-only <newBase> <newHead>` touches only paths owned by the ticket's `files_modified`;
  3. for every owned path, the blob in `newHead` equals the blob in `judgedHead`.
  Refuse the carry (re-owe arch-review) when any identity is unreadable or any condition fails. On success post the carried `merge-gate` status on the new head with the same verdict fields and `carried=patch-id`.
- `base-merge.cjs` `carryVerdict`: pass the judged and new base refs so `carry` can compute both patches; output field `carry` reports `tree-equal`, `patch-id`, or `re-owed` with the failing condition.
- `tests/unit/trailer.test.cjs`: the carried status description keeps the grammar and fits 140 characters.
- NEW `tests/unit/verdict-carry.test.cjs` (hermetic git; stub `gh` capturing status posts):
  - a sibling squash touching other paths lands in the base; own patch identical → carries with `patch-id`;
  - the base-merge duplicates a block inside an owned file → own blob differs → re-owed;
  - a sibling deletes a function the ticket calls in a non-owned file and the ticket's own patch is untouched → carries (CI and the epic PR are the interaction checks, per the scope fence); the same case where the merge had to adapt an owned file so the own patch changed → re-owed;
  - an owned path changed by the sibling (conflict resolved) → re-owed;
  - unreadable judged base → re-owed;
  - tree-equal path unchanged.
