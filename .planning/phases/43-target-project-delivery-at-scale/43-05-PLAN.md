## Goal

D-16 (REQ-174). An arch-review artifact with a finding type the validator did not know failed as `INCOMPLETE_FINDING` and cost a relaunch. An unknown type is kept as an informational note with its original type and never changes the verdict; a `violation` or an incomplete blocking finding still fails the artifact.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/role-artifact.cjs` (at 22ef429b `:1257-1276`): arch-review types `violation` and `adr-outdated` (required fields), `note`/`informational` (summary only); anything else → `fail('INCOMPLETE_FINDING', … unsupported type …)`. The integrator branch starts at `:1277`. Re-read after T-40-18 lands.
- `plugins/delivery-pipeline/scripts/role-artifact.cjs`, `judgmentResultData`: a `conform` verdict currently requires an empty findings index, including informational findings. `completeFindingIndex` checks `blocking_count` against the normalized findings. Both rules were already present at the cited snapshot; normalizing an unknown type alone cannot satisfy the required `conform` case.
- `tests/unit/judgment-artifacts.test.cjs`: the existing conform test rejects a non-blocking ADR `violation`. Preserve that protection while allowing only normalized unknown informational findings under `conform`.
- `shipyard.role-artifact.v1`: the sealed envelope schema, which does not change.

## Scope

- `role-artifact.cjs`, arch-review branch only: a finding whose `type` is a non-empty string outside the known set and which has non-empty `summary` text normalizes to `{type: 'informational', original_type: <raw>, summary, blocking: false}`. A finding of unknown type without summary text or with explicit `blocking: true` still fails `INCOMPLETE_FINDING`; never silently downgrade an explicitly blocking unknown finding. An omitted `blocking` value on an otherwise complete unknown note becomes false. The caller's `blocking_count` must still equal the normalized count.
- `judgmentResultData`: permit `conform` with a non-empty findings index only when every finding was normalized from an unknown type into a non-blocking informational note. A caller-supplied `original_type` on an already known `informational` or `note` type does not qualify. Continue rejecting `conform` with any `violation` or `adr-outdated` finding, including a `violation` marked non-blocking. The verdict field is validated separately and never derived from or changed by finding normalization; non-conform verdicts still require a real blocking finding.
- `tests/unit/role-artifact.test.cjs`:
  - verdict `violation` plus a complete blocking `violation` and an unknown-type note: accepted, verdict stays `violation`, normalized note carries `original_type` and `blocking: false`;
  - verdict `conform` plus an unknown-type note: accepted, verdict stays `conform`, `blocking_count: 0`;
  - a `violation` finding missing `file`: still `INCOMPLETE_FINDING`;
  - unknown type without summary or with explicit `blocking: true`: still `INCOMPLETE_FINDING`;
  - integrator findings: unchanged behaviour;
  - the sealed envelope schema string is unchanged.
- `tests/unit/judgment-artifacts.test.cjs`: retain the existing non-blocking ADR violation rejection; reject a known informational finding with a forged `original_type` under `conform`; accept only the normalized unknown note under `conform`.
- Comment policy on added lines.
