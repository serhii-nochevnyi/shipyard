## Goal

D-16 (REQ-174). An arch-review artifact with a finding type the validator did not know failed as `INCOMPLETE_FINDING` and cost a relaunch. An unknown type is kept as an informational note with its original type and never changes the verdict; a `violation` or an incomplete blocking finding still fails the artifact.

- `plugins/delivery-pipeline/scripts/role-artifact.cjs` (at 22ef429b `:1257-1276`): arch-review types `violation` and `adr-outdated` (required fields), `note`/`informational` (summary only); anything else → `fail('INCOMPLETE_FINDING', … unsupported type …)`. The integrator branch starts at `:1277`. Re-read after T-40-18 lands.
- `shipyard.role-artifact.v1`: the sealed envelope schema, which does not change.

## Scope

- `role-artifact.cjs`, arch-review branch only: a finding whose `type` is a non-empty string outside the known set and which has non-empty `summary` text normalizes to `{type: 'informational', original_type: <raw>, summary}`. A finding of unknown type without summary text still fails `INCOMPLETE_FINDING`. The verdict field is validated separately and never derived from or changed by finding normalization.
- `tests/unit/role-artifact.test.cjs`:
  - verdict `violation` plus an unknown-type finding: accepted, verdict stays `violation`, finding carries `original_type`;
  - verdict `conform` plus an unknown-type finding: accepted, verdict stays `conform`;
  - a `violation` finding missing `file`: still `INCOMPLETE_FINDING`;
  - unknown type without summary: still `INCOMPLETE_FINDING`;
  - integrator findings: unchanged behaviour;
  - the sealed envelope schema string is unchanged.
