## Goal

D-13 (REQ-171). On a 27k-file repository `run-reachability.cjs` hit Node's 1 MiB default buffer on a full `ls-tree -r`, and `sentinel.cjs` read both full recursive trees over the API, which truncates. Both must ask bounded questions: O(1)-output git forms with a large `maxBuffer`, and declared-path comparisons through local git when the repository is checked out, with a path-scoped API fallback that still refuses a truncated listing.

## Scope

- `run-reachability.cjs`:
  - `git()` gets `maxBuffer: 64 * 1024 * 1024`.
  - `declaredFiles` replaces the full `ls-tree -r` with `ls-tree -r --name-only <base> -- <literal paths and the literal prefix directory of each glob>`, then filters with `path-owner.owns`.
- `sentinel.cjs` epic reachability:
  - When the ticket's repository is checked out locally (ROOT or the `repo-resolve` checkout), fetch the head and epic refs and compare `git ls-tree <ref> -- <declared paths and glob prefixes>` blob ids for declared paths only.
  - Otherwise fall back to path-scoped API reads: a non-recursive tree per declared directory (`gh api …/git/trees/<ref>:<dir>`) or `…/contents/<path>?ref=`. Any `truncated: true` answer yields `{ok:null, reason:'truncated listing'}`.
  - An absent declared path reads as absent (not as "not asserted"); a read error stays `{ok:null}`.
- `tests/unit/run-reachability.test.cjs`: synthetic repository whose full listing exceeds 1 MiB of names (generated in `os.tmpdir()`) no longer fails with ENOBUFS; the scoped answer equals the full-listing answer for literal and glob declarations (agreement test).
- `tests/unit/sentinel.test.cjs` (stub `gh` on `PATH`, hermetic git): local-checkout path compares declared blobs only; API fallback path with a truncated directory tree yields `{ok:null}`; a declared path deleted on the epic reads as absent; the full recursive tree endpoint is never called.
