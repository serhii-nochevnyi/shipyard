## Scope

- `deliver-dispatch.cjs`: `build <role> <ticket> [--runtime claude|codex] [--pr <n>] [--failure-file <f>] [--review-file <f>]` for roles `arch-review`, `ci-fix`, `review-fix`:
  - inputs from the graph row (branch, plan path, repo, files) and, for fixes, the failure or review evidence file path (passed by path plus digest, never inlined content);
  - only allow-listed signals; never `type`, model or effort;
  - the output is passed through the target host's exported validator before it is printed; a validation error exits 2 naming the field. A shape validator accepting a role does not establish that the host will authenticate its evidence or construct the required prompt.
  - Codex: emit a role request only when the released host validates its complete targeted inputs and binds them to the graph, PR, and evidence digest at launch. Otherwise exit 2 with a stable, role-specific reason naming the missing host contract. In particular, `requestValue` accepting `arch-review` is insufficient: the current host still requires a caller-built prompt and does not derive the reviewed diff and ADR corpus. Apply the same completeness check to ci-fix and review-fix evidence rather than treating `requestValue` alone as parity.
- `commands/deliver.md`: replace the hand-built request steps for these three roles with the `deliver-dispatch.cjs build …` command.
- `tests/unit/deliver-dispatch.test.cjs`: each emitted role × runtime request round-trips through the real exported validator (imported, never a hand-written shape); no `type` in signals; a missing failure file exits 2; named-reason refusals for incomplete host paths. Prove that Codex `requestValue`/`validateArgs` accepting an `arch-review` request without a prompt does not count as parity.
- NEW `tests/unit/deliver-builders-contract.test.cjs`: `deliver.md` names the build command for each of the three roles and no longer describes hand-built requests for them; each named script and subcommand resolves.
- Comment policy on added lines.
