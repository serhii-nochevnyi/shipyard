## Goal

D-07 (REQ-165). T-02-06 was parked for a screenshot baseline although jsfiller's `pw-debug-tests.yml` (`regenerateScreenshot`) fixed it; it took two hours and a user nudge. Only operator-declared repository remedy workflows (per repository: failure signature, workflow, inputs) run before a human escalation, bounded by the attempt budget and journalled. A commit such a workflow pushes is a declared link of the merge gate's chain and still goes through arch-review and CI. Nothing undeclared is discovered or run; when nothing is declared, escalation names the candidate remedy.

Same-phase parents: T-43-17 (primary; `conveyor-coverage.cjs` and its test, shared `files_modified`) and T-43-08 (`log-event.cjs` and its test, shared `files_modified`; T-43-07, which edits it first, is its ancestor). T-43-01 (`repoValue`) is an ancestor through both.

Risk is high because it dispatches outward workflows; the checkpoint verifies on an operator-owned scratch repository with a trivial declared workflow.

## Scope

- NEW `repo-remedy.cjs`:
  - `match --repo <slug> --signature-file <f> [--json]`: normalizes the failure with `failure-signature.cjs` and returns the declared entry whose `signature` equals it, else `{match: null, candidates: []}`.
  - `run <ticket> --repo <slug> --pr <n> --entry <index>`: refuses unless the entry is declared for that repository and the ticket's attempt budget has room; records the head at dispatch; runs `gh workflow run <workflow> --repo <slug> --ref <branch> -f k=v…` as an argv array with a timeout; journals `remedy_dispatch` (`ticket, pr, repo, workflow, head`). The dispatch counts as an attempt.
  - `attribute <ticket> --repo <slug> --run <id>`: after the run completes, if the branch head's parent equals the recorded dispatch head, the head commit's author login matches the declared workflow bot (from the entry, default `github-actions[bot]`), and the run id is the dispatched one, write a coverage record `kind: 'remedy'` (`conveyor-coverage.record`); otherwise write nothing and report `unattributed`.
- `escalation-record.cjs mark`: before marking, call `match`; when a declared remedy matches and budget remains, refuse to mark and print the `repo-remedy.cjs run …` command; when nothing is declared, mark as today and include the candidate remedy text (workflow names found in the escalation input are only named, never run).
- `conveyor-coverage.cjs`: `record` accepts `kind: 'remedy'` with `remedy: {workflow, run_id, dispatch_head}`; `verify` treats it like any other kind.
- `log-event.cjs`: register `remedy_dispatch: ['ticket', 'pr', 'repo', 'workflow', 'head']`.
- `references/ci-fix.md` and `references/pr-sentinel.md`: the escalation step runs `repo-remedy.cjs match` first and follows its command; remedy commits still go through arch-review and CI.
- Tests (stub `gh`, temp config and state):
  - `tests/unit/repo-remedy.test.cjs`: a declared signature matches and runs once with the exact argv; an undeclared workflow is never run; exhausted budget refuses; attribution writes a `remedy` record only when parent, author and run id match; a mismatched author writes nothing.
  - `tests/unit/escalation-record.test.cjs`: mark refuses with the command while a declared remedy has budget; marks with a candidate note when none is declared.
  - `tests/unit/conveyor-coverage.test.cjs`: `remedy` records verify; a remedy record without `run_id` refuses.
  - `tests/unit/log-event.test.cjs`: `remedy_dispatch` without `workflow` is refused.
  - `bash tests/smoke/docs-smoke.sh` for the two reference files.
