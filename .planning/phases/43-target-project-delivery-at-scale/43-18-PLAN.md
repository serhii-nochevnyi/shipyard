## Goal

D-07 (REQ-165). T-02-06 was parked for a screenshot baseline although jsfiller's `pw-debug-tests.yml` (`regenerateScreenshot`) fixed it; it took two hours and a user nudge. Only operator-declared repository remedy workflows (per repository: failure signature, workflow, inputs) run before a human escalation, bounded by the attempt budget and journalled. A commit such a workflow pushes is a declared link of the merge gate's chain and still goes through arch-review and CI. Nothing undeclared is discovered or run; when nothing is declared, escalation names the candidate remedy.

Same-phase parents: T-43-17 (primary; `conveyor-coverage.cjs` and its test, shared `files_modified`) and T-43-08 (`log-event.cjs` and its test, shared `files_modified`; T-43-07, which edits it first, is its ancestor). T-43-01 (`repoValue`) is an ancestor through both.

Risk is high because it dispatches outward workflows; the checkpoint verifies on an operator-owned scratch repository with a trivial declared workflow.

## Scope

- NEW `repo-remedy.cjs`:
  - `match --repo <slug> --signature-file <f> [--json]`: use `failure-signature.cjs` normalization and `repoValue(cfg, 'repo_remedies', repo)` to return only the declared entry whose signature equals the current failure; otherwise return `{match: null, candidates: []}`. The returned entry index must identify the same normalized repository entry consumed by `run`.
  - `run <ticket> --repo <slug> --pr <n> --entry <index>`: reject an absent, malformed, or out-of-range entry, repository/PR/ticket mismatch, or `attempts >= max_attempts` from the same graph's `attempt-history.cjs --json`. Before dispatch, read and retain the ticket branch head; use only the normalized entry's workflow, inputs, optional ref (ticket branch when absent), and bot. Invoke `gh workflow run <workflow> --repo <slug> --ref <ref> -f k=v…` through the existing `command-runner.cjs` `runBounded('gh', args, {timeoutMs, maxBuffer})`; pass an argv array, finite timeout and bounded output, with no shell. On a successful dispatch, journal exactly one `remedy_dispatch` with `ticket`, `pr`, `repo`, `entry_index`, `signature`, `workflow`, `ref`, `bot`, `inputs_digest` (SHA-256 of JSON-encoded input `[key,value]` pairs sorted by key), `head` (the dispatch head), and the writer's `ts` (dispatch time); do not journal input values. Failures do not consume an attempt or claim a dispatched run. Do not execute any workflow discovered outside `repo_remedies`.
  - `attribute <ticket> --repo <slug> --run <id>`: require a corresponding successful dispatch event and completed successful GitHub workflow run. Validate the supplied run id against that dispatch using GitHub run metadata: repository, workflow path, `workflow_dispatch` event, exact ref/branch, source head, and dispatch time; refuse missing, stale, or ambiguous matches. Re-read the normalized declaration at the recorded entry index and require its signature, workflow, ref, bot, and digest of normalized inputs to equal the journalled dispatch fields. Accept only a branch-head commit whose sole parent is the recorded dispatch head and whose GitHub author login exactly equals the declared bot (default `github-actions[bot]`). Only then call `conveyor-coverage.cjs` `record` with `kind: 'remedy'` and `remedy: {workflow, run_id, dispatch_head}`; otherwise emit `unattributed` without a coverage record. The resulting commit still owes arch-review and CI before merge.
- `escalation-record.cjs mark`: before marking, call `match`; when a declared remedy matches and budget remains, refuse to mark and print the `repo-remedy.cjs run …` command; when nothing is declared, mark as today and include the candidate remedy text (workflow names found in the escalation input are only named, never run).
- `attempt-history.cjs`: add `remedy_dispatch` to `REPAIR_EVENTS` and count every such event as one charged attempt in `attempts` and `next_n`, even when `--limit` hides it. Preserve the existing rule that an ordinary `attempt` with `outcome: 'flake'` is not charged; other ordinary attempts and their rendered history remain unchanged. `repo-remedy.cjs` uses this shared count for its budget gate.
- `pipeline-config.cjs`: accept an optional `bot` field in each `repo_remedies` entry, validate it as one exact, nonempty GitHub login with no wildcard or whitespace, and normalize omitted `bot` to `github-actions[bot]`. Keep malformed entries on the existing warn-and-fallback path. Attribution compares the exact normalized login.
- `conveyor-coverage.cjs`: preserve T-43-17's existing `remedy` kind and generic `record`/`verify` behavior. Add remedy-specific record validation: require a `remedy` object with a nonempty declared workflow, valid dispatch-head commit identity, and a nonempty run id, including refusal when `run_id` is missing; verify must reject an invalid persisted remedy record as well as use the existing generic coverage checks.
- `log-event.cjs`: register `remedy_dispatch` with required `ticket`, `pr`, `repo`, `entry_index`, `signature`, `workflow`, `ref`, `bot`, `inputs_digest`, and `head`; its existing `ts` is the dispatch time. Reject missing dispatch metadata before it can affect the attempt count or attribution.
- `references/ci-fix.md` and `references/pr-sentinel.md`: the escalation step runs `repo-remedy.cjs match` first and follows its command; remedy commits still go through arch-review and CI.
