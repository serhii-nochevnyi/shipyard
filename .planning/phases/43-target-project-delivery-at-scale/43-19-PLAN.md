## Goal

D-02 (REQ-160), enforcer half. `sentinel.cjs mergeOne` checks no receipt or finalization, so eight orchestrator-authored commits merged into epics. For PRs opened after release, the merge gate refuses a head unless every commit since the ticket's base is a covered link (a trusted executor or fixer finalization, a base-merge committed by `base-merge.cjs`, or an attributed declared remedy commit, all as sealed records from T-43-17/18). Any other commit refuses with the command that brings it under the conveyor. PRs opened earlier keep today's rule and are journalled as legacy. `sentinel.cjs` is the only `gh pr merge` in the plugin, and Codex runs the same script, so this covers both runtimes' merge paths.

Same-phase parents: T-43-18 (primary; `conveyor-coverage.cjs`, `log-event.cjs`, `pr-sentinel.md`, shared `files_modified`) and T-43-12 (`sentinel.cjs` and its test, shared `files_modified`; T-43-04 and T-43-08, which edit it first, are its ancestors). T-43-14 is not a parent: the refusal only prints `deliver-dispatch.cjs build ci-fix|review-fix` (a string, not an import); both land in the epic before release.

Risk is high: it makes the merge gate stricter; the checkpoint verifies on an operator-owned scratch repository that a hand commit refuses with the remedy and a legacy PR still merges.

## Scope

- `sentinel.cjs` reads the store and marker only through `conveyor-coverage.cjs` `coverageRoot()` (T-43-17).
- `conveyor-coverage.cjs`: `chain({repo, worktreeOrCheckout, base, head})` walks `git rev-list --reverse <base>..<head>` locally (bounded by a commit cap; exceeding it is `{covered:false, reason:'chain too long'}`), calls `verify` per commit, and returns the first uncovered commit with its subject and author, or `{covered:true, links:[kinds]}`. `base` is the freshly fetched PR base ref (`origin/<baseRefName>` from `gh pr view --json baseRefName`), never a recorded SHA, so commits already on the base (sibling squashes, a parent ticket's commits) are not walked.
- `sentinel.cjs` `mergeOne`, after the gate verdict and before the checks:
  - Legacy: when the coverage store is readable and holds no rollout marker, or the PR's `createdAt` is at or before the marker's `recorded_at`, merge under today's rule and journal `merge_gate_legacy` (`ticket, pr, head`) once per PR. An unreadable store or marker (missing state root, bad envelope, I/O error) is not "no marker": it refuses with the checkout/state-root hint (fail closed).
  - Otherwise require `chain(...).covered`; on the first uncovered commit refuse, journal `merge_gate_uncovered` (`ticket, pr, head, commit`), and print the remedy: re-run the work through the conveyor (`deliver-dispatch.cjs build ci-fix|review-fix <ticket>` or the executor entry point), or remove the hand commit, then re-verify.
  - A missing or unreadable chain (no local checkout, git error) refuses (fail closed) with the same remedy plus the checkout hint.
  - The successful merge journal line gains `coverage: 'chain'|'legacy'`.
- `log-event.cjs`: register `merge_gate_legacy: ['ticket', 'pr', 'head']` and `merge_gate_uncovered: ['ticket', 'pr', 'head', 'commit']`.
- `references/pr-sentinel.md`: describe the coverage refusal, its remedy, and the legacy rule.
- Tests (stub `gh`, hermetic git, temp coverage store and key):
  - `tests/unit/sentinel.test.cjs`: all commits recorded → merges with `coverage: 'chain'`; one hand commit (signed) → refuses naming that commit with the remedy; a hand-resolved base-merge commit (no record) → refuses; a PR created before the marker → merges and journals `merge_gate_legacy` once; no marker in a readable store → legacy; an unreadable store or a tampered marker → refuses; unreadable chain → refuses; a PR whose base-merge brought sibling squashes from the epic walks only the ticket's own and base-merge commits.
  - `tests/unit/conveyor-coverage.test.cjs`: `chain` returns the first uncovered commit in order; the commit cap refuses.
  - `tests/unit/log-event.test.cjs`: both events require their fields.
  - `bash tests/smoke/docs-smoke.sh`.
