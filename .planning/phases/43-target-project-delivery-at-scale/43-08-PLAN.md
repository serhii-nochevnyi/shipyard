## Goal

D-09 (REQ-167). CodeRabbit re-reviewed without re-approving, so `reviewFreshness` reported a stale approval and T-02-10 was parked for a human, although none of the six repositories' epic branches has any rule. A stale approval from a declared bot does not block when the target branch provably requires no review or a human approval exists on the current head; a stale human approval still blocks; otherwise the guard re-requests the review once and escalates with the command; bot identities become configurable. GitHub's own `BLOCKED` merge state still refuses.

Risk is high because this relaxes the merge gate; the checkpoint verifies on an operator-owned scratch repository.

## Scope

- `reviewers.cjs`:
  - Bot identity: `repoValue(loadConfig(projectRoot), 'reviewer_bots', repo)`; entries match exactly or by prefix when they end in `*`; unset means today's CodeRabbit and Copilot rules. An unknown author counts as human (stricter).
  - `reviewFreshness` returns `{fresh, reason, stale_authors, remedy}`: fresh when an APPROVED row is on the head; otherwise, when every stale APPROVED author is a declared bot and either an APPROVED row on the head comes from a positively human reviewer (review `user.type` is `User`, login not ending in `[bot]`, matching no built-in or configured bot identity; an unknown `user.type` is not human for this purpose) or `branchRequiresNoReview(base)` is provably true, fresh with `reason: 'stale-bot-ignored'`; otherwise stale with `remedy: 'reviewers.cjs reinit <pr> --force'`.
  - `branchRequiresNoReview`: rules endpoint answers `[]` AND `gh api repos/{o}/{r}/branches/<b>` answers `protected: false` (positive evidence readable with read access); a 404, 403, error or missing field is false. A classic-protection 404 alone is never evidence (it also means "no admin access").
  - Export `reviewFreshness` and `branchRequiresNoReview` for tests and for T-43-12.
- `sentinel.cjs` `mergeOne`: on `review_fresh === false` with a bot-only stale set, re-request once (`reinit`, journal `review_rerequest` with `ticket, pr, head, reviewers`) and hold; on the next refusal for the same head, escalate with the remedy command. `BLOCKED` still refuses unchanged.
- `log-event.cjs`: register `review_rerequest: ['ticket', 'pr', 'head']`.
- `tests/unit/reviewers.test.cjs` (stub `gh`): bot stale + human fresh → fresh; bot stale + no rules (rules `[]`, branch `protected: false`) → fresh; bot stale + rules `[]` but branch `protected: true` → stale; bot stale + rules `[]` and the branch read fails → stale; bot stale + rules 403 → stale with remedy; human stale → stale; configured bot login `acme-bot[bot]` treated as bot; unconfigured login treated as human when it is a stale approver (stricter); bot stale + a head approval whose `user.type` is `Bot` from an unconfigured login → stale (not a human approval).
- `tests/unit/sentinel.test.cjs`: one `review_rerequest` then escalation for the same head; `BLOCKED` still refuses after a stale-bot-ignored freshness.
- `tests/unit/log-event.test.cjs`: `review_rerequest` without `head` is refused.
