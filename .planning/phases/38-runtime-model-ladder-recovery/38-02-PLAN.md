## Goal

Accept Claude application evidence only from the assistant transcript records
written by the child session that the host launched.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs`
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `tests/unit/claude-runtime-host.test.cjs`
- `tests/smoke/claude-runtime-smoke.sh`

## Scope

Capture the exact `transcript_path`, `session_id`, and optional `agent_type` from
the launched process's `SessionStart` hook. Require a new startup event whose
session ID matches the requested UUID and whose working directory matches the
scoped worktree. Resolve the Claude configuration root from
`CLAUDE_CONFIG_DIR`, expanding a leading `~/`; otherwise use `$HOME/.claude` (or
the process home directory). Accept only the hook's exact transcript path when
it resolves to a regular, non-symlink
`<root>/projects/<project>/<session_id>.jsonl` file. Do not scan sibling project
directories or infer a transcript path from a slug.

Read that transcript for the host-generated `session_id` and consider only
complete `type: "assistant"` records whose `sessionId` equals that ID. Take the
model from `message.model` and effort from that same assistant record; never
combine fields from separate records. Ignore incomplete assistant records,
attachments, foreign sessions, and stdout fields that the CLI does not emit.
Rolling aliases such as `sonnet` and `fable` require a concrete runtime model
ID in the transcript; the alias itself is not application evidence. Wait a
bounded interval for the file to flush and remain stable. Missing, malformed,
or contradictory hook/transcript evidence—including removal or renaming of
required transcript fields—fails closed; never fall back to stdout. Keep the
pinned Opus ID `claude-opus-5-5` exact.

Ordinary workflow launches use only Bash, Read, Edit, Write, Glob, and Grep,
with `--restricted`, `--permission-mode dontAsk`, and disabled permission
prompts. For typed GSD roles, pass the allowlisted role as `--agent <role>` and
omit only `--restricted`, because Claude Code 2.1.280 hides custom agents when
that flag is present. Keep `--strict-mcp-config`, both explicit tool lists,
`dontAsk`, disabled prompts, and the fail-closed OS sandbox in either mode.
Bash runs with filesystem isolation, outside-worktree reads blocked, credentials
denied to shell subprocesses, `failIfUnavailable`, and no unsandboxed fallback.
The host creates one private temporary evidence directory for the SessionStart
command hook. Do not add it to the model sandbox's writable paths: Claude's
sandbox applies to Bash, not hooks, so granting Bash access would let the model
rewrite its own launch evidence. Deny Read, Edit, Write, Glob, and Grep access
to that directory with absolute-path permission patterns such as
`Read(//tmp/.../**)`, then remove it after receipt validation.
Preserve Anthropic OAuth/API credentials for the Claude process and remove
OpenAI/Codex credentials before launch. Deny `CLAUDE_CODE_OAUTH_TOKEN` to
model-issued Bash subprocesses while retaining it for Claude authentication.

For typed launches, require both `SessionStart.agent_type` and
`assistant.agentSetting` on every complete matching assistant record to equal
the requested GSD role. A requested role or receipt label alone is not
application evidence.

Keep the capability-only probe free of model calls and label it as such. Add an
explicitly opted-in live smoke that performs an edit and Bash command inside a
scratch worktree, verifies that an outside-worktree write is denied, and records
a real runtime receipt or machine-readable `unavailable`/`refused` status.

## Out of scope

- Codex runtime selection or authentication.
- Cross-provider fallback.
- Treating synthetic stream output as live evidence.

## Acceptance criteria

- Only complete assistant transcript records for the exact session establish
  applied model and effort; fields from separate records are never combined.
- Rolling Claude aliases match only a concrete native model ID, never the alias
  string itself.
- An attachment with another model, another session's effort, or stdout-only
  values cannot satisfy or contradict the launched session's selection.
- Missing transcript evidence refuses before a compliant receipt is recorded.
- Typed GSD launches pass `--agent` without `--restricted`, and require the
  exact role in both SessionStart and matching assistant transcript records.
- The model sandbox's only writable path is the worktree; the hook evidence
  directory is not made writable to model tools and is explicitly denied to
  filesystem tools.
- The Claude Opus launch and receipt retain `claude-opus-5-5` exactly.
- The capability probe identifies itself as non-live; the Claude child keeps
  Anthropic credentials and receives no OpenAI/Codex credential variables;
  model-issued Bash cannot read the Claude OAuth token.
- The ordinary smoke makes no model call; the opt-in smoke proves scoped edit
  and Bash access, rejects an outside-worktree write, and never fabricates
  success.

## Test strategy

Use a recorded-shape fixture with assistant, attachment, and foreign-session
records. Test exact-session selection, transcript flush timeout, contradictory
evidence, runtime-native observed-model matching, explicit permission arguments,
and fail-closed behavior. Run the live smoke only in the disposable proving
ground.

- `node --test tests/unit/claude-runtime-host.test.cjs tests/unit/claude-dispatch-adapter.test.cjs`
- `node --test tests/unit/dispatch-boundary.test.cjs`
- `bash tests/smoke/claude-runtime-smoke.sh --capability-only`
- `bash tests/smoke/claude-runtime-smoke.sh --live --worktree <scratch-worktree>`
