## Goal

Provide executable, receipt-verified Claude host paths for the judgement roles
used by `/shipyard:deliver`: `arch-review` and `integrator`.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs`
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`

- `plugins/delivery-pipeline/commands/deliver.md`

## Scope

Add a fixed executable host for only `arch-review` and `integrator`. It must
create a run-scoped Claude runtime, resolve the canonical
ADR-014 selection inside the host, and perform resolve → validate → launch →
receipt through the existing dispatch boundary. The request may contain role
signals and bounded task data, but cannot supply model, effort, executable,
prompt path, host module, callback, or authority-bearing resource.

Use the runtime's explicit permission mode, strict MCP configuration, and
worktree-scoped tools. No permission bypass, ambient project Agent, or
unrestricted host filesystem access is allowed.

Load only the exact role reference selected by the host from
`claude-reference-content.cjs`; include its contents in the child prompt and
keep the installed plugin path out of child-visible text. Preserve each role's
bounded worktree and artifact contract. Architecture-review and integration
results are prepared, sealed, and validated by the trusted host before their
verdicts can be consumed.

Keep Claude credentials Anthropic-only and require matching model, effort,
session, and assistant-transcript evidence from the launched child. Missing,
contradictory, inherited, or cross-session evidence refuses before a result is
accepted. A noninteractive Claude Agent or native Workflow fallback cannot
stand in for this host.

Add allowance-free contract tests for both role paths and one opt-in live
smoke in a disposable worktree. The smoke must report `passed`, `unavailable`,
or `refused`; fixtures cannot claim live application evidence.

## Out of scope

- Changing Claude or Codex model/effort ladders.
- Codex role dispatch, which is already connected by T-38-04.
- Rewriting the delivery command's final runtime selection, which belongs to
  T-38-05.
- Jira projection or creating Jira tickets.

## Acceptance criteria

- The executable host accepts exactly `arch-review` and `integrator`, and
  dispatches each through the mandatory boundary.
- The host, not the request, chooses the installed role reference and canonical
  model/effort; the Claude CLI launch and exact-session transcript prove the
  applied values.
- Request validation rejects unknown roles, model/effort overrides, arbitrary
  paths or modules, unbounded task data, and serialized authority.
- Child prompts contain approved reference contents without the installed
  plugin path.
- Architecture-review and integrator artifacts are sealed and validated by the
  trusted host before acceptance; missing or contradictory artifact identity
  refuses.
- Missing or mismatched runtime evidence produces no accepted result or
  compliant receipt.
- The capability-only check makes no model call. The opt-in live smoke proves
  one real role launch in a disposable worktree and records its model, effort,
  session, and receipt evidence.

## Test strategy

Use injected launchers and durable recorder fixtures to test both supported
roles' resolved selection, exact reference, scope, artifact consumer, and
application receipt. Cover missing credentials, unsupported roles, caller
selection overrides, plugin-path leakage, stale or cross-session transcript
records, and receipt reuse. Run one allowance-consuming live launch only by
explicit opt-in.
