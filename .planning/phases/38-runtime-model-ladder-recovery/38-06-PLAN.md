## Goal

Make Claude decomposition invoke the named native GSD agent and accept its
result only when the launched session proves that exact role.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs`
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/scripts/claude-workflow-host.cjs`
- `plugins/delivery-pipeline/commands/decompose.md`
- `tests/unit/claude-runtime-host.test.cjs`
- `tests/unit/claude-dispatch-adapter.test.cjs`

## Scope

Add `claude-decompose-host.cjs` as a fixed executable entrypoint backed by the
T-38-02 runtime host. Accept only `gsd-phase-researcher`, `gsd-planner`, and
`gsd-plan-checker` and route each through the existing typed GSD callback and
resolve → validate → launch → receipt boundary. Do not let callers supply a
module, agent file, or arbitrary role name.

Pass the validated role to Claude Code through T-38-02's explicit `--agents`
definition and `--agent <role>` under `--restricted`. Retain
`--strict-mcp-config`, the explicit scoped `--tools`/`--allowedTools` list,
`--permission-mode dontAsk`, disabled prompts, and the fail-closed filesystem
sandbox. Resolve or inline any trusted agent reference prompts that restricted
mode cannot read; fail closed if required GSD instructions are unavailable.

Accept agent application only when the host-owned SessionStart evidence has the
exact requested `agent_type`, its `session_id` and `transcript_path` identify
the launched session, a separate exact-session `agent-setting` record carries
the same role, and complete assistant records prove model and effort. An agent name in the request,
prompt, or receipt is not evidence. Missing, conflicting, stale, or
cross-session fields fail closed. A role-level model or effort override that
contradicts the ADR-014 selection also fails closed.

Keep GSD agent definitions read-only and preserve Anthropic-only credentials.
The opt-in live smoke starts one real GSD role in a disposable worktree,
performs a scoped edit and Bash operation, and records the applied model,
effort, and role from native evidence. Capability-only checks make no model
call; no fixture or simulated response can report a live pass.

## Out of scope

- Codex typed GSD execution, which belongs to T-38-04.
- Command routing and rollout policy, which belong to T-38-05.
- Changing model/effort mappings or broadening sandbox permissions.

## Acceptance criteria

- The production Claude decomposition entrypoint invokes only the three named
  GSD roles through the mandatory dispatch boundary.
- The CLI receives the exact validated `--agents` definition and `--agent`;
  the GSD launch retains `--restricted`, explicit tools, prompt policy, and sandbox.
- SessionStart `agent_type` and exact-session transcript `agent-setting.agentSetting` both match
  the requested role and launched session before a compliant receipt is stored.
- Missing, wrong, overridden, or cross-session role/model/effort evidence is
  refused before a result is accepted.
- The opt-in live smoke proves one real GSD role, scoped edit/Bash access, and
  applied model/effort; missing runtime/auth is reported as unavailable or
  refused, never as synthetic success.

## Test strategy

Use T-38-02's sanitized Claude Code 2.1.280 hook/transcript fixtures for
deterministic role selection and negative tests. Test all three role mappings,
unsupported roles, absent or mismatched hook evidence, transcript
`agentSetting` mismatch, and model/effort overrides. Run one allowance-consuming
live smoke only by explicit opt-in in a disposable worktree.
