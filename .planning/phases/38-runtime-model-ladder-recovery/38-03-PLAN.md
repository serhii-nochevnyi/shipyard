## Goal

Provide a shipped executable caller that registers the Claude runtime host and
dispatches delivery workflows through its typed host boundary.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs`
- `plugins/delivery-pipeline/scripts/claude-workflow-host.cjs`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/workflows/executors.mjs`
- `plugins/delivery-pipeline/workflows/fix-round.mjs`
- `plugins/delivery-pipeline/workflows/drift-gate.mjs`

## Scope

Add `claude-delivery-host.cjs` as the production bridge. It creates the scoped
runtime host with controller and durable recorder resources, calls
`.register().run()` for the shipped `executors`, `fix-round`, and `drift-gate`
workflows, and emits a bounded result for the caller. Keep authority-bearing
objects out of serializable workflow arguments. Refuse unknown workflow names,
missing runtime evidence, and incomplete recorder/controller setup before
dispatch.

## Out of scope

- Selecting a Codex runtime or credential.
- Changing role mapping or effort policy.
- Editing delivery command prose; the routing change belongs to T-38-05.

## Acceptance criteria

- The host runs each supported workflow through the registered typed binding.
- A missing or invalid host resource fails before the workflow invokes an
  executor callback.
- Workflow names and argument files are restricted to shipped inputs; callers
  cannot inject arbitrary modules or workflow files.
- The resulting dispatch and application receipt retain run, ticket, worktree,
  model, effort, and session identity.

## Test strategy

Use injected callbacks, recorder, and controller to prove workflow selection,
scope preservation, receipt propagation, and refusal for missing bindings or
unrecognized workflow names.

- `node --check plugins/delivery-pipeline/scripts/claude-delivery-host.cjs`
