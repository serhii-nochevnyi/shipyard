## Goal

Provide shipped executable callers for Claude delivery and investigation,
with host-owned reference loading and signed commit finalization for sandboxed
delivery workers.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs`
- `plugins/delivery-pipeline/scripts/claude-workflow-host.cjs`

## Scope

Add production bridges for `executors`, `fix-round`, `drift-gate`, and
`investigation-research`. They create the scoped runtime host with controller
and durable recorder resources, call `.register().run()`, and emit bounded
results. Keep authority-bearing objects out of serializable workflow
arguments. Refuse unknown workflow names, missing runtime evidence, and
incomplete recorder/controller setup before dispatch.

For `planning.v1` investigation results, the trusted host checks the producer
file and policy identity against the verified receipt, copies the validated
bytes to private immutable run storage, and returns that archived reference.
The shared adapter binds the producer's assigned path and digest to the
archived index; executor plans must match the canonical ticket graph before
launch.

Resolve only fixed Markdown references selected by a shipped workflow or role,
from an exact allowlist beneath the installed plugin root. Inline their
contents into the child prompt and remove every plugin-root path from that
prompt. Reject arbitrary caller paths, traversal, symlinks, and unknown
reference IDs. Executable scripts such as the PR reinitialization helper stay
host-owned: fetch review-thread data before dispatch, then run required publish
and reviewer-reinitialization steps from the trusted host after the worker
returns.

The sandboxed Claude worker edits and verifies files but does not commit or
push. A shared host-side finalizer validates the expected base, branch, ticket,
and `files_modified` delta; stages only in-scope changes using a private
temporary Git index; creates a signed commit with the host's configured Git
signer; verifies the signature and expected signer; and only then permits
artifact acceptance or a required push. The worker receives neither signing
credentials nor the GPG agent socket. Missing signer access, out-of-scope
changes, or stale branch state fail closed without publication.

## Out of scope

- Selecting a Codex runtime or credential.
- Changing role mapping or effort policy.
- Editing delivery command prose; the routing change belongs to T-38-05.
- Typed Claude agent selection and decomposition, which belong to T-38-06.

## Acceptance criteria

- The host runs each supported workflow through the registered typed binding.
- A missing or invalid host resource fails before the workflow invokes an
  executor callback.
- Workflow names and argument files are restricted to shipped inputs; callers
  cannot inject arbitrary modules or workflow files.
- The resulting dispatch and application receipt retain run, ticket, worktree,
  model, effort, and session identity.
- Investigation and repair prompts contain approved reference contents and no
  plugin-root file paths; arbitrary and symlinked references are rejected.
- Sandboxed workers do not create commits or push. The host creates and verifies
  the signed, in-scope commit before artifact acceptance or a repair push; a
  missing signature blocks publication.
- Repair-thread reads, publishing, and reviewer reinitialization execute in
  the trusted host, not through a child-readable plugin script path.

## Test strategy

Use injected callbacks, recorder, and controller to prove workflow selection,
scope preservation, receipt propagation, safe reference expansion, and refusal
for missing bindings or unrecognized workflow names. In temporary repositories,
generate an isolated test signing key and verify that the finalizer stages only
declared paths, signs the commit, rejects stale or out-of-scope changes, and
refreshes the child's Git index to match the new tree without staging unrelated
paths. Keep the allowance-consuming live smoke
opt-in and limit it to a disposable worktree.
