## Goal

Make Codex a real delivery and decomposition caller, apply the requested typed
GSD subagent through native collaboration, and prove the selected model,
reasoning effort, parent session, and child role from native session evidence.

## Scope

Extend `codex-delivery-host.cjs` to construct the scoped runtime host, register
the durable recorder/controller, and call both `launchAgent()` for generated
static roles and typed dynamic executor roles through the mandatory dispatch
boundary. Pass the resolver-selected GPT-6 model and effort explicitly, preserve
workspace-write sandboxing, and refuse inherited selection, stale generated
agents, or cross-provider data.

For `gsd-phase-researcher`, `gsd-planner`, and `gsd-plan-checker`, validate the
installed GSD-owned agent definition under the effective Codex home without
modifying it. Codex CLI 0.155.1 has no top-level `--agent` option for `codex
exec`; enable its native `multi_agent` feature and require the parent session to
spawn one child with the exact registered role. The spawn request must set the
resolver-selected model and reasoning effort explicitly; a parent response
without a matching child launch is a refusal. Prove the child by linking its
native transcript to the exact parent thread and validating `agent_role`,
model, and reasoning effort on that child. Before launch, resolve the role to
its exact installed file and validate its content digest without modifying it.
Pin the invocation's `agents.<role>.config_file` through a CLI `-c` override
to that exact file; never edit the user's Codex configuration. In observed
Codex 0.155.1 child sessions, `agent_path` identifies the spawned task path
(`/<root>/<task_name>`), not the role TOML. Match it to the parent's exact
spawn task instead of comparing it with the config file. Independently prove
that the child loaded the pinned role by finding the installed file's exact
`developer_instructions` in a native child `response_item` with
`role: "developer"`; a prompt echo or receipt label is insufficient. Reject missing, foreign, duplicate, or
contradictory role/session evidence, and reject an installed role definition
that overrides the resolver's model or effort.

Add `codex-decompose-host.cjs` as the executable role-specific entrypoint. It
accepts only the three supported planning roles and calls the typed callback
through the existing dispatch boundary. Reuse T-38-03's host-side commit
finalizer for delivery work: Codex children do not write Git metadata or access
the GPG agent; the trusted host validates the ticket delta, creates a signed
commit, verifies its signer, and only then returns a committed artifact. Keep
the model ladder at `gpt-6-luna`/max for ordinary work and use `gpt-6-sol` only
for existing promotion signals. Add an explicitly opted-in smoke that performs
one real typed spawn, edits a scratch worktree, runs Bash, and validates both
the native child evidence and host-created signature.

## Out of scope

- Anthropic runtime or credentials.
- Changing the Luna/max base or Sol promotion signals.
- Anthropic runtime, credentials, or agent definitions.
- Blanket sandbox or approval bypasses.

## Acceptance criteria

- Both static and dynamic delivery calls reach a production Codex launcher.
- Each typed GSD callback spawns the exact named native Codex child role; a
  receipt label or requested role alone cannot satisfy the check.
- The native spawn request supplies the ADR-014 model and reasoning effort;
  the child's thread evidence names the exact parent session and role, with
  actual model and reasoning effort equal to that selection. The host validates
  and records the installed agent file and digest, pins that file with an
  invocation-local `-c agents.<role>.config_file=...` override, matches native
  `agent_path` to the parent spawn's task path, and proves the installed role's
  full developer instructions in the child's native developer record.
- The executable decomposition host rejects unsupported roles and routes each
  supported role through resolve → validate → launch → receipt.
- Every launch carries the resolver-selected native model and reasoning effort
  and records the actual session/process identity. The native transcript's
  session identity, provider, model, and effort agree with the request.
- The active IDs are `gpt-6-luna` and `gpt-6-sol`; ordinary executor work stays
  on Luna/max, and promotion requires its existing approved signal.
- Stale agent digest, inherited selection, missing runtime, or contradictory
  evidence refuses before a compliant receipt is recorded.
- The Codex child cannot commit or access the host GPG signer. A signed,
  in-scope host commit is verified before artifact acceptance; missing signing
  capability blocks publication.
- The live smoke proves edit and Bash access in its scratch worktree and emits
  `passed`, `unavailable`, or `refused` without a synthetic green result.

## Test strategy

Test generated static manifest identity, dynamic/static/typed entrypoints,
resolved model and effort, and that the native spawn request supplies both
resolved values rather than inheriting the parent selection. Assert the CLI
role-config override names the prevalidated file and never writes user config.
Test native parent/child transcript parsing, exact agent role, task path, and
developer-instruction provenance from the pinned config digest,
missing/foreign/mismatched parent or role evidence, optional native path
matching, process evidence, stale-agent refusal, and scoped work permissions.
Test the signed commit using
the temporary-key finalizer fixture added by T-38-03. Run the allowance-
consuming live smoke only by explicit opt-in.
