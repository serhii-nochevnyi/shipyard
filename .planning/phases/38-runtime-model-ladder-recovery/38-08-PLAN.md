## Goal

Launch Claude's round-scoped `pr-sentinel` through the trusted host and keep its
single guard identity visible against every ticket it owns.

## Scope

Extend the trusted Claude role host with the fixed `pr-sentinel` role. Bind its
run and dispatch identity to the exact guarded-ticket set, each member's live
PR head/base, and the validated round artifact. Build the canonical ticket-set
digest from ticket, PR, head, and base identities. The host supplies the
boundary with the host-owned `round:<digest>` subject; the boundary receipt and
durable recorder must preserve that subject. Add round reconciliation that
proves the exact subject, role, dispatch id, launch id, model, and effort. A
ticket-bound receipt or caller-provided subject cannot authorize a round.

Add a dedicated `rounds` collection to the existing dispatch store, keyed by the
one boundary dispatch id. Store the authenticated ticket-set digest, one agent
identity, and each member's PR/head/base snapshot and dispatch fingerprint.
Do not duplicate one dispatch id into N ticket rows; the store deliberately
rejects that. Under the existing store lock, validate the complete set, reject
members with conflicting active ownership, and atomically write one round row
and one journal event. `activeDispatches` projects one held view per still-live
member; `front` counts the shared launch once by role and actual agent id. A
member whose PR merges or base moves expires from that member's projection
without releasing the other members. Clearing requires the exact round id and
removes only that round; a stale clear cannot erase newer per-ticket or round
dispatches. Never infer membership from a prompt, caller-supplied list, or
receipt label.

Create a lock-protected in-flight reservation after boundary validation and
before starting Claude. It projects one shared guard identity while the model is
running, without claiming model application evidence before the receipt exists.
Replace the reservation atomically with the authenticated round row after the
transcript and result validate; clear it on failure, with TTL recovery after a
process crash. Members whose PR merges, head changes, or base moves during the
round expire independently; newly opened PRs outside the original set still
refuse the result.

Fail closed on missing, duplicate, added, removed, stale, or contradictory
members; mismatched round subjects or head/base snapshots; invalid or
cross-session transcript evidence; conflicting active ownership; and stale
clear operations. Refusal leaves prior records intact and does not partially
hide tickets. Preserve per-ticket dispatch behavior and historic records.

Correct the documentation that currently attributes the membership bridge to
T-33-08. That ticket implements fenced session ownership; it does not implement
round-to-ticket dispatch reconciliation. Document the actual host and
round-aware mark/clear contract without promising support until validation
passes.

## Acceptance criteria

- `pr-sentinel` has a fixed executable Claude host path and crosses
  resolve → validate → launch → receipt with explicit model and effort.
- The host authenticates the complete guarded ticket set, round subject,
  dispatch receipt, and live member identities before recording ownership.
- One round mark exposes all and only validated members to `front` and the stop
  gate, preserves the returned launch identity, and counts as one in-flight
  guard regardless of member count.
- Mark and clear operations are atomic, idempotent for the same round identity,
  and reject stale or mismatched identities without changing current records.
- Missing or contradictory ticket-set membership, PR head/base, model, effort,
  session, artifact, or receipt evidence fails closed before an actionable
  result is accepted.
- Existing per-ticket marks, independent guards, usage records, and expiry
  behavior remain valid.
- Delivery and operator docs state that T-33-08 is session fencing and that
  round membership is implemented only by this ticket.
- Capability-only checks make no model calls. The opt-in live smoke launches a
  real `pr-sentinel` in a disposable worktree with shell and edit tools removed;
  it reports model, effort, session, round subject, and receipt evidence without
  performing PR duties or changing a real PR.

## Test strategy

Exercise one boundary receipt over a multi-ticket round and prove every member
is visible while `agentsInFlight` counts the guard once. Test boundary round
subject binding and refusal to reconcile a ticket receipt as a round; exact
round artifact and digest binding; absent or forged receipts; missing and extra
members; stale PR snapshots; a visible pre-launch reservation; concurrent marks;
replayed clear; per-member expiry; read-only smoke tool restrictions; and
preservation of newer dispatches. Verify no failure path writes a partial
overlay or hides a ticket. Run the live sentinel smoke only by explicit opt-in.
