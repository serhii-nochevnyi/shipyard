## Goal

Select the supported production runtime path and allow Claude or Codex to roll
out independently after that provider's own live evidence passes.

## Context (Reads)

- `.planning/architecture/ADR-015-autonomous-dual-runtime-control-plane.md`
- `plugins/delivery-pipeline/scripts/run-rollout.cjs`
- `plugins/delivery-pipeline/scripts/claude-delivery-host.cjs`
- `plugins/delivery-pipeline/scripts/codex-delivery-host.cjs`
- `plugins/delivery-pipeline/commands/deliver.md`

## Scope

Version the rollout contract so each provider has an independent opt-in flag,
capability result, credential status, and rollback. Detect Claude OAuth with
`claude auth status --json` and Codex login with `codex login status`; rely on
exit/status fields only and never log raw credential output. API-key environment
variables are not required for authenticated subscription sessions. A healthy
runtime may be enabled while its peer is unavailable, with no cross-provider
fallback.

Route `/shipyard:deliver`, `/shipyard:investigate`, and `/shipyard:decompose`
through the shipped host selected for that runtime. Do not select the native
Claude Workflow path when its host binding cannot be supplied. Keep capability
probes allowance-free and keep real model calls behind the provider-specific
opt-in smoke.

## Out of scope

- Automatically enabling production rollout after a successful probe.
- Sharing credentials or model selection between providers.
- Deleting or relabelling historical receipts during rollback.

## Acceptance criteria

- Claude and Codex flags can be enabled and evaluated independently.
- Subscription OAuth is recognized through each native CLI without requiring
  API-key environment variables; raw command output never enters logs or JSON.
- One unavailable runtime does not block, enable, or mark green the other.
- Delivery commands call the shipped host and pass each run through the
  mandatory resolve → validate → launch → receipt boundary.
- The native Claude Workflow path is not selected without its host binding.
- Capability-only smoke makes no model calls; provider-specific live smoke
  results are separated as `passed`, `unavailable`, or `refused`.
- Rollback disables only the selected runtime and preserves its receipts and
  historical usage.

## Test strategy

Test legacy flag migration, independent enabled/unavailable combinations,
OAuth and login status parsing, secret-output suppression, independent rollback,
and provider-pure command selection. Run allowance-consuming smokes only with
explicit opt-in.

## Verification commands

- `node --test tests/unit/run-rollout.test.cjs tests/unit/source-contract.test.cjs`
- `bash tests/smoke/runtime-control-plane-smoke.sh --capability-only`
