| Policy version | Runtime | Exact registered key-to-model palette |
|---|---|---|

Add a deeply frozen version-to-runtime palette accessor in the existing adapter. Resolve recorded policy metadata before any model lookup. Preserve existing current exports and v7 routing, role/effort grids, Fable observation rule and policy fingerprint; extending historical lookup must not change the current canonical policy hash. Unknown recorded versions never fall back to current maps or infer a version from a model name.

Serialized run, dispatch and receipt inputs require explicit recorded policy version and SHA-256 hash. Missing metadata raises `MISSING_POLICY_IDENTITY`; an unregistered version raises `UNSUPPORTED_POLICY_VERSION`. Treat an enclosing serialized run as recorded even if its nested dispatch schema marker has been removed. Keep snake-case/camel-case metadata compatibility; conflicting supplied forms raise `POLICY_IDENTITY_CONFLICT`. Empty or null supplied metadata is an error, not a default. Syntax-check and preserve a supplied hash exactly: preservation does not authenticate it. A fresh constructor with no serialized marker and neither policy field may explicitly choose current version/hash. A fresh input supplying only current version may use current hash; hash without version and historical version without hash must refuse. Historical hashes are never manufactured or replaced.

Validate an explicit `model_key` as a symbolic key and a supplied concrete `model` independently against the selected runtime/version. With both present, require the exact native value for that key; another valid same-runtime model also fails with `RUNTIME_MODEL_MISMATCH`. A foreign-runtime key/model fails with `RUNTIME_MODEL_MISMATCH`; an unregistered key/model fails with `UNSUPPORTED_MODEL`. For accepted serialized identities, return the recorded concrete model unchanged. Preserve single-field fresh-constructor convenience under its selected known policy and existing fully absent/null selection semantics. A supplied invalid key or concrete model must never bypass checks through truthiness or a missing counterpart. Current fresh Sol/Sonnet construction still derives their pinned v7 values.

In normalizeRunContract validate every explicit nested dispatch runtime/provider before adding enclosing fields. Known conflicting runtimes raise `RUNTIME_MODEL_MISMATCH`; incompatible providers raise `RUNTIME_PROVIDER_MISMATCH`; unknown runtimes retain `UNSUPPORTED_RUNTIME`. Do not broaden this task into run-scope or controller rewriting.

Normalize each receipt using its own recorded version and preserve its supplied registered model values, policy identity, status and usage status. Retain existing null/unknown/unsupported sentinels. Recorded v7 concrete applied/observed fields must equal registered native values; the v6 Sonnet alias cannot be relabeled into verified Sonnet 5.5. Do not alter current native-observation matching to accommodate history. Existing `policy.validateResolution` is the compliance authority and must continue rejecting historical version/hash as `STALE_POLICY`, including v6 keys whose concrete models happen to be unchanged under v7.
