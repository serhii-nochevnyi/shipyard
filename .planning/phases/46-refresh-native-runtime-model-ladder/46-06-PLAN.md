## Goal

The operator has a reviewable proof set for each new native pair, with a clear hold on unsupported or mismatched accounts.

## Context (Reads)

- `ADR-024:23-28,68-80` requires exact observed application, independent review, isolated installation, preserved history and an operator rollout boundary.
- T-46-01/02/03 supply the policy, static/dynamic and Claude native negative tests; T-46-04 supplies current guidance; T-46-05 supplies the final package, isolated smoke and `ADR-024-ROLLOUT.md`.
- `plugins/delivery-pipeline/scripts/codex-runtime-host.cjs:974-1035,1085-1099` passes an explicit model/effort and reads native evidence; `claude-runtime-host.cjs:301-345` binds assistant records to the expected session.
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs:1860-1929,2025-2061` authenticates repair predecessors and records application receipts. Current installed account entitlement and Claude plugin provenance remain unknown until the isolated check.

## Scope

P46-A..E: independently review the source diff, generated mirror, role matrix, repair chain, stale history and installer provenance. In isolated runtime homes, use the existing authenticated host-owned launch and receipt paths to collect actual requested/applied/observed model and effort for each distinct newly routed pair: Codex Sol 6.1 low/high/xhigh; Claude Sonnet 5.5 low/medium/high/xhigh and Opus 5.5/high. Check the retained Luna/medium sentinel and Fable window rule without inventing additional routing signals. The recorded output includes policy version/hash, package/source digest, runtime CLI/account capability result, exact session/dispatch IDs and an independently reviewable receipt reference. If any model/effort is unavailable or not exactly observed, hold activation and record the refusal; do not relabel synthetic smoke data as a live receipt. Preserve the old reviewed package as rollback target and all in-flight old-policy runs.

## Out of scope

Changing the outer ADR-023 D6 controller, inferring quota savings, weakening approval/repair/independent review gates, rewriting historical evidence, or silently selecting a different model/effort when account capability fails.

## Acceptance criteria

- The targeted P46-A/B role grid, generated hash and static files, native exact-application negatives, repair progression, history classification and isolated installer checks are green under the scoped commands below.
- An independent reviewer records disposition for source and package changes, including any accepted fix. A research report alone does not count: INV-011 evidence is accepted only via its sealed manifest/digest chain, and rollout evidence is from the installed native host.
- For each distinct new pair named in Scope, a same-session receipt shows requested = applied = observed model and effort under the new policy hash. If entitlement or exact observation is absent, evidence says `HOLD`, and no active install occurs.
- The operator reviews package/source provenance, installed home path, prior reviewed rollback package and old-policy in-flight ownership before any activation. D6 remains with its separate owner.

## Test strategy

Run only the named focused regressions and the isolated smoke. Compare independent review findings with the accepted ADR and implementation, then use the installed host in isolated homes for real short native launches. Record receipt references and hashes, not secrets or full private transcripts. The checkpoint is blocking on a mismatch or missing native pair; the automated fixture tests alone cannot satisfy it.
