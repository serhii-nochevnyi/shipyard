## Goal

Two small truths in the test suite: a comment that describes a harness that no
longer exists, and a detector sub-pattern with no test at all.

## Context (Reads)

- `tests/unit/failure-signature.test.cjs:516-518`:

      // (Spawned through bash rather than from an async test body: this harness's
      // `test()` is synchronous and `done()` exits the process, so an awaited body
      // would be marked green before its assertions ever ran.)

  True when written, FALSE since v0.40.0 — T-22-05 made the harness await async
  bodies. Verified still present at v0.41.0.
- That comment has a second life worth preserving: it is the evidence that the
  harness defect was KNOWN during phase 20 and routed around rather than
  recorded, which is why two vacuous tests kept reporting safety for a month.
  **Correct the claim; do not delete the history.** The bash-spawn form is not
  wrong, only differently motivated now.
- `degenerate-green.cjs`'s `skip` mode has a third sub-pattern —
  `xit`/`xdescribe`/`xtest`/`xcontext`, the Mocha-style skip prefix — with
  neither a `fires` nor a `silent` case. Found by the guard reviewing T-21-04;
  it works at runtime, so this is a coverage gap, not a defect.
- Note when checking: grepping for `xit` matches inside `exit`, which is how a
  first look at this file wrongly concluded the tests existed. Search for the
  test-declaring forms, not the substring.
- The file's own convention: every mode has a positive fixture AND a negative
  control, and the controls were proven able to fail by mutation. Follow it —
  a positive with no control would be the one untested guard in a file whose
  discipline is that there are none.

## Scope

- Correct the parenthetical so it states today's behaviour and why the bash
  spawn remains. Keep the sentence recording that the defect was known.
- Add `fires` and `silent` cases for the `xit` family: a test disabled by an
  `x`-prefix in a diff that also removes the enabled form, and a control where
  an `x`-prefixed name appears without anything being disabled.

## Out of scope

`degenerate-green.cjs` itself (the behaviour is correct; only the tests are
missing), the harness, and every other test file.

## Acceptance criteria

- No comment in `failure-signature.test.cjs` claims `test()` is synchronous.
- The `xit` family has a positive case AND a negative control, and the positive
  fails when the sub-pattern is removed from the detector — prove it by removing
  it in a scratch copy, as the file's other controls were proven.
- Assertion counts rise; no file's count drops.

## Test strategy

The new control must be proven able to fail, exactly like the eighteen before
it. A control that cannot fail is what this whole phase is about.
