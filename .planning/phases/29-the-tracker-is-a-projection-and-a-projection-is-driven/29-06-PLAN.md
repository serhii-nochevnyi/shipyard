## Scope

A subsection of `deliver.md` stating, for each item `plan` emitted:

1. Ask the connected tracker MCP for the issue's available transitions.
2. Match the one whose **target status name** equals `target_status`. **Never
   match on the transition's own name** — the MCP schema says in as many words
   that *"Done does not match a transition named 'Review->Done'"*, and T-29-01's
   pin fails the build if `transitionName` appears here at all.
3. Transition by that **id**. Two connected MCP variants require different
   shapes — one takes `transition: {id}` and accepts no name, the other takes
   `transitionId` or `transitionName` — so the id is the only argument that
   works on both.
4. Record it: `jira-project.cjs record <ticket> <key> --transition-id <id> --status <name>`.
5. Target not reachable from the current status → `record --unreachable` naming
   the transitions that WERE offered. Jira workflows forbid arbitrary jumps, so
   this is an ordinary outcome, not a failure.
6. **Never pass a comment through `update`** — the schema says it may be dropped
   with the transition still reporting success, so it would be a silent lie in
   the audit trail.
7. No tracker MCP connected, or `jira_transitions` empty → skip with one line.
   Never an error, never a retry loop, and **never a reason to hold a merge**.
