## Goal

The fifth durable store. `jira-projection.json` records, per ticket, the last
`status_change` already projected, so a re-run, a re-synced board or a replayed
journal cannot transition the same issue twice or walk it backwards.

## Context (Reads)

- ADR-008 D1.
- `plugins/delivery-pipeline/scripts/dispatch-record.cjs` and
  `escalation-record.cjs` — the store discipline to copy verbatim: `withLock` +
  `writeAtomic` around the whole read-modify-write, the lock **beside the
  store** (a lock taken at a worktree cwd serializes nothing), `--graph <dir>`
  accepted in ANY position, and a refusal when the resolved graph dir has no
  `tickets.json`.
- `tests/unit/record-stores.test.cjs` — its header records the two defects this
  discipline exists for: a verdict written into a worktree where state-sync
  never reads it, and six concurrent marks producing five records. This is where
  the new store's contract case belongs, beside its siblings.
- `plugins/delivery-pipeline/scripts/graph-dir.cjs` — resolution order.
- Watch the `-1` case when stripping a flag by index: `i !== flagAt + 1` with no
  flag present reads as `i !== 0` and eats the subcommand. That bug is recorded
  in CLAUDE.md and has been made twice.

## Scope

New `jira-project.cjs` with the store half only:

- `read` / internal accessors for `<graph>/jira-projection.json`, shape
  `{ tickets: { "T-29-01": { projected_to: "pr-open", ts: "<iso>", key: "MYD-1", status: "In Progress", transition_id: "31" } } }`.
- The ORDER is ours and it is total: `pending` < `branched` < `pr-open` <
  `merged`. Expose it as one exported comparator — the planner (T-29-04) and any
  later reader must not each spell it.
- `hasProjected(ticket, to)` is true when the recorded `projected_to` is at or
  after `to`. Forward-only falls out of that: a reopened PR going `merged` →
  `pr-open` is skipped, not projected backwards.
- `--graph` in any position; refuse when the resolved dir has no `tickets.json`.
- Every write under `withLock` + `writeAtomic`, lock beside the store.

## Out of scope

- The planner (`plan`) — T-29-04.
- The recorder (`record`) and the journal event — T-29-05. This ticket may write
  the store from a test helper, but ships no CLI verb that an agent calls.
- Any tracker call.

## Acceptance criteria

- The four store-discipline cases, matching the siblings: `--graph` honoured
  from a foreign cwd; a refusal when the graph dir has no `tickets.json`;
  concurrent writes lose nothing; the write is atomic.
- **Witnessed concurrency mutation**: replace `withLock` with a bare
  read-modify-write, run N concurrent marks, and show FEWER than N records
  land — the same repro that produced five out of six for drift-record. Paste
  the count. An assertion nobody has seen fail is not a guard.
- **Witnessed backwards mutation**: with `merged` recorded, ask for `pr-open`
  and show it is refused; then invert the comparator and show the test goes red.
- The comparator is exported and has exactly one definition in the file
  (`grep -c` it, and report the number).

## Test strategy

Unit in `record-stores.test.cjs`, in real temp dirs with real child processes —
the way the existing store cases run. No network, no tracker.
