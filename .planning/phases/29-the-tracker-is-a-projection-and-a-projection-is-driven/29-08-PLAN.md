## Goal
Prevent the recorder from crediting a newer journal state to an older tracker action.

## Context (Reads)
ADR-008 D1/D5, jira-project.cjs recordProjection/pendingItemFor and acting-half
record invocation in deliver.md. Integration repro on 2026-09-10: plan pr-open,
append merged, record transition to In Progress; current code stores projected_to
merged and emits no remaining work. No network is needed to demonstrate the loss.

## Scope
Require the performed item's own `to` on successful record as well as unreachable
record. Compare it to the current pending item under the store lock. Refuse stale
or missing identity before mutation; retain newer work for the next planner call.
When a reported target status is provided, require it to match the pending target.
Update CLI usage, prompt invocation, log-event refusal guidance and fixtures to
pass the performed `to`. Scope amended after PR #91 review exposed the stale
log-event recovery command.

## Out of scope
Tracker credentials, tracker execution, network transactions, model policy,
new status vocabulary, unrelated store corruption handling and global settings.

## Acceptance criteria
- plan pr-open -> journal merged -> record pr-open refuses, writes no watermark
  or jira_transition, and the planner still offers merged.
- Missing `to`, an unknown `to`, mismatched target status and wrong key refuse.
- A matching `to` and target records once; a retry cannot advance it twice.
- CLI and acting-half invocation carry the emitted item's `to`.
- Existing record/unreachable semantics and all targeted tests remain green.

## Test strategy
Regression first on the real module and temporary local graph. Test CLI and
library paths and assert store/journal bytes unchanged on refusals. Full suite in CI.
