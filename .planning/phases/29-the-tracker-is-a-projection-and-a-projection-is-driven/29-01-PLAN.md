## Goal

Land the guard BEFORE the code it guards. A sweep over our own source that
fails if `transitionName` ever appears in a script or a prompt, so the author of
T-29-06 is caught by a red test rather than by someone's Jira board six months
from now.

## Scope

Add one case to `source-contract.test.cjs`:

- Sweep the tracked files under `plugins/delivery-pipeline/` (scripts, commands,
  references, skills, workflows) and `scripts/`.
- FAIL on any occurrence of `transitionName` outside a comment.
- The failure message must carry the reason, not just the match: the MCP's own
  schema says *"Name of the transition itself, not the target status — the two
  often differ, so 'Done' does not match a transition named 'Review->Done'"*, so
  a projector keyed on transition names works against the workflow it was
  written for and silently does nothing on the next one.
- Assert the sweep is NON-EMPTY (it found files at all), the way the sibling
  sweeps do. A guard that certifies whatever it is pointed at is worse than no
  guard — `source-contract.test.cjs:83` says so about this very table.

## Out of scope

- Any projector code. This ticket ships a guard and nothing else.
- Banning `transition.id` / `transitionId` — those are the CORRECT arguments and
  the ones T-29-06 will use.

## Acceptance criteria

- `node --test tests/unit/source-contract.test.cjs` passes on a clean tree.
- **Witnessed mutation** (ADR-006's standing requirement — an assertion nobody
  has seen fail is not a guard): insert `transitionName` into a scratch copy of
  a swept file, re-run, and paste the RED output into the PR. Then insert it
  into a COMMENT and show the test stays green.
- **Witnessed empty-sweep mutation**: point the sweep at a directory that does
  not exist and show it fails with the non-empty assertion rather than passing.
- Report the exact file count the sweep covers, so a later reader can tell
  whether it shrank.

## Test strategy

Pure source assertion; no fixtures, no network, no tracker.
