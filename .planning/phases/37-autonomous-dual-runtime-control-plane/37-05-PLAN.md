## Goal

Ensure each ticket is cut from the live base and parent-epic state that its
scoped run declares before an adapter is launched.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/epic-branch.sh`
- `plugins/delivery-pipeline/scripts/ticket-worktree.sh`
- `plugins/delivery-pipeline/scripts/graph-dir.cjs`
- `plugins/delivery-pipeline/scripts/state-sync.cjs`
- `.planning/backlog/a-cross-phase-dependency-never-reaches-the-childs-tree.md`
- `.planning/backlog/diamond-child-base-is-materially-incomplete.md`

## Scope

Implement a reachability proof that resolves the repository origin, refreshes
the integration and parent epic refs, verifies ancestry and declared files, and
returns the exact base revision to the controller. Refresh a child after a
parent lands before it becomes actionable. Reused worktrees must report their
distance and remain untouched when origin or ownership does not match.

## Out of scope

- Runtime process launch or model policy.
- Automatic destructive cleanup of local-only branches.
- Jira repository discovery.

## Acceptance criteria

- A child is not actionable until its live parent/base comparison succeeds.
- A stale or ambiguous origin, missing base ref, or failed comparison is a
  retryable pending state with a named reason.
- Worktree reuse proves scope and branch identity before mutation.
- Temporary-repository tests cover parent landing, stale local base, divergent
  origin, and local-only clean branch preservation.

## Test strategy

Use temporary bare and working repositories; do not call GitHub. Exercise both
fresh and reused worktrees and assert no mutation on failed proof.

- `node --test tests/unit/run-reachability.test.cjs`
