## Goal

Define the runtime-neutral `shipyard.run.v1` contract that every controller,
adapter, stop hook, and telemetry writer can validate without selecting a model
or inferring a run from repository-global state.

## Context (Reads)

- `.planning/architecture/ADR-015-autonomous-dual-runtime-control-plane.md`
- `.planning/architecture/ADR-014-INTERFACES.md`
- `plugins/delivery-pipeline/scripts/dispatch-boundary.cjs`
- `plugins/delivery-pipeline/scripts/session-handoff.cjs`
- `plugins/delivery-pipeline/scripts/front.cjs`
- `plugins/delivery-pipeline/scripts/graph-dir.cjs`

## Scope

Create immutable constructors and validators for repository, phase, ticket,
worktree, runtime, dispatch, lease, state revision, checkpoint, wake, and
receipt identities. Define scoped state transitions and an explicit vocabulary
for `running`, deterministic waits, `runtime_unavailable`, `retryable`,
`human_checkpoint`, `completed`, and `failed`. Reject missing scope, mixed
runtime/provider identity, stale revisions, duplicate effects, and serialized
host authority.

## Out of scope

- Launching Claude or Codex.
- Changing the ADR-014 model policy or either provider palette.
- Selecting a global newest front or changing stop-hook behavior.
- Jira projection or product-repository files.

## Acceptance criteria

- The contract validates a complete run identity and rejects an incomplete or
  contradictory identity before a state mutation.
- The same scoped identifier is used for state, wake, lease, receipt, and
  telemetry joins.
- State transitions are monotonic and idempotent for a repeated event key.
- Runtime values are exactly `claude` or `codex`, and a contract cannot carry a
  model id belonging to the other runtime's ladder.
- Tests cover malformed input, stale revision, duplicate event, and serialized
  authority rejection.

## Test strategy

Use pure unit tests with temporary JSON values and no network, credentials, or
runtime process. Assert both accepted canonical records and refusal codes.
