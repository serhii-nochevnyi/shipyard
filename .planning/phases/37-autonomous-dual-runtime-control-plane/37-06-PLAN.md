## Goal

Replace cross-worktree newest-board decisions and foreground babysitting with
run-scoped deterministic waits and an external wake path owned by the controller.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/stop-gate.cjs`
- `plugins/delivery-pipeline/scripts/ci-wait.cjs`
- `plugins/delivery-pipeline/scripts/front.cjs`
- `plugins/delivery-pipeline/scripts/run-controller.cjs`
- `plugins/delivery-pipeline/scripts/run-contract.cjs`

## Scope

Pass run scope and controller status into stop-gate. Remove selection by global
`generated_at`; a missing or mismatched scope refuses or stays pending. Add a
bounded waker that waits on durable CI/review/lease/host events, rechecks the
same run, and launches the next controller step exactly once. Keep deterministic
waiting below the model turn and preserve live merge/gate reads. Technical
unavailability retries automatically; only authorization and repository policy
remain human checkpoints.

## Out of scope

- Changing the front's ordering policy.
- Replacing GitHub check or review semantics.
- Starting a second provider when the selected runtime is unavailable.

## Acceptance criteria

- Two concurrent runs never read each other's front or stop verdict.
- A wait produces a durable wake condition and a bounded retry deadline.
- A settled event wakes only its owning run and is idempotent on replay.
- CI/network/host errors remain unknown or retryable, never green and never an
  instruction to stop permanently.
- A true fixpoint for the scoped run still allows the session to stop.

## Test strategy

Use temporary run stores and fake clocks/events. Test concurrent scopes, stale
fronts, duplicate wake events, unreachable services, and true fixpoint behavior.
