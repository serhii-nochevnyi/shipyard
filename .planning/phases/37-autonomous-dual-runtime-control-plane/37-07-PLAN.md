## Goal

Make every runtime launch measurable as one joinable run/provider/account/role
record so cost and effectiveness can be evaluated without inferred model use.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/dispatch-record.cjs`
- `plugins/delivery-pipeline/scripts/usage-attribution.cjs`
- `plugins/delivery-pipeline/scripts/pipeline-stats.cjs`
- `plugins/delivery-pipeline/scripts/usage-report.cjs`
- `plugins/delivery-pipeline/scripts/run-contract.cjs`
- `plugins/delivery-pipeline/scripts/claude-dispatch-adapter.cjs`
- `plugins/delivery-pipeline/scripts/codex-dispatch-adapter.cjs`

## Scope

Define the run telemetry envelope and join dispatch receipts with provider,
account, role, model, effort, token, tool-turn, quality, recovery, and outcome
facts. Preserve requested/applied/observed/unsupported/unknown distinctions and
report usage gaps explicitly. Feed the existing stats/report path with
versioned baseline/treatment metadata without changing the ladder.

## Out of scope

- Automatic model-policy changes.
- Provider billing API assumptions when counters are unavailable.
- Reclassifying historical sessions without evidence.

## Acceptance criteria

- One run can be joined across launch, receipt, usage, quality, recovery, and
  outcome records without reusing another ticket's dispatch identity.
- Missing or contradictory model/effort evidence remains visible as unknown or
  noncompliant and cannot count as an applied selection.
- Duplicate stream/retry observations do not double-count usage or outcomes.
- Reports include coverage and treatment/policy fingerprints and refuse a savings
  conclusion when attribution or quality/recovery evidence is incomplete.

## Test strategy

Use Claude and Codex fixture envelopes with distinct providers/accounts and
replayed partial updates. Assert deduplication, cross-run isolation, unknown
coverage, and incomplete-report outcomes.
