## Goal

Four mechanisms are correct and unreached. Close each one — by feeding it or by
recording the decision not to — and add the guard that makes an unwired
mechanism a finding rather than a surprise a phase later.

## Context (Reads)

- ADR-007 D6, and the template for the OTHER outcome: `unresolved_count` is
  still written by nobody, and `front.cjs:612-622` explains why — a per-PR
  GraphQL query is the class of field that made a sync cost 41s instead of 7s,
  so "on a board rebuilt from GitHub it is unreachable BY DESIGN, and the
  integrator reading it as dead was right". A reader with no writer that says so
  is a decision. That is the shape each item here must reach.
- `behind_by`: read by `front.cjs`, and `state-sync.cjs` mentions it only in
  comments — there is no `entry.behind_by =` anywhere. CLAUDE.md's reason for
  needing BOTH signals: `mergeStateStatus: BEHIND` appears only where branch
  protection requires up-to-date branches, while `behindBy()` works everywhere.
  So this one wants feeding, and it rides the OPEN-only pass — never the bulk
  `gh pr list` window, which is the `reviewDecision` lesson.
- `needsBaseMerge`: zero occurrences in `deliver.md`, so `fix-round.mjs`'s
  documented argument is passed by nothing the docs describe.
- The `base_merge` journal event: a writer contract and a docs-smoke exemption
  claiming the script "journals itself", with no caller.
- `drift-needed.cjs`: implemented and tested, called from no production command
  or reference.
- `.planning/backlog/-parked-on-front-cjs-renders-only.md`'s subject —
  `front.cjs --parked` computes and prints while only `state-sync --parked`
  writes the board the stop gate enforces on. Same flag, same printed answer,
  one of them inert for everything that enforces.

## Scope

- **`behind_by` is written**, on the open-only pass, beside `merge_state`.
- **`deliver.md` passes `needsBaseMerge` and the base** on the Workflow fix
  round, and names the `base_merge` event's caller — or, if the honest answer is
  that the event has no caller by design, says that instead and the docs-smoke
  exemption is withdrawn. Either outcome is acceptable; silence is not.
- **`drift-needed.cjs` is called where its verdict is used**, or the reason it is
  not is written where a reader looks.
- **`front.cjs --parked` says what it did**: one line naming that the park is
  this render only and that `state-sync --parked` writes the board the stop gate
  reads.
- **The guard**: extend `judgment-contract.test.cjs` into a general
  wired-mechanism pin — for each named mechanism, assert the caller exists in the
  document or script that is supposed to reach it. This is the guard
  `trailer.test.cjs` was, one row short, when phase 27's D2 shipped inert.

## Out of scope

`unresolved_count`, closed by decision and not to be re-opened. The stranded-child
retarget, phase 27's own follow-up. Adding any field to the bulk `gh pr list`
window — the 41s-versus-7s measurement forbids it.

## Acceptance criteria

- A PR that GitHub reports as `CLEAN` while `behindBy()` says 3: the board files
  it under `fix` with a base-moved reason. On base the board files it under
  `merge`, which is the board offering what the guard refuses.
- `deliver.md` contains `needsBaseMerge`; the wired-mechanism pin fails on base
  because it does not.
- `front.cjs --parked T-x` prints the render-only line; without `--parked` it
  prints nothing new.
- Every mechanism the pin names is either called or carries a written decision,
  and the pin fails if a name is added without one.
- **Mutation check.** Remove `needsBaseMerge` from `deliver.md` and the pin
  fails naming it; delete the `behind_by` write and the CLEAN-but-behind case
  fails.

## Test strategy

board/guard disagreement is observable. The wired-mechanism pin extends the file
T-28-03 creates rather than starting a third doc-contract test — one home for
"this document must name its caller".
