## Goal

The background judgment path reads a fact nothing on that path writes. Give
judgment one procedure — measure, resolve, dispatch, record — stated once, and
assert that both entry points produce all four steps.

## Context (Reads)

- ADR-007 D3, and the measurement: `references/pr-sentinel.md` contains ZERO
  occurrences of `log-event.cjs arch_review` and zero of `model arch-review`,
  while `deliver.md`'s inline path has two of each.
- `references/pr-sentinel.md`'s `arch-review` duty entry, which tells the guard
  to run the judge and append the trailer — and its own contested-escalation
  rule, which reads a journalled prior `verdict=violation`. A consumer whose
  producer is on the other path.
- The evidence this is not theoretical: every guard brief in phase 27 had the
  orchestrator patch the resolve step and the record step in by hand. It worked
  BECAUSE of that, which is the definition of a protocol that does not hold.
- `references/arch-review.md:36-50` — the judge already computes and reports the
  base tree, so `measure` has a precedent to follow rather than invent.
- CLAUDE.md's rule on where a rule for a dispatched agent belongs: in the
  `references/` file that agent reads. The procedure is stated once and
  REFERENCED, not duplicated — duplication is how the two paths diverged.

## Scope

- **The four steps, written once.** MEASURE the judged input (the diff size the
  ceiling's window route needs, and whether the verdict is contested), RESOLVE
  model and effort from `pipeline-config.cjs model arch-review --json` with
  `--input-tokens` and `--contested`, DISPATCH the judge, RECORD the
  `arch_review` event with the verdict and the head.
- `references/pr-sentinel.md` names all four in its `arch-review` duty entry.
  `deliver.md`'s inline path references the same statement rather than restating
  it.
- **A contract test over BOTH entry points** — `tests/unit/judgment-contract.test.cjs`,
  a new file, asserting that each of the two documents contains each of the four
  steps inside its arch-review section. It is the same shape as
  `trailer.test.cjs`'s doc pin, which is the guard that would have caught phase
  27's D2 and was one row short.

## Out of scope

Changing what the judge does or what a verdict means. The `arch_review` event's
schema. The `epic_unreachable` event's ownership, which is phase 27's own
follow-up. Any change to `deliver.md`'s dispatch mechanics beyond the reference.

## Acceptance criteria

- `judgment-contract.test.cjs` fails on base: `pr-sentinel.md` has neither the
  resolver call nor the record step, so two of its eight assertions are red
  before the fix.
- Each document names all four steps within its arch-review section — asserted
  by section, not by whole-file `grep`, because both files mention the resolver
  elsewhere for other roles.
- The statement exists in ONE place and the other document references it;
  assert that the four steps are not spelled out twice, since duplication is
  the mechanism that produced the divergence.
- **Mutation check.** Delete the record step from either document and the
  contract test fails naming that document.

## Test strategy

A doc-contract test, deliberately, and not a runtime test: the defect is that
one document does not say something, and the runtime cannot observe an
instruction that was never given. Model it on `trailer.test.cjs:494-508`, which
already extracts an invocation's neighbourhood from a document rather than
matching the whole file.

- `node tests/unit/trailer.test.cjs`
- `bash tests/smoke/docs-smoke.sh`
