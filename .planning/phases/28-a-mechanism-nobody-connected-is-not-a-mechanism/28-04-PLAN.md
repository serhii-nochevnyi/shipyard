## Goal

Three floors are measured against something adjacent to what is in force: the
CLI floor is skipped for a remapped model, the preflight's floor check is
attached to the wrong file, and an explicit environment pin is named as the
remedy and never read.

## Context (Reads)

- ADR-007 D4 and its Family C, each item reproduced.
- `gen-codex-shipyard.cjs`'s `forRole`: `if (remapped) return { model: remapped,
  effort };` — it returns before any `min_cli` comparison, and its comment
  explains why the palette's floor/ceiling does not apply to a remapped tier
  while saying nothing about the CLI floor. Measured: CLI 0.147.0 correctly
  drops Astra from the palette, and `model_profile_overrides.codex.sonnet.model`
  puts it back at `gpt-6-astra/high`, with the "not writing Astra" warning
  printed in the same run.
- `gsd-tune.cjs`'s codex-model-floor blocker: it DOES measure every palette
  `min_cli` against the host, gated on `codexToml.includes(entry.model)`. The
  standard registration keeps `config_file = "agents/shipyard-<role>.toml"` and
  the model lives in that separate file, so on a normally-installed host the
  gate never fires. The check is not missing — it is attached to the wrong file.
- `gsd-tune.cjs`'s `fable-floor` blocker: it reads `cliVersion('claude')` only.
  `ANTHROPIC_DEFAULT_FABLE_MODEL` appears twice in the file, both times as
  comment or remedy prose. Measured: `pipeline.fable: auto`, CLI 2.1.263 and
  `ANTHROPIC_DEFAULT_FABLE_MODEL=claude-fable-5` gives exit 0 and no blockers
  while the environment pins the model ADR-005 ruled out.
- CLAUDE.md on why the env var matters at all: it bypasses the built-in mapping,
  which makes it the STRONGER of the two guarantees and the one that governs a
  host the image pin does not.

## Scope

- **The CLI floor is re-checked after the last remap**, using the `min_cli` the
  original palette entry declared for that model. A remapped model with no
  palette entry has no declared floor and is written as before — this reports a
  known incompatibility, it does not invent one.
- **The preflight reads what is registered.** Resolve the agent files named by
  `config.toml`'s registrations (or a trustworthy install manifest) and measure
  the floor against the models THEY name, with `config.toml`'s own inline models
  still counted. A registration pointing at a missing file is reported, not
  silently skipped.
- **The `fable-floor` blocker reads the explicit pin.** An
  `ANTHROPIC_DEFAULT_FABLE_MODEL` naming anything other than the model ADR-005
  requires is a blocker in its own right, independent of the CLI version, and it
  is REPORTED — never rewritten. Modifying a user's environment is not this
  script's business and the remedy text already says so.

## Out of scope

Forbidding a user's remap, or reversing its precedence over the palette — the
remap outranking us is deliberate and stays. Rewriting anyone's environment or
`config.toml`. Regenerating or reinstalling the bundle, which needs T-28-05 too
and is the operator's act.

## Acceptance criteria

- With CLI 0.147.0 and a remap naming a model whose palette entry declares
  `min_cli: 0.153.1`, the generator refuses that model with one line naming the
  version needed. On base it writes it, so the test fails before the fix.
- A remapped model with NO palette entry is still written — assert it, or the
  fix becomes an allowlist, which ADR-005 D8 explicitly rejected because GSD's
  catalog does not carry every model an operator has.
- A host whose model lives only in `agents/shipyard-integrator.toml`, below that
  model's floor: the preflight reports a `codex-model-floor` blocker. On base it
  exits 0 with no blockers — that green is the defect.
- `pipeline.fable: auto` with a current CLI and
  `ANTHROPIC_DEFAULT_FABLE_MODEL=claude-fable-5`: a blocker naming the pin. With
  the correct pin, or with the variable unset, no blocker from this rule.
- Nothing in either script writes to `~/.codex` or the environment. Assert it.
- **Mutation check.** Move the remap's floor check back above the return, and
  the remap case passes again — watch it, revert. Same for the registered-file
  read.

## Test strategy

TDD against fixtures with a stubbed CLI version, which both suites already do.
The registered-agent-file case needs a fixture host: a `config.toml` carrying a
registration and a separate agent `.toml` holding the model — that shape is the
whole point, so it cannot be flattened into one file. High risk with a
checkpoint: a wrong refusal here breaks a working install, and the failure mode
is an operator who cannot generate agents at all.
