## Goal

A merge that exited 0 duplicated a definition and nothing noticed; a metric
credits the guard's merges to a person. Both are a cheap signal answering a
question it does not answer.

## Context (Reads)

- ADR-007 D8.
- `.planning/backlog/a-clean-merge-can-duplicate-a-block-two-branches-added-alike.md`
  — two branches of one cascade independently added a byte-identical
  `cleanup()`/`trap` block to `epic-branch.sh`; because squash merges share no
  SHAs, a 3-way merge kept BOTH with no conflict. `bash -n` passes (both copies
  are valid) and in shell the second definition silently wins. It recurred on the
  next base-merge of the same round. `base-merge`'s ownership rule could not
  help, because there was no conflict — a clean exit was used to answer "did this
  merge produce a coherent file".
- `.planning/backlog/pipeline-stats-says-a-person-merged-what-the-guard-merged.md`
  — `checkpoint_merge` is `pr.state === 'MERGED' && t.human_checkpoint &&
  withinWindow(...)` and never asks WHO. The comment above it justifies that by
  a behaviour `delivery.preauthorized` retired, and the journal records three
  phase-27 merges as `{"by":"sentinel","preauthorized":true}`.
- `tests/unit/source-contract.test.cjs` — created by T-27-07 as the home for
  assertions about the shape of our own source (the `epics:` wiring line, no
  byte 0x00). A duplicate-definition sweep is that file's kind of case.

## Scope

- **A duplicate-definition sweep over the shell scripts**, in
  `source-contract.test.cjs`: two `^name()` definitions of the same function, or
  two `^trap ` lines, in one file is a defect in every case this repository has.
  It sweeps rather than naming known functions — a list is the shape T-27-07
  replaced.
- **`pipeline-stats.cjs` splits the checkpoint count in two**, reading the `by`
  and `preauthorized` fields the `merge` event already carries: merged by a
  person, and merged by the guard under pre-authorization. The second is worth
  counting separately because it is the only measurement of what the
  pre-authorization question actually saved.
- **The third case becomes a WARNING**: a `human_checkpoint` ticket with a
  guard `merge` event and no `preauthorized` means the guard merged a checkpoint
  nobody authorized. Today it is invisible, folded into the same neutral line as
  the two legitimate cases.

## Out of scope

The `.cjs` half of the duplicate sweep — two top-level `const NAME =` is a
`SyntaxError` that `node --check` already catches, so the shell scripts are the
exposed half.

**Corrected 2026-09-09, after the phase's integrator produced the repro and the
orchestrator re-ran it: this exclusion rested on a premise that covers one of the
two ways a name is bound.** It is true of `const` and FALSE of `function`.
`node --check` PASSES

```js
function cleanup(){ return 1; }
function cleanup(){ return 2; }
```

and the SECOND declaration wins — measured, it returns 2 — exactly as in shell.
So the deterministic layer's `.cjs` files carry the same silent-duplication
hazard the shell sweep exists for, and the sweep should cover `function`
declarations there too. `const` genuinely needs no help. The ticket's scoping
decision was reasonable and its reason was wrong, which is the distinction worth
recording rather than the scope. Any change to how `preauthorized` is written or honoured. The
window logic on the other `pipeline-stats` warnings.

## Acceptance criteria

- A shell script with two `cleanup()` definitions fails
  `source-contract.test.cjs`, naming the file and the function. On base it
  passes, and `bash -n` passes too — that pair is the defect.
- The real duplication that shipped into `epic/27` and was fixed by hand is
  reproducible as a fixture and caught by the sweep.
- A journal with three guard merges under pre-authorization and one human merge
  of a checkpoint prints two counts, not one, and neither line claims the other
  actor's act. On base one line claims all four were a person's.
- A guard `merge` on a checkpoint with no `preauthorized` prints a warning.
- **Mutation check.** Restore the single checkpoint count and the split-count
  case fails; remove the `^trap ` arm of the sweep and the trap case fails while
  the function case still passes — assert both arms separately.

## Test strategy

`source-contract.test.cjs` for the sweep, over fixtures written to a temp dir
rather than against the live tree, so the test states its own subject instead of
depending on the repository staying clean. `pipeline-stats.test.cjs` is a new
file: the script has no unit suite today, and a metric that misattributes an
action is exactly what a unit test is for.
