## Goal

`repeat` is the only verdict whose strategy is `rethink` — a different
hypothesis at the same tier. Today it is unreachable whenever another signature
appears between two occurrences of the same one, so the ladder skips thinking
again and lands directly on the state that opens the ceiling and then hands the
ticket to a person.

## Context (Reads)

- ADR-007 D2. The reproduction, run against a scratch graph with four real
  forty-character heads and `--k 3`:

  ```
  A(1) → verdict=first             distinct=1 seen=0
  B(2) → verdict=progress          distinct=2 seen=0
  A(3) → verdict=progress          distinct=2 seen=1
  A(4) → verdict=repeat_exhausted  distinct=2 seen=2
  ```

- `failure-signature.cjs` — `seen` counts every occurrence of the signature
  after the last green; the adjacency test reads only the last pair.
- `deliver.md`'s repair section: what each verdict routes to, and that
  `--attempt`/`--previous-failed` are accepted as telemetry and route nothing.
  The oscillation backstop's reason is stated there and is NOT to be removed —
  "a signature that oscillates between two values is never the same as the last
  one, so it never reads `repeat`, and it never reaches K distinct".
- `.planning/backlog/the-attempt-backstop-cannot-tell-five-real-fixes-from-five-retries.md`
  — the same mechanism from the other side: the verdict machinery is blind to
  review rounds because a signature comes from a CI log. That is a different
  ticket; do not widen into it.

## Scope

- **`repeat` becomes reachable on recurrence, not only on adjacency.** The same
  signature seen again at a MOVED head is a repeat whatever appeared between:
  the question the verdict answers is "has this exact failure already been
  attempted", and an intervening different failure does not make it novel.
- **`repeat_exhausted` means the depth was APPLIED.** It may only be returned
  when the record shows a `rethink` was actually dispatched at the deeper effort
  — so the attempt row must carry what was applied, not only what was decided.
  `log-event.cjs` accepts it and `attempt-history.cjs` renders it, and
  `effort_applied: unknown` is explicitly NOT evidence: absent proof reads as
  not-yet-spent, which keeps the failure direction on the side of trying again
  rather than escalating early.
- The `plan_defect` K rule and the oscillation backstop keep their current
  behaviour, asserted so this ticket cannot quietly retire either.

## Out of scope

Signing review rounds so the verdict can see them — its own ticket, its own
question. Changing which strategy a verdict maps to. The attempt counter's
existence.

## Acceptance criteria

- `A → B → A` at a moved head returns `repeat`, not `progress`. On base it
  returns `progress`, so the test fails before the fix.
- `A → B → A → A` returns `repeat` then `repeat_exhausted` ONLY if the record
  shows a rethink was applied between them; with `effort_applied` absent it
  returns `repeat` again rather than exhausting.
- The oscillation case (`A → B → A → B → …`, never K distinct, never adjacent)
  still reaches no `repeat_exhausted` and still leaves the attempt backstop as
  the only thing that stops it. Assert it — that is the case the backstop exists
  for and this change must not appear to replace it.
- `plan_defect` still fires at K distinct signatures with no green.
- **Mutation check.** Restore the count-based `seen` and the `A → B → A` case
  fails; make `repeat_exhausted` ignore `effort_applied` and its own case fails.

## Test strategy

TDD in `failure-signature.test.cjs`, driving the state machine through journals
built row by row rather than asserting on a hand-written store — the defect is a
sequence property and a single-row fixture cannot show it. Marked high risk with
a checkpoint: this decides when the conveyor stops repairing on its own, and the
wrong direction either burns paid rounds forever or hands work to a person who
did not need to see it.
