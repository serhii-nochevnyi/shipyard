## Goal

Two mechanisms refuse in the exact state the conveyor creates for every executed
ticket, because both ask "is anything untracked here" while meaning "is anything
unsaved here". And Gate 2 hands an executor a contract no edit can fulfil.

## Context (Reads)

- ADR-007 D7.
- `base-merge.cjs:122` — `if (git(['status','--porcelain']).out) fail('the
  worktree has uncommitted changes …')`. `--porcelain` prints `?? path` for
  untracked files, and T-26-14 writes `.shipyard-pr-body.md` and
  `.shipyard-evidence.md` into EVERY executor worktree as untracked scratch, on
  the reasoning that `scope-gate` reads `git diff` and never sees them. Right
  about `scope-gate`, wrong about every other reader of `git status`.
  Reproduced: exit 2 with both files present, `merged cleanly` with them moved
  aside and nothing else changed.
- Why it is not cosmetic: `base-merge.cjs` is named as THE remedy for a moved
  base in `deliver.md`, `references/ci-fix.md`, `references/review-fix.md` and
  `references/pr-sentinel.md` — three of them read by dispatched agents, none of
  which is told what to do about the refusal.
- `ticket-worktree.sh gc` — same evidence, and `dirty` is a class gc NEVER
  prunes, deliberately. Measured: all five phase-27 worktrees `dirty` including
  two whose PRs were merged, `0 removable`; at cold start 32 worktrees with the
  E2BIG warning printed and gc's own verdict `0 removable`. The count came down
  only because the reaper works from `reapable`.
- `validate-graph.cjs`'s path handling: it parses a declaration, flags entries
  that escape the repo root as `unreachable_paths` (a warning plus a flag, not a
  gate failure, because one unreachable ticket must not stop delivery for the
  valid rest), and checks contested paths. It never asks whether a file EXISTS.
  T-28-04's own predecessor T-27-08 was dispatched against
  `plugins/delivery-pipeline/scripts/gen-codex-shipyard.cjs`, which is not where
  that script lives.

## Scope

- **`base-merge.cjs` and `ticket-worktree.sh gc` ask about TRACKED content**
  (`--untracked-files=no`), and NOT by exempting two known filenames: a list of
  names is the same shape as the pin's list of homes that T-27-07 replaced with
  a sweep, and the next scratch file added would silently re-open it.
- **An untracked path the incoming base ADDS must still refuse.** With the
  pre-check relaxed it is `git merge` itself that refuses, with git's own
  message naming the path — assert that, because it is the case the relaxed
  check stops covering.
- **gc's `dirty` class keeps its meaning** for real uncommitted work; only the
  question changes. A `landed` worktree holding nothing but untracked scratch
  becomes prunable.
- **Gate 2 warns on a declared path that cannot exist**: for a wildcard-free
  entry, a warning plus a flag in the same pass that already resolves paths for
  `unreachable_paths` — never a gate failure, because a plan may legitimately
  declare a file it is about to CREATE.

## Out of scope

`.gitignore`-ing the scratch files. T-26-14 declined it deliberately and this
ticket does not reverse that decision — it fixes the readers that were wrong
about `git status`, which is the narrower and more honest change. Changing what
`reapable` means.

## Acceptance criteria

- A worktree holding only the two scratch files: `base-merge` merges. On base it
  exits 2, so the test fails before the fix.
- A worktree holding a real uncommitted tracked modification: `base-merge` still
  refuses, with the same message.
- An untracked path that the incoming base adds at the same path: the merge
  refuses and the message names that path.
- A `landed` worktree holding only scratch: `gc` reports it removable and
  `--prune` removes it. On base it reports `dirty` and `0 removable`.
- A declared `files_modified` entry with no wildcard and no file on disk:
  `validate-graph` exits 0 with a warning naming it and the flag set. A wildcard
  entry matching nothing is NOT warned about — assert both, or the warning fires
  on every glob.
- **Mutation check.** Narrow the dirtiness fix to the two filenames and the
  "next scratch file" case fails; make the Gate 2 check a hard error and the
  about-to-be-created case fails.

## Test strategy

`files-contract.test.cjs` already builds real git repositories for base-merge,
so the dirtiness cases go there. gc's cases belong in `worktree-smoke.sh`, which
already drives real worktrees. Gate 2's case goes in
`graph-validator-smoke.sh`'s fixture projects. Write the "next scratch file"
case first — it is the one that fails a filename allowlist and passes everything
else.
