## Goal

A shrunk palette or a dropped `-deep` variant leaves an agent file behind that
"the file exists" no longer certifies. The installer must reconcile what it
wrote last time against what it writes now, and remove only its own orphans.

## Context (Reads)

- ADR-007 D5.
- The precise boundary, measured: the bundle payload is ALREADY safe —
  `install-shipyard-codex.sh` does `rm -rf "${BUNDLE_ROOT:?}"` before copying,
  so a bundle script cannot go stale by omission. The agents path is
  `cp "$OUT"/agents/*.toml "$CODEX_HOME/agents/"` with no removal. So this
  ticket is about agent `.toml` files and the registration fragment, not about
  the bundle.
- The reproduction: running the real generator twice — 0.153.4 then 0.147.0 —
  and applying the installer's own copy-over leaves four `-deep` files the
  second generation does not contain.
- ADR-005 D8 on why the count varies at all: a `-deep` file is written only when
  it would DIFFER from the ordinary agent, so a one-entry palette and a
  tier-wide remap both legitimately produce seven agents rather than eleven.
  Varying output is the design, which is exactly why removal cannot be inferred
  from "eleven expected".
- `merge-codex-config.cjs` — the non-destructive `config.toml` merge, and why it
  is non-destructive. An orphan's REGISTRATION lives there, so removing a file
  without its registration leaves a registration pointing at nothing.

## Scope

- **A manifest of what this installer wrote**, produced by the generator beside
  the agents it emits and installed alongside them. It lists the agent files and
  the registrations this run owns.
- **Reconciliation on install**: read the previous manifest, and remove exactly
  the files and registrations it claims that the new manifest does not — never a
  file with no manifest entry, because that is somebody else's agent.
- **No previous manifest is not licence to sweep.** A first install, or an
  install over a hand-made `~/.codex`, removes nothing and says so: the
  conservative direction, because the alternative deletes an operator's own
  agents.
- **A two-stage install smoke** in `codex-shipyard-smoke.sh`: generate and
  install at one palette, then at a smaller one, and assert no orphan agent file
  and no orphan registration survives — and that a foreign agent file placed in
  the same directory is untouched by both stages.

## Out of scope

The bundle payload's lifecycle, which is already correct. Touching the
operator's real `~/.codex` from a test — the smoke isolates `HOME` and must keep
doing so. Regenerating this host's bundle, which is the operator's act after
this and T-28-04 land.

## Acceptance criteria

- Install at an eleven-agent palette, then at a seven-agent one: the four
  `-deep` files are gone and their registrations with them. On base all four
  survive, so the smoke fails before the fix.
- A foreign `shipyard-`-prefixed file the manifest never claimed survives both
  installs. This is the assertion that separates ownership from a name pattern,
  and it must fail if the fix reaches for a glob instead of the manifest.
- No previous manifest: nothing is removed, and the run says which files it is
  leaving alone rather than being silent about it.
- A registration whose file the reconciliation removed is removed from
  `config.toml` in the same act — assert both halves, because either alone is a
  broken host.
- **Mutation check.** Replace the manifest lookup with a `shipyard-*.toml` glob
  and the foreign-file assertion fails. Revert.

## Test strategy

The install smoke, in a throwaway `HOME` — this is a filesystem-lifecycle
property and there is nothing to unit-test about it. Write the foreign-file case
FIRST: the tempting implementation is a glob over the prefix, it passes every
other assertion, and it deletes an operator's own work. High risk with a
checkpoint for that reason: the failure mode of a wrong fix here is data loss on
somebody's machine.
