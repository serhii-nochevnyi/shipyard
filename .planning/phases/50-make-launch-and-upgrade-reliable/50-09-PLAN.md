<objective>Make the host-side admission route honest for legacy history: every in-flight record a launch-admitting host writes in a worktree that has unauthenticated provenance goes through the trusted writer, and a forged or colliding legacy file can never stand in for a new dispatch's sidecar. Nothing outside host admission changes behaviour.</objective>

## Goal

ADR-030 L-4 ("the unauthenticated linked-worktree write path is covered by adoption or pins its own sidecar") and L-7 (Claude and Codex share one admission route). Spike S-1: a linked-worktree executor on a project with legacy history writes an unpinned fourth sidecar that then blocks the project-root host. DECISIONS ("MS1 legacy adoption runs automatically, once per worktree, inside the host") keeps adoption host-side because the Claude sandbox denies the model the authority directory, so the fix must not make the orchestrator's own `dispatch-record.cjs` calls adopt history.

## Scope

In `dispatch-record.cjs`: change `inflightBookkeepingRequired` only. For a linked worktree it additionally returns `true` when `classifyLegacyProvenance(project).state` (the classifier is read-only) is `adoptable`, `adopted`, `blocked` or `unreadable` (the T-50-04 state for an authority namespace that cannot be read: the route cannot tell whether history exists, so it takes the trusted path and the trusted writer raises its own error, rather than silently writing an unauthenticated sidecar); `absent` and `authenticated` keep today's answers. `authenticateBookkeeping`, `mutate` and every caller that does not pass the in-flight `required` value are left exactly as they are, so the unauthenticated shortcut remains for the orchestrator's direct `mark`, `clear` and `clear-round` paths and for the round functions. Add the collision guard to `writeProvenanceOnce` before the existence short-circuit: if the target path is a recorded legacy member and not an authenticated pin, throw an error with code `LEGACY_HISTORY_COLLISION`. Do not change the in-flight subject grammar or any home resolution here (T-50-18).

## Out of scope

Adoption itself, lock changes, preflight wiring, subject parsing, deleting or rewriting any sidecar, and any change to `authenticateBookkeeping`, `mutate` or a non-in-flight caller (the review of this phase rejected widening adoption beyond host admission).

## Acceptance criteria

- A project with legacy sidecars and no catalogue: `recordInflight` with `worktree` equal to the project root adopts and records; the same call with `worktree` equal to a linked worktree also takes the trusted path, so the new sidecar is an authenticated pin and a following project-root `recordInflight` succeeds. `clearInflight` takes the same trusted path in both cases.
- A project with no history keeps today's behaviour: first project-root call creates the authority directory and key; first linked-worktree call with an empty provenance directory is trusted as today.
- Unreadable authority state: with an `EPERM`-coded failure injected on the authority namespace `fs.lstatSync` (`mock.method`), `inflightBookkeepingRequired` for a linked worktree returns `true` and `recordInflight` fails with the trusted writer's raw error without writing a sidecar or dispatches.json.
- Non-admission callers are unchanged: on a legacy-bearing project with no catalogue, each of `reserveRound`, `recordRound`, `clearRound` and the CLI `mark`, `mark-many`, `clear` and `clear-many` writes dispatches.json exactly as before, creates no authority directory, adopts nothing and raises no legacy refusal; a table-driven test enumerates every `mutate()` call site by name and fails if a call site is added without a row.
- A provenance file named `<dispatch_id>.json` that is a recorded legacy member makes `writeProvenanceOnce` throw `LEGACY_HISTORY_COLLISION`; an authenticated pin of the same name still returns false as before.
- Adoption order test: with a run store and a planning-writer lease root in the isolated state directories, driving `recordInflight` through adoption leaves both byte-identical; when adoption refuses (unsafe member) neither is created or modified and no authority directory exists.
- Existing `dispatch-record.test.cjs` cases pass except one deliberate, named change: the case "external canonical graph history is not admitted as ticket-local archive bookkeeping" (`:2210-2234`) currently expects an external-worktree `recordInflight` to write its sidecar unauthenticated and `historicalBookkeepingPins(project)` to stay empty. That is exactly the S-1 path this ticket closes. Keep the case's intent (the canonical history file `historical.json` is never pinned, never altered and never treated as ticket-local bookkeeping) and change its expectations: `historical.json` is absent from the pins and present, unchanged, in the legacy block, and the external review's own sidecar is a pin. The neighbouring case at `:2181-2208` (fresh linked-worker provenance, forged member refused with `/unknown host provenance/`) must pass unchanged. Name every other deliberate change in the SUMMARY.
