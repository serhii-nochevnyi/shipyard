## Goal

ADR-030 L-9 and spike S2: `run-contract.cjs` refuses a repository with whitespace twice, in `safeId` and in two regexes, while the seal pattern allows it; sealed artifacts that carry `repository=owner/repo` must keep verifying.

## Scope

In `run-contract.cjs`: keep `safeId` for ordinary ticket and identifier values; for a ticket value that begins with `phase=` validate it with the shared `parseSubject` family helpers instead of `safeId` (whitespace allowed inside the repository value only), and replace the two hand-written subject regexes with the shared parse; leave the equality checks and the hashed `git-common:` acceptance exactly as they are. In `planning-result-sealer.cjs`: build `SUBJECT_PATTERN` from `REPOSITORY_CLASS`; extend `assertDecompositionSubject(subject, { worktree, repository, adr, acceptedRepositories })` so the subject's repository must equal `repository` or any value in `acceptedRepositories` (default: `[repository]`); `decompositionSubject` builds through the shared builder and refuses a semicolon or control character with `DECOMPOSITION_SUBJECT_INVALID`.

## Out of scope

Any producer (`deliver-dispatch.cjs`, hosts, `role-artifact.cjs`), the integrator family in the authority modules (T-50-18), changing the digest, phase or ADR checks.

## Acceptance criteria

- `normalizeTicketIdentity` accepts planning-input and arch-review subjects whose repository has a space or non-ASCII text and refuses `;` and control characters; non-subject tickets keep `safeId` behaviour (a ticket id with a space is still refused).
- `assertDecompositionSubject` accepts a subject with the old `owner/repo` value when `acceptedRepositories` lists it, refuses it when it does not, and still refuses an ADR digest mismatch and a different repository.
- `planning-result-sealer` and `run-contract` no longer carry their own repository character classes (each builds from the shared one).
- The extended `subject-contract.test.cjs` round-trips planning-input, decomposition-seal and architecture-review subjects for the four repository values through the real consumer functions.
- All existing tests in the four listed test files pass; the single deliberate change (whitespace now accepted) is named in the SUMMARY.
