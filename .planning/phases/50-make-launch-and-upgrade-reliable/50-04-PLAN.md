<objective>Add the read-only classifier and the schema constants that adoption, the dispatch-record route and preflight will all share, so the decision "is this history adoptable, adopted, changed or unsafe" has exactly one implementation.</objective>

## Goal

ADR-030 L-4, L-5 and the L-11 obligation to define the legacy schema marker and version. A preflight must be able to report history problems without creating the authority directory that today's refused launches create (spike S-1).

## Scope

In `role-artifact.cjs` export `classifyLegacyProvenance(worktreePath)`, `LEGACY_BOOKKEEPING_FIELD`, `LEGACY_BOOKKEEPING_SCHEMA`, `LEGACY_BOOKKEEPING_VERSION`, `LEGACY_STATUS`, and `legacyBookkeepingMembers(worktreePath)` (read-only accessor, empty when no legacy record). Decided values (ADR-030 L-4, L-11): field `legacy_bookkeeping` on the catalogue payload, schema `shipyard.legacy-bookkeeping.v1`, version `1`, status `historical-unverified`; the catalogue label stays `shipyard.role-archive-catalogue.v1`. The classifier reads and verifies an existing catalogue through `authorityState(worktree)` without create; a catalogue that cannot be authenticated is reported as an `ARCHIVE_AUTHORITY_INVALID` finding instead of throwing. Unreadable authority state (decision taken here, ADR-030 L-6 and the DECISIONS rule that adoption stays host-side because the Claude sandbox denies the model the authority directory): the member inventory and its unsafe-member findings read only the project's own provenance directory and do not depend on the authority state, so they are computed first; the authority side (resolving the namespace and directory and probing the catalogue with lstat, treating only ENOENT as absent) runs next, and a raw filesystem error from it (an error carrying a `syscall`, which is not a coded `ARCHIVE_AUTHORITY_*` refusal) becomes `state: 'unreadable'` with `unreadable: { code, syscall }`, an empty `members` list and no findings, except that an unsafe-member finding still yields `blocked`. Coded `ARCHIVE_AUTHORITY_*` errors keep their treatment (a finding). The classifier never throws for an authority-side filesystem error.

## Out of scope

Writing the legacy record or changing `trustedBookkeepingMutation` (T-50-07), the route in `dispatch-record.cjs` (T-50-09), any preflight wiring. The classifier never promotes a member to a pin. Making the classifier's unlocked catalogue read safe against a peer session replacing `catalogue.json` while it reads (the read goes through `authorityState`, which T-50-08 makes stable) is T-50-08's work; here the classifier only calls `authorityState` read-only.

## Acceptance criteria

- Returned object: `state` is one of `absent`, `authenticated`, `adoptable`, `adopted`, `blocked`, `unreadable`; `members` is a list of `{ path, bytes, sha256 }`; `findings` is a list of `{ code, path, detail }`; `warnings` is a list of `{ code, path }`; `unreadable` is `null` except in state `unreadable`, where it is `{ code, syscall }` (the filesystem error code and syscall only, never a message with a path outside the worktree). States: no provenance directory or an empty one is `absent`; a catalogue with authenticated pins and only pinned members is `authenticated`; no authenticated record, no legacy record and at least one safe member is `adoptable` with the full member inventory and digests ("no authenticated record" means the catalogue is absent or holds no authenticated pin; a catalogue created by an earlier trusted mutation with an empty `bookkeeping_state` counts as none, which `tests/unit/dispatch-record.test.cjs:2210-2234` exercises); a legacy record whose present members are all unchanged is `adopted`; anything with a finding is `blocked`.
- Findings use the codes defined by T-50-02: `LEGACY_HISTORY_UNSAFE` (symlink, non-regular file, name outside `[A-Za-z0-9_.-]+\.json`, nested directory, a provenance directory that is a symlink, inventory that would push the serialized catalogue past `HISTORICAL_ARCHIVE_MAX_BYTES`), `LEGACY_HISTORY_CHANGED` (a recorded legacy member's bytes differ), `LEGACY_HISTORY_UNKNOWN_MEMBER` (a member that is neither an authenticated pin nor a recorded legacy member while a catalogue exists). A recorded legacy member that is gone from disk is a `LEGACY_HISTORY_MISSING` warning, not a finding.
- Unreadable authority state: with the authority namespace made unreadable (an `EPERM`-coded error injected on the `fs.lstatSync` of the namespace path with `mock.method`, which works whoever runs the test; plus, skipped with a stated reason when the process is root, a real `chmod 000` of the isolated `.local/state/shipyard` directory restored in teardown), the classifier of a catalogue-less project with 64 sidecars returns state `unreadable` with `unreadable.code` equal to the injected code, throws nothing, does not return `adoptable` or `absent`, and leaves the fixture tree and HOME byte-identical with no directory created; the same fixture plus a symlink member returns `blocked` with `LEGACY_HISTORY_UNSAFE`; a forged catalogue still yields an `ARCHIVE_AUTHORITY_INVALID` finding, not `unreadable`; with the injection removed the same fixture classifies `adoptable` again.
- Running the classifier on every fixture leaves the fixture tree and the fixture HOME byte-identical and never creates `role-artifact-authority` content.
- No new member ever appears in `historicalBookkeepingPins` output because of this ticket.
