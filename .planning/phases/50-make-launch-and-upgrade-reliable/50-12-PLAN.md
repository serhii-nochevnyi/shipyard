<objective>Give ADR-030 L-3's "snapshot staleness against the installed Codex CLI is reported by preflight" a concrete, report-only mechanism that needs no per-launch model-catalogue probe.</objective>

## Goal

ADR-030 L-3. The capability snapshot holds only `supportedModels`, `supportedEfforts` and `supportedSelections` and the manifest records no CLI version (`scripts/gen-codex-shipyard.cjs:54-67`, `:360-380`), so staleness against the installed CLI cannot be computed today. Decision taken here (ADR-030 leaves the mechanism open): record the CLI version at install time in the manifest and compare at preflight. Making the comparison a hard refusal needs a measured rule and stays a follow-up (DECISIONS: "Explicit capability evidence").

## Context (Reads)

- `scripts/gen-codex-shipyard.cjs:30-67` (`readCodexCliCapabilities`, the single place that talks to `codex debug models`), `:360-380` (manifest object), `:415` (exports); `tests/unit/gen-codex-shipyard.test.cjs`.
- `plugins/delivery-pipeline/scripts/gsd-tune.cjs:559-573`: `cliVersion` extracts the first dotted number from `codex --version` and treats unreadable output as silence; do not edit `gsd-tune.cjs` here (T-50-21 owns it), reuse the same extraction rule in `runtime-context.cjs`.
- `plugins/delivery-pipeline/scripts/runtime-context.cjs` preflight from T-50-11.
- `scripts/install-shipyard-codex.sh:327-333` (validates the staged manifest against supplied evidence; an additive manifest field must not break that validation).
- Duplicate check: no code records the CLI version with the evidence (searched `cli_version`, `codex --version`); `capture-boundary-fixtures.cjs` and `live-receipt.cjs` record versions for other artifacts and are not reused.

## Scope

Generator: when generating the manifest, run `codex --version` once with a 10 s timeout through the existing `spawnSync` import and store `codex_cli_version` (string or null when unreadable). Preflight: add an injectable `cliVersion` option (default: run `codex --version` with the same timeout and extraction) and emit a `CAPABILITY_SNAPSHOT_AGED` warning naming both versions when the manifest value is a string and differs; unreadable or absent values emit nothing.

## Out of scope

Hard refusal on version drift, any `codex debug models` call at launch or preflight, changes to the installer's evidence refusal, `gsd-tune.cjs`.

## Acceptance criteria

- A generated manifest contains `codex_cli_version` (the parsed version, or null); `validateCodexBundle` still accepts it (existing generator and smoke tests pass).
- Preflight with a manifest version equal to the injected current version has no warning; with a different version has one `CAPABILITY_SNAPSHOT_AGED` warning (exit code still 0); with a null or absent manifest value, or an unreadable current version, has none.
- A bundle installed before this change (no field) never produces a warning.

## Test strategy

Extend `tests/unit/gen-codex-shipyard.test.cjs` with a fake `codex` earlier on PATH; extend `tests/unit/host-preflight.test.cjs` with injected versions. The new preflight cases call `preflight` in the test process and run inside the file T-50-11 created, so they stay under its isolation header: `os.homedir` overridden to a temporary directory before any plugin module is required (the `tests/unit/role-artifact.test.cjs:7-13` pattern, because `archiveAuthorityNamespace` calls `os.homedir()` at call time and setting HOME alone is not enough), with HOME, XDG_STATE_HOME, CODEX_HOME and CLAUDE_CONFIG_DIR pointing at the same directory. Do not add a case that builds its own HOME outside that header, pass `cliVersion` as an injected function so the real `codex` is never run, and keep the file's first test (the `os.homedir()` assertion) in place.
