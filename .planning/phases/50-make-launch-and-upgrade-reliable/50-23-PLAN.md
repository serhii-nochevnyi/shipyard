<objective>Prove the Claude half of the readiness criterion hermetically: from an installed plugin layout and a bare environment the Claude hosts launch and diagnose the same way the Codex hosts do.</objective>

## Goal

ADR-030 L-10 (launch without environment variables on both runtimes) and the L-11 obligation to measure a Claude launch with no `CLAUDE_*` or `SHIPYARD_*` variables.

The Claude half of the library is owned by T-50-28: `stageClaudeLayout(fixture)` (the installed Claude plugin layout, the copy `tests/smoke/model-ladder-runtime-smoke.sh:52` makes, and the `env` of `{ TMPDIR }` inside the work root that every Claude host run adds to PATH and HOME), `installFakeClaude(fixture)` (a fake `claude` that already satisfies `probeClaudeRuntime` and logs argv and environment-variable names to a log baked into its text, read through `readLog`), `installFakeGh(fixture)`, `stageClaudeProject(fixture, name)` (a Claude project the real Claude role host can be admitted against: clean git tree on `main`, an `origin` remote, an excluded local graph holding a `pr-open` ticket, and a fake `gh` registered to answer consistently with it) and `writeClaudeRoleRequest(fixture, project)` (the `pr-sentinel` request file). ## Scope

One scenario file. Stage the Claude plugin layout in the fixture HOME with `stageClaudeLayout`, install the fake `claude` with `installFakeClaude` (it satisfies the probe and records its argv and environment-variable names to a log path baked into its text; read that log through the returned `readLog`), build the Claude project with `stageClaudeProject(fixture, 'claude-no-env')` and its request file with `writeClaudeRoleRequest`, launch `claude-role-host.cjs --args-file <pr-sentinel request>` through `runHost` with an environment of PATH and HOME plus the layout's `env` (`TMPDIR` inside the work root, the only addition; without it the launcher's `os.tmpdir()` is the system `/tmp`, outside the harness), classify the run with `classifyLaunch` over the lines the fake `claude` appended during it, then run `--preflight` alone for each Claude entry. Print one line beginning `MEASURE:` followed by JSON naming which `CLAUDE_*` and `SHIPYARD_*` variable names the fake `claude` received (the host itself adds `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`, `claude-runtime-host.cjs:80-84`, so that is the one expected name) and which config root the host used.

## Out of scope

Changing any host, a real Claude process, model calls, the Codex scenario.

## Acceptance criteria

- The launch is admitted and reaches the native CLI call, as defined in CONTEXT.md ("Hermetic host outcome"): `classifyLaunch` (T-50-01) over the fake `claude` log lines and stderr returns `reached`, meaning the fake logged exactly one native invocation and the host ended with exit 0 or only `RUNTIME_EVIDENCE_*` codes (the expected terminal outcome, because the fake emits no stream), with no `ARCHIVE_*`, `ENV_*`, `LEGACY_*` or `CAPABILITY_*` code and no `RUNTIME_*` code outside the `RUNTIME_EVIDENCE_*` family; the launch's authority state sits under the fixture HOME and its provenance sidecar sits in the project's own `.planning/graph/provenance/`. The scenario never asserts a host exit 0. A run that does not classify as `reached` fails the scenario: a stop before the native call is returned as a finding against the fixture owner T-50-28, naming the first stderr line of the run and the last call the fake `gh` logged (`readCalls`), and is never recorded as a documented gap, because ADR-030 L-10 requires the no-environment launch on both runtimes. The fake `gh` log holds no unmodelled call (`status` 2) after the launch.
- `--preflight` alone exits 0 for the four Claude entries from the installed layout with no variables, and exits 1 with hint lines after the fixture is made incompatible (one provenance member of the `stageClaudeProject` project replaced by a symlink).
- The MEASURE line states the config root resolved (`<HOME>/.claude` with no `CLAUDE_CONFIG_DIR`) and that `CLAUDE_HOME` has no effect.
- The scenario ends with `assertHarnessIsolation`: the write guard log is empty (no mutation outside the fixture work root by the host's own node process, which includes the launcher's temporary directory because `TMPDIR` points into the work root) and the authority state of the launch sits under the fixture HOME; the scenario never lists or reads the real user state, so concurrent real sessions cannot make it fail. Recorded limit (T-50-01): the guard is a `--require` on the host's node process only; processes the host spawns (the fake `claude`, `git`) are outside it and are confined only by their HOME being the fixture HOME.

## Test strategy

Hermetic scenario run by the existing driver; no network, no real model, fake CLIs only (the fake `claude` and the fake `gh` of T-50-28, against a local bare remote).
