<objective>Finish converting `codex-runtime-host.cjs` to the shared resolver after the tracer proved the path, and make its probe CLI explain an unavailable runtime with the correct hint while keeping exit 0.</objective>

## Goal

ADR-030 L-2 and L-6. In `codex-runtime-host.cjs` nine sites default to `~/.codex` while `capabilitiesFrom` has no default (`:162-173`); the host reads native session files from one home while the child could use another (50-RESEARCH Pitfall 11).

## Context (Reads)

- `plugins/delivery-pipeline/scripts/codex-runtime-host.cjs:162-173` (`capabilitiesFrom`, already routed through the resolver by T-50-01 in installed mode), the home sites near `:397`, `:443`, `:732`, `:886`, `:1501`, `:2380`, `:2890`, `:3209`, `:3577` (re-read each; T-50-01 converted only those on its single path), `:2650-2666` (native child environment and its scrub list), `:3715-3752` (`parseCliArguments`, `--capability-only`, `process.exitCode = 0` at `:3750`).
- `tests/smoke/codex-runtime-smoke.sh:104`: a caller of `--capability-only` that reads stdout JSON and relies on exit 0.
- T-50-03: `resolveCodexHome`, `launchEnvironment`, `RESOLVER_CODES`; T-50-02: `formatHint`.
- 50-RESEARCH Pitfall 11 and Open Question Q-3 (does passing the bundle-derived home to the child break a dogfood home that holds no Codex login). Decision taken here per ADR-030 L-2 (locked: the resolver passes the validated home to children): pass it always. Whether a home without a Codex login is visible to the child cannot be observed with a fake `codex` (the T-50-01 tracer and every hermetic scenario use one), so it stays assumption A3 and is measured by the release live receipt from an installed bundle, which T-50-27's release checklist requires; no unit or smoke test here claims to measure it.
- Duplicate check: the sites are the duplicates; the only accessor is T-50-03's.

## Scope

Replace each remaining site's expression with `resolveCodexHome({ scriptDir: __dirname, env })`; keep any `options.env` precedence the call site already has by passing that env object. Route capability loading through the resolver for the explicit-file case as well (flag, env, then bundle) using T-50-03's agreement rules. Make the native child environment exactly `launchEnvironment(resolved, baseEnv)` followed by the existing scrub. In `--capability-only`, when the probe status is unavailable, write `formatHint(code, vars)` to stderr for the mapped code (`RUNTIME_CAPABILITY_MISSING` for `capability_evidence_missing`, otherwise `RUNTIME_UNAVAILABLE` with the reason) and still print the unchanged stdout JSON and exit 0.

## Out of scope

Preflight wiring (T-50-14, T-50-15), changing probe semantics, changing the credential scrub list, the installer.

## Acceptance criteria

- In a source layout with `CODEX_HOME` set, behaviour is identical to today (existing tests pass).
- In an installed layout with an empty env object, every converted site resolves to the bundle home; with a disagreeing `CODEX_HOME` the first call throws `ENV_CONFLICT`.
- The child environment holds the validated `CODEX_HOME`, capability path and runtime and none of the scrubbed credential keys; keys the host did not own are unchanged.
- `--capability-only` with missing evidence exits 0, prints the same stdout JSON as before and prints a `hint[RUNTIME_CAPABILITY_MISSING]` line on stderr; with a healthy fixture it prints no hint line.
- The smoke call at `tests/smoke/codex-runtime-smoke.sh:104` still receives valid JSON on stdout.
