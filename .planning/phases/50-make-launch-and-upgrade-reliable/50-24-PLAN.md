<objective>Prove the upgrade half of the readiness criterion through the installed bundle: old history never blocks the ordinary command and never needs deleting.</objective>

## Goal

ADR-030 L-10's upgrade variants and L-4/L-5. The originating failure was 64 sidecars refusing every launch with `ARCHIVE_AUTHORITY_INVALID`.

## Context (Reads)

- `tests/smoke/installed-launch/lib.cjs` and `scenario-codex-no-env.cjs` (T-50-01): fixture, `runHost` with its write guard, `assertHarnessIsolation`; the driver `tests/smoke/installed-launch-smoke.sh` and, for the Claude spot checks, `stageClaudeLayout(fixture)`, `installFakeClaude(fixture)` and `writeClaudeRoleRequest(fixture, { root, phaseDir })` (T-50-28 owns all three in `lib.cjs`; T-50-01's `lib.cjs` stages only the Codex bundle). This ticket calls them and does not edit `lib.cjs`. The spot checks run `claude-role-host.cjs --preflight --args-file <request>` against this ticket's own projects, which starts no native process, so they need only PATH and HOME; the `TMPDIR` that `stageClaudeLayout` returns is for Claude runs that reach the native call, which this ticket does not make.
- The host-outcome definition (CONTEXT.md, "Hermetic host outcome"): T-50-01's `lib.cjs` owns `classifyLaunch(run, cliLines)` and `readCodexLog()`, and `runHost` returns `{ status, signal, stdout, stderr }`. The fake `codex` emits no native evidence, so an admitted host ends with exit 1 and `hint[RUNTIME_EVIDENCE_MISSING]` after exactly one exec; this scenario classifies each launch (`reached`, `refused`) from the lines the fake appended during that launch and from stderr, and never asserts a host exit 0.

- Duplicate check: S-1's spike script exercises `recordInflight` directly; this scenario exercises the installed host CLI end to end.

## Scope

One scenario file with these cases, each on a fresh project fixture under the installed Codex bundle (no environment variables beyond PATH and HOME), plus a Claude `--preflight` spot check for the symlink and partial cases. Host outcome in every case is the one defined in CONTEXT.md and computed by `classifyLaunch`: a launch is `reached` (admitted: the fake `codex` logged exactly one `exec`, then the host ended with exit 0 or only `RUNTIME_EVIDENCE_*` codes on stderr, the expected terminal outcome) or `refused` (zero `exec` lines, non-zero exit, the named hint code on stderr); "succeeds" below always means `reached`, and "refused" always means `refused` with no native call. (1) headline: 64 sidecars, no catalogue; the launch is `reached`; sidecar bytes identical; `legacy_bookkeeping` has 64 members with status `historical-unverified`; no sidecar is a pin; a second launch is `reached` without a second adoption, meaning the 64 `legacy_bookkeeping` members read through `legacyBookkeepingMembers` are unchanged, compared as serialised JSON, across that second admission. (2) partial history: a subset of sidecars plus a tracked `dispatches.json` whose in-flight rows name dispatch ids that have no sidecar; the launch is `reached`. (3) linked worktree first: a launch from a linked worktree before any project-root launch is `reached` and pinned; the following project-root launch is `reached`. Case 3 uses the same non-typed `pr-sentinel` request as every other case, with `scope.worktree` set to the linked worktree, and not the executor role: the unauthenticated linked-worktree write path of spike S-1 is triggered by host admission (`recordInflight`) whatever the role, while `executorPreflight` (`codex-delivery-host.cjs` near `:1363-1373`) needs a `T-NN-NN` ticket scope, a ticket-graph row whose branch matches the worktree and a plan digest, none of which this fixture models, so an executor launch would be refused before the native call and classify `unclassified`. (4) changed legacy member after adoption: launch `refused` with `hint[LEGACY_HISTORY_CHANGED]` naming the file; nothing deleted or rewritten. (5) new unknown member after adoption: `refused` with `hint[LEGACY_HISTORY_UNKNOWN_MEMBER]` whose remedy says to update the host that wrote it. (6) symlinked member at first admission: `refused` with `hint[LEGACY_HISTORY_UNSAFE]` and no authority directory. (7) fresh clone of a fixture project: the launch is `reached`; record which paths exist (MEASURE line).

## Out of scope

Concurrency (T-50-25), Claude no-environment launch (T-50-23), the downgrade measurement (T-50-27), any production change.

## Acceptance criteria

- Cases 1 to 7 behave as listed, each classified by `classifyLaunch` from the fake `codex` log lines appended during that launch and from stderr: cases 1, 2, 3 and 7 launches are `reached` (exactly one `exec`, terminal outcome exit 0 or `RUNTIME_EVIDENCE_*` only) and cases 4, 5 and 6 are `refused` with exactly the listed code and no `exec` line; no launch is `unclassified`, and no case asserts that the host exited 0. Every `reached` case leaves legacy sidecars byte-identical, and every `refused` case leaves the authority directory absent or the catalogue byte-identical. Case 3 sends the non-typed `pr-sentinel` request with `scope.worktree` set to the linked worktree path, the same request shape as the other cases, never the executor role.
- Adoption happens once: after the case 1 launch the catalogue holds one `legacy_bookkeeping` block with 64 members, and the second `reached` launch leaves those members unchanged (serialised JSON equal), so no second adoption occurred.
- No case needs a deletion, archive or move of any file to proceed, and no remedy line printed in a refusal suggests one.
- Case 7 emits one `MEASURE:` JSON line listing which of provenance directory, run directory and tracked store exist in the clone.
- The scenario ends with `assertHarnessIsolation` (write guard log empty, authority state under the fixture HOME); it never lists or reads the real user state. Recorded limit (T-50-01): the guard covers the host's own node process only, not the processes it spawns (git, the fake CLIs), which are confined only by HOME being the fixture HOME.

## Test strategy

Hermetic scenario through the existing driver; each case builds its own project with real git commands and seeds sidecars with a small deterministic writer. Host outcomes are classified with T-50-01's `classifyLaunch` from the fake `codex` log and stderr, never from the host's exit status alone, because an admitted host exits 1 with `RUNTIME_EVIDENCE_MISSING` after its one exec.
