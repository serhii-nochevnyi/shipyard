## Scope

In `architecture-target.cjs` export: `repositoryIdentity(cwd, { execFileSync } = {})` (realpath of `git -C cwd rev-parse --git-common-dir`, resolved against cwd, then realpath; throws coded `REPOSITORY_IDENTITY_INVALID` when the result contains `;` or a control character or git fails; the optional `execFileSync` replaces node's for the one git call, so a caller that already injects a git runner, such as `codex-arch-review-context.cjs` through `options.execFileSync` in T-50-29, keeps its test seam); `REPOSITORY_CLASS` (decided: one or more characters from `[^;\x00-\x1f]`); `legacyRepositoryForms(cwd)` (the remote `owner/repo` lowercased from `remote.origin.url` exactly as `deliver-dispatch.cjs:805-812` derives it, empty when no remote); `acceptedRepositoryValues(cwd)` (identity first, then legacy forms); and `buildSubject(family, fields)` / `parseSubject(family, text)` for families `planning-input`, `decomposition-seal`, `integrator` and `architecture-review`. Change `PHASE_SUBJECT`'s repository group from `[^;\s]+` to the shared class (the architecture-review parse). The module keeps its current requires.

## Out of scope

Producers and consumers elsewhere (T-50-10, T-50-15, T-50-17, T-50-18, T-50-19, T-50-20, T-50-29). The hashed `git-common:` form stays untouched.

## Acceptance criteria

- `repositoryIdentity` returns the same value from the project root and from a linked worktree of it, works with a path containing a space and with a non-ASCII path, and throws `REPOSITORY_IDENTITY_INVALID` for a path containing `;` or a tab; with an injected `execFileSync` it makes its git call through that function and nowhere else.
- `buildSubject` followed by `parseSubject` round-trips each of the four families for identities: ASCII path, path with a space, non-ASCII path, and the legacy `owner/repo` string; a `;` or control character is rejected by the builder and by the parser for every family.
- `PHASE_SUBJECT` accepts a repository value with a space and a non-ASCII character and still rejects `;`; all existing `architecture-target.test.cjs` expectations other than the old whitespace refusal still pass, and that single deliberate change is named in the SUMMARY.
- `acceptedRepositoryValues` returns the identity first and the legacy `owner/repo` form second when a GitHub origin exists, and only the identity otherwise.
