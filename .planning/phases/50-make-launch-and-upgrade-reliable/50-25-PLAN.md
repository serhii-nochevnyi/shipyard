<objective>Prove that mixed-runtime concurrency is safe on the existing catalogue lock, including at first admission, and settle the UI smoke by checking the GSD install an operator would use for a non-model driver before either running it or recording, with evidence, why it cannot run inside the hermetic core (no driver exists, the install cannot be read, or no install is present).</objective>

## Goal

ADR-030 L-8 and L-10; the INV-017 origin: a Codex and a Claude launch both wrote into one project's provenance directory within ten minutes. L-10 allows "an explicit declared gap if it cannot run non-interactively"; DECISIONS ("The installed-package e2e covers a UI scenario only as a smoke of the existing GSD path") allows the gap only if the GSD path cannot be driven non-interactively, and 50-RESEARCH assumption A7 (`[ASSUMED]`) and Q-7 recommend attempting a real scenario only if a non-interactive GSD driver is found. `gsd-ui-phase` and `gsd-ui-review` are GSD commands the plan has so far assumed are model-driven; this ticket checks instead of assuming. The scenario runs with `HOME` set to the fixture, where the only GSD artefact is the fake `gsd-tools` stub, and CI runs `make test-fast-rest` without installing GSD; the check therefore has to name the install it reads (the operator's, not the fixture's) and define a result for an environment that has none.

The concurrency scenario defines host success where its fakes can reach it. The fake `codex` (T-50-01) and the fake `claude` (T-50-28) emit no native evidence, but each host demands that evidence after its child exits 0, so an admitted host ends with exit 1 and `RUNTIME_EVIDENCE_MISSING` after exactly one native invocation. "Success" in the scenario is therefore admitted and reached the native CLI call, classified from the fake's log and the host's stderr (CONTEXT.md, "Hermetic host outcome"); the scenario never asserts a host exit 0.

## Scope

`scenario-concurrency.cjs`: for five iterations build a fresh project at a new path with `stageClaudeProject(fixture, 'concurrency-<n>')`, the one project both runtimes share, seeded with 64 legacy sidecars written into its `.planning/graph/provenance/` (the fixture excludes the graph directory from git status, so they cannot make the Claude host's clean-tree check fail) and no catalogue (a new path means a new authority directory and key, so every iteration is a first admission that creates the key), then start one Codex host (installed bundle, bare environment; the non-typed `pr-sentinel` request T-50-01's scenario uses, shaped like `deliver-dispatch.cjs:287-298`, with `scope.worktree` set to the project root, `scope.ticket` to the project's `otherTicket` and `scope.phase` to its `otherPhase`) and one Claude role host (installed plugin layout from `stageClaudeLayout`, an environment of PATH and HOME plus the layout's `env`, the request from `writeClaudeRoleRequest(fixture, project)`, fake CLIs including the one from `installFakeClaude`) together using a file-based start barrier. The two hosts hold different tickets on purpose: two admissions of one ticket on one project end, for the second, in `round ticket ... already has active dispatch ownership` (`dispatch-record.cjs` `reserveRound`), a legitimate ownership refusal that is not the race under test and that would classify `unclassified`; with the Codex host on the project's second ticket the shared state is the authority namespace and the catalogue only; wait for both and classify each host with `classifyLaunch` (T-50-01) over the lines its own fake CLI appended during that iteration (read that fake's log length before the barrier and take the new lines after both hosts exit) and over its stderr. Each host must classify as exactly one of: `reached` (admitted: its fake logged exactly one native invocation, then the host ended with exit 0 or with only `RUNTIME_EVIDENCE_*` codes on stderr, which is the expected terminal outcome because the fakes emit no native evidence) or `refused` (zero native invocations, a non-zero exit, and stderr carrying exactly `hint[ARCHIVE_AUTHORITY_BUSY]` with the owner's label and pid). Anything else is `unclassified` and fails the iteration: any other code, including any `ARCHIVE_AUTHORITY_INVALID` text such as `key is malformed` or `changed while reading`, a second native invocation, a BUSY after a native invocation, or an exit 0 with no native invocation. The scenario never asserts that a host exited 0. Per iteration at least one host is `reached` (the lock holder is always admitted); the catalogue authenticates (read through `historicalBookkeepingPins`); `legacy_bookkeeping` holds exactly one block of 64 members, read through `legacyBookkeepingMembers` and kept as serialised JSON; sidecar bytes are identical; and a third sequential launch from either runtime is `reached` (admitted, one native invocation, expected terminal outcome) with the `legacy_bookkeeping` members equal, as serialised JSON, to those read after the concurrent pair, which is the adoption-once check. Add a second shape: one process holds the lock via an injected helper while a host starts, to assert the bounded wait and the named refusal text, classified the same way: held past the 5 s bound the host is `refused` with `ARCHIVE_AUTHORITY_BUSY` and zero native invocations, having waited no longer than the bound plus margin; held for a shorter controlled time and released inside the bound the host is `reached` after waiting.

`scenario-ui-smoke.cjs` exports `candidateRoots`, `classifyDriverCheck` and `validateUiSmokeRecord` for the unit test and runs the scenario only when it is the main module (the driver runs it with node). Steps:

1. Driver check, bounded and read-only: no network, no model run, no execution of either GSD command, at most about 60 seconds, plain fs reads only. Target: the GSD core install an operator would run, never the fixture. `candidateRoots(env, home)` returns the install roots in order from the scenario process's OWN environment and home, captured at scenario start before `runHost` builds any fixture environment: the Claude root (`CLAUDE_CONFIG_DIR`, else `CLAUDE_HOME`, else `<home>/.claude`, plus `/gsd-core`) and the Codex root (`CODEX_HOME`, else `<home>/.codex`, plus `/gsd-core`), exactly the rule of `ensure-gsd-core.sh:352-366` that T-50-06's `Candidate roots:` line confirms; if that line lists a further root, include it. A candidate lying under the harness work root, where the fixture's fake `gsd-tools` stub lives, is marked `excluded: true` and is never read as evidence about GSD. This is the one deliberate read outside the harness roots in the scenario set: it touches only candidate-root existence and the install's command definition files and CLI verb source (paths recorded, contents never), it is a different act from the isolation assertion (which never reads real state), and it reads no state directory, session, credential or agent file and lists no home directory.
2. Decide `driver_check.status`: `not-installed` (every non-excluded candidate root is absent, an lstat ENOENT; the expected status in CI and on any machine without GSD; the record lists every candidate with `exists: false`); `unreadable` (a candidate exists but a read of it is refused, for example by the Claude sandbox; the exact blocked path and error code are recorded); `found` (the install is readable and a verb or documented non-interactive invocation performs each step without a model run; the exact invocation, which names the found install by absolute path so it need not be visible from the fixture HOME, is recorded); `absent` (the install is readable, both commands are model-driven and no such verb exists; the examined definition files and verb names are recorded). A call with no non-excluded candidate throws, so a check that examined nothing cannot produce a record. The record holds paths, verb names and error codes only, never file contents.
3. If `found`, stage a fixture UI phase in the harness fixture, drive `gsd-ui-phase` then `gsd-ui-review` through that invocation under `runHost`'s guard with only PATH and HOME set, assert both exit 0 with no `RUNTIME_*`, `ARCHIVE_*`, `ENV_*`, `LEGACY_*` or `CAPABILITY_*` code in their output (these are the operator's real non-model GSD commands, not a Shipyard host launching a fake CLI, so the host-outcome definition of the concurrency scenario does not apply to them), and print one `RAN:` JSON line with scenario `ui-smoke`, the two steps, status `ran` and the `driver_check`.
4. Otherwise print one `GAP:` JSON line with scenario `ui-smoke`, the two commands in order, status `declared-gap`, a reason and the `driver_check`. Reasons: for `absent`, both commands need a model run and the hermetic core launches no model, a real UI path run belongs to the live receipts at release; for `unreadable`, the exact blocked read and that A7 stays unverified until a release receipt on a machine that can read the install; for `not-installed`, no GSD core install exists in this environment so the check had nothing to read, and A7 stays unverified until a release receipt on a machine that has GSD installed. `not-installed` is an accepted, passing outcome: the absence of GSD never turns the scenario red.
5. The scenario passes its own record through `validateUiSmokeRecord` before printing, so it cannot weaken silently.

`tests/unit/ui-smoke-record.test.cjs` pins `classifyDriverCheck` and `validateUiSmokeRecord` over synthetic evidence for every status (see Acceptance criteria), because a single scenario run exercises only the branch its environment selects.

## Acceptance criteria

- Across five concurrent iterations every host run classifies, through `classifyLaunch` over its own fake CLI's log lines and its stderr, as `reached` (its fake logged exactly one native invocation and the host ended with exit 0 or only `RUNTIME_EVIDENCE_*` codes, the expected terminal outcome) or `refused` (its fake logged nothing, non-zero exit, stderr exactly `hint[ARCHIVE_AUTHORITY_BUSY]` with the owner's label and pid); at least one host per iteration is `reached`; no host run is `unclassified`, so none ends with any `ARCHIVE_AUTHORITY_INVALID` refusal, a second native invocation, a BUSY after a native invocation or an exit 0 without a native invocation; no iteration ends with a corrupt or unauthenticatable catalogue, a doubled adoption, an altered sidecar or an orphaned lock directory; each iteration used a fresh project path, so each one started with no authority directory. No assertion in the scenario requires a host exit status of 0. The Claude host of every iteration is admitted against the shared project (its fake `gh` log, read through `readCalls`, holds no unmodelled call, `status` 2, and its stderr never names a pre-admission refusal such as `PREFLIGHT_FAILED`, `STALE_CONTEXT` or `BASE_REVISION_UNAVAILABLE`), so a `refused` Claude run can only be the named `ARCHIVE_AUTHORITY_BUSY` and a `reached` one carries exactly one invocation in the log `installFakeClaude` returns.
- Adoption is recorded exactly once: after the concurrent pair the catalogue holds one `legacy_bookkeeping` block of 64 members, and the third sequential launch from either runtime is `reached` and leaves those members equal, as serialised JSON, to what was read after the pair.
- The held-lock shape shows the host waiting no longer than the documented bound plus margin and then refusing by name (`refused`, `ARCHIVE_AUTHORITY_BUSY`, no native invocation); with the lock released inside the bound the same launch is `reached`.
- The UI smoke prints exactly one record, `RAN:` or `GAP:`, never both and never none; the record contains `driver_check` with a status of `found`, `absent`, `unreadable` or `not-installed`; a `GAP:` is accepted only with status `absent` (and a non-empty list of the definitions and verbs examined), `unreadable` (and the exact blocked read: path and error code) or `not-installed` (and a non-empty `candidate_roots` list in which every entry that is not excluded has `exists: false` and at least one entry is not excluded), and the scenario fails otherwise; a `RAN:` requires status `found`, the recorded invocation and both steps exiting 0 with no refusal code. In an environment with no GSD install the scenario therefore passes with `GAP:` status `not-installed`.
- The driver check itself ran against the right target: its candidate roots come from the scenario process's own environment and home, never from the fixture HOME; a candidate under the harness work root is `excluded` and never counted; its examined paths, verb names or candidate roots appear in the record; it executed neither GSD command and made no network call (the harness's fake `npx`, `npm`, `curl` and `wget` exit 99 and would fail the scenario if called); the record contains no file contents.
- Unit pin, `tests/unit/ui-smoke-record.test.cjs`: `candidateRoots` honours the precedence `CLAUDE_CONFIG_DIR` over `CLAUDE_HOME` over `<home>/.claude` and `CODEX_HOME` over `<home>/.codex`; `classifyDriverCheck` over injected existence and read functions returns `not-installed` when every candidate is absent (including when the only existing candidate is excluded), `unreadable` with the blocked path and code when a read of an existing candidate throws `EACCES` or `EPERM`, `absent` when the install is readable and offers no non-model verb, `found` with an invocation when one exists, and throws when given no non-excluded candidate; `validateUiSmokeRecord` accepts one valid record per status and rejects each of: a `GAP:` with status `found`; `absent` with an empty examined list; `unreadable` without a blocked read; `not-installed` with an empty candidate list, with a non-excluded candidate whose `exists` is true, or with only excluded candidates; a `RAN:` with any status but `found` or without an invocation; both records or none; a record carrying a file-content field.
- The scenario ends with `assertHarnessIsolation` (write guard log empty, authority state under the fixture HOME); it never lists or reads the real user state. Recorded limit (T-50-01): the guard covers the host's own node process only, not the processes it spawns (git, the fake CLIs), which are confined only by HOME being the fixture HOME.

## Test strategy

Child processes with an explicit minimal environment, a shared fixture HOME so both runtimes share one authority namespace, and generous time margins; no sleeps beyond the 5 s bound in the held-lock case. Host outcomes are classified with `classifyLaunch` from each fake CLI's own log and the host's stderr, never from the host's exit status alone: with the specified fakes an admitted host exits 1 with `RUNTIME_EVIDENCE_MISSING` after exactly one native invocation, and that is the expected terminal outcome. If a host stops before the native call for a reason the fixture does not model, the run is `unclassified`, the scenario fails, and the stop is returned as a finding against the fixture owner (T-50-01 for the Codex host; T-50-28 for the Claude host, whose project, fake `gh` and `TMPDIR` environment it supplies), naming the first stderr line of the run and the last call the fake `gh` logged, never absorbed into the definition and never recorded as a documented gap. The UI smoke is a scenario that asserts its own record shape, backed by a unit test that exercises every status deterministically with injected existence and read functions (no real GSD install is needed or read by the unit test).
