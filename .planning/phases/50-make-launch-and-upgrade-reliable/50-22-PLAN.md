## Scope

New `tests/unit/host-entry-contract.test.cjs` (node:test) and additions to `tests/unit/subject-contract.test.cjs`. The enumeration finds every `*-host.cjs` script in `plugins/delivery-pipeline/scripts` that contains `require.main === module`, plus `deliver-dispatch.cjs`, and requires each to be in exactly one of ENTRIES, LAUNCHER, PROBES or EXCLUDED (a script in none, or in two, fails with its file name). Dynamic part for ENTRIES: run `--preflight` alone from a fixture project (source layout, explicit capability evidence in the environment for Codex entries, a fake claude on PATH for Claude entries) against a clean fixture (exit 0) and a broken fixture (a symlinked provenance member, plus missing capability evidence for Codex entries; exit 1, `hint[CODE]` lines on stderr, no authority directory, no run-store, no private input files). The fixtures must satisfy each host's own graph-directory rule (read `graph-dir.cjs` and the hosts' `inflightGraphDir` and `graphDirectory` functions; a canonical `.planning/graph` holding at least `tickets.json` and the `provenance` directory), because a host whose rule finds no graph directory records no in-flight state and preflight then reports `legacy history: not evaluated`, which would let the broken fixture pass for the wrong reason (exit 0 instead of 1). Static part for the LAUNCHER: inside the `launch` function the preflight call precedes `prepareDispatchDir` (compare the source offsets of the two calls within that function body), and the file requires the shared preflight. Dynamic part for PROBES: each runs with unavailable evidence (no evidence or a missing `--executable`) and exits 0 with its schema's JSON on stdout.

## Out of scope

Production code (a gap found here is returned as a finding against the owning ticket, never patched in this one), the installed-package scenarios (T-50-01 and T-50-23 to T-50-25, under tests/smoke), README.

## Acceptance criteria

- Adding a new `*-host.cjs` with a CLI and no listing in ENTRIES, LAUNCHER, PROBES or EXCLUDED fails the enumeration test with the file name; so does listing one script twice.
- Every ENTRY accepts `--preflight` alone, exits 0 on the clean fixture and 1 on the broken fixture, prints one `hint[CODE]` line per finding and leaves the fixture byte-identical.
- `deliver-dispatch.cjs` is recognised as the LAUNCHER and the order assertion fails if `prepareDispatchDir` is called before preflight inside `launch`.
- `codex-runtime-host.cjs --capability-only`, `claude-role-host.cjs --capability-only` and `claude-runtime-host.cjs --capability-only --executable <missing>` with unavailable evidence exit 0 and keep their stdout JSON shape (the PROBES and the role host's probe mode).
- Union of `RESOLVER_CODES`, `PREFLIGHT_CODES` and the legacy and identity codes is a subset of `LAUNCH_CODES`, and each has a non-empty hint and remedy.
- A scan of `plugins/delivery-pipeline/scripts/*.cjs` finds no expression of the forms `process.env.CODEX_HOME`, `env.CODEX_HOME`, `process.env.CLAUDE_CONFIG_DIR` or `environment.CLAUDE_CONFIG_DIR` outside `runtime-context.cjs` and the allowlist (each allowlisted file named with its reason, for example `codex-notify.cjs` deriving its home from its install location).
- The subject round-trip matrix passes for every family and both runtimes' producers, with the architecture-review family driven from `deliver-dispatch.cjs build`, the Codex context and the Claude role host: for a plain, a space and a non-ASCII path the subject `deliver-dispatch build` launches equals the subject the Codex context rebuilds, and equals the subject the Claude role host builds for the same repository, and a semicolon path is refused with `REPOSITORY_IDENTITY_INVALID` by each producer.

## Test strategy

Child-process runs with explicit environments and isolated HOME and XDG roots; real git fixtures; the family round trip calls each producer's exported builder and each consumer's exported validator, and for the architecture-review family goes through the producers' public entry points with the injections the existing tests already use (`getPullRequest`, default branch). Tests that would acquire a typed-GSD lease under the real home are not used.
