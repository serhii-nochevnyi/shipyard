## Scope

`preflight({ runtime, scriptDir, worktree, graphDir, env, flags, scope, gsdRole, phaseDir, runStoreFile, probe })` (`graphDir` is the graph directory the calling host will record in-flight state into, resolved by that host's own rule and passed through unchanged; see "Graph directory and bookkeeping root" below) returns `{ schema: 'shipyard.host-preflight.v1', ok, scope, findings: [{ code, detail, vars }], warnings: [{ code, detail, vars }], notes: [{ kind, detail }] }`. `scope: 'launch'` runs all checks; `scope: 'environment'` runs only environment and bundle, runtime identity, and policy and agents (used by resume and recover modes, ADR-030 open question Q-4). Checks: (1) `resolveHostEnvironment` errors become findings (`ENV_CONFLICT`, `BUNDLE_MANIFEST_INVALID`, `CAPABILITY_EVIDENCE_STALE`, `RUNTIME_CAPABILITY_MISSING`); checks that need its result are recorded as not evaluated in `notes`; (2) runtime identity through `resolveDispatchContext(worktree, { routed: true, runtime, env, scriptPath: scriptDir })` errors; (3) Codex only: manifest `policy_hash` against `POLICY_HASH` and every `manifest.agent_files` entry present in `<home>/agents` with the manifest digest, reported as one `STALE_GENERATED_AGENT` finding listing the files; (4) injected `probe()` result `unavailable` becomes `RUNTIME_UNAVAILABLE` (reason in detail; capability-evidence reason maps to `RUNTIME_CAPABILITY_MISSING`); (5) launch scope: legacy classification findings and warnings for the bookkeeping root derived from `graphDir`, an `adoptable` state recorded as a note and never as a finding, and an `unreadable` state (the protected authority namespace cannot be read, for example under the Claude model sandbox) recorded as the note `legacy history: not evaluated, authority namespace unreadable (<code>)` with `kind: 'not-evaluated'` and never as a finding, so `ok` is unaffected and the host's own admission, which runs where the authority state is readable, decides; (6) launch scope and `gsdRole`: `assertNoLegacyPlanningWriter` errors as `LEGACY_WRITER_STATE`; (7) launch scope and `runStoreFile` present: `normalizeStore(JSON.parse(file))` errors as `INVALID_STORE`. No check may throw out of `preflight`: each of checks (1) to (7) is wrapped so that a coded error becomes a finding, an unreadable authority state becomes the note above, and any other uncoded error becomes a `not-evaluated` note naming the check and the error code (never a finding, never a rethrow), which keeps the collect-all pass intact. Graph directory and bookkeeping root: preflight derives the root exactly as `dispatch-record.cjs` does (`path.resolve(graphDir, '..', '..')`, then realpath) and runs check 5 and its read-only authority-state read on that root, never on `worktree`; the provenance directory is `<root>/.planning/graph/provenance` and the authority directory is the one keyed by that root. An explicit `graphDir: null` means the host's own rule found no canonical graph directory and so records no in-flight state; an omitted (`undefined`) `graphDir` makes preflight resolve it in the order the Codex host uses (`env.SHIPYARD_GRAPH_DIR`, else `<git top level of worktree, or worktree>/.planning/graph`). A `null`, a non-canonical or a missing directory records `legacy history: not evaluated, no graph directory` in `notes` and is not a finding, mirroring a host that records no in-flight state in that case. `emitPreflight(result, { stdout, stderr })` writes one human line `preflight: ok` or `preflight: N incompatibilities`, one `formatHint(code, vars)` line per finding and one `preflight: warning[CODE]` line per warning to stderr, one JSON line of the result to stdout, and returns exit code 0 when `ok` and 1 otherwise. Export `PREFLIGHT_CODES`.

## Acceptance criteria

- Two simultaneous defects (a disagreeing `CODEX_HOME` and a stale generated agent) produce two findings in one call; a clean installed fixture produces `ok: true` with no findings.
- A legacy-bearing fixture without a catalogue is `ok: true` with a note naming the number of members that adoption will record; a symlink member produces `LEGACY_HISTORY_UNSAFE`; an adopted-then-changed fixture produces `LEGACY_HISTORY_CHANGED`; a forged extra member produces `LEGACY_HISTORY_UNKNOWN_MEMBER`.
- Graph directory, not worktree: with `graphDir` naming project B's `.planning/graph` and `worktree` naming project A, legacy members under B produce the finding (or the adoptable note) even when A has no history, and legacy members under A alone produce nothing; the authority state read is B's. With `graphDir` omitted and `SHIPYARD_GRAPH_DIR` set in the explicit env object, the env value is used; with `graphDir: null`, a non-canonical or a missing graph directory the note `legacy history: not evaluated, no graph directory` is present and `ok` is unaffected.
- Unreadable authority namespace: with an `EPERM`-coded failure injected on the `fs.lstatSync` of the authority namespace path (`mock.method`, so it holds whoever runs the test), `preflight` run in-process on a legacy-bearing fixture does not throw, returns the note `legacy history: not evaluated, authority namespace unreadable (EPERM)` with `ok` unchanged by it, and still reports every other defect of the same call (a disagreeing `CODEX_HOME` together with the unreadable namespace gives one `ENV_CONFLICT` finding and the note in one result); a coded `ARCHIVE_AUTHORITY_INVALID` (forged catalogue) is still a finding, not a note; an injected `probe` that throws a plain `Error` (the existing injection seam, so no module needs patching) becomes a `not-evaluated` note naming the runtime-probe check while the other checks still report; `emitPreflight` of such a result prints no `hint[CODE]` line for the note and returns 0 when no finding exists.
- Running preflight over every fixture leaves the fixture project, the fake HOME state directories and the authority directory byte-identical (snapshot before and after) and never creates `role-artifact-authority` content.
- Every finding code is a member of `LAUNCH_CODES` from `refusal-hints.cjs`; the test iterates `PREFLIGHT_CODES`.
- `emitPreflight` prints one `hint[CODE]` line per finding with tokens substituted (`{host}`, `{bundle}`) and returns 1 only when findings exist; warnings alone return 0.
- `runtime-context.cjs` still loads with only `fs` and `path` at top level and `require('./runtime-context.cjs')` does not load any host module.
