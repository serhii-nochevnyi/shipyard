## Scope

In `launch`, after the runtime and arguments are known and before `prepareDispatchDir`, call preflight in-process with the target host's runtime, the resolved host script directory as `scriptDir`, the worktree, `scope: 'launch'` (typed-GSD roles set `gsdRole`) and `graphDir` set to the resolved launch graph directory (`resolveLaunchGraphDir`, `:315`), which is exactly the directory `spawnDetached` hands the host as `SHIPYARD_GRAPH_DIR`; on failure emit through `emitPreflight`, then throw so `main` exits non-zero with no directory created. Only findings fail the preflight: a `not-evaluated` note, in particular the note T-50-11 records when the authority namespace is unreadable from the caller's process (T-50-04 returns state `unreadable` instead of a raw error, T-50-11 turns it into the note), does not stop the launch, because the host that is spawned performs the authoritative admission where the authority state is readable. Make the spawned child environment `launchEnvironment(resolved, { ...process.env, ...options.env, SHIPYARD_GRAPH_DIR })`. Make the CLI wrapper print `formatHint(error.code)` after the message for coded errors. In the decomposition build, build `subject` and `scope.repository` with `repositoryIdentity(context.projectRoot)` and delete `planningRepository`. In the architecture-review build take `repository` from `repositoryIdentity(input.worktree)` instead of the private git-common-dir expression at `:1159`, so the launched aggregate subject and the one the Codex producer rebuilds come from the one function.

## Out of scope

Changing what hosts do after launch, `status` and `wait` semantics, adding a standalone preflight command (ADR-030 rejects it), the Claude request shapes.

## Acceptance criteria

- With a broken installed fixture, `deliver-dispatch.cjs launch` exits non-zero with every finding as a `hint[CODE]` line on stderr, creates no `dd-*` directory under the isolated dispatch state directory and spawns nothing (assert with an injected `options.spawn` that fails the test if called).
- With a healthy fixture the injected spawn receives an environment equal to `launchEnvironment` output plus the preserved variables.
- With the authority namespace unreadable from the launch process (an `EPERM`-coded failure injected on the namespace `fs.lstatSync` with `mock.method`) and an otherwise healthy installed fixture, `launch` does not throw or exit non-zero because of it, prints no `hint[CODE]` line for it, and calls the injected spawn once; with the same injection and a disagreeing `CODEX_HOME` it still refuses with `hint[ENV_CONFLICT]`, creates no `dd-*` directory and does not spawn.
- `build decomposition` for a project under a path containing a space returns a request whose subject and `scope.repository` use the identity and that the Codex planning host and `run-contract` accept; a project with a GitHub origin no longer yields the `owner/repo` form.
- `build arch-review` for an aggregate phase in a project under a path containing a space returns a request (Codex `scope.ticket`, Claude request) whose subject carries that identity and parses through `parseSubject('architecture-review', ...)`; a semicolon in the project path is refused with `REPOSITORY_IDENTITY_INVALID` instead of the generic subject error.
- With `SHIPYARD_GRAPH_DIR` naming another project's graph than the worktree, the findings preflight prints are those of the launch graph directory's project (the same value the spawned host receives).
- Existing `deliver-dispatch.test.cjs` assertions pass; any assertion expecting the old remote form changes deliberately and is named in the SUMMARY.
