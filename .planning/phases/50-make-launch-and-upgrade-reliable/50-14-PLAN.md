<objective>Wire the shared preflight into the Codex delivery host's CLI so a refused launch is complete, named and side-effect free, and so operators can run the same checks without launching.</objective>

## Scope

Add a `--preflight` flag parse: accepted forms are `--preflight` alone (worktree is the current directory, role-agnostic checks), `--preflight --args-file <json>` (adds the request's worktree and role: typed-GSD role sets `gsdRole`, and `phaseDir` from the scope), and the unchanged launch forms. Insert the preflight call in `runCli` immediately after `canonicalCliScope`, passing the host's own probe function, `scriptDir: __dirname`, `scope: 'launch'`, the host's run-store file path, `gsdRole` and `graphDir: inflightGraphDir(options, scope.worktree)` (the very value the host later hands to `recordInflight`, `null` when it records none, so preflight and admission look at the same provenance directory); on `--preflight` emit and return without side effects; otherwise a failed preflight emits all findings and sets a non-zero exit before `archReviewContext.prepare`. For the two resume modes call preflight with `scope: 'environment'` before their `controller.begin`. Convert `:718-721`, `:928` and `:3065` to the accessors. Keep every existing admission check (`assertNoLegacyPlanningWriter`, the dispatch boundary's own validation) in place.

## Out of scope

The other hosts, `--capability-only` on the runtime host (T-50-13), any change to what happens after a passing preflight, subject changes.

## Acceptance criteria

- With a deliberately broken installed fixture (disagreeing `CODEX_HOME` plus a stale generated agent) a launch exits non-zero, stderr lists both `hint[ENV_CONFLICT]` and `hint[STALE_GENERATED_AGENT]` lines, the run-store file, the authority directory and the lease root do not exist, and no native process starts.
- With `SHIPYARD_GRAPH_DIR` in the explicit environment naming a different project's `.planning/graph` than `scope.worktree`: a symlinked provenance member under that graph directory's project makes the launch refuse with `hint[LEGACY_HISTORY_UNSAFE]` and no state, while the same member under the worktree's own project alone does not; in both cases the verdict equals what `recordInflight` would do (assert by calling it on a copy of the fixture).
- `--preflight` on a healthy installed fixture exits 0 and prints the JSON line; on the broken fixture exits 1; neither starts a run.
- A resume mode with a broken environment refuses before its `controller.begin` (assert the run-store file is untouched).
- Source-layout tests that inject environment values still pass.
