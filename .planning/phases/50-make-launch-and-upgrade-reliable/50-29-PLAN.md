<objective>Convert the one architecture-review producer that still builds its own repository identity, and test it from its real entry point, so the architecture-review family of the L-9 contract is covered at its producer and not only through a test-supplied identity.</objective>

## Goal

ADR-030 L-9 and REQ-200: "one `repositoryIdentity()` ... serve[s] every ... architecture-review subject family on both runtimes" and the contract test round-trips each family. `codex-arch-review-context.cjs` builds the identity with its own `git rev-parse --path-format=absolute --git-common-dir` plus `realpathSync` at four places, and no plan converted it. The value is the same for a valid path, but the producer neither refuses a semicolon or control character by the contract's code nor is pinned by a test that drives it.

## Scope

- In `codex-arch-review-context.cjs`: `common(root)` becomes `repositoryIdentity(root, { execFileSync: options.execFileSync })` (the T-50-05 optional second argument), used for the graph-belongs comparison and for the `phaseBinding` call; `focusedBinding` takes its `repository` from `repositoryIdentity(prepared.canonical.worktree)`. `fileSnapshot` keeps its combined `rev-parse` (it needs HEAD and the tree from the same call) and a test pins its `repository` equal to `repositoryIdentity(worktree)`.

## Out of scope

The subject grammar and helpers (T-50-05), the other consumers (T-50-10, T-50-18), the hashed `git-common:` form, pin readers and the roster (T-50-27's audit), any change to what the review decides.

## Acceptance criteria

- Preparing the aggregate-phase review in a repository whose path contains a space succeeds, and `binding.subject` equals the launched ticket subject with that identity; the same holds for a non-ASCII path.
- A repository whose path contains a semicolon makes the aggregate preparation refuse with `REPOSITORY_IDENTITY_INVALID` (not the generic `invalid aggregate architecture subject`).
- The producer's subject parses through `parseSubject('architecture-review', subject)` and `normalizeTicketIdentity` accepts it, for the plain, space and non-ASCII paths.
- A recording `options.execFileSync` receives the git-common-dir call made by the producer, proving the injectable seam still works.
- `fileSnapshot`'s `repository` equals `repositoryIdentity(worktree)` in the same fixture.
- Every existing test in `codex-arch-review-context.test.cjs` passes; any deliberate edit is limited to an assertion that contradicted whitespace acceptance and is named in the SUMMARY.

## Test strategy

Extend the existing aggregate fixtures with real git repositories created in directories with a space, a non-ASCII name and a semicolon. Drive the public preparation path the existing aggregate scenarios use, with `getPullRequest` and the default branch injected as they already are; no network.
