## Scope

Sections for these obligations, with owning ticket: pin-reader audit (T-50-27), `catalogue.lock` under pid reuse (T-50-08), legacy schema marker and version (T-50-04), run-store and lease ordering during adoption (T-50-09), Claude launch with no `CLAUDE_*` or `SHIPYARD_*` variables and the `CLAUDE_HOME` reader (T-50-23), `.git/info/exclude` writer and fresh clone (this ticket, measured again in T-50-24), reusable GSD preflight (this ticket), upgrade, downgrade, upgrade (T-50-27), snapshot staleness reporting (T-50-12), and the UI-smoke driver check of L-10 (T-50-25 performs the bounded check for a non-interactive driver of `gsd-ui-phase` then `gsd-ui-review`, T-50-27 closes the section from its record; ten sections in all). This ticket fills in, from source and commands, the reusable-GSD-preflight finding, the exclude-writer finding, the `CLAUDE_HOME` reader finding, the run-store and lease reading, and the pid-reuse reading (static, before T-50-08 changes anything).

## Out of scope

Any production change, adoption-dependent tests, the downgrade measurement, the release checklist (T-50-27).

## Acceptance criteria

- The record has one level-two heading per obligation above (ten, including the UI-smoke driver check, which starts `pending (T-50-25)`), each with a `Status:` line of `closed`, `limitation` or `pending (T-50-NN)`, and an `Evidence:` line naming exact commands, files and lines.
- Reusable GSD preflight: records which GSD core install the host resolves (the path the host's own gsd resolver would select, not a guessed home), whether it exposes any doctor or preflight verb with its exact invocation, and a decision (reuse or not) with the reason; if the GSD install is not readable from the execution sandbox the entry says so and carries `limitation` with the exact blocked read. The entry also holds one `Candidate roots:` line listing, separated by `;` and in resolution order, every GSD core directory the installer and host resolution can select: at least `${CLAUDE_CONFIG_DIR:-${CLAUDE_HOME:-$HOME/.claude}}/gsd-core` and `${CODEX_HOME:-$HOME/.codex}/gsd-core` (`scripts/ensure-gsd-core.sh:352-366`), extended if the reading finds another. T-50-25's UI-smoke driver check examines exactly these roots in the invoking environment and derives its `not-installed` status from them, so the line is a contract, not prose.
- `.git/info/exclude`: records the search commands and the result for `plugins/`, `scripts/`, `capabilities/` and `tests/` (writers found or none), what a fresh clone contains (untracked provenance and runs directories are absent; tracked `dispatches.json` is byte-pinned after the first trusted mutation), and the conclusion that adoption must not depend on any exclude entry.
- `CLAUDE_HOME`: records the search result across `plugins/delivery-pipeline/scripts` (readers of `CLAUDE_CONFIG_DIR` versus `CLAUDE_HOME`) and the single comment mention.
- Run-store and lease ordering: records the call order in the Codex and Claude hosts from `controller.begin` to `recordInflight` and what each releases on failure.
- The contract test fails if any obligation heading, status or evidence line is missing, if the reusable-GSD-preflight section has no `Candidate roots:` line with at least one entry, and allows `pending (T-50-NN)` only for the obligations whose owner is a later ticket.

## Test strategy

Contract test over the markdown; no production behaviour changes. T-50-27 tightens the test to forbid `pending`.
