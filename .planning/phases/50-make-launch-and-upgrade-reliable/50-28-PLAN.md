<objective>Take over the parts of the original tracer that do not belong in the thinnest slice: run every installed-package scenario through one driver that CI reaches, pin the resolver across every installed layout the installers produce, and give the three Claude-using scenarios one shared, declared source for the Claude installed layout, its fake CLIs and a Claude project that the real Claude role host can be admitted against.</objective>

## Goal

ADR-030 L-10 (hermetic CI core) and L-2/L-3. T-50-01 proved one path end to end with its scenario run directly; this ticket makes the scenario set reachable from `make test-fast-rest`, widens the resolver's unit coverage from one synthetic layout to all of them, and adds the Claude half of the fixture library to `lib.cjs`, without touching a production file. T-50-01's `lib.cjs` stages only the Codex bundle and a fake `codex`; before this ticket nothing declared who stages the Claude plugin layout, and the wave-8 scenarios that need it would each have had to duplicate it or edit `lib.cjs` concurrently.

The Claude role host is stricter than the Codex host: before `controller.begin` and `recordInflight` it prepares its invocation from a real git project, the canonical ticket graph and live GitHub state, and for `pr-sentinel` it also runs the sentinel round preflight (a fetch, a fast-forward and `state-sync.cjs` in the project). With a layout and a fake `claude` alone every Claude launch is refused before admission (plan-review round 4), the mixed-runtime race of INV-017 is never reached, and ADR-030 L-10 would be reduced for the Claude half. This ticket therefore also owns the project, the fake `gh` and the host-run environment that make a Claude launch reach the native call (CONTEXT.md, Claude role host bullet), and pins them with a unit test that runs the real host.

## Scope

- `tests/smoke/installed-launch-smoke.sh`: bash 3.2 compatible, `set -euo pipefail`, early precondition checks (node on PATH, the `installed-launch` scenario directory beside the script). With no argument it runs, in sorted order, every `scenario-*.cjs` in that directory with node, prints one line per scenario (`PASS <name>` or `FAIL <name> (exit N)`), keeps going after a failure so every result is reported, and exits non-zero if any scenario failed or none was found. With one argument it runs only the scenario whose base name (file name without extension) equals the argument exactly; the argument must match `^scenario-[a-z0-9-]+$` and an unknown or malformed name exits 2 and lists the available names without running anything. The scenario directory is resolved relative to the script's own location so a test can copy the driver beside fake scenarios.
- `Makefile`: target `test-installed-launch` running `./tests/smoke/installed-launch-smoke.sh`, appended to `TEST_FAST_REST` and to the `.PHONY` list.
- `tests/smoke/installed-launch/lib.cjs` (extends the file T-50-01 created; it adds exports and changes no existing export): five Claude helpers. Every one takes the fixture object, which has absolute `home`, `bin` and `workRoot` directories (the object the T-50-01 fixture builder returns, or a bare descriptor in a unit test), refuses with a thrown error when `home`, `bin` or any path it would create is not inside `workRoot`, and writes nothing outside `workRoot`. Every `git` command a helper runs uses an environment of PATH, HOME set to the fixture home, `GIT_CONFIG_NOSYSTEM=1` and `GIT_TERMINAL_PROMPT=0` plus repository-level configuration, so the user's own git configuration (signing, hooks, templates) cannot change the fixture. `lib.cjs` stays free of top-level side effects because unit tests require it.
  - `stageClaudeLayout(fixture)` copies `plugins/delivery-pipeline` of the repository checkout to `<fixture.home>/.claude/plugins/shipyard`, creates `<workRoot>/tmp` (mode 0700) and returns `{ claudeHome, pluginRoot, scriptsDir, tmpDir, env }`, idempotent for one fixture. `env` is exactly `{ TMPDIR: tmpDir }`: the one variable a Claude host run adds to PATH and HOME, because the launcher creates its SessionStart evidence directory under `os.tmpdir()` (`claude-runtime-host.cjs:735`), which without `TMPDIR` is the system `/tmp`, outside the harness work root (the write guard records it) and refused under the Claude sandbox. Scenarios pass `env` as the case addition of `runHost`; `TMPDIR` is neither a `CLAUDE_*` nor a `SHIPYARD_*` input.
  - `installFakeClaude(fixture)` writes an executable `claude` into the fake bin directory that is already first on the fixture PATH and returns `{ executable, logPath, readLog }`. The fake answers `--version` with a version line and status 0, `--help` with every `REQUIRED_HELP_MARKERS` word of `claude-runtime-host.cjs` and status 0, and `auth status --json` with `{"loggedIn":true}` and status 0, which together satisfy `probeClaudeRuntime`; for any other invocation it appends one JSON line holding its argv and the NAMES of the environment variables it received (never their values) to a log path written into the script text itself, because no environment variable may carry it, and exits 0. `readLog()` returns the parsed lines.
  - `installFakeGh(fixture)` writes an executable `gh` into the same fake bin directory (idempotent) and returns `{ executable, stateDir, readCalls }`. The fake reads a project registry `<workRoot>/gh-state/projects.json`, a JSON object keyed by the realpath of a project root, and appends one JSON line `{ cwd, args, status }` for every invocation, modelled or not (`status` is 0 for a modelled call and 2 for an unmodelled one), to `<workRoot>/gh-state/calls.log`; both paths are written into the script text, and `readCalls()` returns the parsed lines. It finds its project by walking up from the realpath of its working directory to the nearest registered root, accepts `--repo <slug>` anywhere and ignores it, and answers exactly the shapes the Claude role host and `state-sync.cjs` make against the fixture project, each projected to the fields named by `--json`: `repo view --json defaultBranchRef --jq .defaultBranchRef.name` (the default branch name and a newline), `repo view --json owner,name` (an owner login and a name), `pr list [--head <branch>] --state open|closed|all --limit <n> --json <fields>` (the registered PRs whose state and head branch match; `closed` means `CLOSED` or `MERGED`), `pr view <n> --json <fields>`, `pr checks <n> --json <fields>` (`[]`, exit 0), `api repos/{owner}/{repo}/branches --paginate --jq .[].name` (the registered branch names, one per line), `api repos/{owner}/{repo}/compare/<a>...<b> --jq .ahead_by` (`0`) and `api repos/{owner}/{repo}/commits/<sha>/statuses` (`[]`). Every other invocation, any call from a directory under no registered project and any call that would write (`-f`, `-X`, a non-GET `api`) exits 2 with `fake gh: unmodelled call: <args>` on stderr; an unmodelled call is a finding against this fixture and is never answered by guessing. It makes no network call and reads only its registry.
  - `stageClaudeProject(fixture, name)` (`name` matches `^[a-z0-9-]+$`; a name already used in this fixture is refused) builds a project at `<workRoot>/projects/<name>` (a realpath) with its remote at `<workRoot>/origins/<name>.git`, registers it with the fake `gh` (installing it first when needed) and returns `{ root, origin, phase, phaseDir, ticket, branch, head, base, otherTicket, otherPhase, otherPhaseDir }`: `phase` is `99`, `phaseDir` `99-claude-fixture`, `ticket` `T-99-01-claude-fixture`, `branch` `ticket/t-99-01-claude-fixture`, `otherTicket` `T-98-01-codex-fixture`, `otherPhase` `98`, `otherPhaseDir` `98-codex-fixture`.
