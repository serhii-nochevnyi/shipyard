## Scope

Tests: `tests/unit/legacy-pin-readers.test.cjs` builds a project with adopted legacy history plus one authenticated record and, for each reader in the audit table, asserts that no legacy path or digest appears in its output or attestation input; where a reader cannot be driven in isolation, assert at the shared accessor and record why in the record. If the audit finds a reader that would treat a legacy member as authenticated, fix it in `codex-arch-review-context.cjs` with a test in `codex-arch-review-context.test.cjs` (those two files are declared only for that case). Measurements: run the baseline's `trustedBookkeepingMutation` (extracted copy, isolated HOME) against a catalogue adopted by the new code and record the outcome; then run the new code again. Record: the pid-reuse result from T-50-08, the schema marker from T-50-04, the run-store and lease ordering from T-50-09, the Claude measurement from T-50-23, the fresh-clone and linked-worktree results from T-50-24, the snapshot-staleness mechanism from T-50-12, and the UI smoke record from T-50-25 into the UI-smoke driver check section (`closed` when the driver check found a non-model driver and the scenario ran it, `limitation` when the check found none (`absent`), found no GSD install in the environment that produced the record (`not-installed`, the expected status in CI, quoting the candidate roots examined) or could not read the install (`unreadable`), quoting the `driver_check` evidence either way and naming the environment that produced the record). Release checklist (in the record): regenerate the package on the epic with `make package-shipyard-codex` before the epic to main PR; confirm `tests/unit/runtime-file-digests.json` is unchanged by this phase (no pinned file was edited) and run the digest-trailer check only if a pinned file changed; run `make test-live` from an installed bundle with no exported variables on both runtimes and attach the receipts; note that a Codex home without a Codex login is an assumption (A3) that no hermetic test can observe, because every scenario uses a fake codex, so the live receipt on the dogfood install is the only measurement and confirms or refutes it; and, if the UI smoke driver check was `unreadable` or `not-installed`, that assumption A7 also stays open until a release receipt on a machine that has the GSD install and can read it.
