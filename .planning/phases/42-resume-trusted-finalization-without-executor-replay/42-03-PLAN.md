## Goal

The phase-42 integration evidence (finding I1) shows that `planVerification` accepts only `node` or an absolute executable. That rejects 19 of 47 open tickets, all of which use bare `bash …` (32 `bash` and 17 `make` bullets repository-wide) with `VERIFICATION_SPEC_UNSUPPORTED`. The Codex executor path would refuse those tickets before launch.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/codex-delivery-host.cjs` `planVerification` (PLAN-derived argv, shell-syntax refusal, `node` → `process.execPath`).
- Phase 42 `INTEGRATION.md` finding I1.

## Scope

- Replace the single `node` special case with a host-owned allowlist:
  - `node` → `process.execPath`;
  - `bash` → the first existing of `/bin/bash`, `/usr/bin/bash`;
  - `make` → the first existing of `/usr/bin/make`, `/bin/make`.

  The allowlist is fixed in code and never taken from PLAN or request input. A missing executable refuses with a named remedy.
- Keep the shell-syntax refusal and the absolute-executable rule for every other program.
- Tests: `bash tests/smoke/x.sh`, `bash -n x.sh` and `make test-docs` resolve to absolute executables with unchanged argv; `sh`, `npm` and `bash -c …` (shell syntax) still refuse.
- Regenerate the `plugins/shipyard/` package mirror.

## Out of scope

Allowing arbitrary PATH lookup, shell interpretation, or changing the verification sandbox profile.
