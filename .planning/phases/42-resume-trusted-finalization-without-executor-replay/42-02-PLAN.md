## Goal

Phase-42 integration (outcome `needs-fix`, 2026-09-26) found one blocker. The finalization HMAC key must be inaccessible to model and verification processes. `codex-delivery-host.cjs` creates the key before the executor launches, but the Codex executor permission profile denies only the signer paths (`codex-runtime-host.cjs` `signerProtectionPaths` / `signerPermissionProfileArgs`). The executor can therefore read the key. Only the verification sandbox (`deniedPaths: [prepared.stateRoot, …]`) denies it.

## Context (Reads)

- `plugins/delivery-pipeline/scripts/codex-runtime-host.cjs` `signerProtectionPaths`, `signerPermissionProfileArgs`, `createCodexCliLauncher`.
- `plugins/delivery-pipeline/scripts/codex-delivery-host.cjs` `stateRootOutsideWorktree`, the key load before launch, and the runtime host construction.

## Scope

- The launcher accepts host-supplied additional protected paths. `codex-delivery-host.cjs` passes its resolved host state root, which holds the key, candidates, verification and finalization records. The executor permission profile then denies them together with the signer paths.
- The additional paths are host configuration only, never an executor request field, and are realpath-resolved like the signer paths.
- Tests: the generated profile args deny the state root, an executor request cannot add or remove protected paths, and the delivery host passes its state root to the launcher.
- Regenerate the `plugins/shipyard/` package mirror.

## Out of scope

Moving key creation, changing the HMAC scheme, or phase-40 provenance work.
