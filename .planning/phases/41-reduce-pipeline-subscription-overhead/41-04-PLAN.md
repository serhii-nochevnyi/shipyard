## Goal

REQ-154 separates completed code work from failed trusted finalization. The host persists an authenticated candidate before commit and can resume only that candidate after a signing, base-resolution or host error.

## Context (Reads)

- P41-D in `CONTEXT.md`; `41-RESEARCH.md:251-260` details the candidate, refusal and crash matrix.
- `plugins/delivery-pipeline/scripts/codex-delivery-host.cjs:138-251,309-331` owns executor preflight and the launch/finalize sequence; `dispatch-boundary.cjs:699-705` supplies `getVerifiedRecord`; `role-artifact.cjs:250-285` demonstrates receipt identity checks.
- `delivery-commit-finalizer.cjs:108-225` owns private-index tree creation, signer verification and commit compare-and-swap. `tests/unit/codex-delivery-host.test.cjs` and `delivery-commit-finalizer.test.cjs` already run hermetic Git fixtures.
- Phase 40 owns planning sealer, request construction and commit-message formatting. Recovery remains a separate host-only entry, not a new executor request form.

## Scope

- Accept a completed typed native child after all parent `wait_agent` calls returned timeout. In `codex-runtime-host.cjs`, parent spawn parsing validates every wait/output pair and boolean timeout status, without requiring the literal successful wait message. The launcher still must pass `readNativeCodexChild` / `parseNativeChildTranscript`: exactly one completion, exact parent/task/role/model/effort/instructions and stable transcript. A successful wait alone is never proof of execution. Preserve blocked handbacks and artifact containment checks. The local phase-41 bootstrap proves this observed race; it is not a shipped implementation.

- After `launchAgent` returns, require the original `getVerifiedRecord` receipt, nonempty scoped delta and stable graph. Before finalizer call, the trusted host writes a 0600 atomic candidate under its outside-worktree state root. Bind canonical repository/worktree, ticket/branch/allowed paths, run/dispatch/launch IDs, authenticated receipt digest, graph and source plan digest, policy hash/model/effort, signer, expected HEAD/base, exact scoped tree digest, and every known verification command/artifact/status/digest. Required pre-commit host checks must pass; downstream CI/review gates remain explicitly pending until their trusted results arrive and cannot be reported green.
- **Trusted verification producer (implemented in this ticket):** add host-only `collectVerificationEvidence(prepared, verificationSpec)` to `codex-delivery-host.cjs` after verified executor completion and before candidate admission. Before model launch, pin the approved source PLAN and its verification specification: exact executable/argv/cwd, time/output bounds and required pre-commit gate IDs. Never accept commands or success values from executor output. Missing/unsupported specifications refuse with a named remedy. Reuse `command-runner.cjs:runBounded` to observe actual process status, signal, error, timeout and bounded output, with no model replay. The trusted runner must enforce a process sandbox denying signing credentials and host evidence/key storage; extend the existing runtime permission-profile path protection for the outside-worktree host state root. If that protected runner is unavailable, refuse rather than execute with signing authority. Capture command/spec digest, run/dispatch, source plan/graph/policy, exact scoped tree before/after, status and bounded output digests. Nonzero, timeout, missing required check or changed scoped tree refuses finalization.
- **Authentication:** atomically persist versioned canonical verification records under protected host state and authenticate them with a separate host-owned HMAC key inaccessible to model and verification processes. Pin record digest in the candidate; resume verifies MAC, exact identity and every required result. Keys and runner callbacks are host configuration, never public executor request fields. Missing/corrupt records remain failed/pending; do not synthesize receipts. Original dispatch authentication still uses `getVerifiedRecord`. Downstream CI/review remains explicitly pending and gates merge, not initial commit. This scoped producer is delivered here, not assumed from phase 40.
- The finalizer exposes the exact tree it signs and compares it with the verified candidate; commit formatting stays in phase 40.
- Add host-only `resumeFinalization(candidateId, liveScope)` under the owner fence. Reload and authenticate the original durable receipt, compare every bound identity and verification item, then call the existing finalizer without `launchAgent`. On any changed identity, including base movement, refuse with named affected checks and leave candidate/gates visible. No partial revalidation path is authorized in this ticket.
- For crash after commit, recognize an already finalized candidate only if trusted finalization record, signed commit/signer, parent, tree, HEAD and scoped changed paths all match; return the same artifact. Otherwise refuse for reconciliation.

## Out of scope

Automatic executor replay, phase-40 input schema migration, general host provenance and commit-message formatting.

## Acceptance criteria

- A completed matching native child is accepted after timeout-only polling, while absent/incomplete/duplicate/mismatched native evidence still refuses. Regression coverage exercises the launcher, not just the parent parser.

- REQ-154/P41-D candidate survives each finalization failure, is authenticated against original durable dispatch and remains visible with failed/pending gates; downstream gate completion is never inferred from signed commit.
- The human checkpoint reviews the completed candidate and exact tree/gate binding before recovery is authorized. Changed identity has explicit refusal, and the T-39-16 scenario separates executor, finalizer and necessary revalidation usage.
