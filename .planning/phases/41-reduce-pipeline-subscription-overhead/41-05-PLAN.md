## Goal

REQ-155 stops a repository-wide fingerprint from rewriting unrelated GSD projections while preserving all legitimate aggregate invalidation.

## Context (Reads)

- P41-E in `CONTEXT.md`; `41-RESEARCH.md:261-274` gives the source-to-output dependency table.
- `plugins/delivery-pipeline/scripts/gsd-sync.cjs:1050-1127,1159-1231` builds one common source fingerprint, generated files and a read-only `--check`. Its renderers at `:625-999` show actual summary, phase and global inputs.
- `tests/unit/gsd-sync.test.cjs` and `gsd-sync-gate.test.cjs` cover generated snapshots and check mode. No new graph or state ledger is needed.

## Scope

- Derive each output fingerprint from the same canonical parsed values its renderer consumes, with existing normalization/hash and sync-version salt. Do not use a manual filename allowlist as a proxy for dependency extraction.
- Ticket SUMMARY inputs: own plan path/content/metadata, own stable delivery status/PR/merge facts and containing-phase identity. Phase UAT/VERIFICATION inputs: phase declaration, member plan/status entries, integration evidence and explicit membership/dependency edges. Include old and new phase aggregates when a plan moves.
- Global STATE inputs: all phase membership/evidence/status, PROJECT core, blockers, activity and stable controller/usage projection. Global REQUIREMENTS inputs: clean ROADMAP requirement text/mapping, PROJECT core and phase evidence. Generated ROADMAP block inputs: clean human ROADMAP, all phase names, plan totals and evidence/status; strip its own generated marker first.
- Keep snapshot construction under the existing publication lock, `--phase` global coherence and `--check` as a read-only byte comparison. Measure changed generated file count and diff bytes on local plan/status/edge fixtures; do not call diff bytes token savings.

## Out of scope

Editing generated ROADMAP/STATE/REQUIREMENTS files by hand or changing their semantic content beyond marker values.
