## Scope

- Add `phase-integrator-preflight.cjs` as a fail-closed, read-only CLI. Derive every phase-41 ticket from the canonical validated graph; verify the graph's phase plan set is complete. Do not accept a caller-supplied subset or an externally assembled ticket list.
- Resolve each ticket to exactly one graph-scoped PR identity, then verify it against live GitHub data: PR number, repository, head branch/head SHA, target epic branch, merged state/time and merge commit SHA. Missing, open, duplicate, stale or mismatched identities refuse with the ticket and a concrete remedy. Reuse the Claude host's moved-head/marker identity rule where applicable; do not broaden PR matching.
- Fetch and pin the canonical phase epic. Record the exact epic branch, commit and tree, plus graph identity. For every ticket's observed merge commit, run `git merge-base --is-ancestor <merge-commit> <pinned-epic-head>`; any failure or a moving epic head refuses before dispatch.
- Emit a bounded versioned JSON proof containing the full sorted ticket set in the existing role-artifact shape (`id`, `pr`, `head`, `base`, `branch`), each matching merge SHA and ancestry result, the ticket-set digest, graph identity, pinned epic head/tree and an overall proof digest. Keep this file as the trusted handoff to the standard integrator; do not put live PR payloads or unbounded command output into the prompt.
- Update the phase-finalization section of `deliver.md` so this CLI runs immediately before the integrator boundary for either runtime. Require the launch worktree and integrator source revision to equal the pinned epic commit, require the runtime's ticket set/digest to equal the proof, and refuse/re-run preflight if the epic moves. The integrator evidence records the proof digest and all per-ticket merge SHAs beside its receipt. The standard phase sealer alone writes `INTEGRATION.md`.
- Add deterministic contract tests with hermetic temporary Git repositories and stubbed GitHub responses. Cover complete proof, missing/open/duplicate/mismatched PRs, stale graph mapping, non-ancestor merge SHA, moved epic head, ticket-set digest mismatch and both runtime launch paths. No real GitHub call is made by unit tests.
- Preserve the high-risk human checkpoint: inspect the proof against the exact head and ticket-set file immediately before integration. An incomplete proof parks the phase without a model launch.

## Out of scope

Generating `INTEGRATION.md`, dispatching a second integrator, changing the final phase verdict schema, altering product requirements, or replacing the native Claude host checks.

## Acceptance criteria

- The preflight refuses before launch unless every canonical phase-41 graph ticket has exactly one matching live merged PR and its merge SHA is an ancestor of the pinned epic head.
- The preflight proof, runtime ticket-set file and integrator input all bind to the same ticket-set digest and exact epic commit/tree. A changed or incomplete set cannot proceed on either runtime.
- The proof records enough bounded evidence for the integrator and human gate to cite all current phase tickets and merge SHAs alongside the integrator receipt.
- T-41-07 never creates or seals `INTEGRATION.md`; the existing phase-level sealer remains the only integration author.

## Test strategy

Use hermetic Git fixtures and deterministic GitHub stubs for the CLI matrix. Contract tests verify the mandatory call is ordered before the integrator boundary on Claude and Codex paths. Live GitHub ancestry evidence is a manual release checkpoint, not a unit-test dependency.
