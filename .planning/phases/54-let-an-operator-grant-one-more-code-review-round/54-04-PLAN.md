<objective>Make the limit a function of the valid records and the authenticated history (ADR-035 R-4, R-15) in the one shared lookup created by T-54-02, with the hosts and the status passing the live base commit and a lazy record reader.</objective>

## Goal

ADR-035 R-4: "effective limit = `ROUND_CAP` + the number of valid records, clamped to a total of 5 rounds. A record counts while its head is the current head (unconsumed), or while its head is an ancestor of the current head and a countable verdict for that head sealed after the record exists (consumed). A record for another PR, base or unrelated head is void." No record can be written until T-54-07, and sealing round 4 or 5 is possible only after T-54-05, so this ticket changes no observable behaviour for any project until those land; its tests inject records through the store from T-54-03 and assert launch and status decisions only.

The lookup accepts any record that is valid by the R-4 rule. The write-time precondition that keeps a record from being consumed by an ordinary round (the live status is `limit` and the ceiling of 5 is not reached) belongs to `extend` in T-54-07, not to this lookup. It is a planner default (54-RESEARCH.md Open Question 4; ADR-035 R-1 and R-15 state no write-time precondition), which the operator confirms when approving the ticket set, not an already-confirmed decision. Because `status` returns `current` as soon as the head has a counted verdict and derives `limit` only afterwards, `limit` is reachable only at a head with no counted verdict, so an operator whose head was just reviewed in round 3 waits until the fixes are pushed (R-15). Reading the store only once the countable verdicts reach `ROUND_CAP`, as this ticket does, is a cost saving and is not that precondition.

## Scope

1. `code-review-core.cjs`: export `ROUND_CEILING = 5`; add and export the pure `extensionState({ records, countable, head, baseCommit, isAncestor })` returning the valid records by the R-4 rule; give `nextRound` an optional `options.limit` (default `ROUND_CAP`) replacing its fixed comparison, so every existing direct caller is unchanged; extend `roundLookup` to accept `baseCommit` and `readRecords` (a function). When the countable verdicts are fewer than `ROUND_CAP` it behaves as today with `limit: ROUND_CAP` and `extension: null` and never calls `readRecords`; otherwise it calls it, computes the valid records, sets `limit = min(ROUND_CEILING, ROUND_CAP + valid.length)`, delegates to `nextRound` with that limit, and returns `limit` and `extension`: the projection `{ operator, at, reason }` (with `at` taken from the record's `created_at`) of the valid record whose head is the current head, or null. This is already the shape the sealed verdict carries (T-54-08), so no later site re-maps it. Add and export `limitMessage(lookup)` returning the state-dependent sentence, the number word for the limit (three, four, five) followed by `rounds are spent; no further review can launch`.
2. The three call sites pass `baseCommit` and a `readRecords` thunk that lazily requires `./phase-code-review.cjs` and calls `readExtensions` with their identity values (roots: worktree and project root); they raise their existing limit refusals with `core.limitMessage(lookup)` and their existing codes, so the three distinct limit sentences collapse into one.
3. `status` adds `round_limit: lookup.limit` to its result beside the unchanged `round_cap`.
