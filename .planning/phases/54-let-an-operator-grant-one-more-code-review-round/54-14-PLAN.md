## Scope

Add tests, in `tests/unit/phase-code-review.test.cjs` only, with names starting `R-11` so the pattern selects them; remove the two interim cases they replace.

1. Sequence: seal three needs-fix rounds; push (head moves); status is `limit` with `round_limit` 3 and the refusal text names both exits; `extend` (operator from a temporary git identity) succeeds; status is `owed`, round 4, scope `delta`, `round_limit` 4; seal round 4 with the record's extension; status is `current` with `extension` equal to the record's values and `repair` `human`, and `fixTickets` returns `[]` and writes the existing diagnostic (as worded after T-54-12; these two assertions are moved here from T-54-06); push; status is `limit` (the record is consumed, `round_limit` 4, `rounds_used` 4); `extend` again; round 5 owed as a delta; seal it, after which status is `current` with `repair` `human` and `fixTickets` again returns `[]`; push; status is `limit` with `rounds_used` 5, `round_limit` 5; a third `extend` refuses at the ceiling and writes nothing.
2. Many fixes, one round: after round 3, three consecutive pushes before any record; one `extend` at the last head gives one round 4 whose `prior_head` is the round-3 head.
3. Voided records cost nothing: a record written at head H, then a push before any review: `limit` stays 3 and a fresh `extend` at the new head works and yields round 4; a base move after `extend` (the injected live PR reports another base commit) voids it; a record file written for PR 53 does not apply to PR 52.
4. Child refusal: the CLI `extend` run with `SHIPYARD_ROLE_CHILD=1` set explicitly in the spawned environment (the helper's clean copy plus the key) exits 1 with `EXTENSION_REFUSED` and a `hint[EXTENSION_REFUSED]` line, and the temporary state directory stays absent. It is the only case here that sets the marker, so it does not depend on the caller's environment, and any in-process variant restores the previous value in a `finally`.
5. Ceiling is final: with two valid records and five sealed rounds a hand-written third record leaves `round_limit` 5 and state `limit`.
6. Publication: for the sealed round-4 head, `publish` posts a status whose description contains `round 4 of 3, extended by` and a comment whose third line carries the extension line, directly under the `Code review — round N, scope S` line, as T-54-10 places it (the first three lines are the marker, the round line and the extension line); after round 5 and a push, `publish` posts the limit status only.
