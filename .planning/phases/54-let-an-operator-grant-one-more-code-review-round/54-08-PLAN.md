## Goal

ADR-035 R-7: "the sealed verdict, the `<!-- code-review -->` comment and the `code-review` commit status carry `round N of 3, extended by <operator> at <time>: <reason>` for an extended round." The sealed verdict has no such field today; 54-RESEARCH.md "Pattern 6" lays out the chain and recommends implementing the field (literal R-7) over deriving the line from the record at publish time, because a derived line can change or disappear after a base move. ## Scope

1. `code-review-core.cjs`: add and export one validator `validateReviewExtension(value, round)`: for a round at or below `ROUND_CAP` the value must be null or absent; above it, an object with exactly the keys `operator` (1 to 128 bytes), `at` (an ISO millisecond UTC string that parses) and `reason` (1 to 200 bytes), none containing control characters; failure is `fail('INVALID_RESULT', 'invalid review extension')`. `normalizeResult` takes `extension` in its options, calls the validator, and adds `review_extension` to its returned object only when non-null. `assemblePacket` adds `review_extension` to `role_context` from `round.extension` only when non-null.
2. `role-artifact.cjs`: `codeReviewManifestFields` appends `review_extension` only when non-null; `codeReviewResultData` calls the same validator against `result.review_extension` and `result.review_round`; the replay options at `:3046` pass `extension: context.review_extension ?? null`; `replayCodeReviewRecord` returns `review_extension` from the manifest and `currentCodeReviewVerdict` exposes it as `extension` (null when absent).
3. `artifact-fixture.cjs` (shared; behaviour for rounds 1 to 3 does not change): `input(binding, round, priorHead, rawResult, extension)` takes a fifth parameter. `undefined` means the fixture's own host-authored value, one constant `{ operator, at, reason }` defined once in the fixture, when `round` is above `core.ROUND_CAP`, and none otherwise; `null` means none; an object means that value. `input` passes it to `core.normalizeResult`, so the normalized result carries `review_extension` when it is non-null. `retainPlanningInput` takes the extension from `input.result.review_extension` unless `options.extension` is given (`null` allowed), passes it in the `round` object it hands to `core.assemblePacket` and in the `normalization` options it hands to `core.normalizeFinal`, so the packet's `role_context` and the sealed result carry the same value. The default above round 3 is what keeps every case that seals a round above 3 and was written before this ticket green without an edit; the refusal cases pass `null` or a bad value explicitly.
4. Tests: new cases in `tests/unit/code-review-core.test.cjs` (appended) and three new `test()` cases in `tests/unit/role-artifact.test.cjs`, registered in `d37Case` by these exact names: `code-review extended rounds seal with a host-authored extension and expose it on the current verdict` (the five-deep lineage whose rounds 4 and 5 carry two different extensions; it also asserts that rounds 1 to 3 of that lineage carry no `review_extension` key); `code-review seal refuses an extended round without an extension, an early round with one and a malformed one`; and `code-review replay stops authenticating when the sealed extension is altered in the archived manifest`.
