## Scope

In `phase-code-review.cjs` only, plus the new test file:

1. Split `publicationNamespace` into a pure `publicationLocation` (home realpath, normalized selector, hashed directory, the refusal of a directory inside the worktree or planning checkout; no file system writes) and the existing creating and validating wrapper that now calls it. The inputs are `{ repository, repo, pr, roots }`; `publicationNamespace(ctx)` builds them from its context. The extension file name is `<pr>.extensions.json` in the same directory.
2. Extract the open, lstat, uid, mode, size, `O_NOFOLLOW`, re-stat read loop of `readPublication` into one helper taking the file, the bound and a validator; `readPublication` becomes a call to it with its current key-set and identity check. Behaviour and messages of the publication path stay identical.
3. Export `readExtensions(input)`. Because its answer decides whether a round is granted, it first validates the ancestor chain from the home directory down to the namespace directory with `fs.lstatSync` only, using the pure location from item 1, and it applies the same per-segment predicate as `publicationNamespace`'s `validate` (`:318-333`, predicate at `:327-331`). That predicate is extracted by this ticket into one helper which the creating wrapper calls after its own `assertPublicationConfig` and `mkdir` (kept in their current order, which the invalidation tests at `phase-code-review-publish.test.cjs:721-846` pin) and which `readExtensions` calls with no `mkdir` and no config assertion. ENOENT at any step returns an empty array. It throws when an ancestor directory is a symlink or not a directory (case `ancestor-symlink`), has a foreign uid or is group- or world-writable, or when the namespace directory (`code-review-publications` or the hashed directory) has a mode other than 0700 (case `namespace-mode`). It then reads the file through the shared hardened reader (item 2), returns an empty array when the file is absent, never calls `mkdir`, and throws a clear error on an unsafe or invalid file. Export `appendExtension(input, record)`: validates the namespace through the creating wrapper, takes `withLock(directory, 'extend-' + pr, ..., { label: 'code review extension', waitMs: 10000 })`, re-reads, returns the existing record unchanged when one with the same head and base commit exists, refuses a seventeenth record, writes atomically, fsyncs file and directory, re-reads and compares.
4. Record format, strict key sets: file `{ schema, repository, selector, pr, records }`; record `{ head, base_commit, operator, created_at, reason }`. Validation on read: `head` and `base_commit` 40 hex; `operator` 1 to 128 bytes, no control characters; `created_at` matches an ISO millisecond UTC string and parses; `reason` 1 to 200 bytes, no control characters; at most 16 records; file at most 8192 bytes.

## Out of scope

The `extend` verb, identity lookup, reason sanitizing and hygiene (T-54-07); limit arithmetic (T-54-04); sealing; texts. `persistPublication` stays as written.

## Acceptance criteria

- With the home overridden, `appendExtension` creates `<home>/.local/state/shipyard/code-review-publications/<hash>/<pr>.extensions.json` with the directory at mode 0700 and the file at 0600, outside the worktree and planning checkout; `readExtensions` returns the stored records unchanged.
- `readExtensions` on a never-used PR returns `[]` and leaves no directory: `fs.existsSync(<home>/.local/state/shipyard/code-review-publications)` stays false.
- Each of these makes `readExtensions` throw: wrong schema, other repository, other selector, other PR, an extra key, a missing key, a record with a bad head, base, time or reason, a file over 8192 bytes, mode other than 0600, a symlink, a non-regular file, a foreign uid (where the test can set one), and JSON that is an array or scalar; the two namespace cases `namespace-mode` and `ancestor-symlink` follow in the next two bullets.
- `readExtensions` throws for `namespace-mode`: the `code-review-publications` directory, and separately the hashed directory, set to a mode other than 0700 (for example 0755 and 0770) after a valid write. It throws for `ancestor-symlink`: `.local/state` or `shipyard` replaced by a symlink to a real directory holding a valid store. In both cases the test asserts the tree on disk is exactly what the test built, so the rejection created nothing.
- `readExtensions` validates the ancestor chain with `lstat` only and creates no directory: a home with `.local` present but `.local/state/shipyard` absent returns `[]` and leaves `.local/state/shipyard` absent.
- A directory inside the worktree or planning checkout is refused.
- `appendExtension` twice with the same head and base stores one record; a seventeenth distinct record is refused.
- The publication tests that pin the record behaviour pass unedited: the mutation matrix, the cross-binding test, the publish-in-place test, and the invalidation pins at `tests/unit/phase-code-review-publish.test.cjs:721-846` (`config invalidation during the final live-head read`, `invalidation after status stops namespace initialization`, `invalidation after namespace validation prevents lock initialization` and `invalidation before ... stops later mutations`). The invalidation pins count `lstat` calls, so an extracted helper that adds or removes one `lstat` flips them; the filter token `invalidation` selects them (commands below).
- `node --check` passes.
