<objective>Wire the two hosts to the sealed field built in T-54-08 so an extended round is actually launchable and sealable end to end (ADR-035 R-7, with R-4 and R-5 already in place).</objective>

## Goal

After T-54-04 the hosts prepare a round-4 launch when a valid record exists, after T-54-05 the round can be sealed, and after T-54-08 the seal accepts and requires an extension for it. What is missing is the host passing the value: `core.assemblePacket` already receives the lookup result as `round`, so the packet carries `review_extension` once T-54-08 is in, but the final normalization in each host builds its own options object without it, so a round above 3 would fail at normalization.

The Codex host has no such refusal to mirror: `codex-code-review-context.cjs:431` destructures `host_context` out of the already-normalized result and silently drops it, and the check before normalization (`:424-426`) covers only the pinned identity keys and the ticket set. The Codex refusal is therefore new code, written with that file's `fail(message, code)` helper (`:26-28`), not an imitation of an existing line.
- Duplicate check: neither host references `extension` today (Grep baseline 0 in both files).

## Scope

1. In each host's final normalization call, add `extension: prepared.round.extension ?? null` to the options object. Do not read the value from `result`.
2. If a reviewer result contains its own `review_extension` key, refuse it with code `INVALID_RESULT` before the result reaches normalization, in both hosts. Claude: next to the existing `host_context` refusal at `claude-role-host.cjs:1200`, in the same style. Codex: a new explicit check placed after the ticket-set comparison and before the `core.normalizeFinal` call (`codex-code-review-context.cjs:424-427`), using `fail('code-review review_extension is reserved to the host', 'INVALID_RESULT')`; do not rely on the `host_context` destructuring at `:431`, which drops a key instead of refusing it, and do not add a second drop. Without the Codex check a reviewer-supplied value would survive the spread inside `normalizeFinal` whenever the host's own value is null.
3. Tests per host: with three sealed rounds and a valid record, the fourth launch prepares round 4 whose packet `role_context.review_extension` equals the record's operator, time and reason; completing it seals a round-4 verdict that authenticates and whose `currentCodeReviewVerdict(...).extension` equals the same values; a reviewer result that includes its own `review_extension` is refused; the same flow for a fifth round with a second record; and a three-round launch still carries no `review_extension` key.
