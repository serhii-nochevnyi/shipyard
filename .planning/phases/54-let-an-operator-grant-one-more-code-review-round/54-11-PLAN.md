## Goal

ADR-035 R-13: "the `limit` refusal of `phase-code-review.cjs`, `deliver-dispatch.cjs build arch-review` and the host messages gets a named hint (and `status` without `--phase` a usage hint) so `refusal-hints.cjs` no longer prints `hint[BUILD_REFUSED]: … a reason this map does not name`; the hint names the extend command and `report`." The incident session showed exactly that default text with no remedy.

## Scope

1. Three new entries in `HINTS`: `CODE_REVIEW_ROUND_LIMIT` (hint: the phase code review has used every round it may run for this PR; remedy: read the findings on the PR, then either run `node {bundle}/scripts/phase-code-review.cjs extend --phase N --pr P --reason "why" --confirm extend-review-round` to allow one more round bound to the current head, five rounds in total at most, or set `delivery_pipeline.code_review` to `report`, which applies to the whole project until it is set back to `hold`); `EXTENSION_REFUSED` (hint: the extension was not recorded; remedy: read the printed reason, which names the failed condition among the operator shell, the limit being reached and below five rounds, the fixes being pushed first (a head that already has a counted review is not at the limit), a delta being possible and a plain reason, fix it and re-run); `USAGE` (hint: the command line does not match the usage printed above; remedy: fix the arguments to match it and re-run).
2. `deliver-dispatch.cjs`: let `buildFail` take an optional hint code and put it in `error.details.hint_code`; when the arch-review gate refusal has `gate.state === 'limit'`, pass `CODE_REVIEW_ROUND_LIMIT`. `error.code` stays `BUILD_REFUSED` and `error.field` stays.
3. `phase-code-review.cjs`: `usage()` also sets `code: 'USAGE'`.
4. `extend` refusals from T-54-07 already use code `EXTENSION_REFUSED`; no change needed beyond the entry.

## Out of scope

Rewording the refusal sentence and the report wording (T-54-12), the `gate` verb's text (T-54-12), other builders' refusals, adding codes to `LAUNCH_CODES`.
