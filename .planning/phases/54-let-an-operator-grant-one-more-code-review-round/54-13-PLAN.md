## Scope

1. The `review_round` row says an integer 1 through 5, and a round above 3 is run only on a record an operator wrote; add a row for `review_extension`: present only for round 4 or 5, the operator, time and reason of that record, owned by the host, never repeated in the result.
2. Procedure item 1: remove the statement that no fourth review is owed; state that rounds 1 to 3 are owed by the host, a round 4 or 5 runs only on an operator record and is always a delta from the last counted review, repairs are allowed after rounds 1 and 2 only so a finding in round 4 or 5 goes to the human, and incomplete reviews still never consume a round.
3. The PR body carries a release-note paragraph (drafted here, edited by the operator): verdicts sealed before this release stop counting once because the reviewer reference changed, so the next review of an in-flight phase PR runs as round 1; a round above 3 now needs an operator record, up to five in total, each a delta without auto-repair; releases before this one cannot read a worktree holding a sealed round-4 or round-5 verdict (they throw `INVALID_RESULT` from the history read, see the S4 record), so such a project must not be downgraded.
