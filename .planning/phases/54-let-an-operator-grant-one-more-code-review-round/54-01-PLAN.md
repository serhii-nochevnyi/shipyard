## Scope

1. A test file `tests/unit/code-review-round-spikes.test.cjs` that builds scratch copies of `plugins/delivery-pipeline` and of `tests/fixtures/code-review` (plus whatever closure the fixture requires, found by running it) under the test's own temporary directory, patches them by exact-text replacement that asserts exactly one occurrence of each target, and drives real sealing through the fixture in child `node` processes with the clean environment. Variants: A, the unpatched copy; B, the ceiling of 5 at normalization and seal validation only; C, the ceiling at normalization, seal validation and the replay-depth bound. Each variant seals a carried needs-fix lineage round by round on the Claude runtime and on the Codex runtime (`retainPlanningInput(..., { runtime: 'codex' })`) and records, per round, the sealing outcome, the `priorCodeReviewVerdicts` authentication flags and the current verdict.
2. S4: seal four rounds under variant C, then read the same worktree and state home with the unpatched copy; record the `priorCodeReviewVerdicts` throw verbatim, and run the unpatched `phase-code-review.cjs status` CLI against it to record its exit status, stderr text and the printed hint.
3. The record `docs/audits/phase54/review-round-spikes.md`: baseline commit and Node version, the exact patch texts, the per-variant tables for both runtimes, the explanation of the seal-time lineage arithmetic (read the seal entry point's lineage argument; the research left this number resting on the probe), the S4 result at all three callers, the three baselines (`node tests/unit/role-artifact.test.cjs --code-review-d37-only`, `node --test tests/unit/claude-role-host.test.cjs`, `node --test tests/unit/deliver-dispatch.test.cjs`: pass counts and wall time each, run one at a time), and a "Findings carried forward" list: the ceiling lands at all three sites in one ticket (T-54-05), no guard can help the older reader so the release notes must say it (drafted in T-54-13's PR body), and the verdict-sealing fixture needs an extension input (T-54-08).

- The spike test passes in the clean environment and asserts, for each runtime: variant A seals rounds 1-3 and refuses round 4 with `INVALID_RESULT`; variant B seals and authenticates rounds 1-4 and refuses round 5 with a message containing `lack authenticated sealed source lineage`; variant C seals and authenticates rounds 1-5 and refuses round 6 with `INVALID_RESULT`.
- The S4 assertions pass: the unpatched copy throws `INVALID_RESULT` with `invalid code-review round, scope or prior_head` from `priorCodeReviewVerdicts` for a sealed round-4 verdict; the patched copy reads all four as authenticated.
- A mismatch with these expectations is recorded as a finding in the doc and the assertion is changed to the observed value; it is never hidden and never turned into a production change.
- The doc has the sections named in Scope item 3 and quotes real command output with the baseline commit hash.
- `git diff --name-only origin/epic/harness-simplification...HEAD` lists exactly the two declared files. Baseline at HEAD: 0 changed files.
- The test never reads or writes the real `~/.local/state/shipyard`: it overrides `os.homedir` and passes a temporary `HOME` to every child.
