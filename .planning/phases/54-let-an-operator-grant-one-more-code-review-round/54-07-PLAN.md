<objective>Give the operator the one command that writes the record, and make the command refuse a grant from a role-hosted child (ADR-035 R-1, R-2).</objective>

## Goal

ADR-035 R-1: "an operator command `phase-code-review.cjs extend --phase N --pr P --reason "…" --confirm extend-review-round` writes one record. One record grants exactly one extra round. There is no `--rounds` argument." R-2: the record is unsigned, a role-hosted child cannot grant itself an extension (existing sandbox plus a refusal under host-child markers), and the same-user orchestrating session acting on the operator's word is trusted exactly as for the existing `report` exit. The claim made is that, nothing stronger.

Planner decisions taken here (54-RESEARCH.md left them open): the marker is one Shipyard-owned variable, `SHIPYARD_ROLE_CHILD`, because the only existing marker, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`, is a Claude Code setting and Codex children carry none; the operator is recorded by name only (the git `user.name` of the worktree, falling back to the OS user), never an email, because the value is published; the `extend` write-time precondition is a planner default, not a decision the operator has already confirmed (ADR-035 R-1 and R-15 state no write-time precondition; 54-RESEARCH.md Open Question 4, assumption A4): `extend` writes only while the live status is `limit` and the ceiling of 5 is not reached, because a record written while rounds are still free would be consumed by an ordinary round and still add one round that nobody confirmed against the findings (R-4). `status` returns `current` as soon as the head has a counted verdict and derives `limit` only afterwards, so `limit` is reachable only at a head that has no counted verdict: an operator whose head was just reviewed in round 3 waits until the fixes are pushed, which matches R-15, and the refusal for state `current` says to push first. The operator confirms this default when approving the ticket set; the reason is plain text with `@`, `<`, `>`, backticks and control characters removed (research assumption A3, no repository policy exists).

## Scope

1. Both runtime hosts set `SHIPYARD_ROLE_CHILD` to `1` in the child environment: in `claudeEnvironment`, and on the Codex `env` object right after `launchEnvironment`.
2. `phase-code-review.cjs` exports `extend(input, options)` and the CLI gains the `extend` verb with no positional argument and the pairs `--reason` and `--confirm` (rejected for the other verbs); usage text is `phase-code-review.cjs extend --phase N --pr P --reason "..." --confirm extend-review-round [--repo owner/name] [--graph dir] [--worktree path]`; a wrong or missing `--confirm` is a usage error with exit 2 and compares against one literal constant.
3. Order inside `extend`, every step before any write: refuse when `process.env.SHIPYARD_ROLE_CHILD === '1'` with code `EXTENSION_REFUSED`; check `--confirm`; sanitize the reason (remove control characters, `@`, `<`, `>` and backticks, collapse whitespace, trim; refuse when empty or over 200 bytes) and the operator name (same cleaning, at most 128 bytes); scan the composed line `round N of 3, extended by <operator> at <time>: <reason>` with `internalLeakViolations` under both the `comment` and `status` contexts when `applies` says so, refusing with the rule names; call `status` for the live context and keep its history; if a record for the same head and base commit already exists, print it and exit 0 without writing; refuse unless the live status is `limit` and the effective limit (`round_limit`) is below `ROUND_CEILING`, as the planner-default precondition stated in Goal (state `current` is refused with a message that the head already has a counted review and the fixes must be pushed first, per R-15; state `owed` is refused as no review limit having been reached; a ceiling refusal states that the human decides from the findings on the PR, or sets `delivery_pipeline.code_review` to `report`, which applies to the whole project until it is set back to `hold`; it uses the exact words `whole project`, and because it is a text that offers `report` it is one more site in T-54-12's sweep); probe with `core.roundLookup` plus a probe record for the live head and base and refuse with the lookup's reason when it is not `ready` (never writing a record that cannot be used); then `appendExtension` with `created_at` from `new Date().toISOString()`. Print a JSON object with `pr`, `head`, `base_commit`, `round`, `limit`, `operator`, `created_at` and `recorded` (`created` or `existing`).
4. `status` keeps its history in its `details` entry so `extend` reuses it instead of rebuilding it.
5. Marker-free test environment, in `tests/unit/phase-code-review.test.cjs` only: `delete process.env.SHIPYARD_ROLE_CHILD` once, right after the `os.homedir` override at `:9-12` and before any fixture is built, so every in-process `extend` call and every spawned environment built from `process.env` starts without the marker; one local helper that returns a copy of an environment object without the key, used by every spawn that must reach a successful `extend` (the existing spawn sites need no edit, because the file-level delete already precedes them); the dedicated refusal cases are the only places that set the marker, through the same file, and restore it in a `finally`. One new case, named so the pattern `extend` selects it, asserts the file starts with the key absent and that the helper drops it from an object that carries it.
