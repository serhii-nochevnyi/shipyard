<objective>Close the two ways an extended round could be wrong: a full review instead of a delta, and a round with no record at the current head (ADR-035 R-6, R-4).</objective>

## Goal

ADR-035 R-6: "Extended round: always a `delta` from the last counted verdict. If the coverage chain does not allow a delta the extension refuses and never falls back to a full review. `repairAllowed` stays true only for rounds 1 and 2; a finding in an extended round goes to the human." `nextRound` already computes the delta condition (`inherit`, `code-review-core.cjs:341-345`) and returns `scope: 'full'` when it is false; for rounds beyond the cap that fallback must become a refusal. `repairAllowed` needs no code change, only tests for rounds 4 and 5.

## Scope

In `code-review-core.cjs` `roundLookup`: when the countable verdicts reach `ROUND_CAP` and are below the effective limit, the round is owed only if `extension` (the valid record bound to the current head) is non-null and the delegated `nextRound` result has `scope: 'delta'`; otherwise return `{ round: null, state: 'limit', rounds_used, limit, extension, reason }` with `reason` equal to `no-record` or `no-delta`. The rounds-spent case carries `reason: 'spent'`. Extend `limitMessage` to a sentence per reason: `spent` keeps the existing wording; `no-delta` says the extended round must be a delta from the last counted review, the coverage chain does not allow one, and no full review will run; `no-record` says no extension record bound to this head exists. Tests: `repairAllowed` over rounds 1 to 5 in core, and one status case that an owed extended round is a delta. No test in this ticket seals a round above 3.

## Out of scope

Writing records and the `extend` verb (T-54-07), sealing the extension (T-54-08), texts on the PR (T-54-10), hints (T-54-11). ## Acceptance criteria

- Core: with a valid current-head record and a broken coverage chain (for example `answer_authenticated: false` on the latest verdict, or a `mergeBase` for which `coverageComplete` is false) the lookup is `limit` with `reason: 'no-delta'` and `scope` is never `full`; with an intact chain it is `ready`, `scope: 'delta'`, `round: 4`.
- Core: a lookup whose records give `limit` 5 but none bound to the current head is `limit` with `reason: 'no-record'`.
- Core: `[1, 2, 3, 4, 5].map(core.repairAllowed)` equals `[true, true, false, false, false]`.
- Rounds 1 to 3 are unchanged: the existing core table and `phase-code-review.test.cjs` D37 loop pass unedited.
- Status: after three sealed needs-fix rounds, a new head and a record written for that head, the status is `owed`, round 4, `scope: 'delta'`, `round_limit` 4. The case stops at the owed status; no test in this ticket seals a round above 3.
