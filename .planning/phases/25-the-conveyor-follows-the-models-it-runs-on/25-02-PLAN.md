## Goal

Every Codex agent carries the model the depth of its role needs, chosen from a
palette the operator declares rather than from GSD's default tier map, plus the
effort that depth is expressed at. The four roles that escalate get a second
agent file at the palette's deepest entry, because on Codex an agent is a FILE
and a signal cannot reach one that does not exist.

*(Re-planned 2026-09-07 from ADR-005 D6–D9, before any code was built. The
first version of this ticket said to write NO model at all and let the
operator's `config.toml` default apply. That was correct only while effort
could carry the whole depth range; the operator's palette caps `gpt-6-astra` at
`high` effort, so depth above that has to come from the model again.)*

## Scope

- **The palette, in `pipeline-config.cjs` and declared in `capability.json`.**
  `codex_models` is an ORDERED list of `{ model, effort }` — the effort to USE,
  never the deepest the model accepts — shipped with the operator's palette as
  the default: `[{gpt-5.6-terra, high}, {gpt-6-astra, high}]`, with
  `gpt-5.6-sol` listed and unselected because `max`/`xhigh`/`ultra` are retired
  (ADR-005 D2) and advertising `ultra` was sol's only distinguishing property. A
  reader that finds the key absent falls back to that default; a malformed entry
  warns and is skipped, and an empty palette means "write no model", which is
  the previous behaviour and a safe floor. `ultra` is NOT added to `EFFORTS`.
  The `max` → `xhigh` clamp for `runtime: codex` is deleted (ADR-005
  D7: both halves of its comment are false — GSD's
  `codexModelEffort._baseline` advertises `max` for every model, and
  `advertisedCodexEffort` returns that baseline for a model it does not name,
  which is what `gpt-6-astra` is). `minimal` → `low` stays.
- **`codexModelFor(role)` → `{ model, effort }`, mirroring the Claude ladder.**
  The effort comes from `resolveEffort`: `low` for the one mechanical role,
  `high` for every other. The model is the palette's FIRST entry (terra, the
  workhorse floor) for every role except the integrator, which takes the LAST
  entry (astra, the ceiling) unconditionally — exactly as `integrator` takes
  `fable` on the other runtime. Nothing else reaches the ceiling statically;
  the `-deep` variants below are how a signal reaches it. A GSD remap key (`model_policy.runtime_tiers.codex.<tier>`,
  `model_profile_overrides.codex.<tier>`) still WINS over the palette, resolved
  through GSD's own resolver rather than by reading `runtimeTierDefaults`
  directly — the claim `CLAUDE.md` already makes and the generator never
  honoured (audit F23).
- **Eleven agents, not seven (ADR-005 D8).** The generator writes a second file
  for the four roles that escalate — `shipyard-ci-fix-deep`,
  `shipyard-review-fix-deep`, `shipyard-pr-sentinel-deep`,
  `shipyard-arch-review-deep` — each carrying the palette's CEILING entry at its
  own effort (astra/high). The integrator gets no variant: one call per phase,
  already at the ceiling. A `-deep` file is written only when the palette has a
  ceiling entry distinct from the floor, so a single-entry palette produces
  seven agents and no dead files.
- **The prose that makes them reachable.** `deliver.md` and `pr-sentinel.md`
  name the `-deep` agents and when to invoke them: `repeat_exhausted` for a
  repair role, a journalled prior `arch_review … verdict=violation` for the
  judge. Both files are the Codex skill's SOURCE, so the generated
  `~/.agents/skills/shipyard-*/SKILL.md` carries it; without this the variants
  exist and nothing calls them. Keep the sentences free of the word "Claude" in
  any runtime-contrasting sense — the generator substitutes it (`CLAUDE.md`,
  "The Codex generator rewrites the word Claude in prose").
- `CLAUDE.md` and `README.md`: replace the baking paragraph with the palette,
  the selection rule, the eleven agents, and the fact that a remap now wins.

## Acceptance criteria

- With the default palette and no remap, the generated files carry exactly:
  drift-check terra/low, and research, ci-fix, review-fix, pr-sentinel,
  executor and arch-review all terra/high, and integrator astra/high. Today all
  seven carry `gpt-5.6-terra` with efforts from the old five-rung table, so the
  test fails on current code.
- The four `-deep` files exist and carry astra/high;
  `shipyard-integrator-deep` does NOT exist.
- A palette of one entry (`[{gpt-5.6-terra, high}]`) produces seven agents and
  no `-deep` file, and the integrator falls back to that entry.
- No generated file carries `xhigh`, `max` or `ultra`.
- `model_policy.runtime_tiers.codex.sonnet = "x-model"` in the fixture defaults
  wins over the palette for the roles that resolve to that tier.
- `resolveEffort` with `runtime: codex` returns `max` for an explicitly
  configured effort of `max`; today it returns `xhigh`, so this fails on current
  code. `minimal` still returns `low`. No built-in path asks for either.
- No model id appears in `scripts/`, `plugins/` or the docs outside the palette
  default and the comments that quote a measurement.
- `deliver.md` and `pr-sentinel.md` each name all four `-deep` agents and the
  verdict that selects them; the generated Codex skill contains them too
  (assert against the throwaway HOME the smoke builds).
- `make test-codex-shipyard` passes.

## Test strategy

Unit-test `codexModelFor` against a fixture HOME; keep the smoke as the
