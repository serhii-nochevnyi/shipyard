## Goal

`gen-codex-shipyard.cjs` stops baking a model id from GSD's catalog into the
seven `~/.codex/agents/shipyard-*.toml` files. Each agent keeps its
`model_reasoning_effort`; a `model =` line is written only when the user's GSD
remap names a model for that tier, resolved through GSD's own resolver. With
no remap, the agent runs at the Codex CLI's configured default — today
`gpt-6-astra` on this host — exactly as GSD's own Codex agents do.

## Context (Reads)

- ADR-003 D2; `CLAUDE.md` "Models are TWO layers" and "`fable` is
  Claude-only" — the paragraph that argues FOR baking ("Without that, all
  seven Codex agents ran at the CLI default and arch-review was the same model
  as drift-check") must be rewritten by this ticket, because its premise is
  gone: `pipeline-config.cjs capForRuntime` (~line 386) caps every role to the
  workhorse tier on Codex, so all seven agents already get the SAME model and
  differ only by effort. Measured 2026-09-07 in `~/.codex/agents/`: seven
  files, seven `model = "gpt-5.6-terra"`, efforts low/high/xhigh.
- `scripts/gen-codex-shipyard.cjs codexModelFor` (~95–125): resolves the tier
  through `pipeline-config.cjs` with `runtime: codex` forced, then reads
  `catalog.runtimeTierDefaults.codex[tier].model` DIRECTLY from
  `~/.codex/gsd-core/bin/shared/model-catalog.json`. It never consults GSD's
  remap keys (`model_policy.runtime_tiers.codex.<tier>`,
  `model_profile_overrides.codex.<tier>`) — the audit (F23) confirmed a custom
  sonnet remap did not change the generated files, though `CLAUDE.md` says a
  remap "takes effect".
- GSD 1.13 `model-resolver.cjs` (in `~/.codex/gsd-core/bin/lib/` after the
  installer runs) is the resolver to call; its `resolve_model_ids: "omit"`
  posture is why GSD's own `gsd-*.toml` carry no `model` key. `deliver.md`
  (~line 344) already states ours carry none — code and prose disagree; make
  the code match the prose (deliver.md itself is T-24-07's / T-25-03's file and
  is NOT edited here).
- The user's Codex default lives in `~/.codex/config.toml` (`model =
  "gpt-6-astra"` here). Never read it into a generated file — a baked copy is
  the defect in a new coat. Do not hardcode any model id in shipyard.
- Effort: Astra supports low…max (no `ultra`); `resolveEffort` clamps `max` →
  `xhigh` on Codex — keep the clamp.
- `tests/smoke/codex-shipyard-smoke.sh` (~91–99) asserts the resolver emits
  tier aliases; grep it for `model =` assertions before editing — the T-24-02
  trap. A NEW unit test `tests/unit/gen-codex-shipyard.test.cjs` drives
  `codexModelFor` with a fixture HOME (a fake `gsd-core` with a resolver stub)
  so the rule is tested without network.

## Scope

- `codexModelFor` → `{ model: <string|null>, effort }` where `model` is
  non-null ONLY if GSD's resolver, given the forced codex runtime and the
  user's effective config (`~/.gsd/defaults.json` + project), returns a
  concrete model from a REMAP key; the catalog default is never emitted. Say
  why in the comment (the capped ladder makes the catalog default identical
  for every role).
- The TOML writer emits `model_reasoning_effort` always, `model` only when
  non-null.
- `CLAUDE.md`: rewrite the baking paragraph and the remap claim to describe
  this behaviour; `README.md`: the Codex section's sentence about baked models.
- Unit test: (a) no remap → no `model` line, effort present; (b) remap for the
  workhorse tier → that model; (c) `fable` degrades to the capped tier and
  still emits no model; (d) `make install-shipyard-codex` output has no
  `gpt-5.6` string (the smoke, against a throwaway HOME).

## Acceptance criteria

  smoke assertion fails on current code.
- With `model_policy.runtime_tiers.codex.sonnet = "x-model"` in the fixture
  defaults, the workhorse-tier agents carry `model = "x-model"`.
- `grep -rn "gpt-" scripts/ plugins/ README.md CLAUDE.md` finds no model id
  outside a comment that quotes a measurement.
- `make test-codex-shipyard` passes.
