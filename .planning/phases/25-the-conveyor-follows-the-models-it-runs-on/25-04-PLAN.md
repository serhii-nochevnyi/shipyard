## Goal

No role is dispatched below `opus`. Depth is expressed by EFFORT, keyed on the
role and its signals rather than on the tier. `fable` is a ceiling the conveyor
reaches by itself through three mechanical routes and never by default, except
for the integrator; and it is never emitted where it would resolve to Fable 5.

## Context (Reads)

- ADR-005 (this ticket's ADR) and the user's decision of 2026-09-07: never drop
  to `sonnet`, play depth with effort, use Fable 5.1 and not Fable 5, and let
  the conveyor rise to `fable` on its own when it needs to.
- **The tier→effort dependency must invert.** `resolveEffort` derives the effort
  tier from the MODEL: `MECHANICAL_ROLES → light`, else
  `(JUDGMENT_ROLES || TOP_TIERS.has(model) || escalated) → heavy`, else
  `model === 'haiku' → light`, else `standard`. With the floor at `opus`,
  `TOP_TIERS.has(model)` is true for every role, so everything collapses to
  `xhigh` and the axis the policy now rests on stops discriminating. Measured
  2026-09-07 with the floor set through `pipeline.models.*`: every role except
  `drift-check` resolved to `opus`/`xhigh`, and — the load-bearing consequence —
  **`--signature-state repeat` stopped deepening anything**, because `xhigh` was
  already the value. Only `strategy: rethink` survived. The repair ladder's
  depth rung is gone until this ticket restores it at `max`.
- **`cfg.effort[role]` is an override that wins over the repeat rule** (it is
  read before the signature check), so the effort table CANNOT be delivered as
  configuration without disabling the escalation it exists to enable. That is
  why the table belongs in code. The two keys set in `.planning/config.json`
  today (`effort.arch-review`, `effort.integrator`) are safe only because
  neither is in `REPAIR_ROLES`; this ticket replaces them with defaults and the
  project config should then drop them.
- **`cfg.models[role]` short-circuits `ladderTier` before any escalation.** The
  floor is currently expressed that way, which means an escalation to `fable`
  could never fire while the config is in force. The floor must move into the
  code so the escalation sits ABOVE it.
- Measured inputs on this repository, 2026-09-07 — the reason a
  window-pressure route alone would never fire here: the ADR corpus is 30 KB
  (~8k tokens), the largest ticket PR diff of the phase was 63 KB (~16k), and
  the phase-24 epic diff, which is the integrator's input and the largest in the
  system, is 210 KB (~52k). Opus 5's ordinary window swallows all of it.
- **The Agent tool takes no `effort` parameter at all** (verified against the
  live schema, CLI 2.1.263): only Workflow's `agent()` carries it. So effort is
  enforced on the Workflow path — executors, drift judges, fix rounds — and is a
  sentence in the prompt for an Agent-spawned background guard. Say so where the
  policy is documented; a reader who thinks effort is enforced everywhere will
  mis-read the guard's behaviour.
- `failure-signature.cjs computeVerdict` already returns `seen` — how many times
  this signature has been journalled — beside the verdict. That is the counter
  route R2 needs, with no new event and no new field on `attempt`.
- The `arch_review` journal event R3 reads is added by **T-24-06**, which is an
  ancestor of this ticket through T-24-07. Read it; do not add it here.
- `gsd-tune.cjs` runs at Step 0 of every delivery and already reports drift
  between what a project sets and what the runtime supports. That makes it the
  home for the Fable 5.1 floor check, not `state-sync.cjs` (owned by phase 26).
- Version floors, from the Claude Code model docs (read 2026-09-07): Opus 5
  needs CLI 2.1.219, Fable 5.1 needs 2.1.255. Below 2.1.255 the `fable` alias
  resolves to Fable 5, which the user has ruled out. `ANTHROPIC_DEFAULT_FABLE_MODEL`
  can also repoint the alias; name it as the second way the floor can be missed.

## Scope

- **Floor.** `ladderTier` returns `opus` wherever it returns `sonnet` or `haiku`
  today. `TIERS` keeps all four values (a user override may still name any), but
  no built-in path resolves below `opus`. `capForRuntime` is unchanged: Codex
  still caps a top tier to its workhorse, and after T-25-02 no model id is baked
  there anyway.
- **Depth.** A new role-keyed effort table, consulted after the override and
  after the signature rule:

  | role | effort |
  |---|---|
  | drift-check | low |
  | research | high |
  | executor, risk low and files ≤ 2 | high |
  | executor, other medium | xhigh |
  | executor, risk high or checkpoint | max |
  | ci-fix, review-fix, pr-sentinel | high; xhigh at risk high |
  | arch-review, integrator | max |

  `signature-state repeat` now raises the repair roles to `max` (it raised them
  to `xhigh`, which is no longer a raise).
- **Ceiling, three routes, each mechanical.** `fable` is returned when
  `pipeline.fable` is `auto` AND any of:
  - **R1 window.** `--input-tokens <n>` exceeds `pipeline.fable_window_tokens`
    (default 250000, five times this repository's largest measured input). The
    caller measures; the resolver decides.
  - **R2 exhausted depth.** A repair role whose verdict is `repeat` and whose
    `seen` is ≥ 3 — the same failure a third time, after a `rethink` at `max`
    already failed. Delivered as a new `SIGNATURE_STATES` value from
    `failure-signature.cjs computeVerdict`, `repeat_exhausted`, so the journal
    remains the single source and the resolver stays a pure function.
  - **R3 contested judgment.** `--contested`, passed when the journal already
    holds an `arch_review … verdict=violation` for this ticket, or when the
    integrator has returned `needs-fix` on this epic before.
  - **The integrator is the one standing exception**: `fable` unconditionally.
    It reads the largest input in the system, runs once per phase, and is the
    last mechanical judgment before a person merges to the default branch.
- **The Codex half is T-25-02's**, an ancestor of this ticket: the palette, the
  selection rule, the `max` clamp's deletion and `ultra`'s admission all land
  there (ADR-005 D6–D8), because they are the same change as writing the model.
  What stays here is the effort table those selections read, and the floor
  check: extend `gsd-tune`'s check to the Codex mirror — first-class
  `gpt-6-astra` configuration needs CLI 0.153.1, so a project whose
  `~/.codex/config.toml` names Astra on an older CLI is REQUIRED drift, with
  the version named.
- **Fable 5.1 or nothing.** `pipeline.fable` (`off` default | `auto`) declared in
  `capability.json`; `off` means every route above degrades to `opus`/`max` with
  the reason printed. `gsd-tune.cjs` reports it as REQUIRED drift when a project
  sets `auto` while `claude --version` is below 2.1.255, naming both the floor
  and `ANTHROPIC_DEFAULT_FABLE_MODEL`. The default is `off` because an
  unconsented Fable request in a background session waits `dialogExpiry` and
  then ends the turn without sending: silence is not consent, exactly as
  decomposition treats pre-authorization.
- Documentation: `deliver.md`'s ladder table, `CLAUDE.md`'s "Models are TWO
  layers" paragraph and `README.md`'s model section state the floor, the effort
  table, the three routes, the integrator exception, the Fable 5.1 floor, and
  the fact that effort is only enforced on the Workflow path.

## Acceptance criteria

- No built-in resolution returns `sonnet` or `haiku`: assert every role at every
  risk, with and without signals, is `opus` or `fable`. Today `drift-check`,
  `research`, `ci-fix`/`pr-sentinel` at low and medium risk, and the executor's
  light path all return `sonnet` — the test fails on current code.
- The effort table holds for every row above, and `repeat` on a repair role
  returns `max` where it returns `xhigh` today.
- R1: `model arch-review --input-tokens 300000` with `pipeline.fable: auto`
  returns `fable`; at 200000 it returns `opus`/`max`; with `pipeline.fable`
  absent or `off`, both return `opus`/`max` and the reason names the setting.
- R2: `computeVerdict` returns `repeat_exhausted` on a third occurrence of one
  signature with no green between, and `model ci-fix --signature-state
  repeat_exhausted` returns `fable` under `auto`. A second occurrence still
  returns `repeat`.
- R3: `model arch-review --contested` returns `fable` under `auto`.
- `model integrator` returns `fable` regardless of every flag, and `opus`/`max`
  when `pipeline.fable` is not `auto`.
- `gsd-tune.cjs` on a fixture project with `pipeline.fable: auto` and a stubbed
  `claude --version` of 2.1.240 exits 1 and names 2.1.255; at 2.1.263 it is
  silent. A project without the key is silent at any version.
- `gsd-tune.cjs` with a stubbed `codex --version` of 0.147.0 and a
  `config.toml` naming `gpt-6-astra` exits 1 and names 0.153.1; at 0.153.4 it
  is silent, and it is silent when the config names no Astra.
- `make test-docs` passes; `deliver.md` contains the new table and the sentence
  that the Agent tool carries no effort parameter.
