## Goal

The container and the smokes run the runtimes the conveyor is actually used
with: Claude Code ≥ 2.1.255 (so `opus` is Opus 5 and `fable` is Fable 5.1
inside the image, as on the host) and gsd-core 1.13.0 (the version installed on
this host's plugin side and the latest on npm).

## Context (Reads)

- ADR-003 D1. `CLAUDE.md` "Build & run" and "Conventions": versions are
  Dockerfile `ARG`s surfaced as Makefile variables; never an unpinned `latest`.
- Current pins: `Dockerfile.base:33` and `Makefile:9` `CLAUDE_CODE_VERSION
  2.1.200`; `Dockerfile:5` and `Makefile:5` `GSD_CORE_VERSION 1.7.0`;
  `tests/smoke/codex-shipyard-smoke.sh:23` `GSD_CORE_VERSION 1.9.1`. npm on
  2026-09-07: `@anthropic-ai/claude-code` 2.1.263, `@opengsd/gsd-core` 1.13.0.
- Version floors from the Claude Code model docs (read 2026-09-07): Opus 5
  needs 2.1.219, Sonnet 5 2.1.197, Fable 5.1 2.1.255. Below 2.1.219 the
  container's `opus` is Opus 4.8 while the host's is Opus 5 — the same tier
  alias meaning two different models depending on where the conveyor runs.
- gsd-core 1.12 → 1.13: the model catalog for claude/codex is byte-identical,
  the alias set is unchanged, and none of the config keys the conveyor reads
  (`runtime`, `git.*`, `workflow.use_worktrees`, `agent_skills`,
  `model_overrides`, `models`, `effort`) changed meaning. What did arrive:
  `dispatch.maxConcurrency`, `hooks.commit_types`, a `gate-status:` COMMIT
  trailer for GSD's TDD audit (see T-25-03). Nothing to adapt, everything to
  re-verify: the codex smoke installs the pinned version into a throwaway HOME
  and asserts against THAT converter, so the pin bump is the test.
- `tests/smoke/base-image-smoke.sh:16` reads the Claude pin from the Makefile;
  `docs-smoke.sh` checks README phrases against the Makefile. Bumping the pins
  without those two staying green is the failure mode.
- The Dockerfile sets `SHIPYARD_GSD_AUTO_INSTALL=0` so the pinned gsd-core is
  not overridden by the installer's `latest` — keep it.
- **Nobody mechanical verifies an image pin** — `make test-fast` never builds
  an image; `test-base`/`test-overlay` are run by a person with Docker. That is
  why this ticket carries a checkpoint: the reviewer runs `make build-base
  build-dev-image test-base test-overlay` once before merging.

## Scope

- `CLAUDE_CODE_VERSION` → `2.1.263` (Dockerfile.base ARG + Makefile default).
- `GSD_CORE_VERSION` → `1.13.0` (Dockerfile ARG + Makefile default + the codex
  smoke's default).
- `README.md` is NOT in this ticket (phase 24's T-24-07 owns it until that
  epic lands): its two `gsd-core@1.7.0` mentions (~lines 237, 368) and the
  Claude Code floor sentence are T-25-03's. `docs-smoke.sh` checks no version
  strings, so the pins and the README may land in that order.
- `base-image-smoke.sh`: keep reading the pin from the Makefile; add an
  assertion that the installed `claude --version` is ≥ 2.1.255 (a floor, not
  only equality, so the next bump does not need to touch the smoke).

## Out of scope

Codex CLI version on the host (not in the image, the user's). The generator
(T-25-02). Any behaviour change in scripts.

## Acceptance criteria

- `grep -n "CLAUDE_CODE_VERSION" Dockerfile.base Makefile` shows `2.1.263` in
  both; `grep -n "GSD_CORE_VERSION" Dockerfile Makefile tests/smoke/codex-shipyard-smoke.sh`
  shows `1.13.0` in all three.
- `make test-docs` still passes (README untouched here); `make test-codex-shipyard` passes against 1.13.0
  (network — run once locally, quote the tail in the PR body).
- Checkpoint reviewer's evidence in the PR: `make build-base build-dev-image
  test-base test-overlay` green, plus `docker run … claude --version` output.

## Test strategy

Pins have no unit test; the smokes are the test. `make test-docs` and
`make test-codex-shipyard` are runnable without Docker (the second needs
network). The image builds are the human checkpoint's evidence.

## Verification commands

- `grep -n "CLAUDE_CODE_VERSION ?= 2.1.263" Makefile`
- `grep -n "GSD_CORE_VERSION ?= 1.13.0" Makefile`
- `grep -n "GSD_CORE_VERSION:-1.13.0" tests/smoke/codex-shipyard-smoke.sh`
- `make test-docs`
- `bash -n tests/smoke/base-image-smoke.sh tests/smoke/codex-shipyard-smoke.sh`
