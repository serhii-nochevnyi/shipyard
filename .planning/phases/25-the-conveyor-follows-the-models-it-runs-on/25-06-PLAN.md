## Goal

The three facts this phase changed — the ladder, the `research` row, and the
gsd-core pin — read the same in every place they are written, and a grep
contract makes the pin's homes agree from now on.

## Context (Reads)

- **The integrator's `needs-fix` on PR #40 (2026-09-08)**, which is this
  ticket's whole origin. Every ticket of phase 25 was `conform` on its own diff;
  the integrator's subject is the seams, and it found three artifacts still
  stating what the phase replaced. Each was missed the same way: **one ticket
  owned the RULE and a different ticket owned the FILE**, and neither's
  `files_modified` contained the other's.
- ADR-005 as amended 2026-09-08 — D1 (the floor with two named `sonnet`
  exemptions), D2 (the effort table), D4 (the integrator's withdrawn `fable`
  exception). ADR-003 D1 for the gsd-core pin.
- `tests/smoke/docs-smoke.sh` is the grep contract on `README.md`,
  `.env.example`, `docker-compose.yml`, `Makefile` and `k8s/`. It covers
  `README.md` only for prose, which is exactly why F1 and F2 below survived
  three reviews.
- **Do not re-litigate the decisions.** The code is correct and was verified by
  running: the integrator re-derived the whole ladder on the epic head and it
  matches D1/D2/D4 row for row, `haiku` is returned by nothing, and
  `runtime: codex` changed in exactly one way (the judges' effort flattening
  D6 mandates). This ticket changes documents and one default, nothing else.

## Scope

- **F1 — `docs/gsd_multilevel_delivery_pipeline.md` §7.5 (lines ~645-657) still
  grants `fable` to the judges.** Three claims to correct: the headline
  "Judgment → the top tier, and the 1M-window one wherever the runtime has it";
  the row `fable  integrator, arch-review`; and the row
  `sonnet  drift-check, research:system-state/…`. The first two are retired by
  D1 and D4 — `fable` is earned through D4's three routes and the integrator has
  no standing exception. The third is now wrong in one half and right in the
  other for a NEW reason: `research` is `opus`/`high` (`xhigh` for
  `--type alternatives`), while `drift-check` really is `sonnet` — but as one of
  D1's two named exemptions, not as "mechanical cross-checking". State the
  exemptions with their reasons, because a row without one is a row the next
  reader deletes.
  **This file matters more than its path suggests:** `README.md:187-293` calls
  it the FULL SPECIFICATION, so it outranks the README for anyone who follows
  the pointer.
- **F2 — `plugins/delivery-pipeline/commands/investigate.md:58`** reads
  `… model research --type facts` (→ `sonnet`, …). Measured: `opus`/`high`.
  This is a shipped command doc AND one the Codex generator converts, so keep
  the mechanism-naming rule in mind while editing (`CLAUDE.md`: the generator
  rewrites the word "Claude" and bare `.claude/` paths).
- **F3 — `GSD_CORE_VERSION` has five homes and T-25-01 moved three.** Measured
  on the epic head:

  | file | value |
  |---|---|
  | `Dockerfile` | 1.13.0 |
  | `Makefile` | 1.13.0 |
  | `tests/smoke/codex-shipyard-smoke.sh` | 1.13.0 |
  | `docker-compose.yml:14` | **1.7.0** |
  | `.env.example:17` | **1.7.0** |

  So `cp .env.example .env` followed by a bare `docker compose build` installs
  the gsd-core version ADR-003 D1 moved off — a functional regression path, not
  a doc nit, and the only must-fix here that is not prose. Bring both to
  1.13.0. Note how it survived: T-25-01's verification grep named exactly the
  three files it changed, and T-25-04 edited *both* stale files (adding
  `ANTHROPIC_DEFAULT_FABLE_MODEL` six lines from the stale default) without
  looking at the line above.
- **The regression guard, which is the durable half of this ticket.** Add one
  `tests/smoke/docs-smoke.sh` assertion: every home of `GSD_CORE_VERSION`
  agrees. Collect the value from each of the five files and fail with all five
  named when they differ — not a spot-check against a hardcoded string, which
  would need editing on every bump and would therefore rot the same way. The
  same shape as the plugin/capability version drift check the repo already has.

## Acceptance criteria

- `grep -nE "fable" docs/gsd_multilevel_delivery_pipeline.md` returns no line
  that assigns `fable` to a role by default; every surviving mention describes
  D4's earned routes or the Codex ceiling.
- `docs/…` §7.5's table matches what the resolver returns for all eight roles.
  Assert it by running `pipeline-config.cjs model <role> --json` for each and
  comparing to the table — a doc test that reads the code, so it cannot drift
  silently again.
- `grep -n "sonnet" plugins/delivery-pipeline/commands/investigate.md` shows no
  claim that `research --type facts` resolves to `sonnet`; the line states
  `opus`/`high` and `xhigh` for `--type alternatives`.
- `docker-compose.yml` and `.env.example` both name 1.13.0; the five-home
  agreement assertion passes.
- **The guard bites:** set `.env.example`'s pin to 1.7.0 and `make test-docs`
  fails naming all five files and both values. Restore, and it passes. Record
  that mutation's output in the PR body — an assertion nobody has seen fail is
  not yet a guard.
- `make test-docs` and `make test-fast` pass.

## Test strategy

The pin agreement and the ladder-table check are both greps over tracked files,
so they belong in `docs-smoke.sh` where the repo already keeps that kind of
contract. Write the mutation check first: it is the only evidence the new
assertions do anything, and the repo has already shipped one assertion that
passed for the wrong reason (a `grep -q` against a file a NUL byte had made
binary). Nothing here needs Docker or the network.
