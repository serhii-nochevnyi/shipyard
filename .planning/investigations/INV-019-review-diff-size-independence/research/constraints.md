## 1. Summary — the constraints that most narrow the option space

1. **The repository contains no context-window number for any model in the Claude 5.5 or Codex 6.1 grids.** The only window-like number is the routing threshold `WINDOW_THRESHOLD_TOKENS = 250000` [R model-policy-internal.cjs:40,306]. The README, capability file and policy contain none [G, E13]. The phase-50 `prompt_too_long` at an *estimated* 640,131 tokens is the only measured failure point, and the estimator is `ceil(bytes/4)` of the JSON [R context-packet.cjs:315-320]. The real window, and whether the estimator under-counts escaped diff text, are unknown (U1).
2. **A review that reads everything in one session is bounded by the window on both runtimes, not by the byte constants.** Codex rejects any native review session containing a context-compaction record [R codex-runtime-host.cjs:1529-1531]. Claude has no compaction detection at all [G "compact|truncat" claude-runtime-host.cjs,role-artifact.cjs → no match] and no per-launch turn or time limit [E14]. Raising `DIFF_MAX_BYTES`/`INTEGRATOR_MAX_PACKET_TOKENS`/`FILE_LIMITS.material` therefore cannot remove the dependency (consistent with `PROBLEM.md`).
3. **"Review-completeness enforced by the host" has three different strengths today** (§2.3): Codex proves native reads of every chunk and rejects compaction; Claude-integrator proves the complete packet was in the model input and echoes a declared coverage inventory; the focused architecture review (Claude, ticket and phase) is **declarative** — the host checks `review_completeness`/lists shape and gates on `complete`, and the reference itself says the declarations "do not prove reading" [R arch-review.md:85-86,124]. "Unchanged in strength" is therefore per runtime×role cell, and whether a new mechanism may stay at the declarative strength or must prove coverage is an open user decision (U7).
4. **One dispatch = one launch = one receipt = one sealed judgment.** A host instance accepts one request [R claude-role-host.cjs:1437-1438], the boundary demands exactly one authenticated launch [R :1146-1152,1494], and `sealJudgment` binds one `dispatchId` [R :1418-1429]. Any chunked/map-reduce/per-unit design needs N dispatches and an aggregation record type that does not exist today; that is a new sealed contract, not a parameter.
5. **Host-owned authority keys are rejected recursively anywhere in a packet** (`receipt`, `selection`, `resolution`, `launch`, `agent`, `model`, `effort`, `capabilities`, …) [R context-packet.cjs:34-38,196-205; test context-packet.test.cjs:218]. Per-chunk coverage records that carry receipts must live host-side (authority namespace or sealed immutable files), not inside a model-visible packet; renaming keys to slip past the check would defeat its purpose (design question, not a workaround).
6. **The Claude child can read only inside the worktree with its file tools** (`blockReadsOutsideWorkingDirectories: true`, pinned by a test) [R claude-runtime-host.cjs:760; test claude-runtime-host.test.cjs:256], and the worktree must stay clean except the evidence file and host-owned scratch [R claude-role-host.cjs:1211-1249]. Host-built reading material (manifests, chunk files) must therefore live outside the worktree, where the existing Claude relay assumes the child can read it — never exercised against a real child (U3).
7. **Claude tool-heavy reviews hit hard evidence ceilings before any window**: stream ≤ 10,000 records and session transcript ≤ 50 MiB at launch [R claude-runtime-host.cjs:276,33,508], then, when a retained Claude review is verified downstream (`originalCurrentResponse`, second-runtime branch), the stream is re-parsed under the same 10,000-record cap and the session transcript must be ≤ 128 MiB and ≤ 20,000 rows [R role-artifact.cjs:3148,3188-3215]. Result ≤ 128 KiB, judgment envelope ≤ 8,192 B, summary ≤ 500 chars [R claude-role-host.cjs:36; role-artifact.cjs:32-33].
8. **The generated mirror must not be excluded by editing `development-artifacts.cjs`.** `isDevelopmentArtifact` also drives CI scope, the comment-policy generated-copy parity check, scope-gate, PR hygiene and the unresolved-review-thread gate (§4). A review-specific exclusion is required, and mirror parity must remain proven elsewhere (§4, MX-3).
9. **Any edit to the review host files invalidates retained focused verdicts bound to the old installed digests** (11 producer files are pinned into each verdict and re-checked at consumption) [R codex-arch-review-context.cjs:1382-1387; role-artifact.cjs:3265-3275]. Rollout needs a plan for in-flight PRs (U9).
10. **The package/digest rules are lighter than they look for this work**: `tests/unit/runtime-file-digests.json` pins only `claude-dispatch-adapter.cjs` and `runtime-adapters.cjs` [E04]; the review host files are not pinned there. But every edit under `plugins/delivery-pipeline/**` changes the generated mirror and its digest/version, and parity is enforced for PRs not based on `epic/*`/`ticket/*` [R package-shipyard-codex.cjs:71-74; E11].
11. **Neither review role is exercised by any automated live gate**: `live-receipt.cjs` requires only the stages research, decompose, executor, publish, sentinel [R live-receipt.cjs:9]; `make test-live` runs `tests/live/live-round.sh` [R Makefile:~124-126]. A size-independent mechanism has no automated live proof at scale unless one is added.
