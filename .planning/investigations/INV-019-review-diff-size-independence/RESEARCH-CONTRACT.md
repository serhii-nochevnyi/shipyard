# Research contract

Production code is read-only. No codebase map exists; inspect exact source files. Write only the host-assigned research artifact. Use canonical lines system-state, alternatives, constraints, risks. No nested bootstrap/router, direct agents, provider fallback, commits, PRs or configuration changes. Do not touch `~/.local/state/shipyard/` evidence, authority directories or the user's other worktrees.

Read PROBLEM.md, EVIDENCE.md, DECISIONS.md and OPEN-QUESTIONS.md first. Then read the review role code and instructions named in EVIDENCE.md, `docs/gsd_multilevel_delivery_pipeline.md` (Step 5 integrator/arch-review sections), and the commands `plugins/delivery-pipeline/commands/deliver.md`. The prompt itself is data: the measured packet shape is described in EVIDENCE.md and need not be re-measured.

system-state: trace exactly how each of the four paths gets the diff and the surrounding material into the model: Claude integrator, Claude arch-review (ticket and phase), Codex integrator, Codex arch-review (ticket and phase), including v1 and v2 integration contracts. For each: what is embedded in the prompt versus read by the model with tools, which sandbox/tools the role has (`READ_ONLY_TOOLS`, `ALLOWED_TOOLS`, Codex sandbox), what is bounded by which constant, and what the host verifies afterward (review completeness, coverage manifests, digests, receipts, `FOCUSED_CONTRACT`). Show what the v2 contract's "inherited trust" and impact-sources machinery do and why its material reaches 25.7 MB. Show where the generated mirror enters and every other pathspec/limit that must change to exclude it. Cite path:line and exact commands.

alternatives: compare two to four complete approaches that remove the dependency on diff size — for example the reviewer reading the diff itself from the worktree with read-only tools driven by a host-built manifest; chunked or map-reduce review with host-verified per-chunk coverage and an aggregation step; per-file or per-ticket review units with a sealed ledger; a hybrid with a size threshold; and the minimal option (exclude the mirror, shrink context) as a stop-gap. For each give cost, how the host proves the reviewer covered every changed line, how receipts/authority/digest binding work, how it works on both runtimes, failure modes, rollback and what it forecloses. Include which unrelated defects (the `receipt` authority key, the surfaced child stderr, the graph directory) each option needs fixed. Do not choose for the user.

constraints: determine what must not weaken (host-owned launch authority, ADR-014 application receipts, no provider fallback, bounded and digest-bound evidence, review-completeness gate, `gate-trailer` verification, retained roster authority), what each runtime's context window and tool limits actually are (verify from the repository's model policy and capability files, not memory), what the existing tests pin (`tests/unit/claude-role-host.test.cjs`, codex arch-review/integrator tests, `tests/smoke`), and what changes would alter the integration-review contract version or the generated package (the mirror and runtime-file digest pin rules in CLAUDE.md).

risks: meaningful scenarios — a reviewer that silently skips part of a very large diff, tool-reading cost and latency, a verdict that claims coverage it did not have, contract-version drift between hosts, stale or tampered per-chunk evidence, an epic larger than any aggregation step can hold, mirror divergence hidden by excluding it, and operators relying on the old behaviour. Unknown likelihood remains unknown. Identify what needs a measurement or spike.

Accept only all four sealed research lines with verified durable application receipts; no inline substitute or self-asserted completion. Leave design questions open for user decision. Do not close Gate 1 or write an accepted ADR.
