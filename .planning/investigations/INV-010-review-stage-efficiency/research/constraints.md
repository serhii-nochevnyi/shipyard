## 5. What the constraints imply for the four questions (constraint-derived bounds, not recommendations)

1. **Launch timing.** Today arch-review already waits for green CI, zero threads and a current base in the current tick (C-P4), and stacked children already wait for parents (C-P3). The only unconstrained timing lever left is **sibling ordering on a shared epic** (R3). Deferring "until the base stops moving" must keep human-checkpoint holds (C-P2) and must not make an unjudged head mergeable (C-H1).
2. **Review input.** Changing from the merge-base diff (C-H12) to an owned-path or own-patch input is a C1 manifest-version change (C-H7, C-H16). It must also stay consistent with the T-43-13 proof, which already treats the own patch as the carried unit (C-H5).
3. **Carry and reuse.** In the sibling cascade C1 cannot help, because the base changes (C-H7). The carry today is tree-equality only (C-H3), and it is lost whenever a conflict is pushed by hand (C-H4). T-43-13 removes most of that, but only after T-43-06 and the checkpoint (C-H6). Any additional carry rule must be an object-identity proof, not a judgement, and must not chain (C-H8, C-S4).
4. **Model and effort by diff size.** It is blocked behind an ADR-014 amendment, a new policy hash and an ADR-021 experiment (C-H14, C-H15). Because it would change `inputTokens` and the rung, it also interacts with the reuse key (C-H16).
5. **Preconditions.** The draft contradiction (C-H10) is decidable before a model turn: a host precondition refusal costs no launch today because it rejects in `prepareArch`. A spike or unit check is still needed to confirm that it rejects before the boundary dispatch; see U3.
6. **Codex parity.** It is limited by the absence of a Codex arch-review host (C-H13).
