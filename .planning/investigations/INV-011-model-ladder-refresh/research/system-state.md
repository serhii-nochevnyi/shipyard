## Current entry points and data flow

The nine routed roles are `research`, `decomposition`, `executor`, `pr-sentinel`, `integrator`, `drift-check`, `arch-review`, `ci-fix`, and `review-fix`. `model-policy-internal.cjs` owns two independent grids, signal rules, predecessor tuples, and a SHA-256 policy fingerprint. Its active identity is `adr-014.v6` / `30e71fb4066fee5b67df14120532c0b4f8aedde169907bc16f70dd2569744968` (`plugins/delivery-pipeline/scripts/model-policy-internal.cjs:26-59,68-203,237-322`) [V4,V5]. The resolver validates exact model, effort, rung, launch mechanism, version and hash; caller-supplied `inline`, `inherit`, or conflicting model/effort is refused (`model-policy-internal.cjs:880-959`) [V6]. `pipeline-config.cjs` passes loaded configuration into canonical resolution and checks project/GSD override sources after resolution (`plugins/delivery-pipeline/scripts/pipeline-config.cjs:1398-1465,1765-1798`) [V7]. Project `.planning/config.json` currently declares `model_profile: balanced`; it is not a license to change the routed grid [V8].

Present concrete mappings are `sol=gpt-6-sol`, `luna=gpt-6-luna`, `astra=gpt-6-astra`, `sonnet=sonnet`, `opus=claude-opus-5-5`, and `fable=fable` (`plugins/delivery-pipeline/scripts/runtime-adapters.cjs:9-19`) [V9]. Astra is registered but unselected. When the expected value is the `sonnet` alias, both adapter and Claude CLI host accept any `claude-sonnet-<number>...`; an observed older Sonnet can therefore satisfy today's alias request. Both functions already fall back to exact equality for a pinned expected value such as `claude-sonnet-5-5` (`runtime-adapters.cjs:26-30`, `plugins/delivery-pipeline/scripts/claude-runtime-host.cjs:295-299,320-340`) [V9,V10]. This matters for the proposed Claude executor ladder: its extra Sonnet/high and Opus/high transitions need a specified, authenticated signal/attempt rule, rather than a model-string edit. ## Repair chain and installed state

Predecessor requirements are generated from adjacent rungs, rather than maintained as a second manual table (`model-policy-internal.cjs:237-265`) [V4]. Today, `repeat` requires a verified Luna/max Codex receipt or Opus 5.5/medium Claude receipt; `repeat_exhausted` requires the preceding Sol/high Codex or Opus 5.5/high Claude receipt (`model-policy-internal.cjs:95-103,138-147`) [V4]. The boundary rereads the durable predecessor by `previous_dispatch_id`, checks matching ticket/runtime/role and exact requested **and** applied tuple, and prevents double consumption (`plugins/delivery-pipeline/scripts/dispatch-boundary.cjs:1860-1929`) [V18]. A receipt-shaped caller object cannot authorize escalation (`model-policy-internal.cjs:469-515`) [V19]. The approved target requires these exact new-policy chains for each fixer (`docs/audits/2026-09-30-model-ladder-refresh.md:80,99`) [V3]:

| Runtime | First | `repeat` requires verified first receipt, then selects | `repeat_exhausted` requires verified repeat receipt, then selects |
|---|---|---|---|
| Codex | Sol 6.1/low | Sol 6.1/low → Sol 6.1/high | Sol 6.1/high → Sol 6.1/xhigh |
| Claude | Sonnet 5.5/high | Sonnet 5.5/high → Sonnet 5.5/xhigh | Sonnet 5.5/xhigh → Opus 5.5/high |

Old v6 receipts must remain v6 evidence and cannot be relabeled as new-policy predecessors; exact policy hash is checked on resolution/receipt (`model-policy-internal.cjs:886-889`; `dispatch-boundary.cjs:1331-1371`) [V6,V18]. Model-axis escalation also checks a host capability snapshot and completed prior attempt, with bounded predecessor fallback if unsupported or unknown (`plugins/delivery-pipeline/scripts/model-capability.cjs:38-80,117-134`; `dispatch-boundary.cjs:2025-2061`) [V20]. Effort-only transitions still pass adapter pair validation [V13,V16].

Read-only installed checks found the Codex bundle and 14-agent manifest on `adr-014.v6` with the same hash as source [V21]. Its stored capability document lists `gpt-6.1-sol/low` as a supported pair [V22]. That is evidence of a persisted capability assertion, not of a new policy, a live host application, or installed Claude identity. Installed Claude plugin provenance and live Sonnet 5.5 effort application are **unknown**; next checks are the host provenance/marketplace inspection followed by a bounded host-owned dispatch after policy activation. Outer coordination is a separate seam: the native nine-role policy does not select its parent model; ADR-023 still describes inherited outer Codex identity and a later explicit-selection candidate (`.planning/architecture/ADR-023-residual-pipeline-efficiency.md:26-39`; `docs/audits/2026-09-30-model-ladder-refresh.md:115-131`) [V23].
